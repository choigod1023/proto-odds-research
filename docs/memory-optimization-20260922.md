# 1GB 유지 우선 메모리 최적화

## 적용 범위

- 실시간 배당 수집에서 사용한 전체 픽 객체를 하위 갱신 전에 해제한다.
  하위 갱신은 최신 DB를 다시 읽는다. 오래된 수집 스냅샷 재사용으로 다른 게시자의
  변경을 덮어쓰지 않는다.
- API는 상세 경기 객체를 개별 압축해 보관하고 요청한 경기만 해제한다.
  목록에는 기존 카드 필드만 보관하고, 쓰지 않는 prediction_performance 캐시는 제거한다.
- 캐시 갱신 실패 시 기존 캐시는 유지한다. 추천 기준, 원장, 수집 주기, DB 쓰기,
  서버 크기와 작업 스케줄은 변경하지 않는다.
- 기존 PR #221의 불필요한 전체 DB 응답 읽기 방지 수정은 이 PR에 포함하지 않았다.

## 동일 데이터 비교

입력: origin/main 1cf4cd56의 docs/data/picks_v2.json, 12,831,809바이트.
Windows 로컬 Python에서 각 변형을 새 프로세스로 실행했다. 메모리는 tracemalloc의
Python 할당량이며 OS RSS, SQLite, 운영체제, 동시 HTTP 요청 전체의 사용량이 아니다.
서버의 현재 데이터 크기와 다르므로 운영 절감량으로 그대로 환산할 수 없다.

- API recent/all/detail 조회 후 유지 할당: 29,811,046 → 21,715,209바이트, 27.2% 감소.
- API 최초 적재 최대 할당: 양쪽 58,662,460바이트. 최초 전체 JSON 읽기는 아직 남는다.
- API revision 변경 최대 할당: 88,479,993 → 80,326,900바이트, 9.2% 감소.
- 배당 갱신의 연속 전체 문서 읽기 구간 최대 할당: 86,008,424 → 58,685,451바이트,
  31.8% 감소. 수집·분석·DB 저장 전체 실행을 측정한 수치는 아니다.
- 할당 추적을 끈 별도 실행의 캐시 최초 구성: 0.103 → 0.185초.
- 상세 1건 조회: 약 0.008 → 0.225밀리초. 압축 해제 비용이 추가된다.
- 캐시 적중 조회: 양쪽 약 0.002밀리초. 실제 HTTP 응답 직렬화 시간은 제외한다.
- recent/all/detail 응답의 SHA-256은 전후 모두 동일했다.

재현: scripts/benchmark_match_cache.py의 설명대로 --base 1cf4cd56과 현재 코드를
각각 실행한다. --trace는 메모리, 생략하면 시간, --collector는 연속 문서 읽기 비교다.
운영 서버에 이 벤치마크를 추가 실행하지 않는다.

## 비용 판정

2026-09-22 확인한 [Fly 공식 가격](https://fly.io/docs/about/pricing/)의 도쿄(nrt),
30일 상시 실행 정가 기준:

- 공유 CPU 1개 / RAM 1GB: $7.45.
- 공유 CPU 1개 / RAM 2GB: $13.99. 1GB 유지 성공 시 월 $6.54, 12개월 $78.48의
  추가 비용을 피할 수 있다.
- 공유 CPU 2개 / RAM 2GB: $14.90. 현재 대비 월 $7.45 추가.
- 기존 10GB 볼륨 $1.50은 변화 없으며 트래픽, 백업, 세금, 할인은 별도다.

아직 실현된 절약액은 없다. 증설을 하지 않았고, 최적화도 운영에 배포하지 않았다.
이번 두 변경의 절감량을 단순히 더해 1GB 충분하다고 판단해서는 안 된다.

## 배포 승인 후 통과해야 할 조건

- 전체 재계산, 실시간 배당, 선수 정보 작업이 겹치는 주기와 경기 집중 시간을 포함해
  OOM이 없는지 확인한다. 6시간 전체 계산 주기를 포함하고 가능하면 24시간을 본다.
- /proc/meminfo의 MemAvailable, 프로세스별 RSS/최대 RSS, 작업 소요시간/대기시간,
  API p95 응답시간과 원천 대비 점수·배당 갱신 지연을 변경 전후 동일 조건으로 비교한다.
- 목표 여유 메모리는 피크에도 150~200MB 이상이며, 대기열이 계속 늘어나면 실패다.
- 부족하면 중복 응답 읽기 방지(PR #221)와 계산 동시성 제어를 추가 검증한다.
  무조건 직렬화해 실시간 갱신을 지연시키거나, RAM 증설로 CPU 병목까지 해결된다고
  가정하지 않는다. 유료 증설은 별도 승인 없이는 하지 않는다.
