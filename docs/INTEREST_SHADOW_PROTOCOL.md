# 관심 픽과 검증된 추천

정책 ID: interest-shadow-v1. 이 변경은 실매수·운영 추천 원장 수정·자동 승격을 하지 않는다.

## 표시 계약

기존 55%·배당 1.50 이상 자격 후보는 관심 픽이다. 현재 승인된 수익성 검증
정책이 없으므로 검증된 추천은 0개다. 과거 recommended 필드, 확률, 배당,
T-30 동결 기록은 변경하지 않는다. 0개 표시는 수집 실패나 경기 없음과 다르다.

## 재현 명령

저장해 둔 추천 API JSON을 입력으로 사용한다. 원본 파일은 변경하지 않는다.

```text
python scripts/audit_recommendation_shadow.py snapshot.json --output audit.json
python -m unittest tests.test_recommendation_shadow_audit
```

보고서는 새 파일만 생성한다. 기존 파일을 덮어쓰지 않으며 원본 SHA256을 기록한다.
원본 JSON의 generated_at을 평가 종료 시각으로 사용한다.
네트워크 호출, 운영 DB 접근, 백그라운드 반복 작업은 이 도구에 없다.

## 고정한 모의 규칙

- 회당 1만 원, 같은 회차의 서로 다른 경기 두 개, 하루 최대 한 조합.
- 주간은 KST 월요일~일요일, 주 최대 2회와 3회를 별도 계좌로 비교.
- 같은 경기 재사용 금지. 경기 시작 30분 전까지 실제 보존된 후보만 사용.
- 기록상 조합이 처음 가능한 시점에 확률 곱이 높은 두 픽을 선택.
- 월 손익에서 모든 미정산 베팅과 다음 1만 원을 차감했을 때 -5만 원 미만이면 보류.
  전월 미정산도 보수적으로 노출에 포함. 수익 목표에 따른 증액은 없다.
- 공식 결과의 settled_at에 정산. 한 경기의 공식 실패만 확인돼도 조합은 실패.
  둘 다 적중/무효인 경우 양쪽 공식 정산을 기다림. 무효는 배당 1로 계산.
- 원래 배당을 곱한 후 소수 셋째 자리 절사, 둘째 자리 올림으로 조합 배당 계산.
- 월 손익은 구매 월 기준, 최대 낙폭은 실제 정산 순서 기준.

historical_flags_mixed_policies는 당시 recommended=true 기록을 사용한다.
p55_proxy는 보존된 후보에 확률·배당 기준만 재적용한 비교용이며
현재 모델의 전체 자격 규칙이나 모든 대안 픽을 재현한 것이 아니다.
검증된 추천의 무베팅 대조군은 손익 0원, ROI 미정의다. 이는 수익 개선이 아니다.

## 다음 시점의 검증

audit_recommendation_shadow.py는 과거 스냅샷 재생이며 전향 운용과 구분한다.
사전에 정책과 의사결정 시각을 고정하고, 그 시각의 원본 스냅샷 및 선택 두 개를
변경 불가 기록으로 보존해야 미래 검증이 가능하다. 나중의 최종 원장으로
과거 구매 기회를 재구성해서 전향 검증이라고 부르면 안 된다.
현재 API가 오래된 생성본을 제공하면 최신 관측이나 새 모의 선택으로 인정하지 않는다.

2026-10-12 승인에 따라 forward-paper 워크플로가 매시 7분/37분 실행하도록 예약한다.
GitHub 예약은 지연될 수 있다. 별도 codex/paper-state-v1 브랜치의 paper/journal.json에
원본 SHA256·정확한 선택 revision·실제 관측 시각을 기록한다. 기존 이벤트는 수정하지
않고 정산 이벤트를 추가한다. SHA 기반 동시 갱신 충돌은 실패로 처리한다.
상태 파일이 없으면 일반 실행은 실패한다. 최초 workflow_dispatch에서만 initialize=true.
이미 존재하는 상태 브랜치의 원장이 없어진 경우 초기화 요청도 거절한다.

확률순/기대수익률순 × 주2회/주3회의 네 계좌는 독립적인 가상 비교 계좌다.
각 계좌 한도는 5만원이며 실제 베팅 권한이나 총 실매수 예산을 뜻하지 않는다.
현재 정책 ID가 일치하는 경기 전 추천 기록만 사용한다. 기대수익률순은 순위만
비교하며 음수 기대수익 후보도 포함한다. 검증된 추천이나 수익 보장으로 승격하지 않는다.
이미 판정된 후보, 미래 관측시각, T-30 이후, 2시간 넘게 오래된 생성본/후보는 새 선택 금지.
미정산은 월이 바뀌어도 노출에 남긴다. 관측 전 정산으로 구매를 소급하지 않는다.

정산 및 데이터 상태 전환은 같은 GitHub 이슈로 보고한다. 변화가 없으면 반복 알리지
않는다. 알림 성공 확인을 원장에 남겨 실패 시 다음 실행에서 재시도한다
(전송 직후 확인 기록 실패 시 중복 알림 가능). GitHub 이메일 수신은 구독 설정에 따른다.
운영 수집 서버에 작업을 추가하거나 DB를 변경하지 않는다. 서버 API는 읽기 전용이다.

별도 기간에서 확률 오차, 월별 손익, ROI, 최대 낙폭, 손실 한도 도달,
고배당 소수 적중 의존도를 함께 검토한다. 표본 수와 미정산 비중도 공개한다.
수익 목표에 맞춘 확률 조정이나 결과를 본 뒤 기준 변경은 하지 않는다.
정책 승격과 운영 반영은 별도 검토가 필요하며 이 PR은 자동 승격 경로를 제공하지 않는다.
