# 추천 갱신 정체 수정

2026-09-25 읽기 전용 점검에서 추천 API generated_at은 09-24 07:51 KST였고,
배당/픽은 09-25 21시대로 갱신돼 있었다. 최근 운영 로그에서 실시간 추천은
여유 75~410MB 상태에서 512MB 시작 조건을 기다렸다. 이는 확인한 최근 구간의
실행 지연 원인이며, 38시간 전체의 모든 원인을 입증한 것은 아니다.

독립 추천 반복 작업을 제거하고 배당 자식 프로세스가 종료된 뒤 추천을 실행한다.
성공 후 최소 300초 간격, 실패/메모리 부족/다른 보조 작업 실행 중이면 다음 배당
종료 때 재시도한다. 보조 작업 잠금 획득은 비차단이며 추천 실행은 90초 제한이다.
실시간 점수와 HTTP는 계속 독립 실행한다. 기존 512MB 보조 작업 제한은 유지한다.

추천용 picks 읽기는 필요한 필드만 SQLite에서 투영하고 해당 후보 경기만 보관한다.
추천 후속 실행의 시작 여유는 256MB다. 이는 보수적 운영 가설이며 실제 운영 최대
메모리를 측정해 안전성을 증명한 값은 아니다. 시작 뒤 증가/다른 실시간 작업과의
경합으로 OOM이 여전히 가능하다. 배당 재실행이 추천 수행 시간만큼 늦어질 수 있다.
새 메모리 대기/실행/실패 로그로 갱신 진행 여부를 구별한다.

추천 예외는 이제 단발 실행에서 exit 1을 반환해 성공으로 잘못 기록하지 않는다.
기존 추천 기준과 동결 기록은 바꾸지 않는다. 병합과 배포는 별도 승인 후 진행하며,
배포 후 추천 생성시각, 배당 지연, 새 OOM, 최대 RSS를 확인하기 전에는 운영 복구나
1GB 장기 안정화를 완료했다고 판단하지 않는다.
