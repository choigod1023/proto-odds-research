# 하이브리드 교체 절차

2026-10-25. 후보는 기존모델75%·픽스터25%, MLB 정규 승패(two-way)로 한정한다.
기존 28경기는 이미 탐색한 자료로, 승인 표본에서 제외한다. 현재 상태는 교체 불가다.

## 순서와 통과 조건

1. 정산 파이프라인: 사전 원장·당시 배당·선택·시장·경기시각을 보존한다.
   공식 결과를 연결하며 미정산은 0원 수익으로 취급하지 않는다. 기존 관심픽
   모의계좌는 하이브리드 비교의 근거로 혼용하지 않는다.
2. 고정 프로토콜: 후보 코드/설정 해시, 모집단, 수집시각, T-30, 작성자 중복 제거,
   정오ET 의사결정, 단폴·두폴 규칙, 제외 사유를 전향 수집 시작 전에 동결한다.
   3개 팔(기존/픽스터/75:25)을 동일 시점·동일 경기에서 기록한다.
   후보를 재튜닝하면 버전을 바꾸고 새 독립 평가 구간을 시작한다.
3. 공식 결과 검증: 경기ID·날짜·홈/원정·시장·핸디캡/기준점이 일치해야 한다.
   결과 충돌/누락/변경된 배당·확률은 자동으로 느슨하게 연결하지 않는다.
   평가 대상 전체와 제외/미정산 건수를 함께 공개한다.
4. 모의 자금: 한 장1만원, 주2회/3회는 별도 가상계좌, 월 순손실5만원과
   미정산 최악 손실을 함께 제한한다. 평가의 주 비교 계좌를 미리 지정한다.
   여러 가상계좌의 예산을 실베팅 허용금액처럼 합산하지 않는다.
5. 정기 평가: 매일 관측하되 매일 좋은 후보를 다시 고르지 않는다. 기존
   scripts/model_review.py의 연구용 선별 기준(각 전략300티켓,26주,2시즌,
   ROI 및 기준모델 대비 개선의 보정된 하한>0,낙폭/손실연속/커버리지 비악화)을
   기본으로 유지한다. 이는 보장이나 검정력 산정값이 아니다. 소표본을 이유로
   수익이 좋아 보일 때 기준을 낮추지 않는다. 주2~3회면300티켓은 장기간이 필요하다.
   연구 선별기는 전향 출처를 인증하지 않으므로 그 통과만으로 운영 승격하지 않는다.
6. 제한 적용: 독립 평가·출처 검증이 통과하면 별도 승인 PR을 만든다.
   CI,사용자 병합·배포 승인,직전 모델로 복구 가능한 설정이 필요하다.
   MLB 대상에만 단계적으로 표시하고 다른 종목에 일반화하지 않는다.
   데이터 신선도/T-30/공식 결과 불일치 시 신규 후보 표시를 중지하고 원장은 보존한다.

현재 구현된 것은 아래 정산 복구와 읽기 전용 감사다. **하이브리드 전향 수집·
3개 팔 자동 모의계좌·승격 자동화는 아직 활성화하지 않았다.**
기존 forward-paper GitHub Actions의 성공은 ROI 검증 성공이 아니다.

## 이번에 확인한 장애와 수정

운영 원장83이벤트:bet18,settlement0,attention18. API의 동일ID36개 leg가 모두
게시/기록시각 변경으로 exact identity에서 탈락했다. 4개 leg는 배당·확률도 달랐다.

수정은 **게시/기록시각만 변경된 재게시**에 한정한다. 원장 revision은 그대로이며
경기/시장/선택/배당/확률/정책 등 나머지 필드는 모두 일치해야 한다. 시각이 미래,
원본이T-30뒤,중복/충돌이면 거부한다. 공식 결과와 정산시각 검증도 그대로다.
배당/확률이 달라진4개 leg는 계속 거부한다. 단, 이미 다른 leg가 공식 실패한
티켓은 기존 규칙대로 전체 손실로 정산할 수 있다.

로컬 관측2026-10-25:매칭0→32/36,기존티켓18건 중16건 정산 가능.
운영 원장은 수정하지 않았다. 이 손익은 과거 관심픽 계좌 결과이며 하이브리드가 아니다.
늦은 정산을 지금 관측했으므로 그 사이의 가상 재투자를 소급 생성하지 않는다.
