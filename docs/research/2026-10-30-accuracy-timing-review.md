## 총괄의 시각 수정

복제된 `publication_rejection`을 Python으로 직접 호출해 UTC와 +09 동시각, 결정 시각 동일/1마이크로초 뒤, 시간대 없는 프레임 시작 시각, 누락 결정/시작, 누락 게시 시각, 결정=시작, 프레임 시작 불일치를 검사했다. 게시가 결정 이후면 거부했고 나머지 예외도 의도대로 거부했다. 결정과 같은 게시 주장은 허용하며 이는 `publication <= decision` 조건과 같다. 회고 자료의 실제 최초 수신이나 구매 가능 가격을 증명하지는 않는다.

**남은 신뢰 경계:** 이 함수는 전달받은 `decision_at` 자체의 출처나 불변성을 검사하지 않는다. 합성 게시 09:40, 경기 10:00에서 decision 09:30은 거부되지만 decision을 09:45로 바꾸면 통과한다. 임의 decision이 위조 가능하다는 뜻이 아니라, 이 함수만으로 선택한 결정 시각의 진위를 증명할 수 없다는 뜻이다. 호출 경로는 case의 결정 시각을 넘긴다. 독립 판정 또는 스냅샷 원장과 event·상품·decision의 동일성을 검증해야 전향 증거가 된다.

또한 함수는 프레임의 event ID·리그·팀을 인자로 받거나 검사하지 않는다. 호출자는 `event_id`로 프레임 dict를 찾지만 dict 생성 때 중복 ID는 마지막 프레임으로 덮어쓰며 리그·팀은 재확인하지 않는다. 합성 프레임의 ID·리그·팀을 바꿔도 시작 시각과 게시 시각만 맞으면 검사 함수는 통과한다. 해당 문제는 미래 입력에 대한 방어 공백이며 이번 실제 445건에서 오연결이 일어났다는 주장이 아니다. 실제 상위 원천 프레임 597건의 중복 event ID는 0이고, 저장된 2026 실제투표 445개에 대응하는 case 445행과 frame의 리그·홈·원정 이름 불일치도 0이었다. 원천 이름과 경기 ID 자체의 진위는 별도로 확인하지 않았다. 최소 제안은 프레임 중복 ID 거부, case와 프레임 event ID·리그·팀의 검증된 동등성 확인, decision의 출처·상품 연계를 명시적으로 요구하는 것이다.

## 검증의 범위

`tests/test_accuracy_timing_review.py`의 합성 검사는 본문에 명시한 방어와 반례를 재현한다. v1.1과 매칭 모듈의 복제본은 지정 PR head에서 가져왔으며, 총괄 변경이나 다른 워커 파일을 고치지 않았다. 최초 전체 pytest는 테스트 원문을 `test_*.py` 이름으로 복제해 경로가 맞지 않아 수집에 실패했고, 복제 이름을 `.txt`로 바꾸어 다시 실행했다. 정확도, ROI, 소스 원본 HTTP 바이트, 외부 수신 인증과 실제 배포는 검증하지 않았다.
