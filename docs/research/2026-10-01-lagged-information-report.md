# 과거 경기 정보가 시장 확률에 더하는 값

이번에는 같은 확률 변환을 다시 비교한 것이 아니라, **실제로 과거 슈팅·일정·
시장 예상 대비 결과를 연결해** 검증했다. 첫 fold의 선택 모델은 시장보다
소폭 나았지만 다음 fold에서는 개선이 이어지지 않았다. 따라서 추가 정보
검증 경로는 구현·실행했으나 안정적인 우위나 운영 채택을 입증한 것은 아니다.

## 무엇을 추가했고 무엇이 이미 있었나

`src/features.py`의 휴식/폼, `soccer_process.py`·`soccer_process2.py`의 K리그
유효슈팅 검정, `accuracy_formula_lab`의 시장 잔차 모델은 기존 자산이다.
이번에는 같은 개념의 유럽 자료 적용을 **7일 지연·학습 전용 스케일링·
bias-only 대조군·피처 제거 비교**로 검사했다. GAP나 새 알고리즘의 발명은 아니다.
기존 토너먼트의 loader 검증, Shin, fold 가드, 정책·정산·bootstrap을 재사용했고
기존 스크립트·결과·운영 코드는 변경하지 않았다.

## 실행과 누출 방지

- 프로토콜은 실제 자료 실행 전 `eaaf6f43`로 단독 커밋했다. 동결 전에는 12개 CSV 헤더만 읽어 통계 열을 확인했다.
- source는 `footballdataset` 고정 커밋 `e82cf59161e82e0fbcdc49ad02819e45c821a5c8`, D1/SP1 2019/20–2024/25, 총 4,116경기다.
- 배당 누락은 0건, D1 2024/25 경기 하나의 HS/AS/HST/AST가 누락이었다. 경기 자체를 빼지 않고 해당 과거 통계만 결측으로 처리했다.
- 슈팅·유효슈팅 순차이와 시장-surprise는 최소 7일 이전의 최근 8경기만 쓴다. 현재 경기 통계·결과는 자신의 피처에 들어가지 않는다.
- 휴식(30일 상한)과 최근 7/14일 경기 수는 현재보다 이른 경기 날짜만 읽는다. 결과는 읽지 않으므로 최근 7일 안의 일정도 사용한다. 동일 날짜는 갱신하지 않는다.
- 휴식 자료는 당시 일정 스냅샷이 아닌 최종 역사 날짜이고, 국내 리그 밖 컵·유럽대항전·대표팀 경기가 빠져 있다. 실제 피로 전체를 측정하지 않는다.
- 결측 중앙값·평균·표준편차는 학습 자료에서만 추정한다. 신규 팀은 미래 집계를 쓰지 않으며, 전부 결측인 학습 열만 0을 기본값으로 쓴다.
- `softmax(log(Shin)+XB)`의 모든 계수(절편 포함)에 평균 NLL 기준 ridge .1/1/10을 적용했다. 시장 쪽으로 강하게 축소하며 피로의 부호도 고정하지 않는다.

Fold A는 2019–21 학습/2022 inner/2023 outer, B는 2019–22 학습/2023
inner/2024 outer다. 선택 뒤 train+inner로 재적합하고 outer 기간에 계수는
고정한다. 온라인 통계에는 7일 지난 결과만 추가한다. 각 outer는 686경기다.
이미 노출된 자료이며 첫 outer가 다음 inner로 재사용되므로 새 holdout이 아니다.

bias-only, 슈팅, 일정, surprise, 전체, 슈팅 제외, 일정 제외, surprise 제외의
8개 구성×ridge 3개+Shin=fold당 25개, 총 **50개 후보 평가·128회 리그별 적합**이다.
실제 자료 실험은 **1회**, 계산 약 10.21초(다운로드 제외), 최적화 실패는 없었다.
선택은 inner log loss만 사용했으며 outer ROI로 구성이나 정책을 다시 고르지 않았다.

## 모든 피처 구성의 outer log loss

낮을수록 좋다. 각 행의 ridge는 해당 구성의 inner에서 선택한 값이며,
행 간 차이는 피처뿐 아니라 선택된 ridge 차이도 포함한다.

| 구성 | 2023/24 | 2024/25 |
| --- | ---: | ---: |
| Shin | .945030 | .968610 |
| bias-only | .944970 | .969147 |
| 슈팅만 | .944904 | .970372 |
| 일정만 | .944994 | .968862 |
| surprise만 | .945042 | .968541 |
| 전체 | .945265 | .968760 |
| 슈팅 제외 | .945658 | .968795 |
| 일정 제외 | .944976 | .968109 |
| surprise 제외 | .944630 | .970507 |
| 전체 inner 선택 | .944630 | .970372 |

전체 inner 선택은 첫 fold `no_surprise:r1.0`(슈팅+일정), 다음 fold
`shots:r0.1`이었다. 선택 모델−Shin log loss 차이의 주 단위 paired 95% CI는
각각 `[-.004265,.003140]`, `[-.002591,.006090]`이었다. Bias-only 대비 CI도
각각 `[-.004195,.003217]`, `[-.002856,.005386]`로 0을 포함한다.
2024/25의 일정 제외 행이 낮다고 그 행으로 승자를 바꾸지 않았다.
이 표본에서는 추가 피처의 안정적인 기여를 구별하지 못했다.

## 미리 고정한 정책의 가상 수익

각 리그/날짜 예산 1, 서로 다른 두 경기의 티켓 하나 이하, 부족하면 현금이다.
모든 H/D/A를 고려하며 조건이 허용하는 1.5 미만 배당도 포함한다.
`p60range`는 1.5≤배당<2.2인 역사적 대조 정책이지 현재 운영 전체의 복제가 아니다.
다음은 각 fold에서 inner가 선택한 모델을 이어 붙인 결과이며 총예산은 482다.

| 정책 | 적중/티켓 | 커버리지 | 적중률 | ROI | 예산수익 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 최고확률, EV 하한 없음 | 115/306 | 63.49% | 37.58% | -8.19% | -5.20% |
| p60range | 4/12 | 2.49% | 33.33% | -18.87% | -.47% |
| p60low | 50/86 | 17.84% | 58.14% | 5.05% | .90% |
| EV≥.02 | 3/68 | 14.11% | 4.41% | -26.94% | -3.80% |
| EV≥.05 | 2/22 | 4.56% | 9.09% | 63.64% | 2.90% |

전체 두 outer를 합친 최고확률 정책은 선택 모델과 Shin 모두 306티켓·115적중이다.
선택 모델 ROI는 **-8.1873%**, Shin은 **-8.6633%**이며, ROI 차이의 paired
95% CI는 **[-5.4624,+6.6011]%p**로 0을 포함한다. 일부 양의 p60low 표본
수익만 강조해서 전체 성과가 좋아졌다고 해석하지 않는다. 선택 모델의 예산수익 차이 CI는
`[-3.50,4.15]`%p로 0을 포함한다. p60low의 예산수익 자체 CI는
`[-2.79,4.69]`%, Shin 대비 차이는 `[-1.29,2.69]`%p였다.

EV≥.05의 63.64% ROI만 따로 추천 근거로 삼으면 안 된다. 첫 outer에서
2/8적중·수익 +28이었지만 다음 outer에서는 0/14·수익 -14였다. 통합
예산수익 CI도 `[-4.76,15.33]`%로 0을 포함한다. EV≥.02도 첫 outer
3/19·수익 +30.68에서 다음 0/49·-49로 바뀌었다. 모델상의 양의 EV는
실제 우위 보장이 아니다. 이 결과로 최대 ROI 정책을 재선택하지 않았다.

[결과 JSON](2026-10-01-lagged-information-results.json)에 모든 후보와 계열의
log loss/Brier/정확도 점추정, 정책별 원장·수익·커버리지·적중률, log loss와
베팅 지표의 Shin/bias-only 대비 CI를 저장했다. 원천·LF 코드·프로토콜 해시와
각 outer 경기의 실제 입력 피처도 있어 재감사가 가능하다. Bootstrap은
ISO 주 단위 paired 5,000회(seed 20261001)이며 선택·다중비교 보정은 아니다.
stake=0 표본의 ROI/적중률은 정의하지 않고 유효 표본 수를 기록한다.

## 문헌과 적용 한계

[Wheatcroft 원문](https://arxiv.org/pdf/2001.09097)은 경기 전에 예측한 통계가
추가 정보를 주는지 다룬다. GAP는 홈/원정 공격·수비 rating을 학습하지만
이번 피처는 최근 8경기의 단순 순차이 평균이다. 원문 §4.1의 베팅은 여러
업체의 최고 배당을 확보한다고 가정하고 홈승/원정승만 허용한다. 이번은
고정 B365·H/D/A·두 경기 티켓이므로 원문의 이익을 이전해 주장할 수 없다.

[Julian 등의 일정 혼잡 검토](https://link.springer.com/article/10.1007/s40279-020-01359-9)는
총 이동거리의 유의한 차이를 확인하지 못했고 성과 효과가 일관되지 않다고
설명한다. 휴식이 짧으면 반드시 진다는 식의 계수는 넣지 않았다.

새로 확보한 것은 시장과 다른 정보를 **시점 제약 안에서 검증하고 제거 비교할
수 있는 실행 경로**다. 기존 가격 변환 실험과의 차이가 코드와 입력에 남았다.
그러나 안정적 우위·실제 Proto 수익·미래 이익을 입증한 단계는 아니다.
최종 배당의 시점 가용성·체결·세금·취소·컵 경기 누락도 해결되지 않았다.
외부 E0/I1/F1 확인 자료는 이번 후보에 추가하지 않았고 운영 설정은 그대로다.

원천 데이터의 이용 허용 범위도 별도로 확인해야 한다.
[Football-Data 공식 안내](https://football-data.co.uk/data.php)는 개인적 이용을
의도하며 상업적 용도나 자동화 봇·스크레이퍼·AI를 이용한 데이터 학습 제품을
그 범위에서 제외한다고 안내한다(2026-10-01 확인). GitHub 미러에서 파일을
얻었다는 사실이나 이번 로컬 검증이 상업·학습 제품 이용 허가를 뜻하지 않는다.
운영 서비스나 학습 제품에 적용하기 전 원천 권리자의 허용 범위와 필요한
별도 허가를 확인해야 하며, 이번 보고서는 그 권한을 확인한 것으로 주장하지 않는다.

## 검증과 재현

자체 테스트 16개 통과. Gradient, 정규화, 현재/미래/6일 이내 결과·통계
변경 불변성, 정확히 7일 허용, 날짜-only 일정, 리그 분리, 최근 8경기 창,
학습 전용 스케일러, cash·두 경기 원장, 프로토콜·최종 해시를 확인했다.
`python scripts/local_lagged_information.py`로 고정 실험을 재실행할 수 있다.
`python -m pytest tests/test_local_lagged_information.py -q`로 검사한다.
