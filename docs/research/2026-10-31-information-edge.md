# 개선 확인과 픽스터 추가정보 모델

사용자는 기존 개선이 실제로 효과가 있는지 확인하고, 없다면 픽스터를 도입했던 동기처럼 새로운 접근을 고안하라고 요청했다. 이전 PR #446은 시점·계약·동결 검증과 연구 통합을 개선했지만 선수 효과를 학습하거나 새 적중률·ROI를 실증한 작업은 아니었다. 서버의 조건부 응답 코드 병합도 수집기 이미지 배포와 별개다. 새 운영 관측과 새 성과 기록의 유무는 별도 워커가 검사한다.

## 문제를 다르게 정의하기

픽스터의 가치는 표 수 자체보다 기존 시장·모델이 놓치는 정보에 있다. 다만 현재 확보한 자료는 대부분 최종 선택 방향이며, 실제 경기 전 선발·결장 사유나 독립적인 당시 수신 증거까지 갖춘 데이터가 아니다. 따라서 이번에 검증할 질문은 **“어떤 작성자의 어떤 리그 선택이, 같은 경기 시장 확률보다 추가로 도움이 됐는가”**다. 이 통계적 추가 예측력은 인과적 정보 우위나 실제 구매 가능성을 증명하지 않는다.

개별 작성자와 리그 효과를 학습하되 표본이 적으면 전체 평균 쪽으로 강하게 줄인다. 시장 확률은 출발점으로 유지하고, 저자의 투표 방향과 시장 확률의 차이를 입력으로 넣는다. 90:10의 고정 혼합이나 단순 적중률 순위는 사용하지 않는다. 같은 경기에서 같은 문서 해시의 복제 표는 묶되, 같은 선택을 했다는 이유만으로 복제·공모라고 판단하지 않는다.

이 구성은 기존 #426 저자 신뢰도와 #430 시장 잔차 연구의 요소를 결합한다. 이름만 바꾼 최초 발명으로 소개하지 않는다. 실제 입력·결합 방식·시간 분할과 기존 실험의 차이는 별도 중복성 조사와 함께 기록한다.

## 논문과의 연결

- [Raykar 등의 Learning From Crowds](https://jmlr.org/papers/v11/raykar10a.html)는 전문가의 신뢰도가 같지 않을 수 있음을 다룬다. 원 논문은 숨은 정답을 추정하지만 우리는 공식 결과가 연결된 지도학습을 수행하므로 같은 알고리즘의 재현은 아니다.
- [Kahn의 전문가 확률 결합 모델](https://arxiv.org/abs/1207.4144)은 사건별 사전확률과 전문가의 편향·보정·의존성을 고려한다. 우리는 전문가 확률을 갖고 있지 않아 선택 방향을 시장 기준 잔차로 표현한다. 이번 수식과 정규화 강도는 프로젝트의 사전 설계다.
- [Soule 등의 소표본 전문가 결합 연구](https://pubsonline.informs.org/doi/10.1287/mnsc.2021.02009)는 신뢰도와 상관 추정의 오차가 복잡한 결합의 이점을 없앨 수 있음을 지적한다. 그래서 시장 단독도 후보로 포함하며, 다수 저자 동시 표본이 적은 상황에서 전체 상관행렬을 추정하지 않는다.
- [Dietrich·List의 의견 결합 검토](https://personal.lse.ac.uk/list/PDF-files/OpinionPoolingReview.pdf)는 공통 정보와 개인 정보, 동등한 대표성과 예측 정확도를 구분한다. 의견을 공평하게 반영하는 투표가 항상 좋은 확률 예측이라는 뜻은 아니다.

논문들이 우리 데이터의 적중률 향상이나 흑자를 보장하지는 않는다.

## 결과를 보기 전에 고정한 실험

프로토콜은 커밋 `396a12e0a477418c8fee66562e36dba4bb274525`에서 먼저 고정했다. 후보는 시장 단독, 공통 정보 계수, 리그·저자별 계층 계수의 세 개다. 6월 이전 자료로 학습하고 6월 로그손실로 한 번 선택한 뒤, 7~10월을 평가한다. 결과의 가용 시각은 경기 시작 +96시간이라는 보수적 가정으로 제한하며 실제 수신 인증이라고 부르지 않는다. 고정 학습과 순차 갱신은 따로 집계한다.

같은 경기·상품·가격으로 단폴 1단위 적중률·ROI·커버리지·확률 손실·선택 변화와 월별 손익·일별 최대 낙폭을 비교한다. 월 손실 제한을 이 단위 ROI 계산에 넣지는 않으며 실제 모의 지갑 설정도 변경하지 않는다. 이미 과거 연구에서 열람한 자료를 다시 쓰므로 새 독립 검증이나 블라인드 평가가 아닌 탐색 연구다. 세부 식·정규화·제외·불확실성 규칙은 `experiments/information-edge-20261031/protocol.json`에 보존했다.

새로운 선발·라인업 효과, 실제 독립 수신 인증과 동결 운영 예측 전체의 재생은 이 실험에 포함되지 않는다. 결과가 없거나 악화되면 수치 그대로 남기고 모델 교체를 하지 않는다.

## 실제 실행 결과

실제 투표·가격·결과를 연결한 회고 자료 446경기를 사용했다. 2026년 445경기는 기존 연구와 전부 겹치며 2025년 1경기가 포함된다. 시점 분할은 학습 구간 273, 검증 51, 평가 122경기였다. +96시간 가용성 가정 때문에 검증용 최초 적합에는 262경기만 사용했고, 7월 1일 고정 재적합에는 323경기를 사용했다. 45개 UTC 날짜에서 순차 재적합했다. 이는 새로 수집한 독립 평가가 아니다.

6월 검증 구간 51경기 중 7월 1일에 결과가 아직 가용하지 않다고 둔 1경기는 선택에서 제외했다. 가용한 50경기의 검증 로그손실은 시장 0.643196, 공통 계수 0.640514, 계층 계수 0.642192였다. 사전 규칙에 따라 공통 계수를 선택했으며, 개인별 계층 모델이 검증에서 우수해 선택됐다고 보고하지 않는다. 평가 결과를 보고 후보·기간·정규화 강도를 바꾸지 않았다. 개발 중 전체 51경기를 선택에 쓰던 시점 오류를 가용 시각 기준으로 바로잡았고, 선택 후보와 평가 예측은 같았다.

동일한 7~10월 122경기, 같은 가격의 균등 1단위 단폴 결과다. 고정과 순차는 같은 경기 집합의 두 분석이다.

## 정보 자체가 부족한 지점과 다음 접근

자료 감사에서 2026년 445경기의 작성자 선택 459개, 출처 6개, source+author 표기 11개를 확인했다. 출처가 여러 개인 경기는 14개였고, 같은 경기 안에서 동일 해시가 중복된 사례는 없었다. 따라서 이번 자료에서 해시 그룹화가 실제 중복을 제거해 성과를 높였다고 설명할 수 없다. 보존된 관측 시각은 모두 해당 판정 이후이며 당시 가격·문서 바이트·독립 최초수신은 인증되지 않았다. source+author 표기는 독립된 개인 신원 인증이 아니다.

다음 접근은 **픽스터의 결론과 분석 근거를 분리한 사실 검증 모델**이다. 예를 들어 선발 A에서 B로 변경, 공식 결장, 최근 24/48시간 불펜 투구 수, 확정 타순의 선수 구성 같은 주장과 공식 근거를 연결한다. 단순 찬성표가 아닌 확인된 입력의 변화량을 별도 선수 효과 층에 넣는 설계다. 실제 선발·결장·불펜의 수치는 이번 446경기 실험에서 학습하지 않았으므로 이 접근의 ROI는 아직 없다.

필요한 입력은 다음과 같다.

1. 주장별 경기·선수 ID, 원문 URL·해시, 발표 주장 시각과 실제 수신 완료 시각.
2. 같은 사실을 확인하는 공식 라인업·결장·경기 기록과 선수별 과거 지표. 확인하지 못한 주장은 사실로 승격하지 않는다.
3. 사실이 확인되기 전과 후의 동일 상품·기준점·완전한 배당 및 실제 관측 시각. 정보가 이미 가격에 반영된 경우와 아직 반영됐는지 확인할 수 없는 경우를 구분한다.
4. T-30까지 실제 가용한 입력만 동결하고, 정보가 늦거나 누락된 경우에는 현재 기록을 보존한다. 연구를 위해 과거 수신시각을 소급하거나 확률을 임의 상향하지 않는다.

이 방향은 과거에도 논의한 선수 정보 보강을 구체적인 수신·변경 이벤트 검증으로 좁힌 것이다. 새로운 데이터 없이 이름이나 혼합 비율만 바꿔 개선했다고 주장하지 않는다. 공식 자료가 갖춰진 전향 표본에서 시장·현재 운영 동결픽·사실 층 없는 baseline·사실 층 후보를 같은 가격으로 비교해야 한다.

## 운영 점검의 별도 결론

10월 31일 09:42 KST 관측에서 최근 목록 생성은 약 14시간 28분 전이었다. 서버 이미지 v82에는 #443 ETag 코드가 없었고, 웹 빌드·Pages 작업의 성공과 수집기 이미지 배포는 별개였다. 이후 09:47~09:49 KST의 제한된 로그에서는 배당 저장은 갱신됐지만 판정 시작이 여유 468~476MiB 대 필요 512MiB 기준에 걸려 보류되는 것을 확인했다. 짧은 로그로 14시간 전체가 같은 원인이었다고 확정하지 않는다.

메모리 기준을 낮추는 로컬 mock은 실행 허용 여부만 보여주며 실제 안전 피크를 입증하지 못한다. 임계값·운영 DB·스케줄·프로세스를 바꾸지 않았고 지연을 해결했다고 보고하지 않는다. 예측 모델의 개선과 별도로 갱신 파이프라인의 메모리 원인·대기 시간을 해결해야 한다.
