# K리그2 공식 매치센터 출전명단 원천 확인

2026-11-03 KST의 제한된 공개 요청으로 공식 매치센터가 과거 경기의 선발·대기 명단과 선수 ID를 HTML에 제공함을 확인했다. 경기 당일 실제로 어떤 시각에 명단이 게시되었는지, 수집자가 T-30 이전에 수신했는지는 이 사후 응답으로 증명할 수 없다. 선발 명단은 공식 경기기록상 선발이며 경기 전 확정 수신을 주장하지 않는다.

## 발견과 보존

공식 홈페이지의 매치센터 링크는 `GET https://www.kleague.com/match.do?year=...&leagueId=...&gameId=...&meetSeq=...`이고, 반환 HTML의 출전 선수 표는 각 팀의 첫 번째 box에 선발, 두 번째 box에 대기 선수를 제공한다. `playerDetailPop(team_id, player_id)`와 선수명·배번·포지션을 연결한다. 페이지 JavaScript는 `POST https://www.kleague.com/api/ddf/match/matchInfo.do`에 `year`, `meetSeq`, `gameId`를 보내 점수·종료 상태를 얻는다. 공식 월별 `POST https://www.kleague.com/getScheduleList.do`도 다른 시즌의 ID·팀·날짜·점수 대조에 썼다.

`raw/`에는 실제 HTTP 응답 바이트와 요청 파라미터, 수신 완료 UTC 시각, SHA-256, 상태 및 길이를 각각 보존했다. 명단은 2026-11-03 10:45 KST경 사후 수신했다. 내부 기록과 바이트 해시는 독립적인 수신 인증이 아니다. 페이지는 경기 후 점수 및 교체 정보를 포함하므로 학습용 사전 스냅샷으로 사용하면 누출이다. 교체 선수 행의 상대 이름은 같은 팀 명단의 유일 일치 때만 ID로 연결하며 불일치는 null이다. 포메이션 라벨, 명단 발표 시각은 이 파서에서 확인하지 못해 null로 남겼다. 좌표를 추정한 포메이션으로 표시하지 않았다.

## 표본 및 연결

- 2024 K리그2 1번 안산(K32)–경남(K20) 1:2, 2025 K리그2 1번 인천(K18)–경남(K20) 2:0, 2025 K리그2 253번 경남(K20)–서울E(K31) 0:0, 2026 K리그2 1번 김해(K41)–안산(K32) 1:4. 인천의 2025 K리그2 참가와 다른 시즌 팀 구성을 고정 ID로 구분한다.
- 네 경기 모두 양 팀 선발 11명씩 88명, 대기 60명, 총 148개 선수 행과 ID를 복원했다. 같은 선수의 다른 경기 출전은 별도 행이다. 공식 일정/기존 공식 결과에서 경기·리그 ID, 홈·원정 팀 ID, 날짜, 점수 4/4 일치. 2025 두 건은 기존 275 결과와 대조했고, 2024·2026 두 건은 별도 보존한 공식 월별 응답과 대조했다. 같은 공식 운영자의 응답이므로 독립 공급자의 인증은 아니다.
- 교체 상대 이름과 분이 모두 있는 K리그2 선수 행은 72개다. 같은 교체는 양쪽 선수에 각각 표시될 수 있으므로 72회를 뜻하지 않는다. 전체 다섯 경기 선수 행 91개 중 상대 ID가 유일하게 연결된 행은 89개, 미연결 2개다. 교체가 없거나 정보가 비어 있는 선수는 제외한 수치다.
- K리그1 대조 2025년 1번은 11명씩 선발·대기 18명으로 별도 파싱했다. 다섯 경기 전부 선택된 연도·대회·경기번호와 팀 ID를 확인했다.
- 기존 `accuracy-review-20261030/inputs/targets.jsonl.gz`의 event_id로 동일 경기 0/5건이다. 다른 ID 체계나 전체 운영 원장은 조사하지 않았으므로 전체 가격 교집합이 0이라는 뜻은 아니다. 같은 상품·완전 배당·판정 시각·정산을 연결한 경기 수는 이번 조사 범위에서 0이며 실제 구매 가능 가격이나 동결 운영픽은 미확인이다.

표본은 K리그2 네 경기로, 전체 시즌 커버리지를 의미하지 않는다. 경기가 없는 날짜나 취소·연기, 표기 차이와 구장별 미완성 명단에 대한 전체 분모는 조사하지 않았다. 실제 프로덕션 DB나 이전 PR #461은 변경하지 않았다.

## 재현과 검증

저장 응답만 파싱: `python experiments/kleague2-official-lineup-20261103/parse.py`. 고정된 5경기를 다시 수집하려면 `python experiments/kleague2-official-lineup-20261103/collect.py --collect`, 월별 일정은 `python experiments/kleague2-official-lineup-20261103/schedules.py`. 기존 캐시의 바이트 해시를 검증하고 있으면 재요청하지 않는다. 호출별 15초 제한, 최대 3MB, 새 요청 간 1초 대기, 403·429 및 기타 비200이면 중단한다. 더 많은 경기를 수집하려면 총괄이 범위와 요청 예산을 별도로 정해야 한다.

`python -m unittest discover -s tests -p test_kleague2_official_lineup_20261103.py -v`: 3개 통과. 원문 변경·해시 위조 후 경기 ID 변경 거부, 11명·선수 ID 중복, 기존 공식 결과 및 월별 일정 대조를 검사했다. 보존된 HTML에는 교체·득점 등 사후 정보가 함께 들어 있으므로 검사는 원천 복원과 데이터 연결을 확인할 뿐 예측 성능을 입증하지 않는다.

후보 가설 하나: 선발 선수의 이전 경기 동일 팀 조합 유지율이 같은 시점 시장 대비 추가 정보를 주는지 전향적으로 검증한다. #461의 이전 365일 450분 이상 출전 선수 수 차이와는 입력이 다르다. `docs/research` 텍스트 검색에서는 선발 조합 유지율 관련 표현을 찾지 못했으나 모든 기존 실험의 중복 여부를 완전히 검증하지 않았다. 선발 수신·과거 선수 ID 및 경기 전 가용 시간, 같은 상품의 전체 가격과 동결 운영픽, 결과를 확보한 뒤 프로토콜을 먼저 고정해야 한다. 이번에는 적합·ROI·모델 채택을 하지 않았다.

## 2026·2025 공식 전체 일정 코호트 확장 — 2026-11-03

소표본 이후 경기 결과나 수익과 무관하게 공식 월별 일정의 K리그2(`leagueId=2`, `meetSeq=2`) 전 건을 먼저 등록하고 2026년 다음 2025년 순서로 수집했다. 일정에서 `endYn=Y`와 `gameStatus=FE`인 경기의 공식 매치센터 페이지를 경기 순서대로 수신했다. 2026년 전체 일정 272건 중 종료 248건은 248개 페이지를 모두 수신·파싱했고 실패·미수신 0건이다. 나머지 24건은 일정의 비종료 상태이며 실제 선발을 갖춘 종료 표본에 넣지 않았다. 2025년 일정 275건은 모두 종료·수신·파싱 완료, 실패·미수신 0건이다. 일정 API의 응답 범위 자체를 독립 외부 원천으로 완전성 검증한 것은 아니다.

523경기 모두 경기·리그 ID, 홈원정 팀 ID, 일정 날짜와 페이지 날짜를 대조했고 양 팀 선발 11명씩 확보했다. 2026년 선발 5,456명·대기 4,461명, 2025년 선발 6,050명·대기 3,848명은 경기별 선수 행이며 고유 개인 수가 아니다. 교체 시간·상대 이름이 표시된 선수 행은 각각 4,665·5,146개다. 같은 교체의 양 선수 행을 중복해 세는 수치이며, 상대 이름의 선수 ID를 유일하게 연결하지 못한 행은 3·18개다. 결과 점수는 같은 공식 일정 응답에서 연결했다. 모든 경기의 점수를 매치센터 별도 점수 API나 독립 공급자와 재대조한 것은 아니다.

기존 평가 입력에는 2026년 K리그2 9경기가 있었고 이번 코호트의 공식 경기 ID·날짜·시각·홈원정 약칭·결과 및 저장된 승무패 3방향 배당과 9/9 연결됐다. 이 9건의 회고 예측 72행은 같은 경기의 여러 모델·방식이며 독립 경기 72건이 아니다. `cohort/price-bridge.json`에 원본 파일 행 번호와 모델·방식, 배당, 공식 경기 ID를 기록했다. 입력에 별도 가격 ID·예측 ID·상품 ID·기간 필드가 없어 null로 남겼다. 이전 0건은 다섯 경기 소표본과의 교집합이며 전체 2026 경기와 기존 입력의 교집합이 0이라는 뜻이 아니었다. 다른 원장·상품·ID 체계를 포함한 전체 운영 기회 수는 여전히 미확인이다. 이 저장 배당의 실제 수신·구매 가능성, 명단의 경기 전 수신, 동결 운영픽은 인증하지 못했다.

명단 파생 행의 상태는 `retrospective_official_actual_starting_eleven`이고 경기 전 발표 확정 여부는 false, 발표 시각은 null이다. 각 경기 페이지는 경기 후 내용이 섞여 있으며 교체와 결과는 진단용 필드로만 둔다. 대상 경기의 경기 후 선수 성적은 예측 특징으로 만들지 않았다. 이번 작업은 자료 연결에 한정하며 모델 적합·성과·ROI를 계산하지 않았다.

수집 기록은 `cohort/raw/`에 원문 응답 바이트를 gzip으로 보존하고 HTTP 요청 파라미터, 현재 수신 완료 시각, 원문 SHA-256과 저장 압축 바이트 SHA-256을 남긴다. `requests`가 전송 압축을 해제한 응답 본문 기준이며 통신선상의 압축 패킷 인증은 아니다. 공식 일정 24개와 경기 페이지 523개, 합계 547개 응답을 저장했다. 운영자가 제공한 원문 표시·내부 해시·실제 현재 수신은 과거 수신의 독립 인증이 아니다.

재개 명령: `python experiments/kleague2-official-lineup-20261103/cohort/collect_cohort.py --years 2026 2025`. 저장 캐시의 양쪽 해시를 확인하고 재사용하며 중복 프로세스는 파일 잠금으로 막는다. 요청당 10초 연결·15초 읽기 제한, 응답 3MB 상한, 새 요청 후 1초 대기, HTTP 비200에서 중단한다. 이후 실행 버전은 연도별 최대 400경기 상한도 적용한다. 중간에 종료되어 응답·메타데이터 한쪽만 남으면 임의로 재작성하지 않고 중단한다. 오프라인 파싱은 `python experiments/kleague2-official-lineup-20261103/cohort/derive.py`다.

원문 `.bin`·`.gz`는 Git에서 바이너리로 보존하고 JSON·JSONL은 LF로 고정한다. `cohort/manifest.json`은 기존 표본과 이번 전체 원문·메타데이터·파생 결과의 정확한 Git 저장 바이트 SHA-256을 기록한다. `python experiments/kleague2-official-lineup-20261103/cohort/manifest.py`로 검증한다. 캐시·429 중단·중복 수집 잠금·신원 오류·9경기 교차표 등 Python 검사 7개가 통과했다. 실제 사이트 429를 유발한 것이 아니라 합성 응답을 사용한 검사다.
