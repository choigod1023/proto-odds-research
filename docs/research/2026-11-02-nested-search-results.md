# K리그1 모델·설정 4,334개 탐색 결과

**넓게 탐색해 개발 적중률이 더 높은 후보와 실행 가능한 설정 파일을 만들었지만,
선정 뒤 계산한 2026년 진단에서는 시장보다 적중률·ROI가 낮았다.** 따라서 이번
후보를 운영으로 자동 전환하지 않는다. 무한히 검색하면 미래 최고 모델을 찾는다는
주장도 하지 않는다. 이번에 실행한 범위는 아래 고정 정의 4,334개다.

## 실행 범위와 실제 설정

사전 계획은 `7d1ad1bf`, 특징 정의·입력은 `00d6b28d`, 전체 탐색 코드·준비 파일은
`b28b02c24b8b820eb68c51c1a79c46cfdf80004b`에 먼저 고정했다. 실행 뒤 개발 선정
결과는 `2d263665`, 정답을 읽지 않은 이후 예측은 `59f1ef8f`에 고정한 다음 정산했다.

가족별 정의 수는 시장/DC 각 1, 잔차 이웃 3,360, 확률 혼합·편향 504,
로지스틱 144, 랜덤 포리스트 108, 히스토그램 부스팅 216이다. 합계 **4,334개**를
2025년의 세 시간 블록에 모두 적용했다. 구성×블록은 13,002회이며 실패는 0개다.
서로 같은 예측도 있으므로 독립 가설 4,334개라고 세지 않는다. 개발 227경기 전체
확률 벡터를 소수점 12자리로 묶은 서로 다른 예측은 4,164개였다. 기본 모델의
학습을 혼합 비중마다 반복하지 않고 재사용했으며 전체 개발 실행은 약 24초였다.

학습/검증 경기 수는 각각 228/123, 347/44, 389/60이다. 각 검증 시작일보다
7일 이전 행만 학습한다. 모든 적격 검증 경기를 세 블록에 걸쳐 한 번씩 평가했다.
특징은 시장·DC 확률, 두 확률의 불일치·마진·엔트로피, 각 팀의 인과적인 최근
5경기 승무패 비율·득실점·휴식일이다. 특징 표준화는 학습 자료로만 맞춘다.
선발/라인업/픽스터 입력을 사용한 실험이 아니다.

선택 기준은 개발 적중 수 최대, 로그손실 최소, 더 단순한 가족, 고정 ID 순이다.
ROI는 같이 기록하지만 ROI 최고 후보를 적중률 최고 후보로 바꾸어 소개하지 않는다.
선정된 설정은 다음과 같다.

- 가족: 최근 팀 성적을 포함한 잔차 최근접 이웃 보정.
- 공간: 시장+DC 확률 6개와 팀 성적 12개를 학습 자료로 표준화한 18차원.
- 이웃 **30개**, prior **10**, **균등 가중**, 보정 비중 **1.0**.
- 별도 시간 감쇠 **없음**. 반감기 30/90/180일도 검색했지만 선정값은 없음이다.
- 매 시간 블록의 과거 행으로 은행을 구성하며 이전처럼 2024년 은행만 고정한
  후보와는 다르다. 최종 메타 모델은 2024~2025년 455행만 사용한다.

실제 파일은 `experiments/nested-search-20261102/development/selected-model.json`이다.
`search.py predict`는 이 파일을 읽어 새 특징에 적용한다. 운영 서비스가 이 파일을
자동으로 읽도록 연결하지 않았다.

## 개발 구간 성적: 선택에 사용한 값

2025년 동일 227경기·같은 기록 가격·100% 선택·정액 단폴에서:

- 시장: **99/227, 43.61%, ROI −14.69%**.
- 선정 잔차 이웃: **111/227, 48.90%, ROI +1.75%**.

각 가족의 개발 적중률 최고 후보도 기록했다. 이것들은 별도의 검증 성공이 아니다.
동률은 해당 가족 안에서 로그손실과 ID로 정리했다.

- 로지스틱: 109/227, 48.02%, ROI +1.35%.
- 랜덤 포리스트: 107/227, 47.14%, ROI −0.81%.
- 확률 혼합·편향: 107/227, 47.14%, ROI −5.19%.
- 부스팅: 104/227, 45.81%, ROI −9.29%.
- DC: 94/227, 41.41%, ROI −15.17%.

4,334개의 점수 중 최대를 고른 **개발 성적**이다. 특히 +1.75%를 미래 기대수익이나
검증된 모의 운용 수익으로 제시하지 않는다. 모든 trial의 설정·성적과 시간 경계는
`development/trials.jsonl`과 `folds.json`에 있다.

## 선정 뒤 이후 기간 성적

2026-02-28~05-17 국내 기록 배당 **77경기**다. 이 기간은 이미 다른 연구에서
열람한 진단 표본이며 완전한 독립 맹검이 아니다. 이번 탐색의 후보 선택 함수는
이 구간의 정답 파일을 읽지 않았고, 예측 파일을 먼저 고정한 뒤 정산했다.

- 시장: **39/77, 50.65%, ROI −1.66%, 손익 −1.28단위**.
- 선정 후보: **37/77, 48.05%, ROI −4.87%, 손익 −3.75단위**.
- DC: 30/77, 38.96%, ROI −22.57%, 손익 −17.38단위.

선정 후보가 시장과 다르게 고른 11경기 중 시장 오답 회복은 3개, 시장 적중 상실은
5개, 둘 다 오답은 3개였다. 시장 대비 적중률 차이의 주 단위 5,000회 재표집
95% 구간은 −10.00~+4.65%p, ROI 차이는 −20.82~+14.53%p다. 재사용·선택 이력을
없애주는 구간은 아니며 우세를 입증하지도 못했다.

확률 오차와 낙폭은 달랐다. 후보의 로그손실/Brier는 **1.02139/0.61085**로 시장의
1.04670/0.63117보다 낮고, 최대 낙폭은 **7.11단위**로 시장 7.74보다 낮았다.
그러나 요청한 적중률·ROI의 우세는 나오지 않았다. 확률 보정이 좋아진 것과 선택한
픽이 더 많이 맞거나 돈을 더 벌었다는 것은 구분한다. 앞선 고정 이웃의 31/77·
ROI −25.40%보다는 나아졌지만 이 사실만으로 현행 서비스보다 우수하다고 하지 않는다.

이번에는 개발에서 고른 **한 후보**를 이후에 정산했다. 4,334개 전부를 이후 구간에서
독립 평가한 것이 아니며, 이후 성적을 보고 다른 가족 후보로 몰래 교체하지 않았다.

## 새 후기 자료와 검증의 한계

자료 워커가 2026년 8월~9월 국내 스냅샷 35경기 후보, 별도 CSV 8월 29경기를
발견했다. 이 두 집합은 23경기가 겹친다. 일부는 기존 연구에도 포함돼 있다.
스냅샷 시각은 HTTP 요청 시작이며 응답 완료 시각이 없고, 보관 원문 HTML의
상품·선택지 라벨을 확보하지 못했다. 별도 CSV도 당시 수신과 원문 선택지 증거가
없다. 새 독립 검증 표본으로 인증해 합산하지 않았고 이 자료의 모델 ROI도 계산하지
않았다. [후기 자료 감사](../../experiments/nested-search-20261102/later-price-audit/REPORT.md)에
경로·파일 해시와 각 제외 사유를 보존했다.

기존 77경기도 국내 파서 계약과 기록 가격을 사용하는 회고 비교다. 실제 당시
가격 수신·실행 가능성을 인증한 것은 아니다. 해외 120경기의 상품·배당 순서 미검증
제외는 그대로 유지한다. 실제 운영 동결픽·픽스터·9:1 입력이 공통으로 없으므로
이 실험을 이들과의 비교로 대체하지 않는다.

ROI는 같은 금액의 가상 단폴 계산이며 월중 손실 5만원 중단을 적용한 사용자 모의
지갑 재생이 아니다. 기존 모의 원장과 월 한도는 변경하지 않았다. 결과를 읽어
유리한 경기만 빼거나 추가 튜닝을 해서 이번 이후 성적을 최고값으로 바꾸지 않았다.

## 검산과 실행 방법

독립 검토 워커와 총괄의 별도 스칼라 구현이 선정 후보의 개발 227개 확률·정산과
이후 77경기×3개 확률 벡터·231개 Decimal 정산을 재계산했다. 최대 확률 차이는
1.11e-16이고 손익도 일치했다. 저장된 trial 4,334개의 선택 순위를 검산했지만
모든 모델을 독립 구현으로 다시 학습한 것은 아니다. 독립 검토는 532행의 최근
성적 특징·7일 경계도 대조했다.

관련 회귀 테스트 25개가 통과했다. 전체 테스트에서 연구/서비스의 동명 `features`
모듈 충돌을 발견해 경로를 분리하고 회귀 검사를 추가했다. 모델·설정·입력을 바꾸지
않았으며 수정 버전 `f1bbf103`으로 별도 출력 폴더에서 탐색·예측·정산을 재현해
4,334개 trial 점수, 선정값, 77경기 예측과 정산의 동일성을 확인했다.
이는 새 독립 실험이나 추가 튜닝이 아니다. 운영 의존성에는 scikit-learn을 추가하지 않고
`requirements-research-models.txt`와 별도 연구 CI에서 설치한다. 일반 CI에 패키지가
없으면 ML 관련 테스트가 명시적으로 건너뛰며, 연구 CI에서 실제로 실행한다. 최종
전체 테스트·최신 커밋의 CI는 총괄 PR 본문에 기록한다.

```text
python experiments/nested-search-20261102/verify.py
python -m pytest tests/test_nested_search_pipeline.py tests/test_nested_ml_models.py tests/test_nested_residual_models.py -q
python experiments/nested-search-20261102/search.py development --registration f1bbf1035262dc6c350214942806268485c2021c --output-root .local-test/new-replay
python experiments/nested-search-20261102/search.py predict --registration f1bbf1035262dc6c350214942806268485c2021c --output-root .local-test/new-replay
python experiments/nested-search-20261102/search.py score --output-root .local-test/new-replay
```

탐색/예측/정산은 `search.py`의 `development`, `predict`, `score` 단계로 분리된다.
기존 산출물을 조용히 덮어쓰는 재실행은 거부한다. 데이터가 같으면 같은 탐색을
무한 반복하는 예약을 만들지 않았고 운영 모델·DB·스케줄·배포를 변경하지 않았다.

모델 선택 자체가 유한 검증 자료에 과적합될 수 있다는 설명은
[Cawley·Talbot 2010](https://jmlr.org/papers/v11/cawley10a.html)을 참고했다.
이는 탐색을 넓히지 말라는 뜻이나 스포츠 성능의 보장이 아니라, 개발 최고값과
이후 성적을 분리해야 하는 이유다.
