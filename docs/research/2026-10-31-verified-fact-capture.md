# 공식 선수 사실 수집: KBO 예고 선발 표본

2026-10-31 KST에 새로 KBO 공식 공개 일정과 타순 응답을 읽었다. 과거 캐시를 이번 사실로 재사용하지 않았다. 공식 일정의 2026-11-01 14:00 KST 삼성(SS) 대 KIA(HT), 경기 ID `20261101HTSS0` 1경기에서 예고 선발 두 명을 수집했다: 홈 후라도 53375, 원정 올러 55633. 두 행은 모두 **probable**, 최종 확정 아님이다. 공식 타순 응답의 `LINEUP_CK`는 false여서 타순 0건이다. 공식 경기 ID·일자·대진과 응답 내 선수 ID를 대조했으나 다른 독립 경기 식별자와 선수 등록부로 교차 인증한 것은 아니다. `canonical_game_id`는 미확보로 null이다.

실제 HTTP 본문을 전부 읽은 뒤 수신 완료 시각을 기록하고 그 바이트의 SHA256을 계산했다. 원문 응답은 배포하지 않아 이후 재해싱은 불가하다. 공식 경로에서 수신한 사실과 외부 독립 수신 인증은 다르며 후자는 0건이다. 게시 주장시각·이전 예상 선발·결정시각·동일 상품 배당·정산은 확보하지 않아 null이다. 현재 표본은 확정 선수 변경이나 모델 학습 자격의 증거가 아니며 대상 경기 결과는 보존하지 않았다. 탐색을 포함해 공식 HTTP 요청은 총 8회였고 저장된 최종 수집은 2회다. 첫 KBO 접근의 JSON 응답 해석 실패 후 정상 공식 요청을 재시도했다. 각 요청에 15초 소켓 timeout과 스트리밍 중 경과 검사·2 MiB 크기 상한을 적용했고 우회·로그인·유료 API는 사용하지 않았다. requests의 socket timeout은 엄밀한 전체 벽시계 상한을 보장하지 않으므로 운영 시간제한 보장은 별도로 필요하다.

`capture.json`은 선수 ID와 구단·상태·경기 ID, 원천 URL과 수신시각, 응답 해시, null 사유 및 내용 해시를 포함한다. 내용 해시는 공식 경기·선수·역할·상태·시작시각을 이용하고 수신시각·응답 해시·표시 이름 변화는 제외한다. 같은 응답의 재수신은 새 선수 사실이 아니다. 이전 값이 없으므로 변경 여부나 이전 가격은 추정하지 않는다. 한국 야구의 공식 일정 파서와 MLB live feed의 기존 엄격한 경기·시간·타순 검사 결과를 정규화하는 함수만 구현했다. MLB 공식 일정 탐색 범위 10월 31일~11월 3일에는 일정이 없었다. 기존 K리그 `lineup_soccer`는 과거 자료이고 NPB `npb_lineups`의 박스스코어는 종료경기 자료이므로 이번 새 경기 전 수집으로 바꾸지 않았다. KBO 기존 `kbo_candidate_source`는 완료 경기 전력 자료이며 `pregame_player_capture`는 문서 현존만으로 확정 타순을 보장하지 않는다.

CLI의 선택적 연결 경로는 `--out`, `--adapter-out`, `--manifest-out`, `--adapter-module`, `--adapter-function`, `--adapter-context`를 명시한다. context는 실제 어댑터에 필요한 registry·baseline·market·input_id와 선택적 workloads를 담은 JSON이다. 값을 생성하거나 덧씌우지 않는다. 실제 어댑터와 `research_dispatch.build_manifest`가 없으면 네트워크 요청 전에 중단한다. 직접 호출하는 `run_capture_pipeline`은 어댑터 및 디스패처를 주입받고 raw facts list를 전달한다. 수집 파일은 어댑터 처리 전에 저장해 처리 실패 시에도 보존한다. 실제 어댑터와 총괄의 실제 디스패처를 합성 입력으로 함께 실행했을 때 독립 인증 false인 유효 입력 한 건이 ready로 처리됐다. 실제 예고 선발 두 건은 누락된 정보로 어댑터에서 rejected였다. 외부 실자료의 registry·baseline·market을 합성해서 넣지 않았다. 표본에는 확정 사실·경기 매핑·실제 판정·동일 상품 가격이 없어 ready가 될 수 없다. 독립 수신 인증 false는 별도 한계로 남기며 연구 입력 준비 여부를 자동으로 막지 않는다. 경계 검사는 이러한 요건과 로컬 수신 원장·출처 일관성·결과 필드 제외를 보수적으로 확인하지만, 원장을 독립 인증하거나 보존하지 않은 원문 바이트를 재검증하지는 못한다. 모델 아티팩트 유무와 연구 자격은 별개다. 실제 통합 전 총괄이 인터페이스와 원천을 별도 검증해야 한다.

기존 운영 수집기는 내부 DB 문서를 쓰거나 축약된 정보만 남길 수 있다. 새 연구 연결에는 공식 원문 응답을 완료한 수신시각과 바이트 해시, 공식 경기·선수 ID, 증거 확인 범위, 동일 상품 가격과 그 관측·수신시각을 보존하는 별도 export 계약이 필요하다. 이 작업은 운영 수집기·DB·스케줄·예측에 연결하지 않았으며 배포나 재시작도 하지 않았다.
