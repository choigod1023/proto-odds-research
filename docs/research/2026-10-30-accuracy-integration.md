# Terra 워커 수정 통합과 병합 검증

사용자가 “계속 작업하고 병합하고 알아서 담당해봐”라고 승인해 총괄이 워커 결과를 검토하고 병합을 진행했다. 최초 연구·검토 기록과 이후 수정본을 구분하며, 연구 코드의 병합을 운영 모델 채택으로 해석하지 않는다.

## 실제 수정

- #438 자료구조는 v1.2로 보완했다. 참조한 경기·상품·선택한 공식 별칭·배당·선발 및 각 관측 내용의 해시를 동결 기록에 묶는다. 시작시각·공식 경기 ID·배당·원문해시·선수 변경을 재해시 없이 하면 거부한다. 두 해시를 모두 다시 만드는 변조의 탐지에는 신뢰 가능한 이전 스냅샷 또는 독립 증거가 여전히 필요하다.
- #440은 리그·날짜·홈/원정의 유일한 키로 먼저 연결한 뒤 점수를 대조한다. 점수 변경은 연결 ID를 바꾸지 않는다. 중복 공식 ID나 불명확한 경기 키는 거부한다. 공식 종료 경기 275건, 기존 이력 연결 23건, 추가 결과 후보 252건은 유지됐다. 이는 당시 선수·배당·사전수신이 확보됐다는 뜻이 아니다.
- #436은 전체경기 승패 상품, 완전한 배당, 실제 학습 상태와 팀 이름 연결, T-30, 입력 가용 시각, 판정시각이 포함된 계약을 검사한다. 핵심 계약 오류는 거부하고 선수 입력만 결측·무효인 경우에는 사유를 남겨 기준 확률을 보존한다. 신뢰 검증 함수와 실제 선수 효과 학습은 아직 구현하지 않았으며, 항상 True인 함수는 합성 시험 외의 인증 수단이 아니다.
- 총괄은 #433 자료 준비 단계의 게시시각 검사를 `게시 < 경기 시작`에서 `게시 ≤ 판정 시각`으로 고치고, T-30 및 원 프레임의 경기 ID·리그·팀 일치도 검사했다. 판정 후 게시 자료, 날짜 형식 오류, 다른 경기 프레임과 늦은 판정의 회귀 사례를 시험했다.
- 총괄의 실제 연결 시험에서 v1.2 저장 규격은 동결 기록을 요구하지만 새로운 추론 입력에는 아직 동결이 없다는 차이를 확인했다. `validate_inference_core`를 추가해 미동결 입력의 식별·상품·배당·관측 관계를 검증한다. 기존 저장 문서 검증의 동결 필수 조건은 유지한다. 최신 구조와 어댑터를 직접 함께 호출하며, 옛 vendor 코드로 연결 시험을 대신하지 않았다.
- #445의 독립 검토용 옛 어댑터는 실제 개발 테스트와 같은 패키지 이름을 썼다. 통합 전체 검사에서 최신 테스트 10개가 옛 모듈을 불러와 실패했고, 검토 사본의 import 이름을 격리한 뒤 관련 42개 검사가 통과했다. 초기 실패 로그도 보존했다.
- #443은 동일 picks 응답에 ETag와 304 조건부 요청을 적용한다. 브라우저는 본문이 같으면 다시 문자열로 읽지 않고 기존 데이터를 유지한다. 로컬 fixture에서 같은 gzip 본문 두 번의 전송량은 2,713,680에서 1,356,840바이트로 줄었다. 본문이 변하면 새 값을 읽고 구형 서버·실패 시에는 마지막 정상 자료를 보존한다. 처음 받는 응답의 크기나 수집·판정 계산량을 줄인 것은 아니다.

## 실제 재실행과 성과의 범위

수정한 자료 준비 코드를 원래 원시 입력으로 임시 디렉터리에서 다시 실행했다. 이력 17,337건과 평가 입력 710건의 gzip 파일은 저장된 원본과 바이트까지 같았다. 2026년 실제 투표 평가 입력 445건도 게시시각 검사에 모두 통과했다. 새 전처리의 제외 사유는 정확한 팀 미연결 6,311건과 불명확한 게시시각 5건이며, 수정 전후 입력 해시와 준비 코드 해시는 `experiments/accuracy-integration-20261030/preparation-replay.json`에 보존한다.

따라서 기존 학습 상태·예측·ROI를 다시 만들어 덮어쓰지 않았다. 이번에 새 적중률이나 ROI 향상을 얻었다고 주장하지 않는다. 선수 효과는 미학습이고 외부 독립 사전수신 인증도 확보되지 않았다. 회고 자료의 수신시각을 과거로 소급하지 않았다.

## 독립 검토와 다음 의존성

총괄의 최종 통합 상태에서 Python 전체 검사 **2,015개 통과, 6개 건너뜀, 93개 subtest 통과**를 확인했다. 프론트 검사 **273개 통과**, 별도 출력 디렉터리로 실행한 Vite 빌드도 성공했다. 전체 검사의 최초 실패 10건과 수정 후 통과 로그는 각각 `full-tests-before-isolation-fix.log`, `full-tests.log`에 보존한다. 최초 실패는 검토 사본의 import 충돌이며, 통과 수치를 덮어써 처음부터 성공한 것처럼 보고하지 않는다.

#439는 저장 정산과 요약값을 별도 계산했고, #442는 초기 인터페이스 차이, #444는 시점과 경기 연결의 추가 반례, #445는 판정시각이 계약에 묶이지 않는 문제를 재현했다. 이 검토들은 각각 지정한 이전 커밋의 기록이다. 최신 수정으로 바뀐 동작과 최초 재현의 의미를 섞지 않는다.

다음 성과 실험에는 검증된 선수·선발·라인업 자료와 팀·상품 매핑, 학습 이력 가용성을 확인할 신뢰 검증기, 결과 확인 전에 고정한 시간 분할·후보·선택 규칙이 필요하다. 현재 입력 경계의 검사가 통과해도 선수 효과 모델의 실증 평가 완료는 아니다.

운영 수집기 이미지 배포·재시작·증설·DB 변경·모의 지갑 변경은 이번 통합에서 수행하지 않는다. 웹 코드 병합에 따른 기존 자동 빌드와 수집기 실행 이미지의 배포는 서로 다른 상태다. 운영 지연 개선과 다음 자동 주기의 성공은 아직 검증하지 않았다.
