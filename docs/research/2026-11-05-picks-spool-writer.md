# 판정 저장의 이중 직렬화와 쓰기 잠금 축소

운영 후속 검증에서 picks_v2 저장 단계가 길어져 300초 제한을 초과했고, 저장된 가격 재시도가 M0 보조 슬롯보다 우선되면서 수집도 지연됐다. 기존 구현은 JSON을 두 번 직렬화하고 두 번째 직렬화를 SQLite BEGIN IMMEDIATE 안에서 수행했다. 이 구간을 실제 테스트로 재현했다. 모든 운영 지연이 이 원인 하나로 설명된다는 뜻은 아니다.

변경은 익명 임시 파일에 한 번만 직렬화·검증한 뒤, 기존 단일 트랜잭션에서 1MiB씩 복사하는 방식이다. RAM에 문서 전체의 새 바이트 사본을 보관하지 않는다. SQLite TEXT 타입·스키마·원자적 교체·이전 스냅샷 읽기·revision 증가를 보존한다. 임시 공간 부족과 복사 실패는 예외로 실패하고 기존 본문과 revision을 롤백하며 임시 파일은 닫힌다. 임시 디스크에 산출물 크기만큼 추가 공간이 필요하다.

로컬 Windows Python 3.14, 외부 네트워크·운영 DB 없이 2,000개 합성 경기 6,714,718바이트를 3회씩 저장했다. 전후 SHA256은 c927c266fffcef7dd7a02f243274996bc2272f344ae75f7520c7d172c31d7af6으로 같았다. 전체 저장 중앙값 0.44554→0.25804초, 측정한 쓰기 트랜잭션 본문 구간 0.22322→0.03559초였다. commit/fsync 이후까지의 전용 잠금 시간을 추적한 수치는 아니며 운영 시간·처리량·메모리 개선을 증명하지 않는다.

관련 Python 41개가 통과했다. 단일 직렬화가 쓰기 잠금 전에 실행되는지, 유니코드·대형 정수·실수·정확한 TEXT 바이트·독자가 보는 이전 스냅샷, NaN·짧거나 긴 복사·중단·임시 파일 오류에서 롤백을 검증한다. CI와 실제 배포 후 자동 주기는 별도 검증한다. 기존 추천 정책·동결 가격·모의 지갑은 변경하지 않는다.
