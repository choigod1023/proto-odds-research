# 검증 파이프라인 자체 감사

사용자가 요청한 것은 모델을 추가하는 일이 아니라 기존 검증이 올바른지 확인하는 일이다. 대상은 [PR #475](https://github.com/choigod1023/proto-odds-research/pull/475)의 `f403ef75da47b02374172581763b44f646094739`다. 감사 규칙은 커밋 `df35e743`에서 고정했다. 운영 모델·DB·지갑·서버·수집 주기는 변경하지 않았다.

**검증기에 실제 빈틈이 있었고 비교·보고 로직도 수정했다. 다만 현재 저장된 확률이나 ROI가 잘못 계산됐다는 증거는 발견하지 못했다.** 모든 확률을 별도 코드로 다시 생성한 결과와 원래 값의 최대 차이는 8.88×10⁻¹⁶이었다. 원래 손익을 양수로 뒤집는 보정은 하지 않았다.

## 확인한 결함과 수정

### 1. 정산 검산이 확률 생성 경로를 검사하지 않았다

기존 verifier는 저장 벡터의 합·argmax·선택·정산·집계를 확인했지만, 그 벡터가 저장 계수와 당시 피처에서 실제로 계산됐는지 검사하지 않았다. argmax가 바뀌지 않는 작은 확률 변조를 넣어도 기존 verifier의 불일치 수는 0으로 나왔다. 이 반례는 합성 fixture만 사용하는 회귀 테스트로 보존했다. 실제 경기 원장은 변조하지 않았다.

`replay_audit.py`에서 원래 `common.py`의 피처·predict 함수를 호출하지 않고 다음을 재구현했다.

- 이전 결과의 날짜+4일 가용성, 팀 Elo, 최근 20경기 결과, 리그 사전 빈도.
- 정확한 월별 학습 마감일, 최소 표본/클래스 조건, 시장 fallback 및 상태·모델 범위.
- 이전 자료만으로 계산한 평균·스케일, 저장 계수에 대한 다항 로짓 목적함수와 gradient.
- 시장 벡터, 두 로짓 확률, 고정 50:50 혼합과 선택 방향.

이 재생을 기본 verifier에 연결했다. 이제 확률 변조, 계수/스케일 변경, 잘못된 마감일·fallback, 빠진 모델, 중복 원본 ID와 누락한 기간/리그 보고를 거부한다. 원본과 원장의 경기 집합, 보고 범위와 시간 절반도 확인한다.

### 2. ‘역배만 제외’ 비교에서 최고 동률까지 빠졌다

기존 `favorites`는 유일한 정배만 남기므로 역배와 최고 동률을 함께 제외했다. 이 정책은 정배만 분석하는 용도로는 맞지만, 역배를 추가하는 효과를 정확히 분리하지는 못한다.

`non_underdogs`를 추가해 최고 동률은 양쪽에 유지했다. 모든 기간·리그에서 `전체 손익−비역배 손익=역배 손익`을 Decimal로 검사한다. 기존 `favorites` 결과는 삭제하지 않았다.

국내 최고 동률은 축구 2·야구 54·농구 11·배구 0건이었다. 전적·전력 모델의 국내 합계 비교는 다음과 같이 바로잡았다.

| 항목 | 손익(단위) |
|---|---:|
| 전체 | −6,010.34 |
| 기존 정배만 | −4,557.37 |
| 수정한 비역배(동률 유지) | −4,567.54 |
| 역배만 | −1,442.80 |

기존 전체−정배만 차이 −1,452.97에는 동률 손익 −10.17도 섞였다. 수정 후 역배의 정확한 증분은 −1,442.80이다. **역배 단독 손익의 원래 계산은 바뀌지 않았다.**

### 3. 결론 코드가 현재 음수 결과를 전제했다

기존 보고 코드는 미채택 여부와 이유를 고정하고, 모든 역배 손익이 음수라는 assert를 두었다. 다른 데이터가 들어와 양수가 돼도 적절한 보고를 만들 수 없는 구조였다.

관측 결과와 판정을 분리했다. 네 종목 범위, 셀별 증분 손익, 기간별 부호, 기술적 구간, 실제 가격·경기 전 수신 증거를 항목별로 평가하고 미충족 사유를 출력한다. 양수·음수·혼합 부호·빈 자료·불확실한 구간을 검사한다. 양수 자료와 필요한 증거를 주면 합성 테스트에서 기준 통과가 가능하고, 현재 데이터에서는 미충족으로 남는다. 이 기준 통과는 운영 배포나 실제 베팅 지시가 아니다.

### 4. 초기 시장 대체와 두 가지 불확실성 대상을 분리했다

전체 ROI에는 학습 표본이 부족한 초기 시장 fallback이 섞였다. 원래 보고에도 건수를 명시했지만 학습 완료 후 성과를 따로 볼 수 없었다. `fallback_only`와 `trained_only` 집계를 추가했다.

| 종목 | 시장 fallback | 학습 완료 후 | 학습 완료 후 전적·전력 모델 ROI |
|---|---:|---:|---:|
| 축구 | 346 | 23,652 | −13.11% |
| 야구 | 708 | 14,270 | −12.21% |
| 농구 | 286 | 6,462 | −12.43% |
| 배구 | 275 | 1,730 | −10.71% |

기존 주 블록 구간은 역배가 나온 주에서의 **선택 베팅당** 기술 통계다. 이를 오류라고 없애지 않고 이름과 대상을 명확히 했다. 역배가 없는 주의 0 손익까지 포함한 **관측 경기 기회당** 증분 구간을 별도로 추가했다. 이는 달력 시간당 손익이나 독립 확증 구간이 아니다.

### 5. 원본 충돌이 과거 캐시에서 되살아나는 경로를 막았다

원본 로더가 상충하는 두 가격을 모두 버린 뒤, 결합 단계가 그 충돌을 모르고 과거 캐시의 한 가격을 다시 채택할 수 있었다. 합성 재발매 가격 충돌에서 이 경로를 재현했다.

원본의 알려진 주시장 충돌 ID를 최종 결합까지 전달해 캐시에서 복원하지 못하게 했다. 현재 보조 CSV에는 주시장 충돌 88개가 있었지만 기존 최종 포함분과의 교집합은 0이었다. 따라서 이 수정으로 현재 데이터가 제거되지는 않았다. 수정한 준비기를 실행해 생성한 국내 원장의 SHA-256도 기존과 같았다.

## 실제 계산 재생 결과

- 코호트별 처리량: 국내 47,729행, 별도 장기 축구 235,799행. 두 코호트 사이의 경기 중복은 완전하게 대조하지 못했으므로 독립 경기 283,528개라고 부르지 않는다.
- 원래 입력 2개·예측 원장 5개·상태 5개, 합계 **12개 불변 산출물의 해시가 출발 커밋과 일치**했다.
- **1,134,112개 확률 벡터**를 독립적으로 재생했다. 최대 확률 차이 **8.88×10⁻¹⁶**, 선택 변경 0건이다.
- 모든 저장 학습 상태의 목적함수 gradient를 검사했다. 최대 절댓값 **6.51×10⁻⁷**로 사전에 정한 수치 허용범위 안이었다.
- 각 코호트의 최초 학습 가능 월에서 두 모형씩, **10개 상태를 다른 매개화와 BFGS로 재적합**했다. 원래 L-BFGS-B 결과와 최대 확률 차이는 **2.40×10⁻⁶** 이하였다. 이는 모든 월을 별도 optimizer로 다시 학습했다는 뜻이 아니다.
- 비균등 시장 확률을 사용한 중앙차분 gradient 오차는 최대 **3.04×10⁻¹⁰**이었다.
- 강한 신호를 넣은 별도 합성 자료의 검증 정확도는 2방향 98.5%, 3방향 91.5%였다. 학습 라벨을 섞으면 38.0%, 37.0%로 낮아졌다. **이 값은 알고리즘 통제 실험이며 스포츠 적중률·ROI가 아니다.**

전체와 역배의 기존 손익은 그대로다. 동률을 보존한 비교, fallback 분리와 보고 대상이 달라졌다. 원장 확률이나 학습 계수를 고쳐 수익률을 올린 것이 아니다.

감사 회귀 테스트 15개를 통과했다. 전체 재실행은 **2,181 passed, 6 skipped, 93 subtests passed**였으며, 입력·예측·상태 원본을 바꾸지 않고 새 비교/검증 항목만 적용했다.

## 남은 자료·해석 한계

- 외부 축구 자료에서 동일 구단으로 보이는 표기 후보 5쌍, 총 1,467회 팀 출현을 찾았다: D1 `MGladbach`/`M'gladbach`, ARG `Colon Santa FE`/`Colon Santa Fe`, NOR `Ham-Kam`/`HamKam`, E0 `Nottm Forest`/`Nott'm Forest`, D2 `Preussen Munster`/`Preußen Münster`. 현재 문자열 키에서는 이력이 분리된다. **실제 동일 구단임을 독립 확인하기 전에는 후보 경고이며 임의로 합치지 않았다.** ROI에 미치는 크기·방향도 측정하지 않았다. 단순 문자열 유사도가 모든 구단 별칭을 찾는 것도 아니다.
- 국내 4,257개 가격은 현재 보조 CSV의 유효 주 승패 가격과 직접 대조하지 못하고 이전 캐시에 의존한다. 원본 전체 시장의 같은 경기 키조차 찾지 못한 부분은 4,254개였다. 두 수치는 같은 정의가 아니다. 환불 여부까지 독립 확인한 자료라는 뜻이 아니다.
- 외부 포함 235,799행의 결과 방향·점수·세 배당은 같은 원본 내부에서 일치했다. 이것은 공식 결과의 독립 증명이나 경기 전 가격 인증이 아니다. 초기 연도에 결측 가격 제외가 집중된 선택 편향도 남는다.
- 날짜+4일은 가정이다. 실제 결과 수신 시각, 경기 전 배당 취득/판매 상태, 라인업 최초 공개 시각을 증명하지 못한다. 과거 자료를 여러 번 연구했으므로 새 맹검 검증도 아니다.
- PR #475는 전적·전력/시장 잔차/50:50 승무패 연구 모형을 비교했다. **운영 픽스터 투표·고정 9:1·이전 score-static을 같은 전체 경기에서 재생한 비교가 아니다.** 이 결과로 해당 모델 전체나 선수 최근 성적 가중 가설을 기각하면 범위를 넘는다.
- 음수 ROI는 ‘아무것도 하지 않기’보다 손해였다는 뜻이다. 같은 경기에서 시장보다 나은지와는 다른 질문이다. 예를 들어 야구 전적·전력 모델의 선택 역배 구간에서는 시장 방향보다 손실을 101.25단위 줄였지만, 그 구간 자체도 손실이고 기술적 구간은 0을 포함한다. 두 판단을 혼동하지 않는다.

## 판단

현재 저장된 모형의 수학·선택·정산이 잘못 연결돼 수익률이 음수가 됐다는 증거는 없다. 그러나 정산 검산만으로 학습·데이터·운영 수익성 전체를 검증했다고 말할 수 없었다. 확률 생성 경로 검증과 비교·보고의 결함을 수정했다.

이번 연구 모형에 역배를 일괄 추가할 근거는 여전히 부족하다. 이 결론은 **검사한 모형과 보존 가격에 한정한 탐색적 결과**다. 실제 운영 모델의 우열, 모든 역배 접근법, 선수 최근 성적을 반영하는 새 가설에 대한 최종 판정은 아니다. 선수 가중 실험에 들어가기 전 동일 경기의 기존 운영 선택·선수 자료·가용 시각·구매 가능 가격을 연결해야 한다.

## 재현

감사 코드와 결과는 `experiments/validation-pipeline-audit-20261031/`에 있다. 기존 검증기의 누락을 재현하기 위해 출발 커밋의 `baseline_verifier.py`를 보존했다. 이 파일은 회귀 테스트용이며 현재 기본 검증기로 사용하지 않는다. 실제 검증은 연구 폴더의 `integrate.py`와 `replay_audit.py`다.

```powershell
python -X utf8 experiments/validation-pipeline-audit-20261031/run.py
python -X utf8 experiments/validation-pipeline-audit-20261031/reaggregate.py
python -X utf8 experiments/all-sports-underdog-20261031/report.py
python -m pytest -q
```

연구 결과 저장/병합은 운영 모델의 채택이나 배포가 아니다. 원래 예측·상태·입력은 해시로 보존하며 이번 수정은 검증·집계·보고에만 적용한다.
