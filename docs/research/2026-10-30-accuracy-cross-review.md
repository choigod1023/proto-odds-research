# 세 연구 PR의 교차 연결 검토

2026-10-30. #438 `13d0bb6508e60b98143e8dbc88f8bdc9abea4d0c`, #436 `b6d7b49473518d22333f67b6ad5328941e2e7f9c`, #440 `586e7664ada1f7075c5f5e4889529256e4df9a02` 기준이다. 검토 코드는 각 PR의 파일을 읽기 전용으로 복제한 뒤 호출하며 SHA256은 `source-hashes.json`에 기록했다. 원본 PR과 운영을 변경하지 않았다.

**판정: 단위 검사를 통과하더라도 세 산출물을 현재 상태로 자동 연결할 수 없다.** 확인한 문제는 합성 fixture로 재현한 계약 차이이며, 이 검토는 성능 비교나 운영 승인 절차가 아니다.

## 차단 사항과 최소 재현

1. **v0 출력은 v1 문서가 아니다.** #436 `infer`의 `provisional-v0` 봉투를 #438 `validate`에 직접 주면 거부하고, 반대 방향도 거부한다. v1의 기존 경기·공식 ID 별칭·상품(시장/기간/라인)·완전한 배당과 관측 리비전을 먼저 확보하고, v0 출력을 그에 맞는 동결 레코드로 명시적으로 변환해야 한다. 시험에서는 신뢰 가능한 v1 예시 배당을 인위적으로 제공했을 때만 모델 확률을 옮겨 통과했다. 이는 실자료에 해당 정보가 존재한다는 뜻이 아니다. v0의 전체 봉투 SHA와 v1 동결 레코드 SHA는 서로 다른 객체의 해시로 같지 않다. 원래 v0 해시와 입력 리비전을 별도 보존하고 명시된 v1 변환 기록을 만들 필요가 있다. v1 형식 채택은 총괄 결정 전 잠정 상태다.
2. **동결 해시와 신뢰 스냅샷의 보장이 다르다.** #438 `validator.py:54-56, 112-126`의 해시는 동결 레코드와 리비전 ID를 묶지만 참조 배당·관측 내용 자체는 포함하지 않는다. 배당 1.8을 9.9로 바꾸어도 해시를 바꾸지 않은 문서는 `validate`를 통과했다. 독립적으로 보관한 원본과 `validate_append`를 비교하면 거부한다. 동결 선택 자체를 고치고 해시를 다시 계산해도 단독 `validate`는 통과하지만 신뢰 스냅샷 비교는 거부한다. 변경된 문서를 그 자체의 기준으로 삼으면 보호가 없다. 외부의 신뢰 가능한 불변 스냅샷·내용 주소 지정 또는 참조 콘텐츠 해시를 별도 보장하고 최초 저장/수정 검증 경로에 반드시 연결해야 한다. 현 validator의 스냅샷 의존 설계 자체를 숨은 동결 검증으로 취급하지 않는다.
3. **상품·시점·출처 기준이 연결 경계에서 빠진다.** #436 `adapter.py:48-62, 72-76`는 product ID가 비어 있지 않은지만 확인하고 시장·기간·라인은 알지 못한다. 합성 `first-half-handicap-minus-1.5`도 전체경기 2방향 baseline 확률을 반환한다. `availability_tier='retrospective'`도 유효한 임의 문자열로 받아들이지만 v1 동결은 `observed`만 허용한다. 경기 시작 15분 전 판정도 어댑터는 허용하나 v1은 T-30을 요구한다. 상품 매핑과 배당 일치, 적합한 가용성, 수신 시각과 T-30을 v1의 외부 관문에서 fail-closed로 검증해야 한다. 어댑터 수용은 해당 상품·자료의 검증이나 전향 인증이 아니다.
4. **선수와 팀 ID 및 출전량이 자동으로 호환되지 않는다.** #438 예시는 홈팀 한 선수와 미확정 이닝(null)만 있어도 유효하지만 #436은 양 팀 전체와 야구 팀당 9이닝 또는 축구 팀당 990분을 요구한다. 이 부분 자료를 직접 주면 거부한다. 양쪽 정책을 명시적으로 조정하고 결측을 0이나 임의 할당으로 채우지 않아야 한다. 어댑터는 중복 선수 ID·다른 경기·늦은 리비전·불완전 합계·수신 인증 true를 거부하나, 실제 선수 권위 DB와의 일치 확인 없이 임의 비빈 문자열은 받는다. 더 중요한 팀 ID도 기존 PR433 상태의 팀명과 다르면 신규 팀 사전분포를 사용한다. 합성 상태에서 팀 ID를 미등록 값으로 바꾸자 확률이 달라졌다. 공식 팀 ID와 과거 상태의 검증된 일대일 연결이 선행돼야 한다. 양 팀의 player ID와 출전량의 검증 가능한 출처도 별도 필요하다.
5. **무효 라인업의 baseline 반환은 호출자가 구현해야 한다.** 라인업 없음은 baseline을 반환하며 정상 합성 라인업도 선수 효과가 아직 없어 같은 확률을 반환한다. 반면 잘못된 선수 입력은 예외를 발생시켜 baseline을 자동 반환하지 않는다. 시험에서 예외 뒤 상태가 변하지 않고 별도 `lineup=None` 호출은 원래 baseline을 재현했다. 안전한 통합은 명시적인 오류 분류와 baseline 별도 실행·근거 기록이 필요하다. 신원/상품/시점 자체가 유효하지 않은 경우까지 무조건 fallback해서는 안 된다.
6. **결과를 이용한 23경기 연결은 사전 경기 식별 증거가 아니다.** #440은 기존 이력의 날짜·팀·결과와 공식 결과를 결합했다. 합성 동명이팀·동일일 두 경기에서 점수에 따라 선택된 공식 경기 ID가 바뀌고, 결과 전에는 둘 중 하나를 식별할 수 없음을 재현했다. 사후 대사로는 쓸 수 있지만 타깃 결과를 이용해 사전 예측 대상을 식별하는 연구에는 사용할 수 없다. 경기 ID·시작 시각 등 사전 독립 키와 중복 거부가 필요하다. 실제 23건에 이런 충돌이 존재한다는 주장은 아니다.

## v0 ↔ v1 필드 대응과 미확보값

- `identity.official_game_id` → v1 `aliases.official_id`; v1 `canonical_game_id`는 별도 검증된 매핑이 필요하다. 리그·팀·킥오프는 `games`에 보존하되 PR433 학습 상태의 팀명과 공식 ID를 검증해 연결해야 한다.
- `identity.product_id` → `products.identity.product_id`; 시장·기간·라인·선택지와 같은 경기의 완전 배당·관측 시각은 v0 어댑터 출력만으로 알 수 없다. 새로 만들어 채우지 않는다.
- `source_published_at_claim`, `raw_sha256`, 최초/수정 수신 → `observations.evidence`의 `published_at_claim`, `source_sha256`, 대응 수신 시각. 이름만 바꾸어 당시 수신이나 원문 해시를 인증할 수 없다. `availability_tier` 값의 의미도 별도 합의해야 한다.
- 하나의 v0 양 팀 라인업 → 팀별 v1 `lineups` 리비전과 해당 `observations`; 선수 ID·포지션·순번·확정 상태·이닝/분을 그대로 보존한다. null과 부분 라인업은 완전한 어댑터 입력으로 바꾸지 않는다.
- v0 배열 확률 → 상품 선택지 순서를 검증한 `freezes.probabilities` 객체; `model_id`, `model_version`, `decision_at`을 옮긴다. v1 `selection`, quote/lineup revision 및 새 `freeze_hash`는 별도 기준이 필요하다. v0 `input_revision`, diagnostics, baseline state 및 원래 해시는 현재 v1 freeze 스키마에 직접 담을 수 없으므로 손실 없는 연결 저장 설계가 필요하다.
- #440의 사후 점수 → v1 settlement의 `score`와 직접 같지 않다. v1은 별도 기존 freeze·상품·`final_at`·result observation·동일한 settlement scope를 요구한다. #440의 `product_id`와 `result_final_at`은 null이고 source scope는 공식 일정 결과다. 이를 가상의 상품 정산으로 변환해서는 안 된다.

## 252건의 의미와 검증 범위

보존된 공식 결과 275개는 고유 공식 ID이고 기존 이력에 연결된 23개를 제외하면 252개다. 모두 과거 경기 이후에 수신됐고 상품 ID와 실제 결과 확정 시각은 없다. 252개는 선수 명단·경기 전 수신·가격·독립 정산 증거가 아니며 적중률 또는 ROI가 개선됐다는 뜻이 아니다. 기존 사전 후보·기간·중복 규칙을 먼저 고정한 별도 평가 없이 새로운 성과를 주장할 수 없다.

교차 검사는 복사한 원 코드와 합성 fixture를 사용하며 외부 영수증/원문 바이트/실제 가격·공식 선수 ID/운영 배포는 인증하지 않았다. 23경기 연결의 점수 일치는 원 보고서의 조사에 의존하며 이번 검사는 원래 history와 공식 HTTP 응답을 다시 대조하지 않았다. 전체 학습 재실행, 정확도·수익률 평가 및 전향 수집도 수행하지 않았다.
