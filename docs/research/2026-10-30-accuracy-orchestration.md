# 승부예측 Terra 워커 운영 계획

사용자 요청에 따라 현재 대화를 총괄·기획 세션으로 두고, GPT-6.1 Terra 워커 5개를 별도 로컬 세션으로 생성해 첫 작업을 시작했다. 앱의 `승부예측 · Terra 워커` 섹션에 모았다. 이 문서는 작업 배정과 채택 기준이며 적중률 개선 결과 보고서가 아니다.

## 역할과 첫 산출물

- **자료구조 — 승부예측 Terra · 자료구조**: 경기·상품·입력 revision·관측시각·동결 예측·공식 정산을 구분하는 스키마와 Python 검증기. 사후 정보, 상품 혼동, 동결픽 변경을 거부하는 사례를 시험한다.
- **개발 — 승부예측 Terra · 모델 개발**: PR #433 상태 모델에 실제 선수·선발·라인업 자료를 받을 연구 어댑터를 만든다. 자료가 없을 때는 기존 확률과 미가용 사유를 보존한다. 합성 입력 시험으로 적중률 개선을 주장하지 않는다.
- **검토 — 승부예측 Terra · 독립 검토**: PR #433 최종 `0ed675a0`의 입력·시점·선택·확률·정산을 검토하고, 독립 Python 계산으로 저장된 적중률·ROI를 재현한다. 이미 공개된 한계와 새 결함을 구분한다.
- **연결 — 승부예측 Terra · 데이터 연결**: K리그2 2025 검증 자료가 23경기인 원인을 추적하고 공식 경기 연결을 늘린다. 검증 가능한 100경기를 목표로 하되 실제 확보량을 보고한다. 이어 예정 K리그·KBO 경기의 공식 선발·타순 수집 가능성을 확인한다.
- **서버관리 — 승부예측 Terra · 서버관리**: 현재 운영 버전, API 응답, 생성시각, 최근 OOM·실패·대기와 메모리·PSI를 한 차례 읽기 전용으로 점검한다. 과거 장애를 새 장애로 집계하지 않는다.
- **기획·총괄 — 현재 세션**: 데이터 규격, 우선순위, 검증 설계, 결과 취합, 후속 작업 배정과 서비스 채택 판단을 맡는다.

요청한 모델은 모든 워커에서 `gpt-6.1-terra`, reasoning은 `high`로 지정했고 앱이 생성을 수락했다. 이는 생성 설정의 확인이며 실제 실행 모델을 별도 텔레메트리로 관측했다는 뜻은 아니다. 세션 ID·경로·생성 설정은 [workers.json](../../experiments/accuracy-orchestration-20261030/workers.json)에 보존한다. 상태는 생성 후 확인한 시점의 기록이며 실시간 상태 파일이 아니다.

## 연결 순서

1. 총괄의 [임시 v0 계약](../../experiments/accuracy-orchestration-20261030/provisional-interface.json)으로 자료구조·개발·연결이 병렬 진행한다. 자료구조 워커는 v1 및 호환표를 제안하고 총괄이 적용 여부를 정한다.
2. 연결 워커는 공식 경기 ID, 당시 상품·가격, 원문 출처, 실제 수신시각을 구분한다. 최근에 가져온 과거 자료를 과거 사전 수신 자료로 소급하지 않는다.
3. 개발 워커는 실제 가용 입력량을 먼저 확인한다. 성과 실험은 결과 확인 전에 가설·후보·분할·선택 규칙·지표를 커밋하고 수행한다.
4. 검토 워커는 별도 구현으로 시점 누출과 정산을 검사한다. 새 워커 PR 검토는 첫 산출물 이후 총괄이 후속 배정한다.
5. 총괄은 동일 경기·동일 시점·동일 가격에서 정확도, ROI, 표본 수, 추천 비율, 손실 안정성을 나눠 비교한다. 여러 후보 중 최고값만 보고 선택하지 않고 시간 분할, 불확실성과 다중 비교를 함께 판단한다.

이전 연구의 새 모델은 시장 대비 유의한 개선을 입증하지 못했다. NPB 고정 예측의 손실 감소도 순차 예측에서 유지되지 않았다. 따라서 이번 목표는 선수 입력과 실제 시점 근거를 보강해 **검증할 수 있는 새 후보**를 만드는 것이다. 스키마·테스트 통과와 실제 적중률 개선은 별개다.

## 작업 격리와 제출

기준 main은 배정 당시 `f5d4ff541d63c6855a9d7deaa0b97df41e2a9681`이다. #435의 조건부 시장 fallback과 실제 배포 상태를 구분한다. 각 워커는 자신의 새 디렉터리에 독립 clone을 만들고 고유 `codex/terra-accuracy-<role>-20261030` 브랜치에서 작업한다. 원본 공유 checkout과 다른 작업의 파일·인덱스는 변경하지 않는다.

공통 지시는 [worker-common.md](../../experiments/accuracy-orchestration-20261030/worker-common.md), 역할별 지시는 [roles.json](../../experiments/accuracy-orchestration-20261030/roles.json)에 보존한다. 첫 작업은 각자의 연구 경로·고유 테스트·보고서만 변경하고, 실제 검사 결과와 `handoff.json`, 커밋, draft PR을 제출한다. 총괄은 앱의 상태 조회와 워커 완료 응답·handoff를 읽어 취합한다. 워커끼리는 직접 메시지를 보내거나 상대 작업 폴더에 쓰지 않는다.

연구 단계에서는 운영 추천, DB, 지갑, 스케줄과 월 손실 제한을 바꾸지 않는다. 병합·배포·재시작·증설·삭제·메일 발송도 배정하지 않았다. 운영 문제를 발견하면 근거와 최소 수정안을 제출하고 총괄이 별도 작업으로 정한다.

## 실행 범위

이번에 켠 것은 **유한한 작업 단위로 진행하는 워커 세션 5개**다. 상주 오케스트레이터 프로그램, 반복 자동화, 정기 감시를 새로 켠 것은 아니다. 워커 완료 후 다음 작업을 자동 배정하는 데몬도 없다. 현재 세션에서 결과를 읽고 후속 작업을 지시하는 방식이다. 개선 성과와 운영 반영은 아직 확인하지 않았다.

## 첫 작업 제출 결과

총괄이 다섯 세션의 완료 응답과 각 독립 저장소의 `handoff.json`·HEAD를 확인했다. 아래 테스트 수치는 워커가 제출한 결과이며 총괄이 전체 테스트를 다시 실행한 수치는 아니다. 모두 draft PR이며 병합·배포하지 않았다.

- 자료구조 [#438](https://github.com/choigod1023/proto-odds-research/pull/438): v1 스키마와 Python 검증기, 관련 검사 20개 통과. 합성 입력 검증이며 공식 원문·외부 수신시각 검증은 아니다.
- 개발 [#436](https://github.com/choigod1023/proto-odds-research/pull/436): 입력 어댑터와 관련 검사 15개 통과. 유효한 입력이어도 현재는 기준 확률을 그대로 반환한다. 선수 효과를 학습한 새 모델이 아니며 새 적중률·ROI는 미평가다.
- 독립 검토 [#439](https://github.com/choigod1023/proto-odds-research/pull/439): PR #433의 저장 예측 정산 23,752건과 요약값 1,400개를 별도 구현으로 검산해 차이 0. 판정 이후·경기 시작 이전 게시물을 허용할 수 있는 입력 검사 빈틈도 재현했다. 실제 2026년 445경기 표본에는 해당 사례가 없어 기존 성과가 변했다는 증거는 없다. 이 재현은 사전수신 인증이나 전체 학습 재현을 대신하지 않는다.
- 연결 [#440](https://github.com/choigod1023/proto-odds-research/pull/440): K리그2 2025 공식 종료 경기 275건을 확보했다. 기존 23건은 날짜·대진·점수로 연결했고 추가 사후 결과 후보는 252건이다. 기존 자료에 공식 ID·시작시각이 없어 정확한 ID/시각 대조까지 확인한 것은 아니다. 선발 선수 자료와 경기 전 수신 인증은 확보하지 못했다. 관련 검사 2개 통과.
- 서버관리 [#437](https://github.com/choigod1023/proto-odds-research/pull/437): 한 차례 관측에서 최근 목록 0.512초, 전체 picks 응답 8.893초·39,682,129바이트였다. 목록 생성시각은 관측 당시 약 24분 30초 전이었다. 최근 외부 점수 요청 시간초과와 작업 대기를 확인했으며, 확인 로그 범위에는 명시적인 신규 OOM 기록이 없었다. 현재 프로세스별 RSS 및 정확한 표본 간격을 확보하지 못해 안정화 판정은 보류했다.

개선 효과가 입증된 상태는 아니다. 다음 의존성은 **스키마·어댑터·실제 연결 자료의 교차 검토 → 확인한 결함 보완 → 학습 가능한 선수 입력 확보 → 사전 등록한 실험 비교**다. 첫 세 산출물 #438·#436·#440의 교차 검토는 독립 검토 세션에 두 번째 작업으로 배정했다. 다른 첫 작업은 종료됐으며 상시 실행을 뜻하지 않는다.
