## 특성 정의와 가용성

기본 이름은 `soccer_prior_{home,away}_` 뒤에 붙는다. 양 팀 각각 최대 7개이며, 결측 항목은 아예 생략한다.

- `observed_games`: 해당 시즌에서 결정일보다 날짜가 앞선 관측 XI 수.
- `history_age_days`: 마지막 관측 경기 날짜와 결정일의 차이.
- `regular_top11_start_share`: 과거 관측 선발 횟수 상위 11명의 전체 선발 점유율. 시즌 최종 순위가 아니라 결정일 이전 기록만 집계한다.
- `previous_xi_regular_share`: 직전 관측 XI 선수들의 누적 선발 비율 평균.
- `previous_churn`: 이전 두 관측 XI 사이 변경 인원.
- `mean_last5_churn`: 과거 마지막 최대 5회 변경 인원의 평균.
- `previous_xi_mean_starts14`: 직전 XI 선수들의 최근 14일 선발 횟수 평균. 실제 출전 시간·부상·실제 피로도를 뜻하지 않는다.

원본에 경기 날짜만 있어 모든 prior 특성의 `max_fact_time`, `observed_at`은 null이다. 정확한 종료·공개·수집 시각을 만들어 넣지 않았다. 증거 등급은 `retrospective_lagged`이며, note에 마지막 사실 날짜와 부분 아카이브 한계를 적었다. 결정 시각의 한국 날짜와 같은 날 경기도 제외한다. 동일 시즌 자료만 사용한다. 같은 팀·날짜에 중복이 있으면 해당 이력을 거부한다.

추가 인계 스키마: 각 `feature_evidence[name]`에 `max_fact_date: YYYY-MM-DD`와 `latest_source_game_date: YYYY-MM-DD`를 명시했다. 각 행의 `source_meta.source_game_dates`는 원본 record ID→경기 날짜 매핑이며, `source_meta.fact_dates`는 이 날짜들의 정렬된 고유 목록이다. 현재 XI 사후 진단은 대상 경기 날짜까지 포함하므로 prior-only 자료와 날짜가 다르다. 날짜를 임의의 정확한 시각으로 변환하지 않았다. 부모 작업은 `max_fact_date + 3 calendar days <= decision_at의 한국 날짜`인 별도 DATE-ONLY retrospective 평가를 만들 수 있지만, 이것을 strict/captured 평가로 승격하면 안 된다. 이 작업의 54행·737행 커버리지는 해당 추가 3일 게이트 적용 전 추출 커버리지다.

기본 명단의 `available_at`을 decision_at으로 쓰고, 없다면 kickoff−30분을 쓴다. ARCHIVE의 `available_at`은 가정한 kickoff−24시간이며 관측 증거가 아니다. 각 cohort의 시간 가용성 자체는 부모의 공통 감사에서 별도로 다뤄야 한다.

30일 넘게 이력이 끊긴 기본 명단 10행에서는 직전 XI·변경·14일 선발량을 제외하고, 관측 누적 점유율과 표본 수·오래된 정도만 보존했다. 보조 ARCHIVE는 양 팀 모두 `previous_xi_regular_share`가 있어야 내보내므로 이런 오래된 이력만 있는 경기와 완전 결측 경기는 제외한다. 휴식일만 있는 행을 선발 특성으로 대체하지 않았다.

## 향후 수집 CLI와 실행 기록

`python scripts/rd_soccer_features.py --capture-url https://www.kleague.com/schedule.do --output experiments/pregame-rd-soccer-20261030`

이 명령은 공식 도메인에 HTTPS GET 한 번만 실행한다. 타임아웃 15초, 응답 상한 1MB, 리다이렉트 차단이며 인증정보나 환경 비밀을 읽지 않는다. 2026-10-30T04:04:35.049787Z에 HTTP 200으로 공식 일정 HTML을 저장했다. 실제 본문과 SHA-256·관측 시각·실패 여부는 `capture-*`에 남겼다. 일정 HTML 저장은 XI 발표나 특정 미래 경기 선발 확보를 뜻하지 않는다.

실제 미래 경기 intake 계약은 위 명령에 `--event-id <정확한 프레임 event_id> --kickoff <시간대 포함 미래 시각> --capture-url <공식 match.do 상세 URL>`을 지정하는 것이다. 과거 kickoff 입력은 거부하며 수집 시각을 과거로 지정하는 옵션은 없다. 원본을 gzip으로 보존하고 시계를 현재 시각으로 기록한다. 현재 공식 HTML의 XI 파서는 구현하지 않았으므로 `normalized_xi=null`, `unverified`를 유지한다. 향후 공식 상세 페이지의 정확한 선수 ID·선발 구분·경기 식별을 파싱하고 실제 관측 시각이 decision_at 이전임을 확인해야 `captured_pregame`으로 승격할 수 있다. 지금 수집한 시각을 과거 첫 수집 시각으로 소급하지 않는다. cron·배포·라이브 생성기는 실행하지 않았다.

정확한 공식 XI 응답 엔드포인트·스키마는 확인하지 못했다. 따라서 네트워크 CLI는 **capture-only**이며 선발 자동 수집기 완료로 보고하지 않는다. 순수 Python API `parse_xi_intake(payload: bytes, clock: CaptureClock, expected: FixtureIdentity, decision_at: str)`를 추가했다. 이는 알려진 실제 공식 스키마라고 주장하지 않는 **정규화 intake 계약**이다. JSON 본문은 `fixture`와 `starters: {home: [선수ID 11개], away: [선수ID 11개]}`를 받아야 한다. `fixture` 필수 필드는 `event_id`, `source_fixture_id`, `league`, `kickoff`, `home`, `away`이며 expected와 모두 일치해야 한다. 양쪽 각각 정확히 고유 ID 11개이고 양 팀 ID가 겹치지 않아야 한다. `clock`은 공식 HTTPS URL, `request_started_at`, `observed_at`, `source_sha256`를 요구한다. payload SHA-256 및 `request_started_at <= observed_at <= decision_at < kickoff`를 검증한다. 본문은 1MB를 넘을 수 없다. caller가 전달한 수집 시계의 진위까지 인증하지 않으므로 이 API도 `unverified`를 반환하고 `publication_at`, `max_fact_time`은 null로 둔다. 공식 응답의 실제 매핑·캡처 원본 연계 없이 모델 특성을 생성하거나 수집 증거 등급을 올리지 않는다.
