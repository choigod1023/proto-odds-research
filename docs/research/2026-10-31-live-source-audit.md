# 선수 사실·배당 소스 접근과 저장 자료 점검

2026-10-31 KST에 코드와 공개 문서를 검토했다. 운영 서버·DB·스케줄 상태는 읽지 않았으므로 아래는 **저장소에 구현된 경로와 로컬 파일**에 대한 판단이다. 현재 운영에서 켜져 있다는 증거가 아니다. 출처의 접근 가능성과 반복 수집·서비스 이용 허가는 다르다.

- **KBO**: `kbo_pregame.py`는 `kbo_official.py` 공식 일정·타순을 우선하고 오류 시 다른 경로를 사용한다. 공식 타순은 `LINEUP_CK`, 경기·팀 ID, 9개 순서 검사를 거친다. KBO 공식 약관은 사전 동의 또는 공식 API 없는 대량 반복 자동수집을 제한하고, 수집 데이터의 재판매·재배포·타 플랫폼 연동·2차 가공도 제한한다. [KBO 이용약관](https://www.koreabaseball.com/Member/Join/Accessterms.aspx). 서비스에 이용할 권한, 해당 엔드포인트가 허가된 공식 API인지, 폴링 빈도와 2차 이용 범위가 확인되지 않아 **새 자동 요청과 연결은 보류**다. 기존 연구에서 수집한 자료의 공개 또는 운영 활용 권한도 별도로 확인해야 한다. 선발 예고를 확정이나 부상으로 취급하지 않는다.
- **MLB**: `mlb_candidate_feed.py`는 공식 게임 ID, 경기 전 시점·상태, 상대 선수 중복, 양 팀 타순과 예고 선발을 검사하지만 양 팀 완전 타순이 없으면 전체 후보를 거부한다. 예고 투수는 확정이 아니다. [MLB 이용약관](https://www.mlb.com/official-information/terms-of-use)은 MLB 디지털 서비스에 대한 자동 스크립트 사용을 제한한다. 해당 API 사용 범위·계약을 확인하지 못해 자동 접근 권한과 지연을 미확인으로 둔다.
- **K리그1·2**: `game_detail.py`에는 선수 명단·교체 파싱, `lineup_soccer.py`에는 과거 K리그1 상세 자료가 있지만 현재 공식 부상·교체의 권한 있는 실시간 피드로 확인된 것은 아니다. [연맹 API 명세](https://api.kleague.com/docs/api_match_player_record.jsp)는 경기·팀·선수 식별과 공식 선수기록을 설명하며 인증키가 필요하다. 키 발급·계약·해당 필드 및 경기 전 제공 시점은 미확인이다. 현재 프로세스의 `KLEAGUE_API_KEY`는 설정되지 않았으나 별도 계정이나 서버의 권한 상태는 확인하지 않았다.
- **NPB**: `japan_info.py`는 NPB 예고 선발을 읽고 `npb_lineups.py`는 공식 박스스코어와 과거 타순을 사용한다. 과거 타순과 예상 타순을 당일 확정 명단으로 치환하지 않는다. 부상·경기 중 교체의 이용 조건, 기계 수집 허가와 지연은 확인하지 못했다.
- **KBL·NBA·V리그 및 기타 축구**: 이번 조사에서는 권한 있는 선수 부상·선발·교체의 현재 데이터와 경기·선수 ID 연결을 실측하지 못했다. 기존 코드나 개별 화면의 존재만으로 커버리지와 업데이트 간격을 주장하지 않는다. 종목별 공식 또는 허가된 피드, 사용권, 정확한 경기·선수 ID와 source/수신 시각이 필요하다.
- **배당**: `odds_live.py`는 기존 코드에서 발매 회차 가격과 내역을 구성하고 `live_market_refresh.py`에 넘기지만, 현 운영 지연·계정 권한은 측정하지 않았다. `wisetoto.py` 원천의 서비스 연동·반복 조회 허용 범위도 미확인이다. [The Odds API 문서](https://the-odds-api.com/liveapi/guides/v4/)는 API 키·쿼터와 상품별 `last_update`를 명시하고, [제공자 갱신 간격](https://the-odds-api.com/sports-odds-data/update-intervals.html)은 주요 시장의 경기 전 60초·진행 중 40초라고 설명한다. 이는 제공자 설명이지 본 서비스의 측정 지연이나 스포츠토토 동일 상품 보증이 아니다. 현재 프로세스에서 `ODDS_API_KEY`, `THE_ODDS_API_KEY`는 비어 있었으며 계정·계약·리그별 실제 응답은 미확인이다. 국내 프로토와 해외 북메이커 가격은 같은 상품으로 자동 결합하지 않는다.

## 로컬 프로토타입과 관측

`inspect_snapshot.py`는 네트워크 호출 없이 로컬 `docs/data/live_odds.json`의 동일 회차·게임번호, 팀·리그·상품명과 가격 벡터를 대조한다. 지정한 전체 snapshot 바이트 SHA256과 파일 생성 주장시각, 실제 로컬 읽기 완료 시각을 보존한다. 결과값은 추출하지 않는다. 이 SHA는 원천 HTTP 응답의 해시가 아니며 파일 생성시각을 원천 게시·수신시각으로 오인하지 않는다. 기간·공식 경기 ID·실제 원천 수신시각은 null, 모든 행의 `quote_eligible`은 false다. 소스 원문도 파일에 없으므로 재검증할 수 없다.

저장 스냅샷의 `generated_at`은 2026-09-05 16:25:57 KST이고 이번 로컬 읽기는 2026-10-31이다. 승패/승무패 가격 벡터 172개가 구조 검사를 통과했다(MLB 36, KBO 10, NPB 10, K리그1 6, K리그2 8 포함). 다른 상품 686개와 가격 불일치·불완전 6개는 제외했다. 이 수는 과거 파일의 상품 행이며 현재 경기나 실시간 커버리지가 아니다. 원천 시각과 동일 상품의 공식 연결이 검증되지 않아 실시간 자격은 0건이다. 검사 요약만 저장하고 개별 가격 원문은 복제하지 않았다.

`protect_previous`는 파싱 오류, 잘못된 시각, 오래된 파일, 같은 생성시각의 다른 내용에서 기존 값을 보존한다. 새 내용이 허용돼도 결과는 관측용이며 자동으로 거래·모델 입력에 넣지 않는다. `safe_poll_decision`은 권한 확인 여부를 호출자가 명시해야 하는 순수 판단 함수다. 권한 미확인·403/401/429는 중단하며 오류 후 대기를 적용하고 최소 간격보다 빠른 설정을 거절한다. 실제 통신·예약·무한 반복은 구현하지 않았다. 60초 바닥과 오류 후 300초는 테스트용 보수 설정이며 출처의 허용 속도나 서비스 SLA가 아니다.

실제 빠른 연결을 위해서는 각 제공자의 서면 이용 범위·비용/쿼터, 인증키 접근 권한, 원천 응답 본문 저장·재배포 허용 여부를 확인해야 한다. 그 다음 허용된 연결에서 경기·팀·선수 공식 ID와 상품·기간·라인·완전 가격벡터, source 시각·실제 HTTP 수신 완료 시각·원문 해시를 묶어 측정하고, 결장/예고/확정/교체를 분리해야 한다. 기존 픽 동결과 가격·정산을 덮어쓰지 않는다.
