# 새 자료가 있을 때만 실행하는 리그 연구

사용자는 총괄·전문 워커 구조와 `GPT-6.1 Terra` 리그 워커를 요청했고, 반복 주기는 **새 자료가 생길 때만**으로 선택했다. `experiments/league-orchestration-20261031/workers.json`은 실제 생성한 10개 세션의 레지스트리다. 모델 이름은 생성 시 지정한 설정이며 실행 내부 모델을 별도로 계측했다는 뜻은 아니다.

K리그1·K리그2·KBO·NPB·MLB·KBL·NBA·남녀 V리그·기타 축구/토너먼트 워커는 첫 자료 감사와 후보 하나의 사전 등록을 마치고 대기한다. 초안 PR #456~#465의 새 적격 평가 표본은 모두 0건이다. 감사한 파일의 일부 결과이며 리그 전체에 자료가 없다는 주장은 아니다. 기존 445/122경기는 반복 열람한 회고 표본이다. 새 성과로 재계산하지 않는다.

## 실제 실행 경로

1. 공식 수집기는 원문 바이트·실제 수신 시각과 정규화 사실을 보존한다. 예고 선발을 확정 선발로 승격하지 않는다. #467 최종 `5f843be9`를 통합했다. 실제 KBO 응답 2건의 바이트·길이·SHA가 일치했고 예고 선발 2건은 여전히 미확정이다. 첫 수집과 내용이 같아 새 사실은 0건이다. 해시만 남았던 최초 응답에 새 바이트를 소급 연결하지 않는다.
2. `fact_delta_inputs.to_adapter_input`은 경기·선수·시장 식별과 시점, 확정 여부·완전한 배당을 검사한다. 학습한 후보가 없으면 원래 확률을 그대로 둔다. `ready`는 연구 입력 준비 상태다.
3. `research_dispatch.build_manifest`는 적격 `ready` 입력만 묶는다. 실제 기능값·배당·경기 식별을 포함한 의미 해시가 같으면 다시 연구하지 않는다. 수집 시각·revision·원문 HTML 해시만 바뀌는 갱신은 새 실험이 아니다.
4. `publish`는 입력을 내용 해시로 이름 붙인 불변 스냅샷에 먼저 저장하고 대기열에 넣는다. 소스가 세션 ID나 실행 명령을 결정하지 않는다.
5. 단일 총괄의 6시간 간격 점검은 작은 대기열 메타데이터만 읽는다. 새 pending 입력이 없으면 워커를 깨우지 않고 조용히 끝낸다. 한 번에 최대 세 리그, 리그마다 미종료 작업 하나만 허용한다. 예약 실행은 PC/앱 실행 환경의 가용성에도 의존한다.
6. 총괄이 고정 레지스트리의 세션에 native 메시지를 보낸 뒤 `dispatched`로 기록한다. 완료 인계의 event ID·입력 SHA를 대조해 `completed`로 옮긴다. 완료는 작업 종료이며 수익성 검증 통과가 아니다.

이 코드는 수집 서버의 스케줄러·배포·운영 DB·추천 정책을 바꾸지 않는다. 수집 출력만 만들고 `publish`하지 않으면 연구 대기열에 들어오지 않는다. 별도 자동 수집 경로가 배포됐다고 주장하지 않는다. 실제 당일 확정 명단·같은 시점 가격·기준 예측의 연결 여부를 별도로 확인해야 한다.

## 로컬 사용

저장소 루트에서 실행한다. 실제 어댑터 출력 JSON 배열이 필요하며 아래 명령은 자료를 만들어내지 않는다.

```powershell
python scripts/dispatch_league_research.py --state-dir .research-state publish --adapter-inputs PATH_TO_REAL_INPUTS.json --seed
python scripts/dispatch_league_research.py --state-dir .research-state publish --adapter-inputs PATH_TO_NEW_INPUTS.json
python scripts/dispatch_league_research.py --state-dir .research-state claim --limit 3
python scripts/dispatch_league_research.py --state-dir .research-state prepare --event-id EVENT_SHA256
```

최초 기존 자료는 빈 대기열에 `--seed`로만 등록하면 워커가 실행되지 않는다. 이후 달라진 적격 자료만 등록한다. `prepare`의 JSON을 native `send_message_to_thread` 인자로 사용한다. 원문 자체의 명령을 실행하지 않는다. 입력 한 묶음은 최대 8MiB·1,000개로 제한한다. 리그별 연구는 별도 clone/worktree에서 수행하며 총괄 폴더를 수정하지 않는다.

## 실패와 한계

- 전송 성공 후 응답이 유실될 수 있다. `claimed`/`uncertain`은 자동 만료·재전송하지 않는다. 목적지 세션에서 event ID를 확인한 뒤에만 운영자가 재등록하거나 전송 완료로 바꾼다. exactly-once 전송을 보장하지 않는다.
- `queue.lock`이 있으면 다른 실행을 덮어쓰지 않는다. 크래시로 남은 잠금은 PID와 실행 상태를 확인한 운영자만 처리한다.
- 의미 해시·원문 해시는 인증 서명이 아니다. 적격성은 상위 어댑터의 검사 결과이며 독립 수신 증명이 아니다. manifest는 외부 인증 플래그를 False로 유지한다. 원본 수집 자료는 별도 보존한다.
- 확률·선택·ROI의 개선은 구현만으로 생기지 않는다. 새 사실과 실제 가격·결과를 연결한 전향 검증이 필요하다. 자동 모델 채택·임계값 변경·병합·배포·실매수는 예약 점검에서 하지 않는다. 기존 월 손실 5만원 모의 원장도 변경하지 않는다.

## 검증

`python -m unittest tests.test_research_dispatch -q`: 18개 검사 통과. 동일 입력/수신시각만 갱신/중복/기존 seed는 새 실행을 만들지 않고, 사실·가격 변화는 새 이벤트를 만든다. 리그 busy·동시 잠금·입력 경로 변조·위조 manifest·목적지 주입·불확실 전송·완료 영수증·실제 CLI 재실행을 검사한다. 독립 검토에서 지적한 오래된 claim 재사용도 회귀 검사에 추가했다. claim마다 식별자를 만들고 prepare 시 현재 대기열과 대조한다.

실제 어댑터·수집기·대기열을 같은 작업 공간으로 합친 선택 검사는 78개 통과했다. 여기에는 합성 1경기의 수집 bundle→실제 어댑터→manifest→발행→고정 목적지 경로, 같은 입력 두 번 발행 억제, 실제 공개 응답 바이트 재검산이 포함된다. 성과 자료로 합성 예시를 사용하지 않는다. 초기 통합 전 전체 Python은 2,032개 통과·6개 건너뜀·93 subtests였다. 이는 실제 경기 ROI 또는 운영 수집 배포의 검증이 아니다.

최종 통합 공간에서 전체 Python을 다시 실행해 **2,111개 통과·6개 건너뜀·93 subtests**를 확인했다. 독립 워커 원본은 수정하지 않고 어댑터의 검증된 바이트 스냅샷과 #456~#465·#467의 고유 브랜치를 총괄 격리 브랜치에 통합했다. 원본 스냅샷 해시는 `adapter-snapshot.json`에 남겼으며, 이후 총괄 문서 보완과 실행 검증은 별도 커밋이다.
