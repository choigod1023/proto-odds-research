# 다른 기간의 투표·시장 우선·9:1 비교와 보존 모델 확인

2026-11-04. 기존 실제 투표 14경기의 결과를 다른 기간에 일반화할 수 있는지 확인했다. 새 비교는 당시 저장된 입력으로 지금 계산한 **후향 가상 비교**이며, 실제 과거 운영 투표의 수익이나 아직 보지 않은 검증 기간의 성과가 아니다.

시장 우선·9:1이 투표보다 일관되게 우수하다는 근거는 확보하지 못했다. 넓은 260경기에서는 손실이 조금 작았지만 모두 적자였고, 경기 전 동결 예측과 교차 확인되는 21경기에서는 투표가 더 좋았다. 두 표본은 중복되며 합쳐서 281경기로 세면 안 된다.

## 1. 260경기: 저장 배당을 사용한 진단

MLB, KST 2026-08-30 02:05~09-24 11:10. 투표 자료가 연결된 278경기 중 동률 18경기를 따로 남기고, 세 방식이 모두 선택할 수 있는 동일 260경기를 비교했다. TailSlips 작성자 계정 62개, 원문 픽 문장 1,749건이며 247경기에 두 계정 이상이 있다. **여러 사이트 또는 서로 독립된 62명의 전문가를 검증한 것은 아니다.**

- 투표: 153/260, 적중률 **58.85%**, ROI **-8.66%**, 가상 손익 -225,200원.
- 시장 우선: 159/260, **61.15%**, **-7.66%**, -199,200원.
- 시장 90%·투표 10%: 159/260, **61.15%**, **-7.37%**, -191,600원.

모든 경기에 단폴 1만 원씩 같은 금액을 적용했다. 적중 시 `배당×베팅액-베팅액`, 실패 시 `-베팅액`, ROI는 총손익/총베팅액이다. 월 손실 한도 계좌의 실제 수익이 아니다. 기존 월 -5만 원 모의 원장은 바꾸지 않았다.

8월 25경기의 투표/시장/9:1 적중률은 56%/60%/60%, ROI는 -16.52%/-9.64%/-9.64%였다. 9월 235경기는 59.15%/61.28%/61.28%, -7.83%/-7.45%/-7.13%였다. 모두 손실이다. 두 달의 표본 수가 크게 다르며 독립된 외부 검증으로 볼 수 없다.

시장은 투표와 50경기에서 달랐고 28경기는 개선, 22경기는 악화했다. 9:1은 투표와 32경기에서 달랐고 19경기 개선, 13경기 악화했다. 시장과 9:1도 18경기에서 달랐다. 서로 9경기씩 맞고 틀려 적중 수는 같지만 적중 배당이 달라 ROI가 다르다.

24개 KST 경기일을 묶은 10,000회 paired bootstrap의 탐색적 95% 구간은 다음과 같다. 계정 간 상관과 장기 변동을 모두 설명하는 구간은 아니다.

- 시장-투표: 적중률 차이 +2.31%p, 구간 -2.63~+7.50%p; ROI 차이 +1.00%p, 구간 -7.60~+9.81%p.
- 9:1-투표: 적중률 차이 +2.31%p, 구간 -1.59~+6.56%p; ROI 차이 +1.29%p, 구간 -5.77~+8.48%p.

**중요한 시각 한계:** 이 표본의 `odds_snapshots.observed_at`은 기존 `src/snapshot.py`가 HTTP 요청 전에 기록한 배치 시작 시각이다. 기록상 배당 시각이 경기 30.13~89분 전이어도 실제 응답 완료가 경기 30분 전이었는지는 증명하지 못한다. 따라서 이 260경기는 T-30 가격의 시점 검증을 통과한 승격 근거가 아니다. 90분 이내 배당만 쓰는 민감도 조건에서도 같은 260경기가 남았지만 이 결함을 해결하지는 못한다.

## 2. 21경기: 경기 전 동결 예측과 연결되는 교집합

MLB, KST 2026-08-30 11:05~09-18 10:38. 경기 전 동결 예측 원장의 원래 선택지·배당·상품 식별자를 재현하고, 그 판단 시각까지 수신된 원문 투표를 연결했다. 연결 22경기 중 동률 1경기를 제외했다. 작성자 계정 33개, 픽 문장 149건, 두 계정 이상인 경기는 20개다.

- 투표: 14/21, **66.67%**, ROI **+6.14%**, 가상 손익 +12,900원.
- 시장 우선: 12/21, **57.14%**, **-13.33%**, -28,000원.
- 9:1: 13/21, **61.90%**, **-4.86%**, -10,200원.

이 교집합에서는 오히려 투표가 우세했다. 작은 표본의 플러스 수익을 미래 수익 근거로 삼을 수 없다. 예측 원장 저장 시각을 추가로 대조했다는 점에서 가격 배치 시작 시각만 있는 260경기와 증거 수준이 다르지만, 외부 시각 인증이나 실제 구매 체결을 입증한 것은 아니다. 입력 가용성에 따라 선택된 표본이며 260경기와의 차이를 모델의 인과 효과로 해석하지 않는다.

실제 운영 `tipster-vote-v1` 14경기(8/14, 57.14%, ROI -4.50%)는 별도다. 위 결과에 과거 운영 정책, 폴백, 연구 모델 성과를 실제 투표 수익으로 섞지 않았다. 연구의 명시적 ML 원문에는 픽스터 자신의 배당이 없는 문장도 허용했다. 지급 배당은 공통 프로토 가격에서만 가져왔으므로 현재 운영 매처와 완전히 같은 입력 집합이라고 주장하지 않는다.

## 3. 원문·배당·공식 결과 연결

- 원문: 기존 `event_records`의 first-observed 로그 14,608개를 읽기 전용으로 내보냈다. source-native `raw_text` 픽 문장과 원래 이벤트 전체를 보존하고 canonical SHA-256을 대조했다. 경기 시작/정산/베이스라인/조합 픽은 배제했다. 원문 선택과 팀, 원천 경기 헤더의 팀·ET 날짜·시각을 확인하고 공식 경기 시각과 10분 이내인 유일한 경기만 연결했다. 한 작성자의 최초 수신 투표 하나만 쓰고 최초 시각의 상충 투표는 보류했다. HTML 전체 원문을 보관한 것과는 구별한다.
- 배당: 동결 예측 원장 10,749행의 해시 체인을 검사했다. 별도로 공식 MLB 상품 560개를 키로 조회해 과거 배당 477개를 읽기 전용 추출했다. 경기·연도·회차·상품번호·팀·날짜·2-way 승패 조건을 확인하고 같은 시각의 상충 배당을 보류해 유일 경기 배당 427개를 남겼다. 이후 원문 투표가 판단 시각까지 있는 경기를 연결했다. 다른 시장 배당·픽스터 배당·마감 배당으로 대체하지 않았다.
- 공식 결과: Betman 2026년 101~130회차의 직접 캡처 DOM 30개를 사용했다. 파일 해시·선택 회차·URL·경기번호·팀·경기 시각·시장·선택지 수·확정 점수를 검증했다. 2-way 무승부는 환급 증거 없이 승패로 바꾸지 않았다. DOM 추출물이며 원래 HTTP 응답 바이트라고 주장하지 않는다.
- 가격 확률: 시장은 같은 상품의 저장 시장 확률을, 배당 관측 표본에서는 저장된 양쪽 배당의 Shin 확률을 사용했다. 9:1은 `0.90×시장확률 + 0.10×작성자별 투표비율`의 최댓값이다. 최적 가중치나 결과 기반 임계값 탐색은 하지 않았다. 세 선택을 먼저 계산한 다음 공식 결과를 붙였다.

직접 원천은 [TailSlips MLB 슬레이트](https://tailslips.com/slate?sport=mlb), [Wisetoto 배당](https://www.wisetoto.com/index.htm?tab_type=proto), [Betman 공식 종료 회차](https://www.betman.co.kr/main/mainPage/gamebuy/closedGameSlipIFR.do?gmId=G101&gmTs=260128&isIFR=Y)다. 각 픽 문장의 원래 개별 URL은 저장돼 있지 않아 임의로 만들지 않았다. 공식 증거의 회차별 URL은 매니페스트에 있다.

다른 사이트 자료도 확인했다. 저장된 공개 픽 33건 중 pick79 정규 URL 18개에서 현재 HTML을 복원했지만 당시 저장된 본문 해시와 일치한 것은 0건이었다. goli 요청은 연결 실패했다. 현재 본문을 과거 원본으로 바꾸어 넣지 않았다. 6개월~1년의 Pickswise/Tony's Picks/Covers/Betblog 등 기존 아카이브도 남아 있으나 경기 후 수집·당시 체결 가격·발표 시점 증명 문제가 있어 이번 경기 전 증거 표본에 억지로 추가하지 않았다.

## 4. 수집 시각 결함 수정과 재현

`src/snapshot.py`는 회차마다 fetch/parse 처리 완료 시각을 가격 시각으로 기록하고, 별도의 `odds_snapshot_receipts`에 시작·완료 시각, 행 수, 배치 해시를 남기도록 수정했다. 이 기록도 외부 시각 인증이나 거래 체결 증거는 아니다. 과거 시각·DB·원장·추천은 고치지 않았다. 기존 코드에서 회귀 테스트 2개가 실패하고 수정 후 통과한 기록은 `timestamp-regression.json`에 있다. **아직 병합·운영 배포하지 않았다.**

입력·정산·결과는 `experiments/tipster-extended-20261104/` 및 하위 `observed-quotes/`의 gzip JSON과 `artifact-manifest.json`으로 보존했다. 각 입력에는 원래 native record, 원문, 이벤트 해시, 가격, 식별자, 공식 결과의 파일 해시·URL·행 번호가 있다. 압축 해제한 바이트 해시와 재계산 결과를 대조한다.

```powershell
python -B -X utf8 scripts/compare_saved_tipster_periods.py --replay experiments/tipster-extended-20261104
python -B -X utf8 scripts/compare_saved_tipster_periods.py --replay experiments/tipster-extended-20261104/observed-quotes
python -B -X utf8 experiments/tipster-extended-20261104/audit_uncertainty.py
```

외부 원본 묶음의 압축 해제 SHA-256:

- 가격 추출: `7f44035953408b5ea0a9d75848be54d5448a21ff1ea4724aa941e1d891f863ad`.
- 예측 원장: `88e42b7cfd090485340f4b07dc7e382ffa4953c4a3c731a358a4add0fe15dc4f`.

별도 워커가 원문 해시의 추출본 내 존재, 동결 원장/배당 가격, 공식 DOM의 경기·점수 및 두 표본의 적중·손익을 독립 재계산했다. 최초 전체 모집단 23/279경기는 헤더 팀 불일치 2건을 배제하면서 최종 22/278경기로 갱신됐고, 유일 투표 승자 21/260경기의 위 수치는 그대로였다.

## 5. 선수·라인업 모델은 어디에 있는가

저장돼 있다. 다만 전부 현재 운영 추천에 활성화돼 있다는 뜻은 아니다. 상세 목록과 Git blob 해시 감사는 [보존 모델 목록 PR #560](https://github.com/choigod1023/proto-odds-research/pull/560)에 별도로 남겼다.

- main: `src/player_info.py`, `src/pregame_player_capture.py`, `src/kbo_starters.py`, `src/npb_lineups.py`, `src/lineup_soccer.py`, `src/lineup_impact.py` 등 수집·연결 코드.
- KBO M0/M1/M2: 원본·수정 코드, 예측, 결과와 독립 검토가 `codex/kbo-player-effects-20261103` 및 review 브랜치에 있다. 원격 HEAD `d08ccb708033fb6b067e84e80eae81ea3c9b4cfa`, `b0dd76f1a740470769449381fd17fd7c7f03bed1`를 직접 확인했다.
- 실제 선발·타순 학습: [#532](https://github.com/choigod1023/proto-odds-research/pull/532), [#534](https://github.com/choigod1023/proto-odds-research/pull/534), [#535](https://github.com/choigod1023/proto-odds-research/pull/535), [#533](https://github.com/choigod1023/proto-odds-research/pull/533)는 이번 확인 시 OPEN·draft·미병합이었다. 총괄 원격 HEAD `2e63d4e79e2f6215f13f2bf2c861346c581732f6`도 남아 있다.
- M0 후속 shrink/NB2/혼합: main의 `experiments/kbo-m0-followup-20261103/`.
- MLB 선수 후보 `linear:l2=10`, KBO 동적 잔차 `e0:residual:0.03`: `data/model_candidates/`, `src/mlb_frozen_candidate.py`, `src/kbo_frozen_candidate.py`. 그 밖의 동적 득점·보정·시장 잔차 연구도 목록에 있다.

이전 실제 명단 연구의 KBO M0는 418/709, 배당 연결 667경기 ROI -4.36%; M2는 396/709, 연결 667경기 -7.38%였다. 이 역시 이미 열람한 후향 자료이며 경기 전 명단 수신·구매 체결이 증명되지 않았다. 이번 MLB 260경기와 모집단이 달라 직접 순위를 매기지 않는다.

이번 결론은 **현행을 바꿀 만큼 우열이 입증되지 않았다**는 것이다. 선수 모델을 버리거나 투표만 남긴 결론이 아니다. 다음 비교는 시각 문제가 없는 가격 수신 기록과 원문·발표 명단이 동시에 있는 동일 경기 표본에서, 보존된 선수 모델까지 같은 조건으로 비교해야 한다. 연구 보존을 위한 PR과 실제 모델 교체·배포는 구별한다.

## 검증 기록

최종 코드로 두 압축 자료의 해시 검사·완전 재계산이 일치했다. 입력/시각 회귀 및 기존 비교 테스트 59개가 통과했고 전체 Python 테스트는 **2,451 passed, 6 skipped, 100 subtests passed**였다. UI 변경은 없다. 원천 HTTP 본문과 전체 DB 내보내기는 별도 증거 폴더에 보존하고 선택된 원문·가격·결과와 검토 기록을 이 연구에 넣었다. 현재 상태는 로컬 구현·검증이며 저장소 병합 및 운영 배포와 구별한다.
