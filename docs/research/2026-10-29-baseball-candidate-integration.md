# 운영 비교 배포와 동결 야구 후보 연결

## 실제 배포 확인

PR #414는 사용자 승인 후 2026-10-29 13:37:51 UTC에 `91d5f7179b26236211cd25b61b7463759e4a3e5b`로 병합했다. 같은 이미지·1024MB 머신을 재시작해 이 checkout을 반영했고 SSH에서 코드 반영을 확인했다. 이미지에 들어가는 supervisor는 변경하지 않았다.

다음 자동 판정은 13:52:17~13:53:55 UTC에 실행됐다. 13:53:28 UTC에 원장 8676~8678번의 새 전향 비교 기록 3건이 저장됐다. 두 건은 세리에A, 한 건은 잉리그컵이며, 경기당 비교 payload는 3,073 bytes였다. 이는 **#414의 시장/투표 비교 기록이 실제 저장된 증거이며 새 야구 후보의 적중 증거가 아니다.**

기존 검증 원장 8,674건과 새 4건을 연결해 총 8,678건의 해시 연결을 다시 검사했다. 과거 기록을 덮어쓰거나 동일 입력에 sidecar만 소급 삽입하지 않았다. 상세는 `experiments/baseball-candidate-bridge-20261029/deployment-414-verification.json`에 남겼다.

## 이번 구현

실제 추천은 `tipster-vote-v1` 그대로다. 새 학습·비중 탐색·후보 재선정 없이 다음 두 동결 모델을 별도 연구 arm으로 연결했다.

- MLB: `linear:l2=10`, 이전 시즌 선수 지표와 공식 공개 타순·투수의 원시 카운트를 사용하는 선형 모델. 이전 연구의 계수/스케일/학습 종료 시각과 이전 시즌 prior를 작은 파일로 보존했다.
- KBO: `e0:residual:0.03`, 상대 강도를 반영한 동적 전력과 동일 시장·동일 투표 집합의 고정 9:1 기준을 쓰는 잔차 모델. 선발·타순을 직접 쓰는 모델이라고 부르지 않는다.

MLB의 경기 전 원천은 기존 선수 수집 작업에서 공식 `feed/live`를 최대 3경기씩 수집한다. 앞으로 30분~6시간 이내 경기만 대상으로 하고, 30분 슬롯마다 조회 순서를 순환해 같은 세 경기만 계속 조회하지 않는다. 요청별 연결/읽기 제한·본문 2MiB·전체 작업 시간 예산이 있다. 이 예산이 모든 MLB 경기의 타순 확보를 보장하지는 않는다.

다음 조건을 모두 만족해야 후보 확률이 생긴다: 정확한 gamePk/시작 시각, Scheduled/Pre-Game/Warmup, 실제 투구 없음, 양쪽 서로 다른 9명의 타순, 필수 원시 통계, 실제 HTTP 수신 완료 시각 ≤ 판정 시각 < T-30. 예상 타순·현재 경기 박스스코어·선수 이름만으로 누락을 채우지 않는다. `probablePitchers`는 **공식 공개 예정 투수**이며 최종 선발 확정으로 표시하지 않는다.

KBO는 2026-10-27까지의 고정 연구 이력 상태와 그 뒤 공식 날짜별 일정/결과를 연결한다. 공식 휴식일의 빈 일정도 증거로 보존하고, 미종료·누락·점수 불일치·기존 경기와 모순되는 빈 응답이 있으면 다음 상태를 만들지 않는다. 실제 로컬 수집에서 10월 28일 0경기, 29일 KIA 4–삼성 6 종료를 확인했고 29일/30일용 상태를 계산했다. seed를 실제 읽은 시각은 14:04:50 UTC로 남겼으며 과거로 소급하지 않았다. 고정 연구 이력의 과거 가용 시각과 이후 수정 여부는 미검증이라는 한계도 계속 기록한다.

수집은 기존 선수 작업, 추론·원장 저장·공식 정산은 기존 판정 작업에서 수행한다. 새 상시 프로세스, 유료 서버, HTTP 요청 경로의 학습이나 대형 이력 조회를 추가하지 않았다. KBO 이력 갱신은 배경 작업에서 한 번 계산하고 경기별로는 작은 상태만 읽는다. 현재 선수 작업은 명목 30분 간격이며 메모리 대기나 원천 미발표로 T-30 전에 입력을 확보하지 못할 수 있다. 이때는 정확한 사유와 함께 unavailable로 남긴다.

## 입력 시각 문제 수정

기존 KBO 경량 갱신은 선택/가격이 변하지 않아 이전 decision을 유지하면서도 `research_player_inputs.observed_at`만 새 시각으로 바꿀 수 있었다. 그러면 이전 원장 identity와 입력이 충돌하거나 `as_of` 뒤 자료로 검사돼 제외될 수 있다. 실제 비교에서도 이런 시각 불일치가 제외 사유였다.

새 구현은 새 판정을 만들 때만 선수 입력을 붙이고, 새 자료를 실제 읽은 시각보다 과거인 `as_of`를 쓰지 않는다. 시장 원천 관측 시각은 별도로 그대로 보존한다. 같은 입력을 재확인한 것만으로 기존 기록의 관측 시각을 바꾸지 않으며 T-30 동결 입력은 보존한다. KBO 상태는 canonical hash가 있어 UI용 여섯 자리 반올림을 적용하지 않는다.

## 기록·정산·수익 제한

새 `features.model_comparison.learned_candidates`에는 모델/입력/특성 해시, 같은 선택 ID·offer·가격, 후보 확률과 사유를 기록한다. 모델 부재·시각 부적격·불완전 타순·전력/투표 누락이면 시장 확률로 채워 성공처럼 표시하지 않는다. MLB 원천은 45분, KBO 상태 관측은 6시간보다 오래되면 새 후보 추론을 보류한다. 이는 검증된 수익 임계값이 아닌 입력 신선도 보호 기준이다.

운영이 보류한 경기에도 후보가 있으면 공식 전체 승패 결과로 연구 정산을 남긴다. 결과 교정은 새 정산으로 추가하고 반복 입력은 중복 생성하지 않는다. 2-way 승패의 무승부는 환급이다. 연구 후보 손익은 `hypothetical_*`, `paper_wallet_affected=false`로 명시한다. 실제 모의 지갑을 거래하거나 월 순손실 5만 원 제한을 변경하지 않는다. 후보 결과를 웹의 운영 적중률에 합치지 않는다.

기존 오프라인 운영 비교기도 저장된 후보 forecast를 읽어 동일 경기의 운영/시장/9:1/후보를 비교하도록 확장했다. 저장된 미래 후보를 다른 계수로 조용히 재계산하지 않으며, 알려진 artifact와 선택·가격 identity를 검사한다. 선택률·정산/미정산·ROI·관측 배치 종료 낙폭과 선택 사건의 Brier/logloss를 함께 계산한다. 선택 사건 점수는 전체 3-class 벡터 점수나 보정 완료 증거가 아니다.

## 과거 자료 재실행 결과

명령은 `python -X utf8 scripts/replay_baseball_candidates.py --output experiments/baseball-candidate-bridge-20261029/replay.json`이다. 경기당 고정 단폴 1만 원, 연구 계산에 월 손실 제한은 적용하지 않았다. 선택한 모델은 바꾸지 않았다. 총 1,220행(MLB 310, KBO 검증 712+평가 198)의 선택·원 단위 정산이 기존 기록과 일치했고 확률 최대 오차는 약 `1.67e-16`이다. 검증 712행을 새 평가 표본이라고 부르지 않는다.

- MLB 추가 집합 230경기 중 자료 적격 **194경기**(2026-07-30~08-23): 시장 기준 109/194 적중, −254,700원, ROI −13.13%. 후보 109/194 적중, −136,000원, ROI −7.01%. 36경기는 원천 시각 조건을 충족하지 못해 이 표본에서 제외했다. 누락 36경기에 시장 대체를 적용한 앞선 230경기 전체 수치와 분모가 다르다.
- MLB 다른 **116경기**(2025-11-01~2026-10-24): 연구 9:1 기준 63/116, −154,800원, ROI −13.34%. 후보 52/116, −283,000원, ROI −24.40%.
- KBO 평가 **198경기**(2026-03-29~07-23): 연구 9:1 기준 119/198, −146,600원, ROI −7.40%. 후보 119/198, −144,500원, ROI −7.30%. 일말 최대 낙폭은 157,700→166,700원으로 커졌다.
- KBO 모델 선택에 사용한 **검증 712경기**(2024-03-23~10-28): 기준 411/712, ROI −11.46%; 후보 417/712, ROI −9.95%. 모델 선택에 이미 쓴 구간이다.

미리 정해진 기간을 나눠도 일관된 우세가 아니다. MLB 추가 집합은 8월 10일 전 77경기에서 후보 +1.52%/시장 −14.58%였지만 이후 117경기는 후보 −12.62%/시장 −12.17%였다. KBO는 7월 1일 전 152경기에서 −6.57%/−6.90%, 이후 46경기에서 −9.72%/−9.07%였다. MLB 기존 116경기는 분할 전후 모두 악화됐다.

MLB 후보는 **310경기 전부 홈을 선택했다.** 추가 표본의 손실 감소를 선수 정보의 효과나 안정적 우세로 해석할 수 없다. 홈 고정 통제군과 구분해 확률 품질까지 관측해야 한다. 현재 근거로 실제 추천 교체나 흑자 기대를 제시하지 않는다.

이 과거 가격은 실제 구매 가능 시각이 독립적으로 증명되지 않았고, MLB timecode 자료는 사후 재생이며 KBO 과거 상태는 기록된 전날 가용 가정을 사용했다. 기준도 현재 운영 투표 재현이 아니라 연구 9:1 또는 시장 단독이다. **기존 연구의 재현과 전향 파이프라인 연결이며, 새로 수익성이 개선됐다는 증거가 아니다.**

## 성능·검증·운영 완료 범위

로컬 warm artifact와 합성 원천으로 같은 MLB capture 20회를 측정했다. 비교 payload 4,055 bytes, tracemalloc peak 약 1.65MiB, 회당 약 0.070초였다. tracing 오버헤드가 포함되며 전체 서버 RSS·최대 메모리·OOM 무재발을 입증하는 측정이 아니다.

회귀에는 실제 frozen artifact 전수 재현, 공식 feed의 잘못된 경기/시각/투구/불완전 타순, 일정 누락/휴식일/취소/교정, 과거 입력 불변, 신규 자료의 as_of, 상태 hash 정밀도, 보류 경기 후보 자동 정산·중복 방지·공식 결과 교정·무승부 환급을 포함한다.

이 문서의 #414 자동 적재는 운영에서 확인했다. 새 야구 후보의 수집·추론·공식 정산은 코드와 로컬 실행으로 연결했으며 실제 배포 후 확인은 별도의 배포 검증 파일에 남긴다. 원천에 적격한 타순이 없거나 경기 결과가 아직 없으면 숫자 예측·실현 ROI가 검증됐다고 주장하지 않는다.

원천·산출물: `data/model_candidates/{mlb,kbo}/`의 동결 artifact·hash·독립 재현 입력, `experiments/baseball-candidate-bridge-20261029/`의 실행 결과·공식 일정 원문·메타데이터·#414 배포 증거. 실제 전체 운영 export는 로컬 `.local-test/`에만 보관한다.
