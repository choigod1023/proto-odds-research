# 공식 근거 코호트 수집과 기준 원장 감사

사용자가 검증 수정 병합 후 워커 분담을 승인했다. #475 → #476 → #479를 merge 방식으로 순차 병합했고, 원격 main `e7494e594a1d2b2fe63c67949db8e09b219e51c3`에 세 PR head가 모두 조상으로 포함된 것을 확인했다. 병합 전 각 head의 Python CI 성공과 mergeability를 확인했으며 #476/#479의 base는 main으로 옮겼다. 운영 모델 교체나 수집 서버 배포는 수행하지 않았다.

## 유한 작업 분담

기존 Terra 세션에 native 메시지로 실제 배정했다. 모델/추론 설정을 덮어쓰지 않았고, 새 임시 에이전트를 같은 역할로 중복 실행하지 않았다.

- **승부예측 Terra · K리그1**: 2025 완료 시즌의 공식 경기일·대진·결과를 확보해 국내 자료와 대조한다. 날짜·정확한 시각·취소/연기·복수 매칭·가격 자격을 구분한다.
- **승부예측 Terra · KBO**: 경기 전에 발표된 선발·타순 원문을 실제 확보하고 당시 같은 시장 가격·공식 결과와 연결한다. 게시시각 주장, 독립 아카이브, 실제 사전 수신, 사후 박스스코어를 구분한다.
- **승부예측 Terra · 독립 검토**: primary 논문 최대 네 개를 검토하고 리그별 후보 하나와 평가/중단 규칙을 제시한다. 새 성능 숫자를 만들어내지 않는다.

각 자료 워커는 GET 20개·검색 8질의 이내로 끝내고, 접근 제한을 우회하지 않는다. 새 자료가 없으면 원인과 실제 감사 범위의 0건을 남긴다. 기존 445/122경기나 KBO51경기를 재실험하지 않는다. 코드가 필요한 작업은 독립 worktree/branch, Python 테스트, commit/push/draft PR까지 수행한다. 출력은 `experiments/verified-cohort-20261101/` 아래 역할별 디렉터리로 나누었다.

첫 산출물의 실제 제약을 확인한 뒤 후속 범위를 좁혀 추가 배정했다. K리그는 공개 페이지가 사용하는 조회 전용 POST가 시즌 목록 경로라는 점을 확인해, 상태 변경 없는 해당 목록 열람 요청 최대10회를 허용했다. KBO는 제3자 기사도 공식 발표 원본과 구분한 `historical_claimed_before` 후보로 보존할 수 있도록 원문 최대3건·추가 GET6개·검색2질의로 제한했다. 어느 경우에도 과거 실제 수신이나 검증 수익률 표본으로 승격하지 않는다. 위 예산은 최초 배정 스냅샷 이후 추가한 유한 작업이다.

이번 요청은 수동으로 배정한 유한 수집·조사 작업이다. 자동 6시간 연구 큐와 일정은 변경하지 않았다. 자동 반복 연구는 기존대로 새 적격 입력이 있을 때만 실행한다. 발송 성공을 완료나 성능 개선으로 기록하지 않는다. 배정 스냅샷은 `assignments.json`이며 이후 실제 결과와 구분한다.

## 총괄이 직접 확인한 기준 원장

비교 대조군으로 쓸 수 있는지 확인하기 위해 저장소의 `data/raw/prediction_ledger/pregame.jsonl`을 읽기 전용으로 감사했다. 현재 운영 서버에서 새로 받은 원장이 아니라 저장된 로컬 스냅샷이다.

- 14,150,261바이트, 1,326행. SHA256 `77c224f03c28217f552cb98b96a02e350a1e0e79d12a7145a81a3296a693d4e0`.
- 예측 `as_of` 범위 UTC 2026-08-28 12:12:14 ~ 2026-09-01 23:01:31. 한국 시각으로 8월 28일 21:12:14 ~ 9월 2일 08:01:31.
- 기존 `operating_ledger_inputs.latest_pre_cutoff` 계약으로 경기별 마지막 T-30 이전 revision을 선택하면 206건이다. 반복 revision을 독립 경기로 세지 않았다.
- 선택된 기록의 모델은 `shin-market-anchor-v1` 196건, `internal-context-blend-v2` 10건이다. 현행 `tipster-vote-v1`로 바꾸어 부르지 않는다.
- 선택 기록에는 현재 계약의 정규화 fixture 필드가 없어 입력 적격 0건이다. 이로 인해 리그도 `unknown`으로 남긴다. 이름/리그를 결과나 다른 임의 필드에서 추정해 복구하지 않는다. 이는 원래 예측이 반드시 틀렸다는 뜻이 아니라 현재 비교 계약에 필요한 입력이 없다는 뜻이다.
- 전체 선택/거부 범위에는 불완전한 같은 시장 배당, 미선택 기록, 일부 feature 시각이 예측 기준 이후인 사례도 있다. 사유는 서로 겹칠 수 있으며 거부 revision도 포함하므로 사유 건수를 독립 경기 수로 합산하지 않는다.

따라서 이 파일을 현재 운영 모델의 성적이나 2025 시즌의 실제 운영 실적으로 쓰지 않는다. 그렇다고 다른 저장소 자료나 현재 운영 서버에 적격 자료가 전혀 없다고 결론 내리지 않는다. 이번에는 수익률·모델 적합·새 예측을 계산하지 않았다.

`src/research_baseline_inventory.py`는 기존 입력 계약을 재사용해 위 범위를 집계한다. 최신 revision이 잘못됐다고 오래된 정상 revision을 대신 선택하지 않으며, 결과 레코드는 선택에 쓰지 않는다. 같은 바이트를 해시하고 파싱한다. `roi_input_eligible`은 구조·시점 검사 결과이고 외부 수신·해시 체인·공식 결과·실제 가격 인증은 별개임을 유지한다.

## 실제 운영 실적과 가상 재현의 구분

현행 투표 정책은 2025 시즌에 운영되지 않았다. 그러므로 2025년 현행 정책의 실제 동결픽을 찾지 못했다는 이유만으로 역사 자료 수집을 중단하지 않는다. 과거의 사전 정보·가격·결과를 연결할 수 있으면 현재 규칙의 **historical counterfactual**을 만들 수 있다. 당시 실제 실행한 운영 모델을 복원하는 **actual operating replay**와 다른 비교임을 명시해야 한다. 두 자료 워커에 이 구분도 전달했다.

모델 후보의 정식 비교는 동일 경기·시장·가격·정산과 정보 가용성을 확인한 뒤 실시한다. 시장 기준, 현행 선택 정책, 후보 모델을 구분하고 과거 9:1 혼합을 현행 정책으로 부르지 않는다. 연구 단위 ROI와 월 손실 5만원의 실제 모의 원장 운용 결과도 분리한다. 이번 작업으로 운영 모델·월 손실 한도·실매수 동작을 바꾸지 않는다.

## 실행과 검사

```powershell
python -m src.research_baseline_inventory --ledger data/raw/prediction_ledger/pregame.jsonl --output .local-test/baseline-inventory.json
python -m pytest tests/test_research_baseline_inventory.py tests/test_operating_ledger_inputs.py tests/test_research_chronology.py -q
```

신규 검사 5개 통과. 기존 운영 입력·경기일 검사와 합친 관련 검사는 69개 통과·1개 건너뜀이다. 중복 revision, 과거 정책 구분, 결과/늦은 revision 제외, 잘못된 최신 revision, 빈 입력과 원본 보존을 실제 실행으로 확인했다. 감사 결과는 `experiments/verified-cohort-20261101/baseline/inventory.json`에 보존했다.

총괄 분리 브랜치에서 전체 Python 검사도 실행해 2,209개 통과·6개 건너뜀·93 subtests를 확인했다(196.99초). 워커의 수집/논문 산출물은 별도 초안 PR에서 검토하며, 이 숫자에 아직 통합하지 않은 워커 코드의 검사를 합산하지 않았다.
