각 시나리오는 설명·순차 단계·관찰해야 할 결과로 구성된다. 실행에 필요한 실제 객체와 호출은 **추후 확정된 코드에 맞춰 격리된 테스트 드라이버로 작성해야 한다**. `run_fixtures.py`는 그 로컬 Python 드라이버를 매 시나리오마다 별도 임시 디렉터리에서 shell 없이 실행하고 JSON 결과를 검사한다. 이는 네트워크를 차단하는 샌드박스가 아니므로 운영 서비스나 실제 데이터에 연결된 드라이버를 사용하면 안 된다. 현재 드라이버는 작성하지 않았고 어떤 실제 collector·queue 시나리오도 통과했다고 주장하지 않는다.

몇 가지 기대는 확인이 필요한 인터페이스 가정이다. 예를 들어 probable 자체를 별도 유효 사실로 보관할 수 있지만 `confirmed`를 요구하는 후보나 dispatch 조건에서는 확정으로 취급하지 않는다. 유효한 확정 사실과 같은 상품 가격이 있다면 학습 모델이 없어도 연구 입력은 ready이며 예측 확률은 baseline을 유지한다. 같은 식별자 문자열도 공식 리그 namespace가 다르면 구분해야 한다. 동일 semantic 이벤트의 재수신과 수정된 사실의 새 revision은 서로 다르다. CLI는 실제 메시지를 보내지 않고 계획과 ack만 처리한다. 전달 수신 여부가 불명확하면 uncertain으로 남겨 자동 재전송하지 않는다. 중복 억제와 재시도는 계획 횟수뿐 아니라 durable 상태와 실패 지점별 side effect까지 최종 구현에서 확인해야 한다.
