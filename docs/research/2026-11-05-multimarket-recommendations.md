# 언더오버·핸디캡 자동 추천과 M0 비교

## 실제 변경

승패 추천과 독립적으로 같은 상품번호·선택지 ID·기준점·전체 경기 기간·공식 정산 규칙을 확인한 언더오버와 핸디캡을 자동 추천한다. 같은 기준점의 검증된 경기 전 픽스터 투표를 사용하며, 적격 투표가 없으면 현재 배당의 최저 배당 선택을 사용한다. 동률·수집 오류·불완전 상품·경기 시작 30분 전 이후에는 새 추천을 만들지 않는다. 임의의 배당 상·하한이나 확률 문턱을 추가하지 않았다.

축구·야구·농구 half-line 총점, 정수 3-way 핸디캡과 야구·농구 half-line 2-way 핸디캡을 지원한다. quarter-line, 정수 2-way, 부분 경기 및 단위가 입증되지 않은 배구는 보류한다. KBO 원래 무승부의 핸디캡은 일반 승패의 무승부 환불과 다르다. 실제 5:5 경기의 공식 조건부 결과로 이를 확인했다.

추천 시점의 가격·선택지·기간·출처를 원장에 보존한다. 공식 결과의 같은 상품 기준으로 정산하며, 최종 점수나 승패 결과만으로 다른 시장을 추정 정산하지 않는다. 부분 정산끼리 기존 결과를 덮어쓰지 않도록 잠금 안에서 최신 원장을 다시 읽고 병합한다. 정정 A→B→A와 서로 다른 예측 개정본의 오정산도 검증했다. 상품별 가상 1단위 성적이며 기존 월 손실 5만원 모의 지갑 거래는 변경하지 않는다.

## M0 도입 범위와 실제 회고 결과

M0_actual의 KBO 득점 분포를 같은 상품·가격 비교자로 연결했다. 공식 선발·명단·가격 등의 경기 전 캡처가 검증된 로컬 파일만 읽으며, 외부 HTTP나 학습은 웹 요청에서 실행하지 않는다. 기존 수집 서버에 5분 Python 작업을 추가하고 현재 메모리 gate와 보조 작업 슬롯을 사용한다. compact capture-index가 달라질 때만 기존 경량 발행 경로를 깨운다. AI 정기 점검이나 새 서버는 만들지 않는다.

고정 44경기의 소급 재현에서는 M0 총점 23/44(52.27%), ROI -10.52%였고 같은 상품의 시장 기준은 25/44(56.82%), ROI -6.14%였다. 핸디캡은 M0와 시장 모두 29/44(65.91%), ROI -13.25%이며 선택도 44건 모두 같았다. 따라서 M0를 신규 시장의 실제 주력으로 승격하지 않았다. 상세 코호트·해시·한계는 [총점 보고서](../../experiments/m0-multimarket-20261105/REPORT.md)와 [핸디캡 보고서](../../experiments/m0-handicap-20261105/REPORT.md)에 있다.

이는 원배당과 공식 결과를 연결한 가상 결과이며 당시 가격의 구매 가능 시점, 실제 체결, 블라인드 검증이나 미래 수익성은 입증하지 않는다. 현재 정책의 전향 성적은 배포 후 쌓이는 별도 원장으로 보여 준다. M0가 같은 시점에 존재하는 상품만 동일 조건 비교에 넣는다.

## 검증과 운영 확인

전체 Python 2,568개 통과(6개 skip, 100 subtests) 후 최종 정산 경합 수정의 관련 Python 149개와 웹 300개, 운영 웹 빌드가 통과했다. 독립 검토는 정산 경합 범위에서 추가 확인된 문제를 발견하지 않았다. 실제 동시 OS 프로세스 스트레스 시험을 했다는 뜻은 아니다. PR CI, 병합 및 실제 배포·웹 확인은 별도 운영 단계다.

## 첫 운영 주기 후속

첫 배포에서 M0가 실제 보조 슬롯을 기다리지만 기존 픽스터용 대기 순서에 포함되지 않아 더 늦게 기다리기 시작한 선수 정보가 먼저 실행됐다. M0도 동일한 120초 대기 후 오래 기다린 원천 우선 정책과 제한된 배당 수집 양보 기회를 받도록 수정한다. 512MiB 메모리 gate, 단일 보조 실행 슬롯, 진행 중 작업 비중단, 정산 재시도 우선 및 15분 양보 재시도 제한은 유지한다. 원천 성공·적격 경기·경기 전 캡처 성공은 별개다.
