# 외부 경기일 오류와 선수 폼 검증의 선행 조건

공식 기록과 다른 경기일 2건을 발견했다. 날짜 문자열이 ISO 형식인지 검사하고 그 날짜에서 4일을 기다리는 것만으로는 시간 누출을 막을 수 없다. 외부 축구 아카이브의 시간순 학습 성능은 날짜를 대조하기 전까지 검증된 결과로 취급하지 않는다. 이 판단은 새 선수 폼 모델의 성능 평가를 대신하지 않는다.

## 공식 기록과의 대조

- NOR Ham-Kam–Lillestrom 2–2: CSV `2022-02-04`, 공식 경기일 `2022-04-02`. 원본 기준 결과 사용 시점이 실제 경기일 기준보다 57일 빠르다. [노르웨이 축구협회 경기 기록](https://www.fotball.no/fotballdata/kamp/?fiksId=7962701), [구단의 과거 대진 기록](https://www.hamkam.no/nyheter/stats-hamkam-lsk).
- NOR Molde–HamKam 1–1: CSV `2023-03-12`, 공식 경기일 `2023-12-03`. 차이는 266일이다. 협회 최종 라운드 표와 구단 경기 보고가 일치한다. 게시일만 보고 경기일을 추정하지 않았다. [협회 2023 시즌 기록](https://www.fotball.no/fotballdata/turnering/hjem/?fiksId=186850), [구단 경기 보고](https://www.hamkam.no/nyheter/uavgjort-pa-bortebane-mot-molde).

원본 `Matches.csv` SHA256은 `ef224cf2c252f07a842b3bcfd4ba5c718c25cedd8937ffa174a74b86b5ba4221`이다. 원본을 수정하지 않았다. 두 건 모두 월·일 전도와 일치하지만 발생 원인이 어느 수집/변환 단계인지는 아직 추적하지 못했다.

공식 웹 자료는 웹 도구가 반환한 텍스트로 읽었다. 로컬 직접 HTTP 요청은 실패했으며 공식 원문 HTML의 해시나 과거 수신 시각을 확보했다고 주장하지 않는다. 레지스트리의 확인 시각은 오늘의 감사 기록 시각이다. 공식 결과의 사후 확인은 경기 전 정보 가용성 증명이 아니다.

## 전체 자료의 범위

원본 238,858행에서 확인한 분류:

- 날짜·점수로 특정한 공식 경기일 불일치 2행.
- 독립 날짜 근거가 아직 없는 238,809행. 미확인은 오류 확정이 아니다.
- 날짜·점수·팀 식별 키가 유효하지 않은 47행(빈 팀명·홈/원정 동일 표기 등 포함).
- 월·일을 바꿔도 유효한 날짜가 되는 83,005행. 위 분류와 중복되는 **모호성 표시**이며 오류 건수가 아니다.

기존 배당·점수·중복 검사를 통과한 235,799행에 새 날짜 검사를 적용하면 공식 근거가 있는 2행만 남는다. 나머지 235,797행은 날짜 미확인으로 격리하고, 기존 품질 검사에서 제외했던 3,059행은 계속 제외한다. 두 행만으로 모델을 학습하거나 성능을 판단하지 않는다.

## 구현한 방어

`src/research_chronology.py`는 원본 전체 SHA, 리그, 원래 날짜, 홈/원정 팀명, 최종 점수가 정확히 일치하는 수동 검토 근거만 적용한다. 미등록 표기나 다른 시즌의 경기에 근거를 전파하지 않는다. 월·일을 일괄 교환하지 않는다.

기존 `experiments/all-sports-underdog-20261031/football_archive.py`에도 연결했다. 기본 동작은 독립 경기일 근거가 있는 경기만 새 연구 입력으로 출력한다. 확인한 날짜와 원래 날짜, 근거 ID를 보존한다. 날짜 정정 전에 원본의 배당·결과 충돌을 제거하며 정정 후 경기 ID가 충돌하면 중단한다. 사후 배당·사전 수신 자격이 확인됐다는 표시는 만들지 않는다.

옛 계산의 재현이 필요할 때만 `--allow-unverified-chronology`를 명시한다. 해당 출력과 감사 파일에는 미검증 진단 상태가 남는다. 이미 저장된 과거 입력·원장·결과는 덮어쓰지 않았다. 기존 PR #475/#476의 수학적 재생/정산 검증은 원천 경기일의 진실성을 검증한 것이 아니므로, 외부 자료의 시간순 학습 우열·월별 손익·낙폭을 채택 근거로 사용하는 판단은 보류한다. 국내 자료에 같은 날짜 오류가 확인됐다는 뜻은 아니다.

## 정정 2건의 진단용 민감도 비교

사전 규칙은 `a132076b`에 저장하고, #476의 실제 모델 코드 해시로 바로잡은 `eb9cadf7` 이후 처음 계산했다. NOR 3,092경기를 두 번 학습했다. 첫 계산은 원본 날짜, 둘째는 공식 기록으로 확인한 2건만 바꿨다. 팀명은 합치지 않았고 같은 경기·같은 배당·같은 결과를 유지했다. 매월 과거 자료만 학습하고 결과를 4일 뒤에 사용하는 기존 규칙과 모델 네 가지를 고정했다.

이는 이전 38리그 통합 학습과 다른 **NOR 단독 진단**이다. 나머지 3,090경기의 날짜는 두 계산 모두 미확인이다. 아래 수치를 정정 완료된 전체 기간의 성능이나 새로운 수익 우위로 제시하지 않는다.

- 시장 정규화: 적중률 51.91% → 51.91%, ROI −4.8309% → −4.8309%. 선택 변화 0건.
- 결과·최근 팀 성적 모델: 적중률 51.16% → 51.20%, ROI −3.4761% → −3.4169%. 선택 변화 1건, 손익 +1.83단위, ROI +0.0592%p. 확률 변화는 최대 6.1695%p.
- 시장 보정 잔차 모델: 적중률 51.55% → 51.55%, ROI −5.5864% → −5.5864%. 선택 변화 0건이어도 확률은 최대 1.5191%p 변했다.
- 시장·팀 모델 50:50: 적중률 52.13% → 52.13%, ROI −3.1763% → −3.1763%. 선택 변화 0건, 확률은 최대 3.0847%p 변했다.

역배만 선택한 하위 집합도 숨기지 않고 `results.json`에 보존했다. 정정 후 결과 모델은 402건/ROI −2.37%, 잔차 모델은 90건/−22.46%, 50:50은 223건/+3.68%다. 마지막 양수도 미확인 날짜가 남은 동일 회고 표본의 하위 결과이므로 채택 근거가 아니다. 추가 튜닝이나 유리한 모델 선택은 하지 않았다.

원장 2개에서 예측 24,736개를 모델 코드와 독립적으로 읽어 확률 합, 선택 방향, Decimal 정산, 같은 경기·가격·결과, 날짜 변경 2건을 다시 검사했다. 이 검사는 날짜의 외부 진실성이나 미래 수익을 증명하지 않는다.

선택이 달라진 것은 원본 날짜 기준 2023-11-11 Haugesund–Brann 한 경기다. 홈 승 → 원정 승으로 바뀌어 손익이 −1 → +0.83단위가 됐다. 정정 후 두 선택의 확률 차이는 약 0.00324%p뿐이다. 이 경계에서 생긴 단 한 번의 이익을 모델 개선으로 일반화하지 않는다.

#476의 별도 재생기로 팀 전력·최근 성적·월별 학습/표준화 상태를 재구성하고 24,736개 확률까지 검사했다. 최대 확률 오차는 약 7.22×10⁻¹⁶, 저장된 계수의 목적함수 기울기 최대값은 8.89×10⁻⁷ 미만이었다. 각 조건의 첫 적격 학습월 두 모델을 다른 최적화 방법(BFGS)으로 다시 맞춘 비교도 허용 오차를 통과했다. 이것도 **기록된 날짜를 전제로 한 수학적 재생**이며 남은 날짜의 사실 확인을 대신하지 않는다.

## 아직 하지 못한 선수·라인업 비교

이번 진단에는 선수·픽스터 입력이 없다. KBO 과거 경기별 실제 출전 기록은 사후 박스스코어이므로 경기 전에 받은 선발 라인업으로 소급하지 않는다. MLB의 과거 timecode 재구성 역시 실제 HTTP 수신 시각이 경기 후라면 전향 표본으로 세지 않는다.

이번에 추가 조회한 MLB 공식 일정은 2026-10-31~2026-11-02 범위에서 경기 목록이 비어 있었다. NBA 공식 일정 GET은 403이었다. 이 두 요청으로 다른 기간·리그까지 자료가 없다고 결론 내리지 않는다. 적격 선수 표본이 늘었다거나 선수 폼 적용 ROI가 계산됐다고 보고하지 않는다.

다음 성능 비교는 독립적으로 경기일을 대조한 코호트와 경기 전 가용 시점을 증명한 선수 자료가 연결돼야 한다. 먼저 공식 날짜의 일괄 연결을 늘리고, 확정 선발/라인업·과거 선수 통계의 기준 시점·당시 배당·공식 결과가 모두 충족되는 경기를 분리해야 한다. 국내 원장과 외부 회고 자료를 섞어 표본을 부풀리지 않는다.

## 재현과 검증

```powershell
python -m src.research_chronology --source <Matches.csv> --registry experiments/chronology-witness-20261031/witnesses.json --output .local-test/chronology-audit.json
python experiments/all-sports-underdog-20261031/football_archive.py --source <Matches.csv> --date-witnesses experiments/chronology-witness-20261031/witnesses.json --output .local-test/strict.jsonl.gz --audit .local-test/strict-audit.json
python experiments/chronology-witness-20261031/run.py --raw <Matches.csv> --normalized experiments/all-sports-underdog-20261031/inputs/external-football.jsonl.gz --model-code experiments/all-sports-underdog-20261031/common.py
python experiments/chronology-witness-20261031/verify.py
python -m pytest tests/test_research_chronology.py tests/test_all_sports_football_archive.py tests/test_chronology_diagnostic.py -q
```

`run.py`는 이름 그대로 사전 등록한 미검증 진단이며 엄격 검증 통과를 반환하지 않는다. 입력과 모델 코드의 고정 해시가 다르면 계산을 거부한다. `results.json`, 두 날짜 조건의 `ledger.jsonl.gz`/`states.json`, `archive-audit.json`, `strict-normalizer-audit.json`, `verification.json`이 실행 근거다.

이 변경은 연구 경로에 한정한다. 운영 모델, 서버, 수집 스케줄, 동결 예측, DB, 실제 베팅을 변경하지 않았다. 운영 모의 원장의 월 손실 5만원 제한도 유지했다.

검증 실행: 전체 Python 테스트 2,202개·93 subtests 통과, 6개 건너뜀(152.26초). 이후 빈 입력 차단·CLI 차단 종료 코드 보강을 포함한 최종 관련 테스트 26개도 통과했다. 최종 커밋 전체 검사는 PR CI에서 별도로 확인한다.
