# 배당·기준점 변동 로그 누락 점검

## 확인한 결함과 수정

`snapshot.snap()`은 직전 배당 문자열만 비교했다. 배당이 같고 핸디캡·언더오버 기준점만 바뀌면 원본 스냅샷은 보존되지만 `odds_changes`와 변동 건수에는 반영되지 않았다. 화면 이력 및 원본 스냅샷 자체가 모두 누락됐다는 뜻은 아니다. 기존 예측·정산·가격 원장은 이 수정 대상이 아니다.

직전 스냅샷의 상품 조건도 읽어 같은 시즌·회차·상품번호·날짜·종목·리그·홈/원정·시장·선택지 수에서 가격 변경, 기준점 변경, 동시 변경을 구분한다. 같은 숫자의 표기 차이와 단순 시각·결과 변경은 변동으로 세지 않는다. 다른 경기로 재사용된 번호를 가격 이동으로 세지 않는다. 기존 `_load_last()`의 기본 가격 문자열 반환과 CSV 헤더는 유지하며, DB 이벤트에는 이전 기준점과 변경 유형을 추가한다. 새 DB 스키마·상시 작업·모델 채택·LLM 호출은 없다.

## 운영 자료를 읽은 범위와 재생

운영 DB는 `mode=ro` 및 `query_only` 연결로만 읽었다. 132회차의 변경 후보 211상품에 8초 상한을 둔 추출 결과는 143상품, 원본 관측 16,647행, 압축 상태 1,129개였으며 **잘린 자료**다. 전체 회차나 전체 DB를 대표하지 않는다. 동일 상태의 반복 관측도 각 실제 DB 행 ID와 관측 시각을 보존했다. HTTP 응답 원문·수신 완료 시각을 증명하는 자료는 아니다.

이 추출의 비교 가능한 연속 관측에서 가격만 변경 170회, 가격·기준점 동시 변경 4회, 기준점만 변경 12회를 찾았다. 기존 배당 문자열 비교는 마지막 12회를 변동으로 기록하지 못한다. 이 수는 서로 다른 경기 수가 아니라 관측 간 전이 수다. 예를 들어 하나은행–KB스타즈 언더오버는 `135.5 → 137.5`, 배당 `1.76,1.72` 유지였다. 애틀호크–워싱위저는 핸디캡 `-6.5 → -7.5`, 언더오버 `231.5 → 229.5` 이동에서도 각각 가격이 같았다. 실제 변경 순간이 아니라 각 수집기의 관측 사이에 생긴 변화다.

실행 결과와 예시는 `experiments/market-change-log-20261108/audit.json`에 보존했다. 원본 압축 추출 SHA-256은 `de85c69eb6339a81473754374d71116864dd2a6e02e6fefd0f354fc1b412ed45`다. 로컬에서 다시 계산한다.

```powershell
python scripts/audit_snapshot_term_changes.py --slice C:/Users/user/AppData/Local/Temp/market-movement-20261108/db-changed-products-132.json.gz --output experiments/market-change-log-20261108/audit.json
python -m pytest -q tests/test_snapshot_term_changes.py tests/test_db_native_archive.py tests/test_snapshot_rounds.py tests/test_kleague_snapshot_replay.py tests/test_odds_live.py
```

관련 65개 테스트, Python 회귀 2,707개 및 100 subtests가 통과했다. 6개는 skipped이고 기존 113만 건 연구 원장 감사 1개는 로컬에서 제외했다. CI에서는 제외하지 않는다. SQLite와 기존 CSV 모드 모두에서 배당 유지·기준점 변경을 기록하고 재실행으로 중복 변동을 만들지 않는지 검사했다. 운영에서는 생성기 실행·재시작·DB 수정·과거 로그 소급 생성·병합·배포를 하지 않았다.

## 병렬 연구와 해석

- [PR #633](https://github.com/choigod1023/proto-odds-research/pull/633): 저장된 가격을 표시하면서 “현재 프로토 배당”이라고 쓰던 출처 문구를 수정했다. 비교 가능한 같은 상품의 2-way 선택 186건 중 11건에서 저장가와 나중 응답가가 달랐다. 숫자는 간이 감사 범위이며 수익성 검증이 아니다.
- [PR #634](https://github.com/choigod1023/proto-odds-research/pull/634): 기준점 이동의 식별 가능성과 같은 신규 상품에서 방향 유지·변경을 비교한다. 새 기준점의 시장확률만으로 옛 기준점 확률은 일반적으로 결정되지 않는다. 원래 티켓은 원래 기준점·가격으로 따로 정산해야 한다.
- [PR #635](https://github.com/choigod1023/proto-odds-research/pull/635): 같은 기준점의 최초 방향과 T-30 이전 최종 방향을 비교한다. 정식 선택지 순서·사전 기록·물리 경기 중복을 확인하고, 방향 변경으로 얻은 적중과 잃은 적중을 함께 센다. 평가 결과를 보고 규칙이나 계수를 튜닝하지 않는다. 연구 PR의 최종 결과 파일을 확인해야 하며 이 로그 수정으로 적중률 개선이 입증되는 것은 아니다.
- [PR #632](https://github.com/choigod1023/proto-odds-research/pull/632)는 원래 기준점으로 미정산을 복구하는 별도 수정이다. 이번 변경에 복제하거나 포함하지 않았다.

배당 `o`에서 손익분기 확률은 `1/o`이고, 추정 확률 `p`가 있을 때 단위 기대 순수익은 `p*o-1`이다. 배당 변화만으로 실제 `p`가 얼마나 달라졌다고 단정하지 않는다. 전체 방향 가격의 정규화 역배당은 시장 기준 확률이며, 독립 모델의 신뢰도 또는 픽스터 지지율과 구분한다. 기존 예측의 숫자를 사후에 갱신하지 않고 시점별 평가를 분리한다.

확률 평가는 로그손실과 Brier를 적중률·실현 ROI와 함께 확인한다([Gneiting & Raftery, 2007](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf)). MLB 시장의 시간별 가격 연구에서도 최신 예측이 항상 개선되지 않고 과잉 반응이 관찰됐다([Simon, 2024](https://pubsonline.informs.org/doi/10.1287/mnsc.2022.00456)). 이는 프로토나 현재 모델에 같은 우위가 있다는 증명이 아니라, 가격이 움직이는 쪽을 무조건 추종하지 않고 동일 조건으로 검증해야 할 근거다.
