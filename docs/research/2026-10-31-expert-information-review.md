# Expert-information 실험 독립 검토

2026-10-31. 사전 등록 원문은 총괄의 `396a12e0a477418c8fee66562e36dba4bb274525`, negative-control 추가는 `f962647e`다. 원문·추가 규칙과 검토한 코드의 SHA256은 `snapshot-sha256.json`에 기록했다. 아래에는 개발 중간 스냅샷의 검토 이력과 최종 커밋에 대한 후속 검산을 구분해 기록한다.

**당시 스냅샷의 최종 결과 판정은 보류했다.** 검산한 `run.py` SHA256은 `8813770006923e94da3ff422cf01311e63bc423f0acda2d84b3374f7fee07129`, 당시 `results.json`은 `facedf75634e1cc0959b04730041b669c7e8efc7c58067b4b73ac517b0461c5d`다. 검사 도중 원본 run.py가 `fd6af34fe8c1aaf526d8756388fe5f361df25ea4dfd4d4a1390470b117f00cd2`로 바뀌어, 이 저장 결과가 최신 코드로 재생됐다는 최종 증거는 없다. 당시 원본 비교에서 나머지 11개 스냅샷 파일은 같았다. 마지막 차이는 target/frame의 회고 코호트 검사 추가였고, 입력 preflight에서 실제투표 target에 연결된 각 446개 frame은 모두 그 조건에 맞았다. 이는 새 코드의 전체 재실행이나 개발 최종 커밋 인증이 아니다.

## 최종 커밋 재검산 (후속 확인)

개발 PR #453의 head `863b13ea1015fadb5b57b68af4a50b7af09b3c3b`에서 13개 코드·프로토콜·입력·출력 파일을 직접 추출해 재검산했다. `verification.json`의 `hash_convention`은 `.py`·`.json`·`.jsonl`은 CRLF를 LF로 정규화한 바이트, gzip은 원본 바이트의 SHA256이다. 해당 기준으로 코드·입력·프로토콜·예측·정산·결과 해시는 모두 일치했다. 개발 작업본 13개도 정규화 후 커밋 파일과 일치했다. 이 중 7개 텍스트 파일은 줄바꿈 표현 때문에 원시 바이트 해시는 달랐다. 내용이나 수치의 차이는 없었다.

독립 Decimal 정산 1,220행, 요약값 660개, frozen/prequential 학습 cutoff 488행, 선택 모델 대 시장의 주간 bootstrap 12개 셀은 모두 차이 0이었다. validation loss 세 개도 최종 개발 코드를 재호출해 일치시켰으며 독립 모델 재구현은 아니다. `source_sha256`을 문서 SHA로 대체하던 동작은 최종 코드에서 제거됐고, parent/copy 프로토콜 커밋도 별도 표기한다. 아래 내용은 그 수정 전 스냅샷의 관찰을 보존한 이력이다.

최종 커밋과 저장 산출물의 해시 대응을 확인한 것이며, 원본 HTTP·전향 수신·실행 가능 가격이나 수익성을 인증한 것은 아니다. 새로운 ROI 실험은 수행하지 않았다.

## 검토 결과와 잔여 쟁점

1. 저장 결과의 `protocol_commit`은 `a1ed59f8849a29b753fa9a45df482ad294ed5862`이지만 제공된 원문 기준 및 `protocol-origin.json`의 parent commit은 `396a12e0a477418c8fee66562e36dba4bb274525`다. 두 SHA의 관계는 독립 확인하지 못했다. protocol 원문 바이트 SHA256 `061716c82b9b5487c7c52db03ec57d1718de699f185ef1380f43567a64289a4d`는 일치한다. 결과에는 원문 사전등록 커밋과 개발 측 복사 커밋의 역할을 명시하고, 최종 코드·입력·예측·정산의 SHA를 연결해야 한다. 기존 `verification.json`은 예측·결과 등은 해시하지만 `run.py`는 해시에 포함하지 않는다.
2. 검토 스냅샷 `groups`는 `document_sha256`이 없을 때 `source_sha256`도 동일 문서 그룹 키로 사용한다. 사전등록은 동일 문서 SHA로만 군집하고 hash가 없으면 source+author별로 분리한다. `source_sha256`이 해당 문서 원문 바이트 해시와 동등하다는 증거가 없다면 규칙 해석이 다르다. 같은 source SHA만 있고 서로 다른 source+author인 합성 두 표는 스냅샷에서 한 그룹, 엄격 문서 해시 해석에서는 두 그룹이다. 전체 원천 frame의 raw 표 중 document SHA 없이 source SHA만 있는 표는 385개였다. 해당 target에 연결된 446개 경기에서 두 해석의 그룹 **개수 차이는 0**이었고, 그 관측은 새로운 성과를 증명하지 않는다. 해시 의미를 확인하거나 부재 시 명시된 fallback을 사용해야 한다.
3. 업데이트된 코드는 June 검증 중 결과 가용 대용 시각이 July 1 이후인 행을 선택에서 제외한다. 이는 미래 정답을 끌어와 July 1 모델을 선택하는 오류를 막기 위한 엄격한 인과 해석이다. July 1 frozen 재학습과 UTC 일별 prequential의 96시간 대용 시각 기준을 각각 분리하며, exact cutoff 포함 여부는 코드와 독립 검사에서 구분했다. 96시간은 실제 결과 최초 수신의 증거가 아니다.
4. negative-control은 같은 경기의 실제 전문가 방향을 시장 정배로 치환하는 진단이며 선택과 독립된 새로운 holdout이 아니다. sham이 유사하거나 나아도 전문가 방향의 독립적 신호를 주장할 수 없고, 차이가 나더라도 인과효과나 실행 가능한 수익을 입증하지 않는다. 모든 표본은 반복 열람된 회고자료다.

## 실행한 검사

- `input_preflight.py`는 원문 target·frame·case를 모델 함수 없이 대조했다. 실제투표 입력 446행에서 ID·리그·팀·시작·상품 선택지·저장 확률·가격·결과·결정 시각 불일치는 0이고, 게시 주장이 결정 이후이거나 알 수 없는 raw 표는 0이었다. 이것은 공식 원문, 독립 수신, 구매 가능 가격 검증이 아니다. 데이터의 446개는 대상 입력 수이며 독립 경기의 전향 성능 표본으로 부르지 않는다.
- 독립 Decimal 원장 `independent_ledger.py`는 검토 스냅샷의 예측/정산 1,220행을 원 target 가격·결과와 대조해 차이 0을 확인했다. `final_snapshot_audit.py`는 리그/전체 성과 요약·coverage·로그손실·Brier·월 손익·일별 마감 낙폭·시장 대비 선택 변경 총 660개 항목, frozen/prequential 학습 시각 관련 488개 행, 선택 모델 대비 시장의 주간 5,000회 bootstrap 12개 셀을 별도로 계산해 차이 0을 확인했다. 각 숫자는 검산 범위이지 독립 경기 수나 미래 수익이 아니다. 상세는 결과값을 복제하지 않은 `final-snapshot-audit.json`의 해시·검사 건수를 참조한다.
- 합성 fixture에서 유효 시각 뒤인 현재·미래 결과를 바꿔도 더 이른 frozen·순차 예측이 같았고, July 1 이전에 가용하지 않은 June validation 결과를 바꿔도 검증 선택이 같았다. 실제 표본 전체에 대한 라벨 변형 재실행은 이번에 하지 않았다.
- gradient는 중심차분과 독립적인 likelihood+global/league/author ridge 1/4/16 항 합계로 대조했다. 그룹별 평균 가중·미등록 작성자 0 offset·예측 함수의 outcome 필드 거부를 합성 자료로 확인했다. 셋의 validation loss는 개발 코드를 다시 호출해 재현했으며 독립 모델 구현은 아니다.
- 최초 완성 전 스냅샷의 재현과 수정 중 결과를 최종 성과로 해석하지 않았다. 학습·선택·평가를 일반 운영 생성기나 서버에서 실행하지 않았다.

실제 사전수신 외부 인증, 유효한 당시 매수 가격, 원문 HTTP 해시의 진위, 독립 정산, 최종 개발 커밋·최종 hash 대응, 실제 운영 모델의 성능은 확인하지 않았다. 원본 개발 작업은 수정하지 않았고 병합·배포·운영 변경도 하지 않았다.
