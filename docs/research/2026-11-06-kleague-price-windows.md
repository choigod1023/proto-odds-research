# K리그1·2 발매 초반 및 경기 30분 전 배당 비교

2026년 133회차부터 수집 서버의 기존 실시간 배당 작업이 받은 와이즈토토 응답을 사용한다. 베트맨 G101의 회차 응답을 한 번 별도로 받아 회차 개시·마감과 동일 상품번호의 정규시간 승무패 일정·팀 ID·상품 마감을 확인한다. 공식 회차 조회는 작업당 최대 1건이고, 같은 회차에서 참조 수집에 실패한 경우 최소 2분 뒤에 재시도한다.

발매 시작 후 1시간 안의 첫 적격 응답과 킥오프 35~30분 전의 첫 적격 응답을 저장한다. 상품 마감 전이어야 하며, 경기 전 상태의 완전한 승무패 가격과 동일 회차·상품번호·리그·킥오프가 필요하다. 회차 참조와 응답 본문을 SHA-256으로 구분해 gzip으로 저장한다. 보존하는 바이트는 원천의 HTTP 응답 본문이고, 시각은 응답 본문을 모두 읽은 때다. 한 HTTP 응답이 여러 상품의 근거이면 본문 한 개를 공유한다. 수집이 밀리거나 원천에 해당 구간의 가격이 없으면 해당 구간은 비어 있다.

운영 볼륨의 `/data/research/kleague-price-windows-v1` 아래 회차별로 근거를 보관한다. 같은 응답에서 파싱한 가격은 기존 `odds_snapshots`에 일반 배당 관측과 같은 형식으로 넣는다. 수신 시각의 초·시즌·회차·상품번호로 행을 찾아 전체 가격과 상품 메타데이터가 일치하는지 확인한다. 원본 해시가 일치하고 재파싱한 행도 같은 값이어야 정산 표본에 포함한다. 연구 기록 실패는 배당 게시 오류로 전파하지 않는다.

저장소 루트에서 비교 대상 회차의 증거 폴더와 해당 DB 행을 읽는다. 서버에서는 다음 명령으로 정확한 DB 행만 JSON으로 추출할 수 있다.

```text
python scripts/compare_kleague_price_windows.py export-db-quotes --evidence /data/research/kleague-price-windows-v1 --db /data/proodd.sqlite3
```

추출 JSON과 해당 회차의 증거 폴더를 로컬로 가져온 다음, 저장소 루트에서 아래 명령을 실행한다. 공식 K리그 일정에서 리그·팀 ID·킥오프로 유일하게 연결한 정규시간 종료만 사용하고, 공식 경기 ID마다 한 번 채점한다.

```text
python scripts/compare_kleague_price_windows.py score --evidence path/to/evidence --db-quotes path/to/db-quotes.json
```

정산 30경기 및 3회차부터 기술 통계를 출력한다. 기준 모델은 30분 전 역배당을 정규화한 확률이다. 후보는 발매 초반과 30분 전 정규화 확률을 각각 `p_open`, `p_t30`이라 할 때, `log(p_t30) + β × (log(p_t30) − log(p_open))`에 softmax를 적용한다. 계수 `β = -0.528823663214722`는 발매 시작 후 1시간과 킥오프 45~30분 전 배당 기록을 연결한 2026년 9월 24일 이전의 과거 62경기에서 적합했다. 새 표본의 응답 수신 증거 및 35~30분 구간 기준은 과거 학습 자료와 별도로 적용한다. 두 방식의 로그손실과 최고 확률 픽 적중률을 계산하고, 경기마다 같은 금액을 걸었다고 가정해 둘 다 같은 30분 전 배당으로 ROI를 계산한다.
