# 종목·리그 및 선택 시장 확대

사용자 요청에 따라 단발성 워커 3개를 축구, 타 리그·종목, 픽스터 시장 추출로 나눴다. 정기 AI 점검을 다시 켜지 않았다. 기존 수집·동결 예측·월 손실 5만 원 모의 원장·실매수는 변경하지 않는다. 이번 PR은 시장별 자료 조사와 별도 비교 후보 경로 구현이며, 새로운 종목별 예측 모델을 학습해 성과 개선을 입증한 작업은 아니다.

## 승무패만 나오는 원인

2026-11-03 14:27:38 UTC, 최근 범위 API가 HTTP 200/0.877초로 응답했다. 문서 생성 시각은 14:13:02 UTC다. 최근 91경기는 축구 66, 농구 22, 야구 1, 배구 2경기다. **언더오버 182개, 핸디캡 306개 선택지**가 이미 있지만 최종 픽 82개는 승무패 63개와 승패 19개뿐이다. 나머지 9경기는 최종 픽이 없다. 선택지는 상품의 각 방향을 센 수로, 182경기 또는 306개 상품이라는 뜻이 아니다. 과거·예정이 섞인 최근 범위이며 오늘 경기 전체 통계도 아니다. [관측 메타데이터와 응답 해시](../../experiments/multi-market-live-20261103/inventory.json)를 보존했다.

`public_tipster_votes`는 전체 경기 승패 추천만 추출하고 `market_type=full_game_winner`로 기록한다. `fixed_tipster_hybrid.context`는 그 타입만 투표로 받아들이고, `apply`는 승패·승무패 옵션에서 최종 방향을 선택한다. 따라서 다른 시장 배당이 수집돼 있어도 현재 투표 정책의 최종 픽은 다른 시장으로 바뀌지 않는다. 기존의 언더오버 모델이 잘 작동해서 배제된 것이라고 해석하면 안 된다.

## 구현

- 경기 상세에 **승무패·핸디캡·언더오버 비교**를 추가했다. 시장 필터, 기준점별 상품 번호, 각 방향 배당과 배당 기반 확률을 표시하며 사용자가 최종 픽과 별도로 방향을 직접 비교할 수 있다. 내 선택 목록에 담기는 가격 원장 일치와 명시적 경기 기간·정산 범위를 확인한 선택에만 허용한다. 현재 대부분의 다른 시장은 이 증거가 없어 비교만 가능하다. 시작·T-30 동결·자료 지연·재계산 중에도 새 사전 선택을 담지 않는다. 이 경로는 자동 모델 추천으로 승격하는 기능이 아니다.
- 명시적인 전체 경기 기준점과 방향이 있는 픽스터 추천을 별도 후보로 추출한다. 언더오버와 2방향/3방향 핸디캡을 분리하고, 3방향 핸디의 비정수 기준점·전반/쿼터·기준점 누락·중복 모순은 거부한다. 현재 상품의 기준점·선택지 전체·배당·기간·정산 범위 충돌·n_way를 대조한다.
- 기존 수집기가 이미 받은 동일 HTML과 수신 완료 시각을 재사용한다. 추가 HTTP 요청이나 수집 주기를 늘리지 않는다. 원문 바이트 해시와 URL도 기존 관측 이벤트에 일치해야 한다. 별도 시장 이벤트는 `candidate_only=true`로 남기며 기존 승패 투표에 섞지 않는다. 원문이 바뀌어도 동일 작성자·동일 시장 기준점의 최초 관측 identity를 유지한다.
- 출처·경기 identity·T-30·작성자별 최초 표를 검증해 현재 상품에 유일하게 연결된 후보만 표시한다. 동률/상충은 방향을 보류한다. 지지율을 적중확률로 쓰지 않고 `affects_selection=false`, `affects_probability=false`, `validated_edge=false`를 유지한다.
- 배당과 승무패 투표가 바뀌지 않아도 새 시장 후보가 있으면 표시 자료만 갱신한다. 기존 decision snapshot·입력 revision·선택·확률·원장을 바꾸지 않는 회귀 검사를 추가했다. HTTP 요청 처리 중 수집·학습은 하지 않는다.
- 독립 검토 후 원문의 홈·원정 순서가 뒤집힌 핸디캡은 보류하도록 수정했다. 원정/무 방향의 홈 기준점이 명시되지 않으면 기준점을 추측하지 않는다. 작성자의 최초 표는 현재 가격 기준점과 매칭하기 전에 먼저 고정하며, 이후 다른 기준점의 표를 최초 표로 대체하지 않는다. 기준점 없는 독립된 언더/오버 행이 섞여 있어도 후보를 보류한다.

**실제 기준점이 명시된 공개 원문에서 추출 성공한 사례는 이번 작업에서 검증하지 못했다.** 기존 실물 형식의 `오버`, `핸디 승`처럼 기준점이 없는 표현은 보류한다. 새 규칙을 합성 fixture로 검증한 것을 실제 자동 수집 성공이라고 말하지 않는다. 현재 메타데이터 파서는 승패 추천이 없는 글에서 종료하므로, 언더오버만 있는 글은 이 경로의 미지원 범위다. 추후 원문 형식·실제 수신 및 공식 시장 규칙을 확보한 뒤 넓혀야 한다.

배구의 세트/득점 단위와 연장 포함 여부 등 원문 정산 범위를 확증한 새 데이터는 확보하지 않았다. 위 후보는 시장 identity 비교 자료이며 구매 가능하거나 같은 정산 범위라는 인증이 아니다. 운영 추천을 다른 시장으로 자동 전환하거나 수익 검증을 통과했다고 표시하지 않는다.

## 워커가 확인한 다른 종목·리그 자료

[축구 보고서](2026-11-03-soccer-markets.md): K리그1/2에서 언더오버 763/842개, 3방향 핸디캡 872/851개 상품의 점수·기준점·배당·결과 방향을 연결했다. 동일 원시 아카이브 점수와 대조한 것이며 공식 결과를 독립적으로 인증한 것은 아니다. 사전 가격 수신 증거는 0건이다. K리그 언더오버 2.5의 단순 저배당 방향 기준선은 2023~2024 적중 52.22%/ROI −14.84%, 2025~2026 적중 54.30%/ROI −12.78%였다. 자료 확인 후 정한 회고 기준선이지 새로운 학습 모델이나 채택 근거가 아니다.

[타 리그·종목 보고서](2026-11-03-other-markets.md): 다른 해시의 2023~2024 원시 파일에서 MLB 핸디 4,951행/합계 4,825행, NPB 각각 1,817행, NBA 각각 2,300행, KBL 각각 501행을 확인했다. 이 숫자는 유효 정산 표본이 아닌 상품 원시 행 수다. 배구는 핸디 1,125행/합계 1,108행이 있으나 세트/득점 단위와 일부 리그 원문 손상이 해결되지 않았다. 시점·단위·후보 예측의 연결이 부족해 새 모델 적중률·ROI 비교는 미산출로 남겼다.

축구 워커 원본 해시 `9ffddb2d...`와 타 종목 워커 원본 해시 `daf3ac67...`는 다르다. 전자는 171,565행, 후자는 78,403행이다. 같은 전체 자료로 취급하거나 중복 여부를 모른 채 합산하지 않는다. 두 보고서와 JSON에 입력 해시·기간·단위·제외 사유를 각각 보존했다.

## 검증 및 후속 범위

로컬 Python 전체 테스트 2,364개 통과, 6개 건너뜀, 하위 검사 100개 통과. 이후 검토에서 찾은 방향·최초 관측·모호함 문제와 조회 실패를 의견 부재로 오인하는 문제를 수정하고 관련 경로 158개도 통과했다. 웹 테스트 297개와 production build를 실행했고 실제 API를 읽는 로컬 브라우저에서 전체 시장 → 언더오버 → 오버 선택을 확인했다. 이미 시작한 경기에서 새 사전 선택 저장 버튼이 비활성화되는 것도 확인했다. 원격 웹사이트에 이 UI를 배포한 검증은 아니다.

전체 테스트는 기존 연구의 동명 `features.py` import 충돌로 처음 중단됐다. 새 시장 코드를 넣지 않은 축구 워커 worktree에서도 같은 문제가 재현됐다. 운영 모듈을 고치지 않고 KBO 연구 테스트 두 개가 자기 sibling 모듈을 명시적으로 읽게 분리해 전체 실행을 복구했다.

다음 모델 비교는 시장별로 구분해야 한다. 축구의 득점 합계·골 차이, 야구의 득점 합계·런 차이, 농구의 총점·점수 차이, 배구의 세트와 득점은 목표·가격·정산 정의가 다르다. 이번 자료 조사와 후보 수집 경로를 그 비교의 입력으로 삼되, 승패 적중률이나 ROI를 다른 상품의 성과로 재사용하지 않는다. 새 후보가 실제 원문·동일 상품·공식 결과까지 연결되면 그 시장의 동일 경기에서 기존 선택과 비교한다. 그 전에는 새 시장을 숫자 채우기용 자동 추천으로 올리지 않는다.

연구 워커는 이번 요청에 한 번씩 실행했고 종료했다. 정기 AI 점검 2개는 계속 정지 상태다. 병합·배포·운영 재시작·증설·실제 베팅은 수행하지 않는다.
