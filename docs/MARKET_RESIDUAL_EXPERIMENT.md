# 시장 기준 보정 모델: 1단계 검증 도구

운영 추천·확률·동결·DB를 바꾸지 않는 로컬 실험이다. PR #240의 단순 최근 폼 모델과
별개로, 기존 원장에 실제 저장된 `ai_candidate`와 시장 확률을 비교한다. 모델 버전과
종목을 명시적으로 고정하며 서로 다른 후보 버전을 섞지 않는다.

## 모델과 검증

`logit(p) = logit(p_market) + beta * (logit(p_model) - logit(p_market)) + intercept`

- 학습 기간: beta를 0~1 범위에서 로그손실과 고정 L2 벌점으로 적합한다.
- 보정 기간: beta를 고정하고 절편만 적합한다. 시장 기준선에도 같은 절편 보정을 한다.
- 최종 평가 기간: 모든 계수를 고정하고 Brier, 로그손실, 적중률과 실현 ROI를 비교한다.
- 각 기간은 예측 수집 시각으로 배정한다. 학습·보정에 쓰는 정산도 각 종료 시각 전에
  원장에 저장돼 있어야 한다. 평가 결과도 평가 종료 시각까지 알려진 것만 사용한다.
- 경기별 마지막 T-30 이전 revision을 결과를 보기 전에 선택한다. 정산이 없다고
  정산된 이전 revision으로 돌아가지 않는다. 무효·정산 충돌은 제외한다.
- 학습·보정은 적중/실패 양쪽과 최소 100건, 평가도 최소 100건을 요구한다.
  100건은 실행 안전장치이지 통계적 유의성이나 충분한 검정력을 뜻하지 않는다.

최종 기간의 모든 기록된 픽을 두 확률로 평가하면 적중률·실현 ROI는 같아야 한다.
확률 개선 여부는 Brier/로그손실로 본다. 별도로 각 정책의 추정 EV 상위 25%를
동일 건수로 선택해 커버리지를 맞춘 실현 ROI를 비교한다. 이는 고정 예산 비교일 뿐
양의 EV 보장이나 실제 추천 정책이 아니다. 음의 EV인 선택지도 포함될 수 있다.

## 실행

검증용 로컬 원장 복사본을 사용한다. 원장 해시 체인을 검증하며 읽기용 잠금 파일을
일시 생성할 수 있지만 예측/정산은 추가하지 않는다. DB 모드에서는 실행을 거부한다.

```powershell
python scripts/evaluate_market_residual.py data/raw/prediction_ledger/pregame.jsonl --sport bs --version score-distribution-shadow-v1 --train-end 2026-09-05T00:00:00Z --calibration-end 2026-09-15T00:00:00Z --test-end 2026-09-26T00:00:00Z
```

현재 로컬 자료의 실행 결과: 늦거나 잘못된 revision 27개 제외, 최종 선택 중 고정
종목/시장/버전 범위 밖 189경기, 범위 안 미정산 17경기. 적합 가능한 정산 표본 0건으로
`insufficient_data`를 반환한다. ROI를 0%로 출력하거나 성능 향상으로 해석하지 않는다.
이 날짜 구분은 탐색용이며 사전에 등록한 확증 실험이 아니다.

## 남은 단계와 제한

1. 실제 운영 정산 저장 및 정확한 prediction revision 연결을 확인한다.
2. 선발·불펜·확정 라인업의 경기 전 숫자 입력과 출처/관측 시각을 확보한다.
   현재 원장의 자유 형식 설명을 뒤늦게 숫자로 복원해 과거 예측으로 취급하지 않는다.
3. 리그별 보정과 추가 정보의 효과를 시간순으로 분리한 구간에서 비교한다.
4. 날짜/경기 단위 불확실성 평가 및 별도 미래 구간 검증을 추가한다.
5. 그 후 모든 지원 선택지의 평가와 경기 중복 노출을 제한한 2조합 정책을 검증한다.

이번 단계는 선택된 과거 픽에 대한 보정 검증이다. 모든 마켓의 최적 픽 선택,
선발/라인업 학습, 보수적 승률 하한, 조합 수익률은 아직 구현하지 않았다.
원장 해시는 기록 무결성을 검사할 뿐 원천 결과의 진위나 배당 구매 가능성을 보장하지
않는다. 실행을 반복해 가장 좋은 기간만 보고하면 과적합이므로 모든 실험을 기록하고
최종 정책은 별도의 이후 기간에서 검증해야 한다. 자동 승격은 항상 금지한다.
