# 오늘 추천의 배당 대비 가치 정책

정책 버전: `daily-value-v1`. 이 변경은 **이미 기록된 경기별 선택 중 오늘
강조할 픽을 고르는 기준**이다. 경기별 방향을 새로 만들거나 미검증 모델을
운영 모델로 승격하는 변경은 아니다.

## 왜 바꾸는가

이전 정책은 적중확률 55% 이상을 적중확률 순으로 골랐고, 리그별 기본 3개
외에도 60% 이상이면 계속 추가했다. 같은 시장 마진이라도 저배당은 보통
적중확률이 높으므로 오늘 추천이 저배당에 쏠릴 수 있었다.

예를 들어 59%·1.50배의 추정 기대수익은 −11.50%, 56%·1.72배는
−3.68%다. 이전 정렬은 전자를 먼저 골랐지만 새 정렬은 후자를 먼저 고른다.
이것은 계산 예제이지 수익 개선을 입증하는 실전 백테스트가 아니다.

## 계산과 선택

- `p`: 같은 가격 revision에서 검증 승인된 최종확률. 승인이 없으면 Shin
  시장확률을 사용한다. 정책 승인 표식, shadow 확률, 과거 배당구간 ROI만으로
  확률을 올리지 않는다.
- `q`: 유효한 검증 구간 전체가 있으면 그 하한. 구간이 없거나 불완전하면
  `min(시장확률, p)`를 비교 기준으로 사용한다. 후자는 통계적 신뢰하한이 아니다.
- 추정 기대수익: `p × 현재 배당 − 1`.
- 순위용 비교 기대수익: `q × 현재 배당 − 1`.
- 손익분기 확률: `1 ÷ 현재 배당`.

기존 자동 선택 안전조건(홀짝 제외, 시장 최유력만, 2.20배 미만)은 유지한다.
적중확률 50% 이상이면서 비교 기대수익 −15% 이상인 후보만 남긴다.
같은 KST 날짜·리그에 이 기준을 통과한 1.50배 이상 후보가 있으면 우선하고,
없을 때만 1.50배 미만을 보조로 허용한다.

비교 기대수익 → 추정 기대수익 → 적중확률 → 일정·선택 키 순으로 정렬한다.
리그별 기본 최대 3개이며, 추가는 **검증된 구간 하한의 기대수익이 양수**인
경우에만 허용한다. 후보 부족을 채우기 위해 기준을 무시하지 않는다.

50%, −15%, 3개는 위험·노출 제한을 위한 운영 설정이다. 외부표본으로 학습한
최적값이나 수익성 보증이 아니다. 음수 기대수익 후보는 여전히 손실 가능성이
있는 시장 비교 추천이며, 화면에서 그 사실과 기대수익 부호를 숨기지 않는다.
고배당 할당량이나 배당 자체에 대한 가산점은 없다. 더 나은 가치가 있으면
저배당이 다시 상위에 올 수도 있다.

## 저장·화면·배포

`src/daily_value.py`는 `today_combo` 후보에 `daily_recommendation`을 추가한다.
정책 버전, 확률 출처를 나타내는 검증 표식, 비교 수익, 추천 여부, 리그 순위와
제외 사유 코드가 기존 런타임 DB artifact에 저장된다. `recommendation_refresh`
변경 이력은 자동 조합이 꺼져 있어도 오늘 추천과 가격·가치 변화에 반응한다.
운영용 CSV는 만들지 않는다.

브라우저는 `daily-value.js`의 동일 정책으로 현재 원장·가격에 맞춘 후보를
재평가한다. stale offer 및 사전 기록 확인은 기존 정합성 경로를 유지한다.
배당 변경 후 과거의 가치 점수를 그대로 쓰지 않으며, 경기별 판정 원장과
사용자가 저장한 베팅 결과는 이 정책 변경으로 덮어쓰지 않는다.

서버 코드를 배포하고 정상 추천 갱신 주기가 실행돼야 DB에 새 주석과 변경
이력이 저장된다. 프런트엔드 배포만으로 백엔드가 갱신되지는 않는다.
이 PR 작업은 서버 재시작·배포·DB 이관을 실행하지 않는다.

## 검증 범위

Python/JavaScript 동일 입력의 계산·추천 결과 동등성, 저배당보다 가치가 높은
후보의 순위, 미검증 확률/잘못된 구간 차단, 임계값 경계, 날짜별 정원,
고확률 무제한 추가 차단, DB 산출물과 변경 이력 저장을 회귀 테스트한다.
실전 수익 개선 검증은 별개이며, 사전 기록의 시점·당시 배당을 고정한 시간순
외부표본 평가에서 커버리지·배당 분포·적중률·수익률을 함께 확인해야 한다.
