# 경기별 추천 확률 검증: 데이터 준비 상태

## 범위

현재 추천 정책을 변경하거나 모델을 승인하지 않는 오프라인 감사다.
예측 시점에 저장한 시장 확률과 모델 후보 확률을 같은 선택지의 실제 결과로
비교할 수 있는지 먼저 검사한다. 수익률을 계산하는 백테스트는 아직 아니다.

```powershell
python scripts/audit_probability_validation.py <local-pregame.jsonl>
```

입력 파일을 읽기만 하며 SHA-256과 감사 결과를 표준 출력으로 반환한다.
운영 DB 연결, 생성기 실행, 파일 저장, 모델 학습, 정책 변경은 하지 않는다.
잘못된 JSON 등 입력 오류는 실행 실패로 처리한다.

## 검사 규칙

- 시간대가 있는 예측·수집·시장 관측·킥오프 시각을 요구한다.
- 시장 관측 ≤ 예측 ≤ 수집이며, 모든 관측이 킥오프 30분 전보다 빨라야 한다.
- 결과나 확률의 유무를 보기 전에 event_id별 마지막 적격 예측을 선택한다.
  최신 예측이 미정산이어도 정산된 이전 예측으로 되돌아가지 않는다.
- 동일 선택지/오퍼의 시장 확률과 AI 후보 확률이 모두 있어야 한다.
- 정산은 snapshot_id와 selection_id가 정확히 일치해야 한다.
- 서로 다른 적중 결과, 취소·무효, 불명확한 출처·정산 시각은 제외한다.
- 적격 쌍이 있어도 자동 승인하지 않는다. 모델 버전별 검토와 시간 분할이 남는다.

`exclusions`는 예측 행 수준의 제외와 마지막 예측 수준의 제외를 함께 담는다.
따라서 전체 예측 수에서 단순 차감할 수 없다. 미정산은 실패 또는 ROI 0%가 아니다.
`official-` 버전/출처 필드는 출처의 진위를 인증하지 않는다. 해시 체인 검증과
원천 결과 대조는 별도로 해야 한다. event_id가 달라도 동일한 실제 경기인지
확인하고 재발행 경기·동일 경기의 여러 시장을 중복 표본으로 세지 않아야 한다.

## 다음 검증의 사전 규칙

1. 원천 경기 결과를 정확한 경기·시장·선택지 식별자로 연결한다. 이름 유사도만으로
   결과를 붙이지 않는다. 과거 복원은 원장과 분리하고 복원 시각·출처를 남긴다.
   연결 불가·정정·취소 경기는 별도 집계한다. 과거 복원 자료는 전향 검증이 아니다.
2. 기존 원장의 후보 확률과 모델 버전을 그대로 사용한다. 현재 모델로 과거 경기를
   다시 예측한 결과를 당시 예측으로 취급하지 않는다. 모든 후보 시장이 없으므로
   현재 자료만으로 경기별 최적 시장 선택 전략을 검증했다고 할 수 없다.
3. 결과 분석 전에 연속된 학습/검증/최종 평가 날짜를 고정한다. 동일 실제 경기는
   한 구간에만 속하게 하고, 학습 시점에 아직 정산되지 않은 결과는 사용하지 않는다.
   날짜 범위와 최소 표본 요건은 자료 범위 확인 후 성능을 보기 전에 고정한다.
4. 시장 확률 단독을 기준으로 모델 후보, 학습 구간에서 보정한 후보를 비교한다.
   Brier 점수·로그손실·확률 구간별 보정 오차를 먼저 보고, 픽 수·커버리지·적중률·
   고정 단위 실현 ROI를 함께 본다. 후보/임계값을 많이 시도한 결과는 탐색 결과로 표시한다.
5. 두 경기 조합은 동시에 구매 가능했던 배당과 서로 다른 실제 경기만 사용하고,
   조합 생성 규칙·중복 경기 노출·하루 예산을 사전에 고정한다. 모든 가능한 조합을
   독립 표본으로 세지 않는다. 날짜 단위 재표집으로 불확실성을 평가한다.
6. 최종 평가 구간이 부족하거나 개선의 불확실성이 크면 정식 추천으로 승격하지 않는다.
   확률상 기대수익과 과거 실현 ROI를 구분하며 수익을 보장하지 않는다.

학습·보정·최종 평가·조합 백테스트는 이 PR에서 구현하거나 완료한 작업이 아니다.
우선 정산 연결 자료가 필요하다. 운영 DB에 정산을 추가하는 작업도 하지 않았다.
