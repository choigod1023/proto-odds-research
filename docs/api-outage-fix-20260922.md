# 경기 목록 불러오기 장애 수정

## 원인과 범위

- 운영 감시에서 목록 API 30초 타임아웃이 반복됐다. 브라우저는 15초 후 실패 처리한다.
- 기존 목록 캐시는 요청마다 DB revision을 확인하며, 변경 시 전체 예측 JSON을 읽고 상세 기록을 압축하는 동안 잠금을 잡는다. 캐시 갱신 중에는 다른 목록 요청도 대기한다.
- CPU 대기 압박과 반복 OOM도 관측됐다. 이 수정은 HTTP 요청 경로의 병목을 줄이는 것으로, 1GB 운영 전체의 OOM 해결을 보장하지 않는다.

## 변경

- 미배포 PR #227의 압축 응답 캐시 및 가벼운 health 메타데이터 조회를 포함한다.
- 목록 요청은 DB나 가공 잠금에 접근하지 않고 준비된 압축 응답을 반환한다. 단일 백그라운드 작업이 30초 간격으로 최근 목록과 사용자가 요청한 전체 목록을 갱신한다.
- 갱신 실패·메모리 부족 시 마지막 정상 응답을 유지한다. 원래 generated_at, revision을 바꾸지 않는다. 같은 날짜 내 오래된 응답이 반환될 수 있으며 장기 대기는 계속 감시해야 한다.
- KST 날짜가 바뀌거나 아직 준비된 목록이 없으면 503을 반환한다. 전날 목록을 오늘 목록으로 잘못 표시하지 않는다.
- 상세 요청도 DB 전체 재계산 없이 준비된 해당 경기만 읽는다. 갱신 작업과 충돌하면 기다리지 않고 503, revision이 다르면 409를 반환한다.
- 다른 산출물 API는 작은 메타데이터에서 revision이 같으면 큰 JSON 재조회를 생략한다.
- 첫 로딩 실패 화면에 재시도 버튼을 추가한다. 새 작업자 시작 직후 목록 준비 전에는 재시도가 필요할 수 있다.
- 픽 동결·적중 판정·추천 정책·운영 DB 내용은 변경하지 않는다. RAM 증설 없음.

## 검증

- DB/가공이 정지한 상태에서도 병렬 독자가 기존 응답을 받는 회귀 테스트.
- 첫 요청, 전체 목록 지연 준비, 갱신 실패, KST 자정, 상세 revision 및 잠금 충돌 검증.
- Python 783개 및 58 subtests 통과, 웹 232개 통과, 프로덕션 빌드 통과.
- 웹 테스트에서 기존 Vite 개발 포트 충돌 경고가 있었지만 테스트는 모두 통과했다. npm 설치의 기존 high 취약점 1건은 이번 장애 수정 범위 밖이며 별도 검토가 필요하다.
- 병합 및 배포 후 실제 목록/API를 별도로 검증한다. 단기 응답 성공으로 장기 무장애를 주장하지 않는다.
