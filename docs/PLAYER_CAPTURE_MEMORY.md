# 선수정보 수집 기회와 조회 범위 수정

운영 관측에서 선수정보 문서는 2026-09-23 이후 낡아 있었고 수집기는 512MB admission
기준 때문에 66분 이상 대기했다. 기존 30초 폴링은 배당 종료로 생기는 여유와 연결되지
않았다. 또한 #242의 입력 보존은 약 7MB/2,099경기 문서 전체를 Python으로 읽었다.

이번 변경은 배당 프로세스 종료 및 추천 후속 실행 후 Event로 선수정보 대기자를
깨운다. 선수정보 스레드 수와 수집 주기는 그대로이며, 기존 락 안에서 512MB 조건을
다시 확인한다. 메모리 기준을 낮추거나 실시간 점수를 멈추지 않는다. 이벤트를 놓쳐도
30초 폴링이 남아 있다. 종료 후 기회가 있으면 더 빨리 재검사하는 개선이지 대기 시간
상한이나 실행 중 OOM 방지가 아니다. 다른 보조 작업이 락을 잡고 있으면 여전히 대기한다.

경량 시장 갱신은 DB에서 리그·정확한 팀명·전체 kickoff에 해당하는 선수정보만 읽는다.
시간대는 SQLite julianday로 비교하고 최대 2행을 반환해 중복 경기를 임의 선택하지
않도록 한다. Python의 전체 JSON 전송·디코딩은 피하지만 SQLite JSON 스캔은 남는다.
많은 신규 경기에서는 반복 스캔 비용이 생길 수 있으므로 RSS/지연 감소량은 아직
실측했다고 주장하지 않는다. 조회 결과 없음과 원천 없음은 모두 매칭 불가로 처리한다.

추천 방향·확률·고정 픽·원장 과거 기록은 변경하지 않는다. 새 입력이 없는 이유 중
이미 고정된 픽만 존재하는 경우는 이 변경으로 해결되지 않으며 소급 기록하지 않는다.

검증: 전체 Python 테스트 및 웹 테스트/빌드. 추가 회귀 테스트는 미래/다른 경기 제외,
동일 kickoff의 시간대 변환, 중복 후보 보존, 메모리 부족 상태에서 이벤트가 와도
작업이 실행되지 않음, 대기 중 락 해제를 확인한다.

운영 판정에는 새 이미지 배포가 필요하다(supervisor 변경). 배포 후 선수정보 실제
실행→정상 완료→문서 원천 시각 갱신→새 경기 사전 입력 저장→정산 연결을 확인해야 한다.
현재는 코드 검증 단계이며 수집 정상화·적중률/ROI 개선이 입증된 상태가 아니다.
