# 두폴 검증용 후보 수집

추천 정책 변경 없이 PR #247의 후보 보존 부분을 현재 main에 맞춰 적용한다.
기존 실험 분석기와 수익률 주장은 이 PR에 포함하지 않는다.

- research 후보 중 저배당과 역배도 저장한다. 지원 마켓, 관측 시간창,
  유효 확률 및 overround 필터를 통과한 후보 목록이며 모든 원천 마켓은 아니다.
- 확률 출처, 시장 확률, 산식 버전(Shin 구현 파일 SHA-256), 적용된 결정 모델
  버전/아티팩트 해시, 선택 방향, 배당, 회차/게임 번호를 보존한다.
- generated_at/source_generated_at/live_odds_at/recorded_at과 공동 batch ID를
  기록한다. 동일 ID는 같은 수집 묶음이라는 뜻이지 실제 구매 가능성 보증은 아니다.
- fresh 15분, T-30 이전 첫 관측만 허용한다. 기존 기록을 새 후보로 보충하거나
  과거 확률 출처를 추정해서 채우지 않는다. 결과는 공식 정산으로만 갱신한다.
- 경기당 최대 24선택, 전체 후보 목록 예약 용량 256 KiB(선택당 정산 여유 256바이트).
  한도를 넘으면 목록 전체를 제외하고 사유를 기록한다. 이는 직렬화 예산이지
  프로세스 RSS 상한이 아니다. 기존 28일/2000경기 제한도 유지한다.
- roster_status_counts, roster_complete_events, roster_reserved_bytes를 관측한다.
  예산 소진 후에는 완전한 후보 기록이 늘지 않으며 이를 성공으로 판단하지 않는다.
- 운영 추천/하이라이트/자동 조합 비활성 상태는 유지한다. 과거 누락은 복구되지
  않으므로 배포 이후 실제 완전한 batch와 공식 결과가 쌓여야 비교를 시작한다.

## 배포 후 확인(이번 PR에서는 미실행)

새 미래 경기의 candidate_roster, capture_version, observation_batch_id와 확률
출처/버전을 확인한다. 기존 기록의 변경 없음과 저배당/역배 기록을 확인하고,
정산 후 해당 선택들의 hit/miss/void가 보존되는지 확인한다. 표본 수뿐 아니라
누락 사유 및 메모리/API 응답도 관찰한다. 이 수집 변경은 ROI 개선 증거가 아니다.
