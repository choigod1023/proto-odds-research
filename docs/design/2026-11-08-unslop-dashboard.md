# PROODD 화면 정리 기록

대상은 `markets.html`, `dashboard.html`과 이 두 페이지의 경기정보 모달이다. 새 추천·예측값·정산 기능을 추가하지 않고 기존 콘텐츠와 섹션 순서를 유지했다. 제품 이름, 기존 한국어 폰트와 주 메뉴도 유지했다.

## 방향과 발견한 문제

제품은 경기·추천·정산 근거를 대조하는 기록 화면이다. 차분함·정확함·높은 정보 밀도를 기준으로, 기록지의 정렬을 시각적 기준으로 삼았다. 강조는 적중 집계와 현재 선택한 픽에 두고 경기 시각·선택·배당·결과는 열과 숫자 형식을 맞춘다.

기존 화면은 이미 중립색을 사용하므로 전면적인 색상 교체나 장식 추가가 필요한 상태는 아니었다. 다만 최근 결과의 적중 카드마다 배경·테두리를 강조해 모든 결과가 경쟁했고, 목록의 경기 시각과 결과를 세로로 비교하기 어려웠다. 일부 보조 글씨는 작고 글꼴 두께·간격이 제각각이었다. 기존 정보를 지우거나 모델 성과를 새로 만들지 않는 범위에서 polish 모드로 진행했다.

## 적용한 순서

1. 간격: 4px 단위로 페이지·패널·목록 간격을 맞췄다. 모바일은 16px, 큰 화면은 32px 페이지 여백을 사용한다.
2. 색: 중립 표면과 세 가지 텍스트 역할을 사용한다. 최근 적중 결과 전체를 색칠하던 처리를 제거하고 결과 텍스트와 집계에만 강조색을 둔다. 기존 손실 의미 색상은 유지한다.
3. 아이콘: 장식 아이콘이나 새 라이브러리를 추가하지 않았다. 기존 기능을 표시하는 제어와 로고를 유지한다.
4. 문구: 정책 혼합·90일 범위·최근 최대 10건·공식 결과와 무효 제외 안내를 유지했다. 실제 적중률이나 수익성 주장을 추가하지 않았다.
5. 글꼴: 기존 한국어 폰트를 유지하고 제목·본문 두께와 크기를 정리했다. 수치는 tabular figures를 쓴다.
6. 배치: 최근 결과는 같은 섹션 안에서 종목/리그·경기·KST 시각·결과 열로 표시한다. 각 행은 원래의 상세 모달을 여는 버튼이다. 모바일은 같은 정보를 읽기 순서대로 쌓는다. 기능이나 섹션을 삭제하지 않았다.
7. 세부: 패널·컨트롤의 둥근 모서리와 여백을 맞췄다. 모달 헤더·탭·본문·표 간격을 통일하고 닫기 제어의 44px 터치 높이를 보존한다.
8. 시각 자료: 실제 경기와 집계가 중심이므로 가짜 차트·이미지·장식용 지표를 추가하지 않았다.
9. 움직임: 로딩 줄의 반복 shimmer를 제거했다. 실제 로딩 상태 표시는 남기고 reduced-motion에서는 전환과 애니메이션을 끈다.

`web/src/unslop.css`는 두 진입점에서만 읽는다. 다른 진입 페이지의 디자인을 무심코 바꾸지 않도록 범위를 제한했다. 배당·추천 정책·API·정산 계산·저장 기록은 변경하지 않았다.

## 검증

- 기존 웹 테스트 312개 통과, Vite 전체 빌드 통과.
- 실제 읽기 전용 운영 API를 사용하는 로컬 화면에서 최근 결과 10행, 종목 필터, 전체 KST 시각, 상세 열기·닫기, 원래 경기정보를 확인했다.
- 390×844 모바일에서 결과 목록과 내 기록 페이지를 확인했다. 페이지 scrollWidth 375px, viewport 390px로 페이지 전체 가로 넘침은 없었다. 종목 선택 영역의 내부 가로 스크롤은 의도한 동작이다.
- 밝은 테마의 내 기록과 어두운 결과 목록을 확인한 뒤 테마를 자동으로 복원하고 임시 viewport를 해제했다.
- Python으로 표면 대비를 계산했다. 어두운 패널의 primary/secondary/muted/accent 대비는 14.995/8.228/6.196/9.261, 밝은 패널에서는 17.928/7.814/6.044/8.249로 모두 4.5 이상이다. 이 검사는 수정한 기본 텍스트 토큰에 대한 것이며 사이트 전체 접근성 인증을 뜻하지 않는다.
- 상세에서 최종 점수 미연결 안내 등 기존 데이터 한계도 그대로 표시한다. 이번 UI 작업이 데이터 누락을 해결했다고 주장하지 않는다.
