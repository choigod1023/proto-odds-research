# 경기 전 선수 정보 검증 이력

이 기능은 운영 픽을 바꾸지 않는 연구용 보존 경로다. 선발·라인업·결장 정보가
추가되었다는 이유만으로 확률에 보너스를 더하거나 검증된 추천으로 승격하지 않는다.
실매수 API는 호출하지 않는다.

## 과거 자료

`experiments/pregame-archive-search-20261024/`에 실제 조회 결과를 보존했다.
NBA 공식 부상 보고서 1개의 경기 전 Wayback PDF 보관본에서 2경기 후보를 확인했다.
원문 게시 시각, 제3자 보관 시각, 이번에 읽은 시각은 서로 다르다.
파일명 날짜나 현재 API가 돌려주는 과거 라인업만으로 사전 공개를 인정하지 않는다.
후보의 운영 경기 ID·당시 배당·사전 예측 연결이 끝나기 전에는 ROI 표본에 넣지 않는다.
2경기는 독립된 2개 데이터셋이 아니며, 개선 효과를 추정할 표본 수도 아니다.

## 앞으로의 수집

- 기존 `player_info` 및 `kbo_pregame` 수집 성공 후 연구 이력을 보존한다.
- 경량 시장 판정 갱신 후 배당·기준 예측·공식 판정을 연결한다. 픽이 변하지 않아도
  선수 정보는 변할 수 있으므로 변경 없음 경로에서도 연구 수집을 시도한다.
- 새 대용량 예측 작업이나 별도 네트워크 수집 루프는 추가하지 않는다. 기존 수집 주기와
  메모리 대기를 따른다. 따라서 수집 실패·대기로 T-30을 놓치면 적격 표본이 없는 것이다.
- 리그·정규화한 양 팀·전체 경기 시작 시각을 일치시킨다. 날짜 없는 팀 조합이나
  연전·더블헤더의 첫 일치 결과로 임의 연결하지 않는다.
- T-30 전에 실제 관측한 내용만 사전 표본으로 받는다. 원천 갱신 시각과 실제 보존 시각을
  분리하며, 나중에 읽은 내용을 과거 관측으로 소급하지 않는다.
- 최종 픽스터 픽은 입력하지 않는다. 시즌 로스터는 당일 선발이 아니고,
  명단 미포함·벤치 시작은 부상 확정이나 로테이션 의도의 증거가 아니다.
- 선발, 결장, 로테이션의 확인 범위는 원천마다 다르다. 없는 항목은 미확인으로 유지한다.
  모든 종목의 세 항목 수집을 보장하는 기능은 아니다.
- 공식 결과는 같은 이벤트뿐 아니라 정확한 `snapshot_id`와 `selection_id`에 연결한다.
  시장 적중 결과로 최종 경기 점수를 추정하지 않는다. 미판정·충돌을 실패로 세지 않는다.

## 저장·활성화

`PROODD_RESEARCH_DB_PATH`를 명시해야 활성화된다. 미설정 시 아무 파일도 만들지 않는다.
Fly 설정은 `/data/pregame-research.sqlite3`이며 운영 DB와 분리한다. 소스 런타임 DB는
읽기 전용으로 접근한다. 기존 수집 결과·원장·픽은 수정하지 않는다.
연구 저장 실패는 기존 수집을 실패시키지 않으며 상태 로그로 남긴다.
이 설정을 커밋한 것과 운영 서버에 배포해 실제 기록이 생긴 것은 별개의 상태다.

연구 프로세스는 Linux 가용 메모리 256MiB 미만이면 시작하지 않고, 최대 12초만 실행한다.
입력 JSON 크기·행 수를 제한한다. 연구 DB가 약 47MiB에 이르면 신규 증거 수집을 멈추고
약 63MiB까지 기존 표본 정산용 공간을 남긴다. 한도에 도달하면 `needs_archive`를 로그로
알리며 자동 삭제하지 않는다. 운영자가 이력을 보존한 뒤 다음 보관소로 전환해야 한다.
정산 순회 커서는 별도 파일에 보존해 시간 제한에 걸려도 항상 첫 기록만 재검사하지 않는다.
이 제한 때문에 누락된 표본이 생길 수 있으며, 이를 정상 수집이나 모델 개선으로 세지 않는다.

MLB 부상자 명단은 선수별 실제 성공 관측 시각을 보존한다. 일부 팀 호출 실패 후 전체
갱신 시각만 새로 찍힌 캐시를 새 부상 정보로 쓰지 않는다. 현 수집 원천이 제공하지 않는
명시적 로테이션 발표와 농구·배구 당일 선발은 여전히 미확인일 수 있다. 벤치와 타순은
보존하되 감독의 로테이션 의도로 바꾸어 해석하지 않는다.

```powershell
python scripts/export_pregame_research.py PATH_TO_RESEARCH_DB paired-new.jsonl
python scripts/compare_pregame_research.py paired-new.jsonl --as-of 2026-10-24T12:00:00+00:00 --output baseline-audit-new.json
```

내보내기는 새 파일에만 쓰며 불완전한 표본도 사유와 함께 보존한다.
완전한 연결은 검증 완료나 수익성 증명이 아니다. 현재 예측만 보존되어 있으면
추가 정보 모델과의 수익률 차이는 `null`이다. 0% 개선으로 바꾸어 표시하지 않는다.

비교 도구의 `--challenger`에는 별도로 보존한 모델 예측 JSONL을 넣는다. 같은 pair ID와
내용 해시, 모델 ID, 확률, 학습 종료·예측·입력 기준 시각, 모델/설정 해시를 요구한다.
세부 필드는 스크립트 설명에 있다. 도구가 메타데이터를 검사하더라도 모델 제작자가
기재한 시각 자체를 독립적으로 증명하는 것은 아니다. 실제 전향 검증에는 예측 당시
이 파일을 보존해야 한다. 지금 예측을 돌린 뒤 과거 날짜를 적어 넣으면 안 된다.

출력에는 종목별 적중률·Brier·동일 금액 단폴 ROI와 별도의 한도 적용 2폴 모의 계정이
있다. 단폴 진단 ROI는 월 손실 한도가 적용된 실제 운용 수익이 아니다. 같은 선택의
확률만 보정하면 그 선택의 적중 결과는 그대로이며, 확률 보정과 조합 선택 효과를
구분해서 읽어야 한다. 모델 효과는 동일 표본·동일 시각의 기준 모델과 비교한다.
미판정 표본을 제거해 수익률을 좋게 만들지 않으며 최대 2,000행의 명시적 로컬
평가 구간만 받는다. 여러 구간을 나누면 월 손실 상태까지 이어야 하므로 구간별
모의 계정 손익을 단순 합산하지 않는다.

## 비교 규칙과 월 손실 한도

1. 종목·시장별로 같은 경기와 같은 배당 시점의 기준 모델/추가 정보 모델을 비교한다.
   정보가 있는 경기만 고르는 효과와 정보 자체의 효과를 구분하고 누락률도 보고한다.
2. 학습·보정은 평가 경기보다 앞선 기간만 사용한다. 시즌/시간 순서로 분리한 홀드아웃을
   남긴다. 실제 결과를 본 뒤 좋은 선수 가중치나 필터를 고르는 결과는 최종 검증이 아니다.
3. 기준 모델, 선발만 추가, 결장만 추가, 명시적 로테이션만 추가, 결합 모델을 비교한다.
   결측값을 건강·정상 로테이션으로 채우지 않는다. 원천의 확실성도 따로 다룬다.
4. 적중률과 Brier 점수, 확률 보정, ROI, 월 손익, 최대 낙폭, 손실 월 비율을 함께 본다.
   ROI는 적중률과 다르며, 2폴의 독립성을 자동으로 가정하지 않는다.
5. 기존 모의 운용의 **1회 1만원·2폴·주 2회/3회·월 손실 5만원** 규칙을 유지한다.
   미정산 금액까지 최악 손실로 예약하고 한도 초과 시 신규 모의 베팅을 막는다.
   종목별로 5만원씩 나누어 총한도를 늘리지 않는다. 모델별 가상 계정은 대안 비교이며
   여러 계정의 손익을 합산해 실제로 동시에 운용한 수익처럼 제시하지 않는다.
6. 기존 `scripts/audit_recommendation_shadow.py`와 `scripts/run_forward_paper.py`의
   손실 한도·미정산·월 경계 회귀 테스트를 유지한다. 이번 기능은 그 정책을 바꾸지 않는다.
7. 표본이 충분하지 않거나 개선의 불확실성이 크면 미검증으로 남긴다. 자동 모델 승격은 없다.

손실 제한은 이 규칙을 지킨 모의 운용의 한도다. 수익을 보장하거나 외부에서 따로 하는
베팅의 손실까지 제한하지 않는다.
