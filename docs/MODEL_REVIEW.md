# 모델 교체 심사: 로컬 1단계

`scripts/model_review.py`는 기존 실험 결과를 읽어 운영 기준 모델과 여러 후보의
수익 안정성을 일괄 비교한다. 학습·배포·DB·현재 픽을 변경하지 않는다.
자동 실험 실행과 사전 원장 수집까지 연결된 완성형 오케스트레이터는 아직 아니다.

## 운영 경계

현재 코드의 기준 모델은 `ai_decision.OPERATING_MODEL_VERSION`의
`shin-market-anchor-v1`이다. 이전 연구의 `old_gap`는 연구 비교군이지 운영 모델이 아니다.
CLI 기본 champion은 `shin`이며 실제 배포 상태를 조회하거나 같다고 보증하지 않는다.
`probability_pipeline.evaluate_promotion`의 미사용 자료·확률 검증과
`ai_decision.PROMOTED_ARTIFACT_HASHES`의 코드 승인 장치를 우회하지 않는다.

이 심사기는 연구 형식의 입력만 지원하므로 결과가 좋아도 `research_followup_only`다.
`production_action=none`, `approval_required=true`는 항상 유지한다.
JSON의 상태를 운영 승격 플래그로 연결해서는 안 된다.

## 실행

```powershell
python scripts/model_review.py --input <실험결과.json> --output <새심사결과.json> --champion shin --candidates old_gap fixed_prior_constant inner_selected --policy highestprob --as-of 2026-10-02
```

입력은 PR #261의 `folds[].forecasts`, `folds[].ledgers[model][policy]` 형식이다.
소스 파일은 읽기 전용이며 출력은 새 파일로만 생성한다. 기존 출력이 있으면 실패한다.
모델별 날짜·리그 예산이 다르거나 중복되면 중단한다. 정산은 경기 결과와 원배당으로
다시 계산하며, 두 경기 중복·배당·원장 손익 불일치를 거부한다.

## 시간과 비교 기준

`--as-of`는 심사일이다. 경기일 +7일이 지난 결과만 사용한다. 이후 결과를 바꿔도
당시 심사 지표는 바뀌지 않는다. 이 가정은 실제 사전 기록 시각 인증을 대신하지 못한다.
입력 파일 전체 SHA256은 미래 행 변경 시 달라져도 정상이다.

같은 ISO 주의 모든 리그를 함께 재표집해 후보의 ROI 하한과 기존 대비 ROI 차이 하한을
계산한다. 등록 후보 수 × 사전에 정한 심사 횟수 × 두 검정에 Bonferroni 보정을 적용한다.
`--planned-looks`는 결과를 보기 전에 정해야 하며, 반복 심사하면서 1로 두면 안 된다.
이 CLI는 심사 등록부를 영구 관리하거나 이전 실행 횟수를 검증하지 않는다.
해당 등록부와 불변 사전 원장 연결 전에는 자동 운영 승격을 허용하지 않는다.
과거 연구 전체의 후보 탐색까지 보정하는 것도 아니다.

기본 심사 조건은 양쪽 300장 이상, 26주 이상, 두 시즌 이상, 보정한 두 하한 >0,
참여율 유지, 최대 누적 손실·연속 손실 악화 없음이다. 리그·시즌별로 양쪽 30장 이상,
후보 ROI 양수 및 기존 이상도 요구한다. 이는 보수적인 공학적 초안이며 검증된 최적
기준이나 수익 보장이 아니다. 부적합 결과에 맞춰 조건을 완화하지 않는다.
부트스트랩 꼬리 표본이 부족하면 하한을 미확인으로 처리한다.

최대 누적 손실은 일별 동시 예산을 합산한 고정 단위 손익 경로에서 계산한다.
연속 손실은 손익 음수인 활성 날짜를 세며 현금/0손익 날짜로 끊지 않는다.
베팅이 없으면 ROI는 null이며 0% 수익으로 표시하지 않는다.
적중 수는 보고하지만 높은 적중률만으로 승격하지 않는다.

## 다음 연결 단계

1. 후보 코드·학습 종료 시각·데이터 해시·정책·심사 일정의 불변 등록부.
2. 같은 추천 시점의 후보 확률·배당을 T-30 계약에 맞게 append-only 기록.
3. 공식 결과의 이용 가능 시각으로 정산하고 확률 보정·Brier·log loss까지 공동 심사.
4. 모델 선택 절차 자체를 과거 시점→다음 기간 순서로 재현해 평가. 현재 CLI의
   `--replay-dates 2024-08-01 2025-01-01 --as-of 2025-07-01`은 이 경계의 모의
   재현 기능이다. 시점별로 고정 기준 모델과 후보를 비교하고, 통과한 후보가 없으면
   기준 모델을 선택한다. 통과 후보 중 ROI 차이 하한이 가장 큰 것을 그 뒤 기간에만
   적용한다. 새 데이터 성과가 아니라 노출된 연구 자료의 반사실 모의 결과다.
5. 통과한 버전만 사람에게 교체 제안. 승인 후 별도 PR·CI·배포·롤백 확인.

기존 실험은 사후 연구 자료여서 1~3의 증거가 없다. 이 코드는 이 부족함을 성공으로
간주하지 않는다. 현재 PR은 자동 비교·보류 판단의 기반만 구현하며 스케줄러,
운영 실행 관리자, 유료 자원, 원격 알림을 추가하지 않는다.

## 기존 자료로 실행한 결과

PR #261 결과를 입력해 2026-10-02 시점의 최고확률 두폴 정책을 심사했다.
`old_gap`, `fixed_prior_constant`, `inner_selected` 모두 보류다. 양수 ROI 하한,
기준 모델 대비 양수 차이 하한, 리그·시즌별 안정성이 모두 미달했다.
실현 ROI는 각각 −5.7641%, −4.6334%, −8.1591%다.

2024-08-01·2025-01-01 심사 후 다음 기간을 모의 평가한 예제도 두 번 모두 Shin을
유지했다. 해당 평가 151장 ROI는 −7.5581%였다. 교체 보류는 수익성 인증이 아니다.
심사 날짜와 초안 기준은 이미 결과를 본 뒤 정했으므로 이 예제는 시간 경계·보류
동작을 확인한 것이며 선택 전략의 미노출 수익 검증이 아니다.

입력: PR #261의 `docs/research/2026-10-01-gap-cold-start-results.json`.
출력과 정확한 입력 SHA256: `docs/research/2026-10-02-model-review.json`,
`docs/research/2026-10-02-selector-replay.json`. 연구 PR은 독립 실행 도구를 추가할 뿐
이전 연구 PR을 병합하거나 운영에 가져오지 않는다.
