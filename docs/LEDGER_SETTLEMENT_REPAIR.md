# 경량 갱신의 예측 정산 연결 누락

## 원인과 수정

`generate_v2._sync_prediction_runtime`에는 정산 호출이 있었지만 자주 실행되는
`live_market_refresh.refresh_once`에는 예측 기록 호출만 있었다. `refresh_document`는
킥오프 이후 사전 픽·가격 보호를 위해 기존 선택지가 있는 경기를 건너뛰며,
변경이 없으면 `refresh_once`도 곧바로 반환했다. 이 경로만으로는 공식 결과가
피드에 들어와도 예측 원장에 정산이 추가되지 않았다.

새 경로는 원본 공식 시장 피드를 별도로 검사한다. 경기 event_id, 선택지 selection_id,
회차·게임번호까지 포함한 offer_id가 모두 일치할 때만 기존 revision을 정산한다.
픽·확률·사전 배당을 다시 만들거나 바꾸지 않는다. 구매 선택지가 여러 번 발행되면
다른 회차의 결과로 대신 정산하지 않는다. 모호한 중복 행·미확정 결과는 건너뛴다.

변경 없는 갱신에서도 정산하며, 원장 기록 후 산출물 저장이 실패한 경우 다음 실행이
정산 표시를 복구한다. 같은 결과 재처리는 추가하지 않고 공식 결과 변경은 기존
append-only 정산 규칙을 사용한다. 경기 문서가 사라져도 원장/피드 식별자가 같으면
정산 가능하다. 현재 연도가 붙지 않는 원천 피드의 특성상 연말 경계와 오래된 피드의
복원은 별도 검토가 필요하며, 임의 연도 추측으로 연결 범위를 넓히지 않는다.

## 로컬 복원

```powershell
python scripts/replay_ledger_results.py <original-ledger.jsonl> <new-ledger.jsonl> <official-odds.json.gz> [more-feeds.json]
```

새 파일에 원장을 복사한 뒤 원본 해시 체인을 검증하고 정산을 추가한다.
원본/기존 출력 파일을 덮어쓰지 않으며 DB 환경 변수가 설정된 경우 거부한다.
복원 시각은 현재 기록 시각으로 남는다. 과거에 결과를 알고 있었다고 소급하지 않는다.
원천 자료의 진위와 완전성은 운영자가 별도로 확인해야 한다.

로컬 1,326행과 보관된 9월 초 최근 배당 피드를 대조한 시험에서는 연결 0건이었다.
이는 수정 실패가 아니라 해당 피드에 과거 선택지의 정확한 결과가 없다는 뜻이다.
이 시험을 운영 DB 복원 완료 또는 ROI 검증으로 보고하지 않는다.
최근 피드에서 빠진 회차는 원천 아카이브를 확보한 뒤 같은 식별 규칙으로 복원해야 한다.

운영 적용에는 PR 병합과 백엔드 배포가 별도로 필요하다. 이 변경 자체가 운영 DB를
수정하거나 과거 결과 전체를 복원한 것은 아니다.
