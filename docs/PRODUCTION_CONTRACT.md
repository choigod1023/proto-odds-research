# 운영 계약과 회귀 방지 기준

## 2026-10-29 동결 야구 후보의 연구 기록

- 실제 선택은 아래 `tipster-vote-v1` 계약을 유지한다. MLB `linear:l2=10`, KBO `e0:residual:0.03`은 이미 동결한 연구 후보이며 새로 학습·선정하거나 운영 추천으로 승격하지 않는다.
- 기존 선수 수집 작업에서 MLB 공식 feed의 경기 전 9인 타순·공식 공개 probable pitcher와 필수 통계만 제한 수집한다. probable pitcher를 최종 선발 확정이라고 표시하지 않는다. 실제 HTTP 수신 완료 시각을 가용 시각으로 쓰고, T-30 뒤 수집·경기 진행·잘못된 경기·불완전 타순은 거부한다.
- KBO는 고정 연구 이력의 종료 상태와 그 뒤 공식 일정/결과의 날짜별 누락·휴식일·취소까지 확인한 증분으로 전력을 계산한다. 연구 이력의 과거 가용 시각은 미검증으로 남기고, seed를 지금 읽은 시각을 과거로 소급하지 않는다. 전력 상태는 경기 날짜와 일치하고 실제 판정 전에 가용해야 한다.
- 같은 예측·시장 가격의 연구 후보 확률·선택·artifact/입력 해시를 기존 원장 부가 필드로 기록한다. 수집·재학습·과거 상태 재구성을 HTTP 요청이나 경기별 추론 안에서 수행하지 않는다. 별도 상시 프로세스나 유료 증설을 추가하지 않는다.
- 새 선수 자료는 실제 읽은 시각 이후의 새 판정에만 붙이며, 입력이 같으면 기존 예측의 자료 수집 시각만 바꾸지 않는다. T-30 동결·기존 해시 원장·과거 배당은 보존한다.
- 공식 결과는 운영이 보류한 경기의 연구 후보에도 별도로 연결한다. 후보 가상 정산은 실매수/모의 지갑 거래가 아니며 실제 모의 지갑의 월 순손실 5만 원 제한을 변경하지 않는다. 후보를 추천 적중률에 합산하지 않는다.

## 2026-10-28 픽스터 투표 선택 전환

- 사용자가 실제 추천 전환을 명시했다. 새 경기 전체 승패/승무패 선택은 `tipster-vote-v1`이며 시장90:투표10 혼합을 대체한다. 경기 전 실제 수신 완료 ≤ T-30, 작성자별 최초 관측 한 표와 기존 종목·팀·일정·시장 검증은 유지한다. 동일 최초 시각의 상반된 작성자 표는 제외한다.
- 최다 득표가 유일하면 해당 방향을 선택한다. 유효 표가 없거나 동률이면 보류하며 시장 정배나 다른 마켓으로 대체하지 않는다. 작성자가 한 명일 수도 있으며 작성자/발행처 수와 표 수를 명시한다.
- 투표는 선택 방향에만 작용한다. 지지율은 적중확률이 아니며 최종 확률·EV의 확률 입력은 동일 선택의 시장 기준 확률을 그대로 쓴다. `affects_selection=true`, `affects_probability=false`, `validated_edge=false`, 승인 상태와 수익성 미검증 표시는 유지한다. 과거 혼합 정책의 동결 확률은 당시 계약으로 읽는다.
- 전환은 새로운 미동결 판정에만 적용한다. T-30 이후 기존 선택·배당·확률·결과와 이전 원장을 소급 변경하지 않는다. 경기별 투표 선택과 일일 55%·배당1.50 관심 하이라이트는 구분한다.
- 모의 운용은 `tipster-vote-single-v1` 계정의 단폴 1만원으로 전환하며 새 2폴·주2/3회 비교 거래를 만들지 않는다. 기존 거래는 보존·정산하고 모든 종목·미정산 노출을 포함해 월 순손실 5만원 한도를 유지한다. 실매수하지 않는다.
- 모의 원장 정산을 위해 새 정책의 경기 전 revision을 각각 보존한다. 더 최근의 보류 revision은 오래된 픽의 신규 모의 거래를 막지만, 이미 기록한 거래의 선택·배당 revision을 지우지 않는다. 공식 결과는 각 보존 revision에 연결한다.
- 2025-10-28~2026-10-27 회고 연구의 동일 가격 주 분석 492경기에서 시장 -10.11%, 픽스터 -8.10%, 9:1 -8.97%였다. 이 승인으로 미래 흑자 또는 안정적 우세가 입증된 것은 아니다.

이 문서는 수집기·예측 원장·추천 정책·프론트 표시를 수정하는 사람과 AI가 반드시
지켜야 하는 현재 운영 계약이다. 과거 구현을 되살리거나 병합할 때 코드 조각보다 이
계약을 우선한다.

## 2026-10-26 경기별 선택 정책 전면 전환

- 2026-10-28 픽스터 identity 보완: TailSlips v2·v3·v4의 경기 전 최초 관측을 동일한 T-30·단일 경기·작성자 중복 제외 조건으로 읽는다. v4 전환 첫 관측은 baseline이며 과거 자격을 소급하지 않는다. 자정 뒤 결과 연결은 전날 시작을 관측한 유일한 미채점 후보에만 허용하며, 다음 날 경기 전 관측은 기존 연결을 해제하고 별도 픽으로 보존한다.

- 사용자 요청에 따라 `market90-tipster10-v2`를 야구·축구·농구·배구의 경기 전체 승패/승무패 선택 정책으로 적용한다. 아래 MLB 한정 조항보다 우선한다.

- 공개 원문은 픽천국의 명시적 추천 픽/SportsEvent와 골리의 전체 경기 추천 구간만 읽는다. 편집팀은 한 발행처 투표로 세며 작성자별 최초 관측을 보존한다. 종목·리그·팀·일정의 유일한 일치와 실제 HTTP 수신 완료 시각 ≤ T-30을 요구한다. 반경기·핸디캡·합계·모호한 이름은 섞지 않는다.
- 픽천국의 datePublished가 경기 시작 시각을 반환하는 사례를 확인했다. 해당 값은 원천 주장으로만 보존하고 게시 시각으로 인정하지 않는다. 운영 전향 관측은 실제 수집 시각을 증거로 사용하며 과거 시점 증명이나 과거 ROI 표본으로 소급하지 않는다.
- 다종목 수집기는 15분 주기, 회당 목록 5개·본문 최대 16개, 응답 크기/시간 제한과 순환 커서를 사용한다. 각 목록의 첫 글은 매회 확인하고 남은 요청 예산으로 과거 글을 순환한다. 실패·매칭 제외·실제 입력 수를 `public_tipster_intake`에 기록한다. 자동 경량 판정은 배당이 그대로여도 새로운 픽스터 증거로 새 판정을 게시한다.

- 두 픽스터 작업 모두 2분 이상 대기하면 오래 기다린 순서로 다음 보조 작업 슬롯을 받는다. 진행 중인 배당 판정 재시도는 유지하고, 새 배당 수집 한 주기는 양보할 수 있다. 새 관측이 저장되면 수집 자식이 종료된 뒤 같은 메모리 슬롯에서 판정과 응답 게시를 이어서 실행한다. 실패한 게시 신호는 독립 복구 주기가 재시도하고, 관측 변화가 없으면 추가 판정을 만들지 않는다.
- 축구 등 3-way는 무승부도 비교한다. 단일 완전한 시장만 허용하고, 불완전하거나 중복된 시장은 보류한다. 핸디캡·합계의 모델은 승패 혼합 대상으로 확대하지 않는다.

- 새로운 미동결 판정부터 적용하며 과거 결과·정산·T-30 동결 판정은 소급 변경하지 않는다. 월 손실 5만 원 한도와 실매수 금지는 그대로다.

## 1. 경기 상태

- 카드 상태는 경기 자체의 상태다. 예측 원장 저장 여부와 섞지 않는다.
- `BEFORE`는 예정, 최신 `STARTED`는 진행 중, `RESULT`·`END`·`ENDED`는 종료다.
- 취소·연기는 종료나 진행 중으로 오인하지 않고 별도 상태로 표시한다.
- 실시간 피드 장애만으로 시작 시각이 지난 모든 경기를 `확인 중`으로 만들지 않는다.
  Fly 직접 응답이 실패하면 `docs/data/live_scores.json`의 마지막 정상 스냅샷을 쓴다.
- `확인 중`은 실제 결과 원천과 매칭되지 않거나 종료 여부가 불명확한 개별 경기에서만
  허용한다. 한 날짜의 모든 경기가 동시에 확인 중이면 장애로 간주한다.
- 팀명 매칭 키에는 `MM.DD`를 포함한다. 연전 경기를 팀 조합만으로 합치지 않는다.

## 2. 사전 예측 원장과 동결

- 모든 경기의 사전 판단을 append-only 원장에 저장한다. 추천뿐 아니라 관망·보류도
  선택, 확률, 배당, 근거, 스냅샷 ID와 함께 보존한다.
- 최종 픽 변경 가능 시점은 경기 시작 30분 전까지다. T-30 이후에는 픽과 정확한
  prediction revision을 고정한다.
- 경기 시작 후 현재 배당으로 과거 픽을 새로 만들거나 바꾸지 않는다.
- 보존된 스냅샷을 원장에 기록할 때 시장 관측 시각은 현재 실행 시각이 아니라 해당
  스냅샷의 `as_of`다. 현재 시각은 T-30 동결 판단에만 쓴다. 관련 변경은 PR #156이다.
- 종료 후 적중/실패는 저장된 정확한 사전 revision에 공식 결과를 연결해 계산한다.
  사전 기록이 실제로 없는 경기만 `사전 기록 전 경기`로 표시한다.
- 모의 원장의 공식 결과 연결에서 게시/기록시각만 바뀐 재게시는 원래 사전
  revision을 덮어쓰지 않고 허용한다. 경기ID·시작시각·팀·시장·기준점·선택·
  배당·확률·정책 등 나머지 identity가 모두 같아야 한다. 원본 T-30과 재게시
  시각 순서도 검증하며, 배당/확률 변경이나 중복 매칭은 계속 보류한다.
- 라이브 중에는 고정된 사전 확률과 현재 점수·남은 시간을 결합한 현재 적중확률을
  `LIVE` 옆에 표시한다.

- 2026-10-12 사용자 요청: 아래 자격 기준을 통과한 현재 후보의 화면 이름은
  '관심 픽 · 수익성 미검증'으로 구분한다. 검증된 추천은 승인된 검증 근거가
  없는 동안 0개로 유지한다. 이 표시 변경은 과거 recommended 값, 선택·확률,
  T-30 동결 원장을 바꾸지 않는다. 모의 월 손실 한도는 5만 원이며 실매수하지 않는다.
  아래의 과거 '오늘의 추천 픽' 표현 유지 조항보다 이 구분을 우선한다.

- 2026-10-10 사용자 승인: 새 추천은 예상 적중 55% 이상, 배당 1.50 이상(상한 없음)
  (`daily-p55-o150-unbounded-v4`)으로 완화한다. 추천 수 확대를 위한 변경이며 수익률 개선을
  입증한 변경이 아니다. 기존 60% 정책과 더 이전 정책의 추천 이력은 당시 기준으로
  해석하고 T-30 이후 기록·추천 여부를 소급 변경하지 않는다.
- 2.20 이상도 확률·시장 자격 조건을 통과하면 추천할 수 있다. 상한 제거는 확률
  조작이나 55% 미만 추천을 허용하지 않는다. 현재 시장 기준으로 자격을 갖춘
  고배당 픽이 없으면 없는 그대로 표시한다. 연구용 자동 조합 정책은 변경하지 않는다.

- 경기별 픽은 각 경기의 최종 방향이다. `오늘의 추천 픽`은 그중 운영 기준을 통과한
  일부만 뽑은 부분집합이다.
- 오늘의 추천은 별도 조합 카드가 아니라 해당 개별 선택을 형광색으로 강조한다.
- 전 경기를 추천하거나 전 경기를 하이라이트하지 않는다.
- 리그별 후보를 평가하되 기준 미달 픽을 숫자를 채우기 위해 억지 추천하지 않는다.
- 추천 이유와 추천하지 않는 이유를 모두 데이터에 보존하고 대시보드에 표시한다.
- 사용자 문구를 임의로 `시장 우세` 중심으로 바꾸지 않는다. 프로젝트 고유의 검증된
  선택 기준과 `오늘의 추천 픽` 표현을 유지한다.

## 4. 데이터·캐시·장애 복구

- 실시간 점수·배당·추천·판정은 마지막 정상값을 유지한다. 일시 실패가 정상값을
  `null`, `확인 중`, `추천 없음`으로 덮어쓰면 안 된다.
- 모바일 새로고침과 복귀 시 캐시 무효화 쿼리, `no-store`, visibility/focus/online 재조회가
  동작해야 한다.
- 날짜 분류는 KST 기준이다. 전날부터 진행해 자정을 넘긴 경기는 오늘 화면에서도
  사라지지 않아야 한다.
- 수집기의 무응답과 “경기 없음”을 구분한다. 무응답이면 기존 예정 경기와 원장을
  보존한다.

## 5. 완료 판정 체크리스트

1. 배포 전 현재 운영 JSON과 화면을 캡처하고 증상 수치를 기록한다.
2. 회귀 테스트에 실제 실패 형태를 넣는다. 정상 예제만 추가하지 않는다.
3. Python 전체 테스트, 프론트 전체 테스트, 프로덕션 빌드를 실행한다.
4. PR CI 성공 후 병합하고 원격 `main`이 변경 커밋을 포함하는지 확인한다.
5. Pages 배포 완료와, 백엔드 변경 시 Fly 서버의 새 커밋 로드를 별도로 확인한다.
6. 캐시 우회한 실제 배포 화면에서 상태 개수, 픽 고정, 하이라이트, 라이브 확률을
   다시 확인한다.
7. 병합과 배포가 끝났어도 실제 증상이 남아 있으면 완료라고 보고하지 않는다.

## 6. 운영 주의

Fly 수집기는 1 GB 머신에서 여러 수집 작업을 병렬 실행한다. 정규 전체 갱신 중에
수동으로 `generate_v2.py`를 하나 더 실행하면 OOM과 502를 만들 수 있다. 검증은 정규
실행 로그를 기다리거나, 격리된 로컬 데이터로 수행한다.

- DB에 넣었다고 전체 JSON 조회 비용이 사라지는 것은 아니다. 경기별 조회가 같은
  선수 문서를 반복 파싱하지 않도록 한 갱신에서 필요한 경기만 묶어 읽는다.
- 배당 수집과 판정은 운영에서 별도 일회성 프로세스로 실행한다. 수집 프로세스가
  종료된 뒤 판정을 시작하고, 무거운 보조 작업과의 동시 실행을 막는다.
- 배당 저장 성공과 판정 게시 성공을 별도로 기록한다. 판정의 메모리 대기·시간 초과·
  실패는 성공으로 세지 않으며 다음 주기에서 재시도한다. 메모리 시작 검사는 실행 중
  OOM 방지를 보장하지 않는다.
- 저장 배당 판정이 실패하면 같은 스냅샷으로 총 3회까지만 시도하고, 첫 실패부터
  600초가 지나도 다음 시도는 최신 배당 재수집부터 시작한다. 실패 간격은
  60/120/180초로 늘리며 성공하면 초기화한다. 기한은 실행 사이에 검사하므로
  실행 중인 DB 트랜잭션을 TTL 때문에 끊지 않는다. 프로세스 재시작 시에도
  최신 배당 수집부터 시작한다. 마지막 정상 응답과 T-30 동결 원장은 유지한다.
- 이 재시도 기한은 화면의 모든 `재계산 대기`를 자동 해제한다는 뜻이 아니다.
  원장 충돌·사전 기록 누락은 검증 없이 정상 픽으로 대체하지 않으며, 경기 시작
  뒤의 배당으로 사전 기록을 소급 생성하지 않는다.
- 원장 조회는 직렬화된 전체 행과 파싱된 전체 행을 동시에 보관하지 않는다. 이 최적화가
  원장 해시 검증 생략이나 과거 기록 삭제를 허용하지는 않는다.
