# 운영 계약과 회귀 방지 기준

## 2026-11-06 경기 추천 1픽 사전 기록

- 경기 추천 1픽은 기존 운영 선택들 중 배당 1.50 이상을 우선하고, 동일한 시장 기준 적중 가능성으로 비교해 경기당 하나를 고른다. 마감 전에 예측 원장의 해당 revision에 상품·기준점·선택·배당을 함께 기록하며, 브라우저는 이 저장값을 표시한다.
- 경기 시작 30분 전부터 사전 기록을 고정한다. 기존 원장에 없던 픽을 나중에 소급 생성하지 않는다. 같은 경기·상품·선택의 공식 결과로만 정산하며, 결과가 수정되면 원본 예측을 보존한 채 정산 revision을 추가한다.
- 발매 중 기준점·배당 변경 후에도 저장 당시 조건으로 정산한다([프로토 공식 안내](https://www.sportstoto.co.kr/proto_intro)). 최신 기준점의 적중·실패를 이전 기준점에 복사하지 않는다. 야구·농구 전 경기 상품에서 이전 기준점 결과가 사라진 경우에만, T-30 이전 원장의 정확한 상품·기준점·규칙과 `source=proto` 확정 원점수를 연결해 기존 정산 경로로 revision을 추가한다. 경기 날짜·시각·리그·종목·홈/원정이 일치하고 최신 원점수 기록들이 모두 합의하며 현재 공식 상품 결과와도 일치해야 한다. 원점수 철회·충돌, 기간·규칙 미확인, 다른 상품, 축구는 이 복구 경로에서 계속 보류한다. 가격은 원장 배당을 유지하고 모의 지갑을 변경하지 않는다.
- 1픽 성적은 시장별 추천, 오늘의 관심 픽, 모의 지갑과 별도다. 가상 1단위 기준의 실현 ROI는 환불을 포함한 정산액 기준이고 적중률은 환불을 뺀 경기 기준이다.

## 2026-11-05 K리그1·KBL 핸디캡 선택

- 새 경기 전 판정에서 K리그1 정규시간 3방향 핸디캡은 동결 팀 득점 모델, KBL 연장 포함 반점 핸디캡은 동결 팀 점수차 모델을 먼저 적용한다. 해당 두 시장에서는 모델이 유효할 때 모델 선택을 자동 추천으로 기록한다.
- 공식 현재 배당의 관측 시각, 알려진 두 팀, 정확한 상품과 선택지 식별자가 있어야 한다. 입력 누락이나 모델 보류 시 기존 상품 정책을 적용한다. T-30 동결 이후의 기록은 다시 쓰지 않는다.
- 경기 상세에서 두 모델의 예상 적중확률과 기대 ROI를 같은 상품의 시장 기준과 함께 표시한다. 원장에는 동결 모델 해시와 배당을 보존하고 공식 상품 결과로 정산한다. 회고 계산에 사용한 가격은 사전 집행 가능성을 입증하지 않으므로 수익성 미검증으로 표시한다.

## 2026-11-05 경기 상세의 모델별 픽 비교

- 정확히 같은 상품의 경기 전 기록에서 모델별 방향·배당·예상 적중확률·기대 ROI를 표시한다. 기존 KBO 원천 검증에서 함께 확인한 M0 actual·M0 projected·M1 projected만 득점 모델로 쓴다. 픽스터 지지율을 적중확률로 바꾸지 않는다.
- 세 모델이 동일 선택·가격에서 모두 적중확률 55% 이상, 기대 ROI 양수일 때만 경기당 한 개의 비교용 픽을 고른다. 모델별 최솟값을 기준으로 기대 ROI, 확률 순서로 비교하며 동률이면 보류한다. 비교는 지원되는 언더오버·핸디캡에 한정한다. 승패와 기존 시장별 운영 추천, T-30 원장, 모의 지갑은 바꾸지 않는다.
- 기대 ROI는 정상 정산을 가정한 베팅액 대비 `P(적중)×(배당−1)−P(실패)`다. 과거 성적은 같은 리그·시장·기준점·방향·정산 규칙의 동결 기록을 공식 상품 결과로 따로 집계하고 표본 수를 표시한다. 경기 전 원천이 없거나 과거 표본이 없으면 해당 수치를 꾸미지 않는다.
- 기존 368경기·721상품 KBO 회고 자료에서 197경기 선택, 171경기 보류, 107/197 적중(54.31%), ROI −13.63%였다. 같은 상품의 시장 최저 배당은 102/197(51.78%), ROI −20.13%였다. 이 비교는 수익성 인증이나 실제 구매 시점 증명이 아니다. 재현은 `scripts/replay_market_pick_frontier.py`에 보존했다.
- 후보는 기존 판정과 함께 생성하고 기존 공식 결과 경로에서 별도 정산한다. 상세 응답과 같은 revision에서만 표를 복원하며 목록에 모델 행을 싣지 않는다.

## 2026-11-05 사용자 승인: 시장별 실제 추천·정산

- 사용자 요청으로 언더오버·핸디캡의 `market_recommendations`를 별도 실제 자동 추천으로 게시한다. 같은 경기·회차·상품번호·기준점·기간·단위·정산 규칙의 완전한 선택지에만 적용하며, `reference_only`의 불일치 의견은 계속 추천 근거에서 제외한다.
- 같은 기준점의 유일한 경기 전 작성자별 최다 투표가 있으면 그 방향을 선택한다. 유효한 표가 없으면 현재 승패 정책과 같은 시장 최유력 방향을 사용하고 시장 기준이라고 표시한다. 투표 동률·수집 장애·상품 불명확·T-30 이후에는 보류한다. 지지율을 적중확률로 표시하지 않는다.
- KBO M0의 원래 동결 계수는 변경하지 않는다. 공식 확정 명단·이력으로 서버에서 경기 전에 저장한 실제 M0 분포만 시장별 비교 확률로 기록한다. 44경기 회고에서 총점 M0 ROI -10.52%, 동일 상품 시장 -6.14%, 핸디캡 M0/시장 모두 -13.25%였으므로 M0를 신규 시장의 우수한 주력 모델로 승격하지 않는다. 이 표본은 독립 전향 검증이나 당시 구매 가능성 증명이 아니다.
- 축구는 정규시간, 야구·농구는 연장 포함 전체 경기 규칙으로 분리한다. 하프라인 언더오버, 정수 3-way 핸디캡, 야구·농구 하프라인 2-way 핸디캡만 허용한다. 원래 무승부였던 KBO 하프라인 핸디캡에도 조건을 적용하는 실제 공식 원본을 확인했다. 정수 2-way, quarter-line, 전반·이닝·세트별 상품, 단위 미확인 배구 상품은 이번에 확대하지 않는다.
- 새 추천은 기존 예측 원장의 해당 사전 revision에 선택·가격·정산 규칙·원천·M0/시장 비교를 함께 보존한다. 공식 프로토의 정확한 상품 결과로 별도 정산하고 원래 승패 선택/적중률과 섞지 않는다. 취소·공식 무효는 환불로 집계하며 뒤늦은 현재 가격으로 과거 추천을 만들지 않는다.
- 기존 월 손실 5만 원 모의 지갑과 이미 동결된 승패 추천은 보존한다. 새로운 시장별 성과는 상품별 가상 1단위 성적이며 실매수나 지갑 거래 생성이 아니다. 수익성 검증 표식은 계속 false다.
- M0 수집은 기존 서버의 보조 작업 슬롯을 공유하는 5분 Python 작업이다. 재학습·LLM 호출·새 상시 서비스·증설은 추가하지 않는다. 원천 수집 후 compact index를 복구하고 변경이 있을 때 기존 판정 게시 경로를 깨운다. 사용자 PC의 예약 작업 성공을 서버 수집 성공으로 보고하지 않는다.
- 공식 규칙: https://www.sportstoto.co.kr/terms_allocation.php , https://www.sportstoto.co.kr/proto_rules.php . 상품별 명시된 기간/단위가 다르면 일반 규칙으로 덮어쓰지 않는다.

## 2026-11-03 시장별 비교 후보

- 2026-11-04 연결 보완: 경기 전 실제 수신한 공개 원문의 팀 기준 핸디·득점 합계 의견 중 현재 프로토 기준점과 다르거나 기간/정산 방식이 미확인인 것은 별도 `reference_only`로 표시한다. 조합글의 개별 의견이라는 맥락을 보존하며 투표·예측·가격 원장에 합산하지 않는다. 오늘의 고유 경기·팀·시간·T-30·작성자를 대조하고 원문 기준점을 프로토 값으로 대체하지 않는다. 기존 본문 16개 제한 안에서 참고글 하나를 확인하며, 기존 목록에 없을 때만 공개 목록 1회를 더 조회한다(목록 최대 6회). 참고 스트림 장애·상한은 승패 입력 장애로 전파하지 않는다.

- 승패·승무패 최종 운영 선택과 별도로 핸디캡·언더오버의 시장별 비교와 사용자 직접 선택 경로를 둔다. 자동 최종 추천·확률·T-30 동결 원장·월 손실 한도는 변경하지 않는다.
- 같은 HTTP 수신 바이트·시각에서 명시적 기준점/방향을 추출한 의견만 `candidate_only` 이벤트로 추가한다. 출처·경기·T-30·작성자별 최초 관측·현재 상품의 기준점/기간/정산 방식이 일치하는 후보를 표시하고 동률/모호함은 보류한다. 지지율을 확률로 바꾸지 않는다.
- 별도 후보는 `affects_selection=false`, `affects_probability=false`, `validated_edge=false`다. 기존 승패 투표에 섞지 않으며, 후보 표시만 바뀌어도 기존 예측 revision을 다시 쓰지 않는다. 정산 범위·가격 수신·실제 판매 가능성은 미확인 상태를 유지한다.
- 현재 지원 원문은 기존 메타데이터 검증을 통과한 승패 추천을 함께 가진 글이다. 언더오버만 있는 글, 기준점 없는 추천, 배구 단위·정산 범위가 확인되지 않은 의견을 검증된 실전 추천이라고 표시하지 않는다. 실제 기준점 있는 원문 수집 성공은 별도로 확인해야 한다.

## 2026-10-29 동결 야구 후보의 연구 기록

- 실제 선택은 아래 `tipster-vote-v1` 계약을 유지한다. MLB `linear:l2=10`, KBO `e0:residual:0.03`은 이미 동결한 연구 후보이며 새로 학습·선정하거나 운영 추천으로 승격하지 않는다.
- 기존 선수 수집 작업에서 MLB 공식 feed의 경기 전 9인 타순·공식 공개 probable pitcher와 필수 통계만 제한 수집한다. probable pitcher를 최종 선발 확정이라고 표시하지 않는다. 실제 HTTP 수신 완료 시각을 가용 시각으로 쓰고, T-30 뒤 수집·경기 진행·잘못된 경기·불완전 타순은 거부한다.
- KBO는 고정 연구 이력의 종료 상태와 그 뒤 공식 일정/결과의 날짜별 누락·휴식일·취소까지 확인한 증분으로 전력을 계산한다. 연구 이력의 과거 가용 시각은 미검증으로 남기고, seed를 지금 읽은 시각을 과거로 소급하지 않는다. 전력 상태는 경기 날짜와 일치하고 실제 판정 전에 가용해야 한다.
- 같은 예측·시장 가격의 연구 후보 확률·선택·artifact/입력 해시를 기존 원장 부가 필드로 기록한다. 수집·재학습·과거 상태 재구성을 HTTP 요청이나 경기별 추론 안에서 수행하지 않는다. 별도 상시 프로세스나 유료 증설을 추가하지 않는다.
- 새 선수 자료는 실제 읽은 시각 이후의 새 판정에만 붙이며, 입력이 같으면 기존 예측의 자료 수집 시각만 바꾸지 않는다. T-30 동결·기존 해시 원장·과거 배당은 보존한다.
- 공식 결과는 운영이 보류한 경기의 연구 후보에도 별도로 연결한다. 후보 가상 정산은 실매수/모의 지갑 거래가 아니며 실제 모의 지갑의 월 순손실 5만 원 제한을 변경하지 않는다. 후보를 추천 적중률에 합산하지 않는다.

## 2026-10-28 픽스터 투표 선택 전환

- 사용자가 실제 추천 전환을 명시했다. 새 경기 전체 승패/승무패 선택은 `tipster-vote-v1`이며 시장90:투표10 혼합을 대체한다. 경기 전 실제 수신 완료 ≤ T-30, 작성자별 최초 관측 한 표와 기존 종목·팀·일정·시장 검증은 유지한다. 동일 최초 시각의 상반된 작성자 표는 제외한다.
- 최다 득표가 유일하면 해당 방향을 선택한다. 유효 표가 없거나 동률이면 보류하며 시장 정배나 다른 마켓으로 대체하지 않는다. 작성자가 한 명일 수도 있으며 작성자/발행처 수와 표 수를 명시한다.
- 투표는 선택 방향에만 작용한다. 지지율은 적중확률이 아니며 최종 확률·EV의 확률 입력은 동일 선택의 시장 기준 확률을 그대로 쓴다. `affects_selection=true`, `affects_probability=false`, `validated_edge=false`, 승인 상태와 수익성 미검증 표시는 유지한다. 과거 혼합 정책의 동결 확률은 당시 계약으로 읽는다.
- 전환은 새로운 미동결 판정에만 적용한다. T-30 이후 기존 선택·배당·확률·결과와 이전 원장을 소급 변경하지 않는다. 경기별 투표 선택과 일일 55%·배당1.50 관심 하이라이트는 구분한다.
- 모의 운용은 `tipster-vote-single-v1` 계정의 단폴 1만원으로 전환하며 새 2폴·주2/3회 비교 거래를 만들지 않는다. 기존 거래는 보존·정산하고 모든 종목·미정산 노출을 포함해 월 순손실 5만원 한도를 유지한다. 실매수하지 않는다.
- 모의 원장 정산을 위해 새 정책의 경기 전 revision을 각각 보존한다. 더 최근의 보류 revision은 오래된 픽의 신규 모의 거래를 막지만, 이미 기록한 거래의 선택·배당 revision을 지우지 않는다. 공식 결과는 각 보존 revision에 연결한다.
- 2025-10-28~2026-10-27 회고 연구의 동일 가격 주 분석 492경기에서 시장 -10.11%, 픽스터 -8.10%, 9:1 -8.97%였다. 이 승인으로 미래 흑자 또는 안정적 우세가 입증된 것은 아니다.

이 문서는 수집기·예측 원장·추천 정책·프론트 표시를 수정하는 사람과 AI가 반드시
지켜야 하는 현재 운영 계약이다. 과거 구현을 되살리거나 병합할 때 코드 조각보다 이
계약을 우선한다.

## 1. 경기 상태

- 카드 상태는 경기 자체의 상태다. 예측 원장 저장 여부와 섞지 않는다.
- `BEFORE`는 예정, 최신 `STARTED`는 진행 중, `RESULT`·`END`·`ENDED`는 종료다.
- 취소·연기는 종료나 진행 중으로 오인하지 않고 별도 상태로 표시한다.
- 실시간 피드 장애만으로 시작 시각이 지난 모든 경기를 `확인 중`으로 만들지 않는다.
  Fly 직접 응답이 실패하면 `docs/data/live_scores.json`의 마지막 정상 스냅샷을 쓴다.
- `확인 중`은 실제 결과 원천과 매칭되지 않거나 종료 여부가 불명확한 개별 경기에서만
  허용한다. 한 날짜의 모든 경기가 동시에 확인 중이면 장애로 간주한다.
- 팀명 매칭 키에는 `MM.DD`를 포함한다. 연전 경기를 팀 조합만으로 합치지 않는다.

## 2. 사전 예측 원장과 동결

- 모든 경기의 사전 판단을 append-only 원장에 저장한다. 추천뿐 아니라 관망·보류도
  선택, 확률, 배당, 근거, 스냅샷 ID와 함께 보존한다.
- 최종 픽 변경 가능 시점은 경기 시작 30분 전까지다. T-30 이후에는 픽과 정확한
  prediction revision을 고정한다.
- 경기 시작 후 현재 배당으로 과거 픽을 새로 만들거나 바꾸지 않는다.
- 보존된 스냅샷을 원장에 기록할 때 시장 관측 시각은 현재 실행 시각이 아니라 해당
  스냅샷의 `as_of`다. 현재 시각은 T-30 동결 판단에만 쓴다. 관련 변경은 PR #156이다.
- 종료 후 적중/실패는 저장된 정확한 사전 revision에 공식 결과를 연결해 계산한다.
  사전 기록이 실제로 없는 경기만 `사전 기록 전 경기`로 표시한다.
- 모의 원장의 공식 결과 연결에서 게시/기록시각만 바뀐 재게시는 원래 사전
  revision을 덮어쓰지 않고 허용한다. 경기ID·시작시각·팀·시장·기준점·선택·
  배당·확률·정책 등 나머지 identity가 모두 같아야 한다. 원본 T-30과 재게시
  시각 순서도 검증하며, 배당/확률 변경이나 중복 매칭은 계속 보류한다.
- 라이브 중에는 고정된 사전 확률과 현재 점수·남은 시간을 결합한 현재 적중확률을
  `LIVE` 옆에 표시한다.

  선택 기준과 `오늘의 추천 픽` 표현을 유지한다.

## 4. 데이터·캐시·장애 복구

- 실시간 점수·배당·추천·판정은 마지막 정상값을 유지한다. 일시 실패가 정상값을
  `null`, `확인 중`, `추천 없음`으로 덮어쓰면 안 된다.
- 모바일 새로고침과 복귀 시 캐시 무효화 쿼리, `no-store`, visibility/focus/online 재조회가
  동작해야 한다.
- 날짜 분류는 KST 기준이다. 전날부터 진행해 자정을 넘긴 경기는 오늘 화면에서도
  사라지지 않아야 한다.
- 수집기의 무응답과 “경기 없음”을 구분한다. 무응답이면 기존 예정 경기와 원장을
  보존한다.

## 5. 완료 판정 체크리스트

1. 배포 전 현재 운영 JSON과 화면을 캡처하고 증상 수치를 기록한다.
2. 회귀 테스트에 실제 실패 형태를 넣는다. 정상 예제만 추가하지 않는다.
3. Python 전체 테스트, 프론트 전체 테스트, 프로덕션 빌드를 실행한다.
4. PR CI 성공 후 병합하고 원격 `main`이 변경 커밋을 포함하는지 확인한다.
5. Pages 배포 완료와, 백엔드 변경 시 Fly 서버의 새 커밋 로드를 별도로 확인한다.
6. 캐시 우회한 실제 배포 화면에서 상태 개수, 픽 고정, 하이라이트, 라이브 확률을
   다시 확인한다.
7. 병합과 배포가 끝났어도 실제 증상이 남아 있으면 완료라고 보고하지 않는다.

## 6. 운영 주의

Fly 수집기는 1 GB 머신에서 여러 수집 작업을 병렬 실행한다. 정규 전체 갱신 중에
수동으로 `generate_v2.py`를 하나 더 실행하면 OOM과 502를 만들 수 있다. 검증은 정규
실행 로그를 기다리거나, 격리된 로컬 데이터로 수행한다.

- DB에 넣었다고 전체 JSON 조회 비용이 사라지는 것은 아니다. 경기별 조회가 같은
  선수 문서를 반복 파싱하지 않도록 한 갱신에서 필요한 경기만 묶어 읽는다.
- 배당 수집과 판정은 운영에서 별도 일회성 프로세스로 실행한다. 수집 프로세스가
  종료된 뒤 판정을 시작하고, 무거운 보조 작업과의 동시 실행을 막는다.
- 배당 저장 성공과 판정 게시 성공을 별도로 기록한다. 판정의 메모리 대기·시간 초과·
  실패는 성공으로 세지 않으며 다음 주기에서 재시도한다. 메모리 시작 검사는 실행 중
  OOM 방지를 보장하지 않는다.
- 저장 배당 판정이 실패하면 같은 스냅샷으로 총 3회까지만 시도하고, 첫 실패부터
  600초가 지나도 다음 시도는 최신 배당 재수집부터 시작한다. 실패 간격은
  60/120/180초로 늘리며 성공하면 초기화한다. 기한은 실행 사이에 검사하므로
  실행 중인 DB 트랜잭션을 TTL 때문에 끊지 않는다. 프로세스 재시작 시에도
  최신 배당 수집부터 시작한다. 마지막 정상 응답과 T-30 동결 원장은 유지한다.
- 이 재시도 기한은 화면의 모든 `재계산 대기`를 자동 해제한다는 뜻이 아니다.
  원장 충돌·사전 기록 누락은 검증 없이 정상 픽으로 대체하지 않으며, 경기 시작
  뒤의 배당으로 사전 기록을 소급 생성하지 않는다.
- 원장 조회는 직렬화된 전체 행과 파싱된 전체 행을 동시에 보관하지 않는다. 이 최적화가
  원장 해시 검증 생략이나 과거 기록 삭제를 허용하지는 않는다.
