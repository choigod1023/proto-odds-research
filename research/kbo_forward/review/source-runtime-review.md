# 원천 연결 및 고정 실행본 사전 점검

대상은 피처 생성기 `4b62ac97ac39f6a229364e88ee921351bb39330a`와 예약·런타임 구현 `626d5e02f2299a514d19107906f423d92b8dc06d`다. 공식 어댑터와 미완성 수정본은 포함하지 않는다. 실시간 수집·예약 작업 설치를 수행하지 않았다.

## 피처 입력의 신뢰 경계

`features.build_row()`는 문서상 호출자가 제공한 일정·이력의 출처를 인증하지 않는다. 일정의 HTTPS 호스트와 본문 해시는 확인하지만 `body`를 파싱해 `events`와 대조하지 않는다. 합성 시험에서 본문을 `{"game":[]}`로 바꾸고 그 해시를 맞춘 뒤 별도의 events에는 완료 경기 1건을 남겼다. 이 불일치에도 팀 피처와 선수 피처가 산출됐다. 이는 피처 생성기 단독 호출의 재현이며, 아직 인계되지 않은 공식 어댑터가 같은 불일치를 허용한다는 증거는 아니다.

따라서 원천 어댑터는 수신한 일정 원문에서 팀별 경기 목록과 상태를 직접 유도하고, 원문 바이트 해시·실수신 시각·경기 식별자·KST 날짜·팀·공식 완료 여부와 증분 기록을 대조해야 한다. 임의로 제공된 `events`, URL, 자기 해시 또는 `source_verified` 불리언만으로 적격 처리를 허용하지 않는다. 연도·월 경계, 더블헤더·취소·연기·재편성·오류 응답·누락된 박스스코어를 포함해 완료 일정의 누락이 없다는 증거가 없으면 해당 시점 이력은 확인되지 않은 것으로 둔다.

고정 seed가 오래되었을 때 대상 팀별 완료 일정과 선수 기록의 해당 기간 보완이 확인되지 않으면 팀뿐 아니라 타자·투수 피처에도 오래된 수치를 넣지 않아야 한다. 원천 worker의 `covered=False` 처리와 `source_verified=False`가 최종 runner까지 전파되는지 실제 통합 커밋에서 재검증한다. 피처·가격 기존 테스트는 13개와 하위 검사 5개가 통과했지만 위 원문 불일치 반례나 실제 공식 어댑터 연결을 증명하지 않는다. 반례 코드는 `audit_feature_source_initial.py`다.

## 고정 실행본과 권한

기존 bootstrap은 깨끗한 코드 범위의 HEAD에서 Git archive를 만들고 파일별 해시를 기록한다. 그러나 예약 실행 스크립트는 매 실행 전 저장된 파일 해시나 Python·라이브러리 환경을 확인하지 않는다. 따라서 커밋 SHA 이름의 디렉터리라는 사실만으로 실행할 때의 바이트와 환경이 고정됐다고 단정할 수 없다. 실행 직전에 신뢰할 수 있는 별도 기준에 대해 필수 코드·모델·입력 파일을 검증하고 누락·변조 시 수집을 중단해야 한다. Git 대상 전체와 import 가능한 경로·패키지의 범위, 외부 Python 또는 의존성 교체에 따른 영향을 함께 검토한다.

예약 작업은 제한 권한의 로그인 사용자로 작성돼 있고 이름이 같은 기존 작업이 있으면 등록 전에 중단하도록 돼 있다. 현재 기본 상태 디렉터리가 없어서 실제 디렉터리 ACL과 상속, 예약 작업 주체의 읽기·쓰기 권한, 런타임의 다른 사용자 수정 가능성은 아직 확인할 수 없다. 설치 후에는 실제 등록된 task action·실행 파일 경로·주체·ACL·파일 해시와 절전 및 재로그온 동작을 확인해야 한다. 이 검토는 예약 작업 설치를 뜻하지 않는다.

원장 종료 후 잠금, 6개 이상 후보 공정성, 가격 원문/조건 일치와 경기별 실패의 성공 표시 문제는 `initial-runner-review.md`에서 고정 커밋 대상으로 재현했다. 부모 작업 공간의 수정 중인 파일은 검토 기준으로 확정하지 않았으며, 새 커밋이 인계되면 관련 반례를 다시 실행해야 한다.
