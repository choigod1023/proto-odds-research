# Runner·원장·예약 작업 초기 독립 감사

대상 고정 커밋 `626d5e02f2299a514d19107906f423d92b8dc06d`. 공식 어댑터·피처 구현은 아직 인계 전이다. 테스트는 합성 입력과 임시 디렉터리에서 실행했으며, Windows 작업 생성·실행과 실제 원천 요청은 하지 않았다. 기존 runner·ledger 테스트 9개는 통과했다.

## 예약 설치 전 수정 권고

1. **프로세스 강제 종료 후 원장 쓰기가 계속 막힌다.** runner의 `single_writer` OS 잠금은 종료 시 풀리지만, 실제 원장 append는 별도 `forward.append_locked`의 `O_EXCL` 파일 잠금을 쓴다. append 도중 프로세스를 종료하는 합성 시험에서 `paired-ledger.jsonl.lock`이 남았고, 재시작 후 append가 `FileExistsError`로 실패했다. 예약 작업은 5분 실행 제한이 있어 실제 강제 종료 가능 경로가 있다. OS 잠금으로 원장 append도 보호하거나, 소유 프로세스 생존 여부와 파일 무결성을 검증하는 안전한 잠금 복구가 필요하다. 살아 있는 다른 작업의 잠금을 임의 삭제해서는 안 된다.
2. **6번째 후보부터 반복적으로 굶는다.** `candidates[:5]`를 고른 다음 이미 처리한 앞 5개를 건너뛰므로, 일정의 앞 다섯 경기가 이미 저장된 상태에서도 6번째는 다음 주기에 선택되지 않는다. 합성 경기 6개를 두 번 실행한 결과 캡처 5건, 다음 캡처 0건이었다. 완료된 후보를 먼저 제외하거나 커서를 영속화하고 주기별 공정 순회·결측을 검증해야 한다.
3. **가격 원문과 정규화 상품의 연결은 runner에서 독립 검증하지 않는다.** 실제 `prices.parse_detail()`은 원문을 파싱하지만, `price_packet()`은 지정된 원문 바이트의 해시만 검사하고 전달받은 odds·상품이 원문의 해당 행과 같은지 재계산하지 않는다. 합성 원문 홈 1.80과 전달된 홈 9.99의 불일치가 그대로 통과했다. 또한 `q`에 `market` 키가 있으면 `price_packet` 자체를 우회한다. 이것은 삽입된 테스트용 `price_fn`의 반례이며 기본 실제 가격 함수가 9.99를 생성했다는 증거는 아니다. runner의 신뢰 경계를 고정하고 우회 형태를 제거하거나 명시적 테스트 전용 경로로 격리하며, 독립 재파싱·원문 행 ID·가격·상품·판매 상태를 검증해야 한다.
4. **원천 오류가 전체 성공 상태로 표시된다.** 경기별 snapshot 오류는 `excluded`에 들어가지만 `report.status`는 `ok`, CLI 종료 코드도 0이다. 모든 경기 수집이 실패한 합성 사례로 확인했다. 실제 오류와 정상 결측·판매 미개시를 구분하고 실패·부분 실패를 상태와 알림에 반영해야 한다. 현재 검토한 경로는 JSON 보고서 파일을 쓰지만 사용자에게 알리는 기능은 확인되지 않았다.
5. **무승부 환급 규칙의 공식 근거가 별도로 필요하다.** `prices.parse_detail`은 공식 응답의 `야구 승패`·`일반 승패`와 승/패 두 선택지를 검사하고 `draw_void_refund`를 부여한다. 두 선택지가 있다는 사실만으로 무승부 환급 규칙이 원문에서 입증되지는 않는다. 해당 상품과 적용 시점의 공식 정산 규정 원문을 보관·대조하기 전에는 검증된 환급 상품으로 승격하지 않는다. 이 지적은 실제 규칙이 환급이 아니라는 주장이 아니다.

이전 `e862ee62` 감사에서 재현한 동일 결과의 더 늦은 수신 watermark 누락 및 유효하지 않은 unpriced 모델 저장은 `626d5e02`의 원장 코드에서도 그대로다. 출처 검증 플래그 자가 선언도 원장 API 경계에 남아 있으며 실제 adapter 및 runner 연결의 강제 경계를 검토해야 한다. 상세는 `initial-ledger-review.md`를 참고한다.

## 예약·동결 관련 추가 확인

- 설치 스크립트는 같은 이름의 기존 작업이 있으면 중단하고, 제한 권한·대화형 사용자로 동작하도록 작성됐다. 설치는 수행하지 않았으므로 실제 권한, 재시작·절전 동작과 오류 알림은 미확인이다. `StartWhenAvailable`은 누락 실행을 깨운 뒤 실행할 수 있어도 과거 수신 시각을 만들 수 없으며 마감 지난 기회를 소급 캡처하지 않아야 한다.
- bootstrap은 커밋 archive의 개별 바이트를 runtime 생성 시 확인하지만, `scheduled_run.ps1`은 매 실행 전에 저장된 런타임 파일의 해시를 다시 확인하지 않는다. 런타임에 변경이 생겨도 경로가 같은 한 실행할 수 있으므로 실행 시 전체 필수 파일 해시·모델 해시·의존성 환경 확인 또는 불변 권한이 필요하다. 이 내용은 코드 검토이며 실제 변조를 수행하지 않았다.
- `audit_runner_initial.py`는 앞의 1~4번 반례를 합성 시험으로 재현한다. 고정 커밋과 일치하는 파일을 검증하고 실행한다. 이 재현 코드는 수정 전 동작을 증명하는 것이며 수정 후에는 기대 결과를 반대로 바꾼 회귀 테스트가 필요하다.
