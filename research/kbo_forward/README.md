# KBO 실제 경기 전 M0·고정 혼합안 비교 수집기

이 작업은 운영 추천을 교체하지 않는다. 기존 M0와 M0/shrink/NB03 각 1/3 혼합안을 같은 경기·같은 입력·같은 배당·같은 정산 규칙으로 기록하는 별도 전향 관측이다. 실매수·베팅 API는 없으며 기존 월 손실 5만 원 모의 거래 원장을 읽거나 수정하지 않는다.

## 실제 실행 경로

`runner.py` → `ConnectedOfficial` → 공식 KBO 일정/확정 타순/선수 검색/과거 일정·박스스코어 원문 → `features.py` → 동결된 2023–25 계수의 `ledger.infer_frozen` → 별도 append-only 원장 순서다. Betman 일반 승패의 직접 원문을 검증해 배당을 연결한다. 최초 완전한 예측은 경기 시작 최소 30분 전이고 실제 판매 마감·회차 마감 이전에 추론까지 끝나야 한다.

- KBO 리그·회차·공식 경기 ID·날짜·시각·홈/원정 팀·선발 ID·확정 타순 9명 순서를 확인한다. 선수 이름만 같다는 이유로 ID를 추측하지 않는다.
- 시드는 고정된 연구 입력의 SHA를 검증해 현재 시점에 읽는다. 과거 수신 시점 증거라고 주장하지 않는다. 시드 이후 모든 날짜의 공식 일정과 필요한 완료 박스 기록을 확인한다. 휴식일·취소와 누락도 구분한다.
- 학습 당시 팀 범주 계수를 그대로 쓰도록 공식 코드 SS/HT 등을 모델 입력 복사본에서 삼성/KIA로 변환한다. 모델 가중치는 변경하지 않는다.
- 현재 날짜와 같은 날의 성적, 미래 통계, 수신 뒤에 생긴 이력, 최근 명단을 오늘 확정 타순으로 대체한 입력은 쓰지 않는다.
- 공식 박스스코어의 볼넷+사구를 볼넷으로 만들지 않는다. 분리할 근거가 없는 값은 결측이며 원래 고정 모델의 결측 처리를 따른다. 원문 검증은 모든 변수가 완전하다는 뜻이나 모델 우위의 증명이 아니다.
- Betman 일반 야구 승패만 현재 원천 어댑터의 지원 상품이다. 승1패 가운데 선택지는 1점 차이며 무승부가 아니다. 전반·핸디캡·합계와 함께 제외한다. 일반 승패의 무승부는 환급한다. 원장에 있는 3-way 정산 기능은 이 실제 수집기가 3-way를 공급한다는 뜻이 아니다.
- 배당 원문 수신은 캡처 시점에서 10분 이내여야 한다. 상품·선택지·배당·매치 ID·판매 상태·정확한 시작/마감 시각을 원문에서 다시 파싱해 정규값과 비교한다. 날짜가 다른 경기나 불완전·중복·이미 닫힌 가격은 제외한다.

## 기록과 재시작

`paired-ledger.jsonl`은 해시 체인과 OS 파일 잠금으로 보호한다. 시작된 판정의 선택·확률·배당은 덮어쓰지 않는다. 공식 결과를 별도 정산으로 기록하고, 점수 정정도 새 correction으로 남긴다. 같은 결과를 더 늦게 확인했다는 증거를 별도 confirmation으로 보존해 오래된 상충 결과가 최신 정정을 대체하지 못하게 한다. 부분 기록·해시 훼손은 자동 삭제/절삭하지 않는다.

사전에 관측한 경기 기회도 먼저 남긴다. T−30까지 예측이나 가격을 확보하지 못한 경우 별도 이유가 남아 성공한 표본만 보이는 문제를 줄인다. 배당 없는 예측은 두 모델의 적중률만 별도로 정산하며, ROI를 생성하거나 유효 가격 표본에 합치지 않는다. 결과가 들어오기 전에는 예측의 성공·실패를 알 수 없다.

원천의 실제 수신 UTC와 원문 바이트 SHA를 보존한다. 정규 이력과 원문을 다시 비교한 후, 큰 원문 묶음은 내용 해시로 주소를 정한 gzip 파일로 보관하고 원장은 해당 해시를 참조한다. 이는 로컬 시계·보관 원문에 근거한 관측이며 외부 공증 시각이나 실제 구매/체결 증거는 아니다.

## 자동 실행과 상태

기본 상태 폴더는 `C:/Users/user/Documents/ChatGPT/sportstoto-research-state/kbo-m0-forward-v1`이다. 공개 원문, 원장, `last-run.json`, `summary.json`, 설치 영수증과 고정 runtime이 이 폴더에 분리돼 있다.

`bootstrap_runtime.py --state <경로> --install`은 커밋된 코드를 별도 `runtime/<commit>`에 보존한 후 새 Windows 예약 작업 `ProtoKboM0Forward-v1`을 설치한다. 다른 작업이나 기존 동명의 작업은 덮어쓰지 않는다. 이 PC가 로그인·절전 해제·온라인 상태일 때 5분마다 실행한다. PC가 꺼져 있거나 사용자가 로그아웃한 동안 수집을 보장하지 않으며 과거 예측을 소급 생성하지 않는다. 운영 Fly 서버·DB·기존 연구 자동화 큐와 스케줄을 변경하지 않는다.

매 실행은 두 날짜 일정과 제한된 결과 재확인만 먼저 읽는다. 경기 3시간 전부터 필요한 명단·이력을 수집하며, 완료 이력과 선수 식별 원문은 제한된 캐시로 재사용한다. 공식 요청은 한 실행 최대 80회, 1.5초 이상 간격, 타임아웃·백오프를 적용한다. 별도 Betman 경로도 횟수/페이지와 간격에 제한이 있다. 동시에 두 실행이 돌지 않고, 5개보다 많은 후보는 순환한다. 최초 기록을 보존하며 수집 실패도 다음 주기에 재시도한다.

`python -B -X utf8 research/kbo_forward/runner.py --state <경로> --status`로 네트워크 없이 현재 합계를 읽을 수 있다. 요약의 captured는 유효 가격과 두 예측을 저장한 수, paired_settled는 공식 결과까지 연결한 수다. observed_pregame_opportunities·closed_without_priced_prediction·unpriced_outcome_comparison은 서로 다른 분모다. 혼합해서 적중률/ROI를 소개하지 않는다.

## 비교 판단

처음부터 고정한 두 모델을 유지한다. 상품별 새 적격 정산 200경기와 관측 8주를 모두 채운 시점이 첫 검토 조건이며, 우위를 증명하는 충분 표본 수는 아니다. 적중률·ROI·기간별 손익·일 마감 기준 최대 낙폭을 같은 경기로 비교한다. 자동 채택·추가 튜닝·실제 추천 변경은 하지 않는다. 결과가 적거나 누락이 많으면 그 상태를 그대로 보고한다.

회고 연구 2024–26 ROI는 이 새로운 원장에 포함하지 않는다. 기존 보관 가격에는 사후 선택 편향이 있었으므로 과거 ROI와 새 전향 ROI를 합치지 않는다. 관련 사전 계약과 이전 결과는 `experiments/kbo-m0-followup-20261103/REPORT.md`, 이번 수집 계약은 `contract.json`에 있다.
