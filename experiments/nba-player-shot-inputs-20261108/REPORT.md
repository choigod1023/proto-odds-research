# NBA 선수별 슛 위치와 경기 전 라인업 입력 조사

고정된 NBA 1,185경기 이력 풀을 이용해 선수별 PBP 슛 위치와 선수 박스의 선발 여부·표시 출전시간을 연결했다. 대상 비교 경기 1,260개는 이력 풀의 크기와 별개다. 기존 라인업 연구는 사후 선수 조합과 4일 지연 대용을 사용했으며 경기 전 실제 수신을 입증하지 못했다. 이번에도 과거 원문은 2026-11-08에 수집한 사후 자료로, 당시 가용성을 입증하지 않는다.

## 슈터 귀속과 분 단위 표시

슛·자유투 263,925건 중 263,530건을 첫 participant ID, 공격 팀 선수 박스 및 설명문의 슈터 이름이 모두 일치할 때만 귀속했다. 어시스트나 블록 참여자를 슈터로 대신 쓰지 않는다. 여러 participant가 포함된 귀속 사건은 73,816건이다. 미귀속 395건은 이름·ID 불일치 363건, 첫 participant가 해당 팀 박스에 없는 경우 32건이며 36팀-경기에 분포한다. 예를 들어 ESPN 박스의 Alex Sarr와 PBP의 Alexandre Sarr는 이름이 달라 자동으로 합치지 않았다. 팀별 미귀속 시도·성공은 `team_audit.jsonl.gz`에 남겼다.

선수 행 31,948개 중 선수 박스와 시도·성공이 일치한 행은 25,756개, 박스는 있지만 다른 행은 84개, 선수 박스 통계가 없는 행은 6,108개다. 명시적으로 표시되는 `accounting_ok`와 `team_attribution_complete`를 함께 확인해야 한다. 선수 ID가 없고 활동이 기록되지 않은 항목 21건은 임의 ID를 만들지 않았다. 선수의 hard 및 soft 시도·성공은 2점/3점 계열별로 보존되며 전체 팀 슛은 귀속분과 미귀속분의 합으로 기존 팀 박스와 대조했다.

출전시간의 정수 분 표시를 초로 환산한 값은 정확한 초가 아니다. 팀별 총 표시값을 정규시간 240분과 연장당 25분의 합과 대조하면, 표시 단위 오차 범위 내인 사례가 2,293팀-경기, 시간 누락 또는 그 범위를 벗어나 확인이 필요한 사례가 77팀-경기였다. 오차 범위 통과는 정확한 선수별 초를 입증하지 않는다. 1피트 soft 위치는 비공식 ESPN 내부 좌표 가설이며 공식 NBA 존이 아니다.

## 경기 전 사용 가능성

선수의 타깃 경기 실제 출전시간·선발·출전 여부는 사후 정보여서 경기 전 입력으로 사용하지 않는다. 대상 1,260경기 모두 보존된 summary 영수증이 해당 KST 날짜의 시작 이후이고, 그중 4건은 404 본문이다. 별도로 보존된 발표·수신 시각을 검증할 수 있는 확정 선발 자료를 발견하지 못해 **엄격한 경기 전 확정 라인업은 0경기**다. 이 숫자는 조사한 자료 범위의 결과다. 선수 명단이나 예상 출전시간 proxy도 생성하지 않았다.

[NBA의 선발 명단 제출 규칙 안내](https://official.nba.com/nba-board-of-governors-approves-clarification-of-rule-governing-traveling-violations/)와 [NBA 오늘의 선발 페이지](https://www.nba.com/players/todays-lineups?hidenav=true)는 현재 출처의 가능성을 보여 주지만, 이번 과거 경기의 당시 게시·수신 원문을 증명하지 않는다. [NBA 부상 보고서](https://official.nba.com/nba-injury-report-2026-27-season)는 출전 상태 정보이며 확정 선발 명단과 다르다.

## 재현 및 제약

```powershell
python scripts/export_nba_player_shots.py --pool <games.jsonl.gz> --predictions <기존_predictions.jsonl.gz> --archive <ESPN_보존폴더> --out <출력폴더>
python -m pytest tests/test_nba_player_shot_inputs.py -v
```

기존 원천 풀과 대상 예측 해시, 경기별 원문 해시를 확인하고 전체 팀의 박스 합을 재검증했다. [스키마](SCHEMA.md)와 `pregame-lineup-coverage.json`은 사용할 수 있는 자료와 금지 필드를 구분한다. 생성된 이력만으로 타깃의 실제 선수 구성이나 출전시간을 만들 수 없으며, 과거 D-4 경계는 당시 실제 가용성의 증거가 아니다. 예측 성능이나 ROI는 측정하지 않았고 운영 변경은 없다.
