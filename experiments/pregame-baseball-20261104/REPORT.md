## 직접 재계산한 동일 fixture·가격 표본
`python -X utf8 experiments/pregame-baseball-20261104/overlap.py`는 고정 예측과 기존 가격의 정확한 `fixture_id` 교집합을 계산한다. `overlap.json`에 모든 fixture_id·market_id·배당·선택·결과와 입력 파일 SHA-256을 기록했다. ID에 의한 진단 연결이며 배당의 당시 공식 상품·구매 가능성이나 명단의 사전성을 입증하지 못한다. 시장은 낮은 양방향 배당, 모델은 높은 2-way 확률을 선택하고 무승부 환급·단일 1단위로 계산했다. 픽스터 및 9:1, 월 손실 제한, 2폴 정책을 계산한 결과가 아니다.

- 2026: `kbeffects` 원본 공식명단 가정 M0/M1/M2 및 같은 가격·결과 667경기. 시장 ROI -9.0315%, M0 -8.2999%, M1 -13.1574%, M2 -8.7316%. 2025 matched-training 모델과 별도 학습 실험이다.
- 투표는 `vote-accuracy-same-period-20261104/inputs.json` 14개 스냅샷 중 야구 1개를 살폈고 해당 `source_event_id`가 없어 공식 fixture ID로 연결할 수 없다. 확인된 exact-ID 교집합 0은 전체 투표 원천에 야구가 없다는 뜻이 아니다. 별도 원문 ID 매핑과 배당 상품 매핑이 필요하다.

## 2026 M0 차이 재검증과 모델 식별

actual-training의 M0_actual(-4.36%)과 player-effects-v2의 M0(-8.30%)는 이름은 비슷하지만 동결된 서로 다른 계수다. 전자는 2023–25 확정명단 paired 학습 2,182경기, 후자는 예상명단 기반 전체 2,187경기 학습이다. 두 실험 모두 평가 명단은 사후 복원한 공식 타순·선발이며 실제 수신을 입증하지 못했다. player-effects-v2의 M0는 actual-training 결과에 별도 맥락 대조로 보존된 oldfull_M0와 667/667 확률이 정확히 같다. M0는 개별 선수 역할 계수가 아닌 집계 선수 특징을 사용한다.

두 원본 장부의 교집합 667경기를 직접 비교한 결과 가격 출처 객체·양방향 가격·상품 ID 차이 0, 승자 차이 0이다. 원 배당 수신시각은 두 경우 모두 검증되지 않았다. 동일한 2-way 확률 최대 선택과 무승부 환급을 적용할 때 두 M0 확률은 667경기에서 다르고 선택 방향은 80경기에서 다르다. actual-training 순손익이 26.31단위 높아 ROI 차이는 26.31/667=3.9445%p다. 따라서 차이는 동일 가격·동일 규칙에서 **모델 학습본과 확률·선택**에서 발생한다. 학습 표본과 계수도 동시에 다르므로 각각의 개별 인과 효과를 분리한 것은 아니다. `export_predictions.py`가 원본 아티팩트로 이를 재계산하며 `model-manifest.json`에 완전한 계수 해시와 실행 코드 파일 해시를 보관한다. 코드 해시는 해당 파일만의 해시이며 전체 의존성 묶음의 완전한 식별은 아니다.

## 예측 교환 및 수집 재개

`model-predictions.jsonl.gz`는 기존 2025 actual-training M0/M2 각 727개, 2026 actual-training M0/M2 각 470개, 2026 player-effects-v2 M0/M1/M2 각 470개로 총 3,804개를 내보낸다. 원본 2025 각 731개·2026 각 709개 중 시작시각/팀 메타데이터가 빠진 예측은 내보내지 않고 manifest에 1,203 모델-경기 단위로 명시했다. 각 모델의 계수/코드 해시, 입력 계열, 실제 원본 파일 해시와 fixture ID를 제공한다. train_end는 학습 경기의 마지막 날짜이지 모델이 그날 이미 만들어졌다는 뜻이 아니다. `as_of`와 `received_at`은 null, `timing_basis=retrospective`, `input_record_ids=[]`이며 선수 입력 레코드 그래프가 없어 엄격 경기 전 판정이나 완전한 공통 엔진 결합을 주장하지 않는다. actual-training M1은 두 해 모두 `notimplemented`다.

`--start YYYY-MM-DD --end YYYY-MM-DD --max-requests N --evidence ... --output ... --cursor ...`로 제한 배치를 실행한다. 각 호출은 최대 60개 HTTP 요청 및 날짜 31일까지만 진행하고 날짜와 경기 인덱스를 cursor에 저장한다. 동일 cursor로 재개하며 완료 후 `--refresh` 또는 새 `--capture-id`는 현재·미래 경기의 별도 관측을 추가한다. 과거 완료 타순은 해시 검증된 원문을 재사용한다. 요청 실패와 빈 날짜는 구분한다. 전체 기간 수집을 실행하거나 완료했다고 주장하지 않는다. 두 번째 실제 조회의 metadata와 `batch-records.jsonl`도 보존했다.

## 본문 수신 완료 시각 기준

새 HTTP 응답은 `response.content`를 읽은 뒤 실제 UTC를 기록하며 metadata와 교환 레코드에 `timestamp_basis=http_response_body_completed`를 남긴다. 기존 캐시 metadata를 변경하거나 수신 시각을 새로 만들지 않는다. 기존에 기준이 없는 캐시에서 레코드를 만들면 `timestamp_basis=unknown`이다. 엄격 gate에는 실제 수신, 원문 해시 검증, 알려진 본문 완료 기준이 모두 필요하며 batch 시작 시각을 수신 완료 시각으로 사용하지 않는다. 과거 경기의 사후 조회는 새 본문 완료 시각이 있어도 경기 전 수신 증명이 아니다.

completion-basis-20261104 관측의 원문과 metadata는 이전 관측과 별개로 추가했다. 이전 metadata·레코드에는 기준을 소급 삽입하지 않았다. 모델 예측에는 실제 과거 수신과 본문 완료 증거가 없으며 retrospective로 유지한다.

## 관측 ID 보완

새 레코드는 kind·source_fixture_id·source_url·body_sha256·received_at을 키 정렬과 공백 없는 UTF-8 JSON으로 직렬화한 SHA-256 전체를 `fixture:` 또는 `lineup:` 뒤에 붙인다. 같은 응답의 캐시 재생은 같은 ID이고, 같은 본문을 다른 시각에 다시 관측하면 새 ID다. 기존 레코드는 변경하지 않았다. `synthetic-observation-identity.json`은 외부 HTTP 요청 없이 만든 테스트 예시이며 실제 수집 증거가 아니다. 이는 관측 로그만 구분하며 source fact의 의미 변화나 worker 큐 갱신을 뜻하지 않는다.
