# KBO 회고 구원 등판 이력 기반 실험

기존 보존 이력에서 경기별 구원투수 ID를 재구성하고, 대상 경기 최소 4일 전까지의 등판만 이용해 새 후보를 학습·평가했다. 2026년 같은 경기·배당 443건에서 시장 기준은 252/433 적중(58.20%), 가상 1단위 ROI -10.58%였고, 구원 등판 집중도 후보는 248/433(57.27%), ROI -11.95%였다. 환불 10건은 적중률에서 제외하고 ROI에는 포함했다. **이번 후보는 적중률과 ROI를 개선하지 못했다.**

## 데이터와 누수 방지

기존 `kbo-actual-training-data-20261103`의 `paired-{train,test}-projected` 보존 입력은 각각 2025년 731경기·2026년 709경기의 경기별 홈/원정 및 직전 1~2일 구원 등판 게임·선수 ID·아웃 기록을 담는다. 그 이전에 보존된 원천에서 생성된 파생물로, 개별 과거 HTTP 수신·종료 시각은 인증되지 않았다. 이 파일들의 경기별 이전 이력을 모아 팀·경기 ID 기준 **2,463개** 고유 이력 키를 얻었고 충돌 키는 0개였다. `schedule_coverage_verified=false`이므로 전체 이력이 빠짐없이 수집됐다는 뜻은 아니다. 이전 공식 25일 캐시만 재생한 결과가 아니라 더 긴 기존 paired 이력을 사용했다.

대상 경기 D의 특징은 각 팀에서 D-18~D-4에 관측된 경기의 투수별 구원 등판 횟수 `n_i`로 계산한 `Σ n_i(n_i−1) / Σ n_i`의 원정-홈 차이다. 팀별 최근 구원투수의 반복 사용 정도를 나타내는 **이력 대리 지표**이며 실제 가용·피로, 부상이나 엔트리를 뜻하지 않는다. 팀별 5경기 이상 식별된 경우만 사용한다. 동일 경기의 팀·선수 기록이 대상일 이전에 충돌하는 것으로 알려졌다면 그 시점부터 해당 경기 키를 제외하고, 선수 ID 없거나 중복인 구원 기록도 제외한다. 이름만으로 ID를 만들지 않았다. 대상 경기 당일의 실제 선발·타순·출전·점수를 특징에 쓰지 않는다.

원래 사전 규약 `e98aa19a`에 더해, 최초 실험 후 점검에서 **이력 기록이 대상 경기보다 이른 날짜의 paired 입력에서 이미 확인된 경우만 사용**하도록 출처 경계를 강화했다. 이는 평가 성적에 따른 모델 선택이 아니라 미래 행에서만 등장하는 과거 경기 기록의 잠재 누출을 막기 위한 조치다. 이후 별도 검토에서 나중에 알려진 충돌이 과거 특징까지 바꾸지 않도록 동일 경기의 버전별 최초 관측일을 보존하고 대상일 이전에 확인된 버전만 비교하도록 수정했다. 실제 자료의 전체 충돌 키는 0개였고 수정 전후 개별 예측은 바이트 단위로 같았다. 이 검사는 날짜 순서를 보장하지만 해당 경기의 실제 종료·원문 수신 시각이나 중간 누락이 없음을 증명하지 않는다.

- 2025: 731개 대상 중 이력 부족 77, 특징 가능 654, 그중 가격·결과 미연결 51, 공통 603. 2025-04-02~06-28 326경기 학습, 07-04~10-14 277경기 검증 후 603경기로 계수를 다시 적합해 고정했다.
- 2026: 709개 대상 중 이력 부족 234, 특징 가능 475, 그중 가격·결과 미연결 32, 공통 443. 2026-04-07~10-10을 모두 평가했으며 결과 후 기간을 골라내지 않았다. 2026월별 공통 표본은 4월 70, 5월 128, 6월 122, 7월 90, 8월 20, 9월 12, 10월 1이다. 후반부 이력 누락과 작은 표본에 주의해야 한다.
- 전체 paired 입력부터 2025년 명단 확인 실패 5경기가 제외된 사후 선택 표본이다. 기존 2025 가격 교집합은 무승부가 모두 사후 제외되어 있어 결과 의존 선택 편향이 있다. 이는 승패 표본 전체 성능이 아니다.

후보는 정규화된 동일 양방향 시장확률을 offset으로 `logit(P_home) = logit(P_market_home) + βX`를 사용하며 계수 하나와 L2=0.1을 고정했다. 2025 전반 학습 β=-0.10393, 2025 전체 재적합 β=-0.08431이다. 기존 M0 비교는 같은 경기의 보존된 `M0_projected` 연구 예측이다. 예상 명단·선발은 이전 경기에서 투영된 연구 입력이지 대상 경기의 실제 최종 타순을 넣은 예측이 아니다. M0에는 이전 달력일 기준 이력이 들어가므로 본 후보의 4일 lag와 동일한 입력·시점은 아니다. 어느 쪽도 실제 운영 모델 재현이나 과거 사전 수신의 증명은 아니다.

## 같은 2026 경기·가격 비교

| 모델 | 선택 적중/결정 | 평균 배당 | 조건부 ROI | LL | Brier | 일 마감 MDD |
|---|---:|---:|---:|---:|---:|---:|
| 시장 | 252/433 (58.20%) | 1.541 | -10.58% | 0.67697 | 0.24196 | 51.14단위 |
| 기존 M0 projected 연구 예측 | 245/433 (56.58%) | 1.600 | -10.59% | 0.68618 | 0.24639 | 56.11단위 |
| 신규 구원 반복 사용 후보 | 248/433 (57.27%) | 1.546 | -11.95% | 0.67907 | 0.24296 | 57.24단위 |

세 모델은 동일 443경기·정확히 같은 경기별 가격 벡터와 승자·무승부 환불 규칙을 사용한다. 미정산 제외/공통 443건, 환불 10건이다. 공통 표본 내 coverage 100%와 전체 보존 경기 대비 443/709(62.48%)는 별도다. 배당 수신·거래 가능성은 미인증이라 위 ROI는 당시 구매 가능한 성과가 아닌 조건부 가상 1단위 참고치다. 가격·정산이 더 완전한 모집단에 일반화하지 않는다. H/UO는 평가하지 않았다.

후보는 시장 대비 26경기, 기존 M0 projected 대비 103경기의 선택이 달랐다. 날짜 블록 paired bootstrap 2,000회(고정 seed)의 후보−시장 95% 구간은 적중률 **-2.95~+0.97%p**, ROI **-4.84~+1.91%p**, 로그손실 **-0.00136~+0.00554**, Brier **-0.00070~+0.00266**이다. 모두 0을 포함한다. 기존 M0 대비 구간과 2025 검증 및 2026 월별 성적은 `summary.json`, 개별 결과는 `predictions.jsonl.gz`에 있다. 2026 결과는 이전 연구에서도 열람돼 독립 블라인드 검증이 아니다.

## 공개 수집 경로와 이용조건

이전 #662의 MyKBO 선수 HTML을 다시 살펴보니 연도 선택은 `form phx-change="change_year"`이며 `select`의 `name=year`다. 단순 `?year=2025` GET은 서버 렌더 결과를 바꾸지 않았다. 자동 접근은 사이트 약관에 허용되지만, [MyKBO 약관](https://mykbostats.com/tos) 제8항 해당 조항은 스포츠 베팅을 돕는 용도로 서비스 내용을 사용하는 것을 금지한다. 이번 작업은 배당과 ROI 평가를 포함하므로 해당 사이트를 모델 입력으로 사용하지 않고 추가 수집을 중단했다. 약관 확인 전에 일정 페이지 1건을 탐색했으나 실험에는 쓰지 않았다. 이 제한은 이전 PR #662에서 robots만 확인하고 이용조건을 충분히 짚지 못한 부분을 보완한다.

KBO 공식 `robots.txt`는 사전 승인 없는 자동 수집과 전체 경로 접근을 제한한다. 별도 탐색한 야구나라 선수 페이지는 HTTP 403이어서 우회하지 않았다. 스토브리그는 [이용약관](https://stoveleague.net/support/terms)에서 자동화 수단을 이용한 대량 수집을 금지한다. 현재 요청의 베팅 성능 평가에 이용 가능한 새로운 장기간 자동 수집 권한을 확인하지 못해, 요청량·재개형 대량 HTTP 수집기와 모의 HTTP 테스트는 만들지 않았다. 실제 신규 HTTP 수집 영수증도 모델 데이터로 남기지 않았다. 이는 수집 부분이 미완료라는 뜻이며, 기존 보존 자료를 이용한 위 회고 모델 계산과 분리한다. 다음 단계는 해당 용도를 허용하는 제공자나 명시적 이용 허가를 확보하고, 원문·HTTP 영수증·라이선스·경기별 시각을 보존해 결측을 줄이는 것이다.

## 재현과 한계

`python -X utf8 experiments/kbo-history-20261108e/run.py`는 기존 로컬 연구 아티팩트를 읽어 모델·예측·요약을 다시 만든다. BLAS/OMP 스레드 1개로 실행했다. 입력 SHA-256은 `summary.json`에 있고, 원본 대량 파일과 개인 자료는 커밋하지 않았다. `python -X utf8 -m unittest discover -s tests -p test_kbo_history_20261108e.py -v`의 5개 테스트에서 같은 날/미래 기록 거부, 대상일 기준 충돌 처리와 미래 충돌 불변성, 4일 lag·미래 witness 차단, 무승부 환불을 검사했다. 운영 DB·원장·지갑·스케줄·배포는 변경하지 않았다.
