## 후속: 시즌 목록과 명단 재개 수집 (2026-11-04)

`--season-collect`는 2025·2026 K리그1/2의 월별 공식 일정 48페이지를 페이지 단위 캐시로 확보한다. 기존 46페이지는 이전 작업의 원문 해시와 실제 수신 시각을 검증해 그대로 가져왔고, 2025 K1의 1월·12월 두 페이지는 새로 받았다. 페이지 원문과 메타데이터는 Git 밖 evidence/season에 있다. 1,003 일정과 그중 종료 955경기 결과를 내보냈다. 리그·시즌별 일정/종료는 2025 K1 228/228, K2 275/275, 2026 K1 228/204, K2 272/248이다. 기존 919 배당과 조인하지 않았으므로 두 파일은 source_fixture_id를 기준으로 메인에서 대조해야 한다.

시즌별·리그별로 순환 선택해 각 한 경기의 공식 페이지에서 팀 ID와 날짜, 양팀 각각 11명의 고유 선수 ID를 확인했다. 완결된 기록은 2025 K1/K2 각 1, 2026 K1/K2 각 1이다. 모두 현재 받은 경기 후 원문으로 `retrospective`; 나머지 종료 경기 951건은 이 출력에서 명단 미확보다. 다른 기존 아카이브에 이미 있는 명단도 이 컬렉터로 아직 가져오지는 않았다. 페이지가 비거나 부분 명단이면 `not_displayed_on_official_page` 또는 `partial_or_unparseable`로 구분하며, 공개되지 않았다고 단정하지 않는다.

2026 K1 경기 205의 사전 공식 페이지에는 선발명단이 표시되지 않았고, 공식 matchInfo API 응답의 data에는 lineup 필드가 없었다. 이는 해당 응답과 시점에 한정된 관측이다. 다른 공식 채널의 미공개 여부, 이후 변경 여부, 확정명단의 공표 시각은 증명하지 않는다. HTML 수신은 실제 시각만 기록하며 선발 확정이나 역사적 사전 수신을 인증하지 않는다.

이 후속 작업의 새 HTTP는 총 16회(일정 API 2회, 과거 경기 페이지 7회, 미종료 경기 페이지 3회, matchInfo API 4회)이며 순차 실행했다. 이 중 경기정보 API 1회는 응답 구조를 확인한 탐색 호출이어서 원문을 저장하지 못했고, 이후 별도 재요청한 응답 3회는 원문과 실제 수신 시각을 보존했다. 재시도 0, 개별 실행당 최대 60회, timeout 10/15초, 응답 3MB 상한, 오류 즉시 중단이다. 사전 수신 입증된 과거 명단은 0건이다.

고정 스크립트와 명시 인자로 실행:

```
python -X utf8 scripts/collect_soccer_comparison_sources.py --season-collect --evidence C:/Users/user/Documents/Codex/pregame-soccer-evidence/season --output experiments/pregame-soccer-20261104/season-records.jsonl --years 2025 2026 --leagues 1 2 --max-requests 60 --max-lineups 4 --probe-unfinished --forecast-fixture kleague:2026:1:205 --refresh --capture-id 20261104-first
```

`--max-lineups`는 4개 고정이 아니라 전체 종료 경기 중 누적 처리할 페이지 수다. 예를 들어 60까지 늘리면 이미 받은 페이지는 재사용하고 나머지는 요청 예산 안에서 수집한다. 예산이 소진되면 중단하며 다음 실행에서 캐시로 재개한다. 명단이 48페이지의 누락분과 함께 60회 예산에 다 들어가지 않으면 예산을 넘기지 않고 중단하므로 다시 실행해야 한다. 기본 일정 캐시는 변경되지 않으며, 아래 후속 정정처럼 `--refresh`는 대상 월의 별도 버전을 추가한다. `--refresh --capture-id <새 ID>`는 해당 ID의 경기 페이지·API 원문과 관측 레코드를 새 파일로 남기고 이전 관측을 수정하지 않는다. 같은 ID 재실행은 해시를 확인해 재개하며 내용 충돌은 중단한다. 임의의 미종료 경기 ID는 `--forecast-fixture`로 고른다. 기존 출처의 게시 주장이나 수신 시각을 새로 만들지 않는다.

## 수신 시각 기준 (후속)

새 HTTP 요청은 응답 본문을 모두 읽은 직후의 UTC `received_at`과 `timestamp_basis: "http_response_body_completed"`를 원문 메타데이터와 교환 레코드에 남긴다. 본문 크기 초과나 요청 실패는 완료 관측으로 저장하지 않는다. 기존 캐시와 919개 기존 배당은 시각 기준을 소급 추정하지 않고 레코드에 `timestamp_basis: null`을 둔다. 기존 캐시 메타데이터와 수신 시각은 변경하지 않는다. 개별 원문에 포함된 게시 주장 시각도 수신 시각으로 바꾸지 않는다.

별도 ID `20261104-completion-clock`으로 미종료 경기의 HTML과 matchInfo API를 각각 새로 수집해 두 응답 모두 본문 완료 시각 기준을 기록했다(추가 HTTP 2회). 기존 관측 `20261104-first`의 수신 시각과 원문을 유지했다. 새 관측은 당시 페이지에서 명단이 표시되지 않았다는 증거이며, 확정명단이나 과거 사전 수신의 증명은 아니다. 공식 일정 결과 및 과거 경기 라인업은 여전히 경기 후 `retrospective`다.

메인 비교 게이트는 `actual_receipt`, 검증된 본문, 알려진 `http_response_body_completed` 기준을 모두 요구해야 한다. 배치 시작 시각만 있는 모델·배당 출처는 엄격히 제외한다. 이 축구 컬렉터는 해당 게이트 자체를 구현하거나 조건을 충족하는 모델·배당 출력을 주장하지 않는다.


## 일정 갱신과 관측 식별자 정정

`--refresh`는 한국 시각 기준 현재 월 이후의 선택 연도·리그 일정 페이지와 명시한 미종료 경기의 기존 월이 과거인 경우 그 월도 `capture-id`별 원문으로 새로 받는다. 과거 완료 월은 기존 캐시를 사용한다. 이전 원문은 변경하지 않으며 페이지마다 공통 요청 예산을 차감한다. 예산 소진 시 중단하고 같은 ID로 재실행하면 이미 받은 버전은 해시 검증 후 재사용한다. 같은 ID로 달이 바뀌어 재개하더라도 기존 버전이 있는 월은 그 버전을 유지한다. 명시된 경기가 새 일정에서 종료되었다면 결과를 내보내고 미종료 명단 조회는 하지 않는다. 새 일정들에 해당 경기가 없거나 동일 ID의 월별 정보가 충돌하면 추측하지 않고 중단한다.

일정·결과·명단의 신규 출력 `record_id`는 종류, 원천 경기 ID, 수신 시각과 본문 SHA-256으로 산출하므로 같은 경기의 새 관측은 이전 ID와 충돌하지 않는다. 이전에 생성한 교환 파일과 증거는 재작성하지 않았다. 메인 통합은 `payload.source_fixture_id`로 경기와 관측 버전을 구분해야 한다.

이번 정정은 fake HTTP만으로 검증했다. 과거 미종료 경기의 월 이동과 시간 변경, 예산 소진 후 재개, 0회 예산 캐시 재실행, 기존 원문 보존, 다음 캡처의 종료 결과·ID 변경을 테스트했다. 실제 HTTP 추가 요청은 0회다.
