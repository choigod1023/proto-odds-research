# KBO 득점 분포 모델 및 평가기: 학습 전 고정 계획

총괄 사전 계획 `867afbdd`와 `contract.json`을 따른다. 실제 자료·라벨을 읽거나 훈련하기 전 이 파일을 커밋한다. 이전 e0 잔차 또는 시장 혼합이 아닌 독립 홈·원정 득점 강도의 정규화된 포아송 회귀다. 2026년은 기존 연구에서 본 기간으로 맹검이 아니다. 선수 데이터 워커가 완료하기 전에는 합성 데이터만 사용한다.

## 구조와 고정 설정

양 팀 득점은 조건부 독립 Poisson으로 가정한다. 홈·원정 각 행의 log 강도는 공통 절편 + 홈 지시자 + 공격팀/수비팀 전력 + 대응되는 사전 특징의 선형 결합이다. 동일 분포·최적화·규제의 팀 전용 대조와 선수 추가 후보를 독립 적합한다. 선수 기여는 선발투수·타순·불펜 결측 여부까지 포함하며, 선발/타순 추가 및 불펜 추가를 개별 구분하는 고정 ablation을 제공한다. 각 모형의 수치 특징은 훈련 행의 관측값 평균으로 결측 대체하고 표준편차로 나눈 뒤 결측 표시 열을 추가한다. 훈련에서 완전 결측 열은 평균 0/척도 1/결측 표시 1이며, 실측 0과 구별한다. 처음 본 팀은 모든 팀 지시자가 0이며 별도 미관측 팀 표시를 남긴다. 절편을 제외한 계수의 L2 패널티 {1,10,100}만 2025년 검증 득점 로그손실로 선택하고 동률은 더 큰 규제를 택한다. 후보의 최소 1개 선수 특징 관측이 없으면 선수 효과를 주장하지 않는다.

학습은 2024-12-31까지, 검증은 2025년, 진단은 2026년으로 고정한다. 각 행은 kickoff보다 최소 30분 전 decision이고 훈련 라벨의 실제 완료·수신이 평가 decision의 7일 이전이어야 한다. split은 특정 시즌 하나가 최소 100/30/30경기 미만이면 중단하며 시험 성적을 기준으로 변경하지 않는다. 2025 선택 후 2024~2025 라벨을 이용해 최종 학습하고, 2026 타깃 라벨을 읽기 전 예측 JSONL을 별도 저장한다. 외부 결과 가용성에 대한 소급 가정은 `retrospective_unproven`으로만 분리한다. 평가기 인터페이스는 특징과 라벨을 각각 받으며, 예측 함수는 라벨을 받지 않는다.

득점 분포는 양 꼬리 합 ≤1e-10이 될 때까지 상한을 확장해 계산하고, 그리드의 홈승·무·원정승을 정규화한다. 무승부 환불 2-way는 홈/원정 조건부 확률을 제공하되 무승부 확률과 무효 결과를 별도로 보존한다. 3-way는 무승부를 독립 선택지로 둔다. 모든 시장 비교는 동일 fixture, 상품, 가격 및 사전 시각 근거가 있는 경우에만 수행하며 미확인 가격과 시장이 없으면 ROI를 계산하지 않는다. 동일 금액 Decimal 단폴이며 실제 지갑이나 월 제한을 변경하지 않는다.

검증 진단으로 2025 및 2026의 점수 잔차 분산/평균과 홈·원정 잔차 상관을 보고한다. 독립 포아송이 이 현상을 설명한다는 보장이나 미래 수익 주장은 하지 않는다. 월별 손익·일 마감 최대낙폭·기회/가격/정산/무효/미정산 분모를 보고한다. 독립 관측 주 block bootstrap 5000회 seed 20261103을 사용하되 주 수가 2 미만이면 구간을 생략한다.

## 고정 특징과 입력

값은 계약의 `{value, available_at, availability_basis, source_id}` 및 아래 출처 시점 필드를 사용한다. 숫자 범위 외 명시적 정보만 사용한다. 팀 공통 입력: `home_team_strength`, `away_team_strength`, `home_rest_days`, `away_rest_days`, `park_factor`. 선수 추가: `home_lineup_strength`, `away_lineup_strength`, `home_starter_strength`, `away_starter_strength`, `home_bullpen_load`, `away_bullpen_load`. 공격팀 득점에는 해당 팀 공격/타순, 상대 팀 전력/선발/불펜, 양 팀 휴식 및 구장 정보를 넣으며 양 팀 대칭으로 뒤집는다. 선수 특징이 어떤 측도 사용 불가하면 누락값 및 mask로만 처리한다.

팀 전력·휴식·선수 통계 등 과거 경기 기반 특징에는 `history_max_completed_at` 및 `history_fixture_ids`를 요구한다. 소스 최대 완료시각이 decision보다 과거여야 하고 타깃 ID 포함을 금지한다. 검증 시점 층에서는 feature.available_at과 대응 source.received_at이 모두 decision 이하이며 유효해야 한다. 회고 층의 가용 시각이 미확인일 수 있으나 이를 추정해 채우지 않는다. 당일 이전 경기의 완료시각이 없으면 과거 유래 특징을 차단한다. 타깃 경기 라벨과 선수 성적은 특징에 넣지 않는다. 라벨은 별도 fixture_id keyed 파일로 점수·최종 상태·완료/수신 시각·revision을 기록한다.

## 검증과 인계

합성 데이터로 시점 누출·동일날 완료 누락·타깃 ID·중복·feature/label 분리와 테스트 라벨 변조 불변성을 확인한다. 홈/원정/무승부 합 1, 2-way 조건부 확률과 환불, 포아송 꼬리 한계·결측 마스크·split 경계·정산 Decimal 정합성을 검사한다. 데이터 부재 시 `ready_for_data`, 실험 점수 없음으로 종료한다. 입력 결측과 범위가 이 계약과 맞지 않으면 변환 기준을 결과 이전에 고정하고 다시 커밋한다. 새 패키지나 운영 코드·기존 원장을 수정하지 않는다.

데이터 워커의 실제 입력 또는 타깃 결과를 읽기 전 확장: 선발투수만, 타순만, 불펜만의 단독 추가 모델을 함께 고정한다. 전체 비교 모드는 `team`, `starter`, `lineup`, `bullpen`, `starter_lineup`, `player` 여섯 개이며 각 모드의 L2 설정은 기존 {1,10,100} 그대로다. 합성 자료를 이용한 소프트웨어 검사만 이미 수행했으며 실제 경기 데이터 학습·선정은 수행하지 않았다.

실제 수신시각이 기록되지 않은 과거 라벨의 처리: `retrospective_unproven` 층에서만 `received_at=null`과 `availability_basis=retrospective_completion_assumption`을 명시하고 실제 경기 완료시각을 7일 경계의 대리 시점으로 사용한다. 완료시각도 없는 자료는 대체하지 않는다. `point_in_time_verified`에는 실제 수신시각이 필수다. 해당 가정은 과거 수신 증거가 아니며 실험 데이터를 아직 읽지 않았다.
