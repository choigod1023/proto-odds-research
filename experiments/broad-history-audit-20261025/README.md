# 과거 데이터 범위 확대와 고정 75:25의 불안정성 점검

2026-10-25 로컬 실행. 최종 인벤토리는 `validated/results.json`이다.
`results.json`은 종목 식별자 이상 2행을 별도 분리하기 전의 첫 실행 기록이다.

## 실제 조사 범위

로컬 `data/raw/snapshots/odds_timeseries_*.csv` 41개 파일의 2,881,889행을 모두 읽었다.
야구 1,693,510행, 축구 1,122,648행, 농구 42,149행, 배구 23,580행이고
나머지 2행은 인식할 수 없는 종목 식별자라 시장 집계에서 제외했다.
반복 시점의 배당과 경기 내 여러 시장을 포함하므로 이 수치를 경기 수로 부르지 않는다.
원본 데이터는 변경하지 않았다.

모든 Git ref에서 경로별 변경 기록을 조회했다. 픽스터 원본은 279개 변경,
사전 모델 원장은 31개 변경, 웹 생성본은 709개 변경이다. 이는 Git 이력 메타데이터
조회이며 이번에 709개 생성본 내용을 전부 복구했다는 의미가 아니다.
직전 PR356에서는 해당 픽스터 관측 기간의 생성본 306개를 읽어 28경기를 연결했다.
Git 마지막 커밋 날짜가 더 늦어도 내부 관측 데이터가 그 날짜까지 이어진다는 의미는 아니다.

[Betshoot 원본 JSON](https://www.betshoot.com/archives/tipsters.php?export=json)을
Python과 curl로 다운로드하려 했으나 연결 재설정으로 실패했다. 웹 검색/읽기로 공개
아카이브 형식과 [추적 정책](https://www.betshoot.com/results-tracking-policy/)은 확인했지만,
그 아카이브의 전체 행을 계산하거나 새 하이브리드 표본으로 넣지 못했다.
출력의 external=null은 확보 실패이며 0% 수익이라는 뜻이 아니다.

[Football-Data](https://www.football-data.co.uk/data.php)는 장기간 경기 결과와 배당을
제공하지만 자동 수집/AI 학습 용도 제한을 명시하고 있어 대량 다운로드하지 않았다.
또한 경기 결과·배당만으로 당시 우리 모델과 픽스터가 무슨 확률을 냈는지 복원할 수 없다.

## +7.39%가 유지되는가?

75:25 비율을 고정했고 후보를 다시 고르지 않았다. 기존 개발 표본 28경기에서만
민감도를 계산했으며 새 독립 표본 검증으로 표현하지 않는다.

- 전체 28경기: ROI +7.39%.
- 8월 30일 7경기: -37.57%.
- 8월 31일 6경기: +4.50%.
- 9월 1일 8경기: +14.00%.
- 9월 3일 6경기: +44.33%.
- 9월 4일 1경기: +65.00%.
- 9월 3일을 제외한 22경기: **-2.68%**.

날짜 단위로 묶어 20,000회 재표집한 기술적 95% 범위는 -20.4%~+35.6%였다.
단 5개 날짜이며 같은 표본에서 후보를 고른 편향을 보정하지 않았다. 따라서 이 범위를
통계적으로 신뢰할 미래 기대수익률 구간으로 해석하면 안 된다. 날짜 하나의 포함 여부에
수익 부호가 바뀌는 현상만으로도 안정 수익 주장은 할 수 없다.

## 결론과 미완료 범위

배당 관측 데이터는 많지만, 시점이 맞는 모델 확률·픽스터 의견·정산 결과의 공통
자료가 부족하다. 이번 조사로 추가한 독립 하이브리드 평가 표본은 0개다.
전체 과거 경기에서 +7.39%가 재현된다고 확인하지 못했다. 그렇다고 전체 기간의 실제
수익률이 반드시 음수라고 확정하는 것도 아니다.

월 손실 5만원 정책, 75:25 비율, 운영 모델은 변경하지 않았다.
이번 계산은 단폴 개발 표본의 민감도이며 2폴 월간 손익 재검증이 아니다.
웹 전체나 모든 과거 경기를 수집한 것은 아니고, 외부 원본 다운로드와 독립 평가를
완료하지 못한 한계를 남긴다. 대량 경기 결과만 다른 모델로 재예측해 이를 기존 모델의
당시 실적으로 둔갑시키지 않았다.

## 재현

```powershell
python -X utf8 scripts/audit_broad_history.py --paired <PR356-results-primary.json> --output-dir <new-output-directory>
python -X utf8 -m pytest -q
```

외부 수집 성공 시 원본은 `.local-test`에만 보관하고 원본 SHA256을 결과에 남긴다.
외부 원본 전체를 Git으로 재배포하지 않는다. 실패 시에도 로컬 범위와 개발 표본의
불안정성 점검을 실행한다. 전체 테스트 1,343개와 하위 테스트 67개 통과, 2개 건너뜀.
