# J1 공식 경기 명단·배당 원문 감사 (2026-11-03)

상태: `partial_complete_retrospective`. 대상은 실제 프로토 편성이 확인된 2025 J1 정규리그이며, 예선·컵·승강 플레이오프·진출 상품은 포함하지 않는다. [J리그 공식 경기 검색](https://www.jleague.jp/j1/match/search-list/?category=j1&startdate=2025-02-01&enddate=2025-02-28&period=custom)에서 월별 원문 11개로 380개 서로 다른 경기 URL ID를 확인했다. 미리 고정한 결과 독립 순위 규칙으로 100개를 균등 선택했고 2025-02-14~12-06에 분포한다. 나머지 280경기는 이번에 개별 명단을 요청하지 않았다. 이 표본은 프로토 대상 경기만을 전수 선정한 것이 아니다.

공식 `/match/j1/2025/{id}/lineup/` 100개 HTTP 200 원문에서 양 팀 선발 11명씩 2,200명 전원을 추출했다. 1,949명은 공식 선수 프로필 링크, 251명은 같은 공식 HTML의 직렬화 데이터에서 팀 ID·성명·포지션/등번호가 유일하게 일치하는 playerId로 확인했다. 양쪽 정보가 충돌하거나 여러 ID가 일치하면 실패시킨다. 교체 명단은 총 1,798명이며 1,570명은 선수 링크 ID가 있고 228명은 ID를 확인하지 못했다(91경기). 공식 경기 ID는 URL ID를 사용했고 공식 팀 ID는 club URL slug다. 정확한 원문과 현재 수신 시각은 `evidence/requests.jsonl`과 `evidence/*.gz`에 있다.

[예시: 2025-02-14 감바 오사카 대 세레소 오사카](https://www.jleague.jp/match/j1/2025/021401/lineup/)의 원문은 선발·벤치와 경기 후 교체/득점 표시가 함께 나타난다. HTML을 지금 수신한 시각은 2026-11-03 UTC이며 2025년 발표·수신 시각이 아니다. 따라서 사전 선발로 사용할 당시의 확정이나 T-30 수신은 독립 인증하지 못했다: strict PIT 0/100. 선발·벤치는 소급 원자료로만 기록한다. 화면의 포메이션도 사후 교체가 반영된 시점일 수 있어 사전 포메이션을 null로 둔다. 원문의 선수별 골·교체와 대상 경기 점수는 선발 입력에서 제외했다. 경기 종료 점수는 별도 `postgame-labels.jsonl.gz`에만 보존한다.

## 공식 가격 교집합

이전 K리그 가격 조사에서 보존한 베트맨 공식 2025 회차 71개 원문과 수신 원장을 읽기 전용으로 복사하고 해시를 확인했다. 대상 100경기 중 **83경기**는 J1 코드 SC007, 양 팀 ID·한글 이름과 J리그 club slug의 수동 대조, 같은 날짜, 두 원천 킥오프 차이 15분 이내, 정상 전체경기 승무패 3개 가격, 게임·구매 제한 코드 0, 결과 점수·결과코드 및 단일 상품 일치로 연결했다. 83건의 실제 최대 킥오프 차이는 5분이며 J리그 화면의 실제 시작과 베트맨 예정 시각 차이가 있다. 17경기는 확보된 회차 원문에서 모든 조건에 맞는 유일한 후보가 없었다. 원천 회차가 불완전할 수 있어 해당 17경기를 미발매·취소로 단정하지 않는다. 팀명 대조는 수동 crosswalk이므로 독립 검토가 필요하다. `price-joins.jsonl.gz`와 `price-exclusions.jsonl.gz`에 각 근거·제외를 남겼다.

가격의 과거 관측시각과 체결 가능성, 경기 전 확정 여부는 인증되지 않았다. 배당과 결과를 현재 추출한 것은 수익성·정확성 실험이 아니다. 원문 레코드에 일반 승무패 유형을 검사했으나 과거 판매 규칙 원문으로 독립적인 상품 정산 범위를 추가 확인해야 한다. 연장·승부차기 및 합산·진출 상품은 결합하지 않는다. score는 라벨이고 feature가 아니다.

## 수집 방식과 한계

2025-02~12 11개월 검색의 고유 URL ID를 정렬하고 `floor(i*(N-1)/99)`, i=0..99를 선택했다. [사전 프로토콜 커밋](https://github.com/choigod1023/proto-odds-research/commit/5b6448b) 이후 수집했지만 URL 접근성 및 3개 경기의 기존 화면은 사전 탐색했으므로 전체 과정이 블라인드였다는 뜻은 아니다. 과거 시즌의 검색 요청은 사이트 개편으로 2026 현행 페이지에 리디렉션될 수 있었다. 보관된 `evidence/census-02.html.gz`는 그 실패 사례이며 모집단에서 제외했다. 실제 성공한 새 `/j1/match/search-list/` 요청 11건과 명단 100건은 상태, URL, query, 현재 UTC 수신, SHA-256과 압축 원문으로 보존했다. 본 수집 111회는 한 호스트 순차·1.2초 이상·15초 제한이며 이전 탐색 요청은 원문을 전부 보존하지 않았다. UEFA 호스트에서 첫 시도가 403이어서 해당 호스트에 재시도하지 않았다.

공식 사이트의 로스터 HTML은 공식 발표 당시 문서 스냅샷이 아니며, 과거 사전 가용성·교체 전 포메이션·선수 상태·부상·결장은 확인하지 못했다. 380개 경기의 URL census와 100개 표본이 시즌 공식 일정 전체와 일치하는지 별도 원본 일정 대조는 아직 하지 않았다. 원문 바이트 해시는 저장 무결성 확인이지 독립 수신 인증이 아니다. 원본의 선수 명단에 사후 변경이 있었다면 이를 배제할 수 없다.

다음 후보 가설은 **이전 경기 공식 선발과 이번 공식 선발의 연속성**이 같은 시점 시장에 추가 정보를 주는지다. 선발 11명과 이전 경기 11명의 ID 교집합을 사용하되 이전 경기 결과·선수 기록은 대상 결정 전 실제 수신된 것만 허용한다. 이번 대상 경기 득점·교체·최종 결과는 입력에서 금지한다. 현재 자료만으로 가설을 적합하거나 ROI를 계산하지 않았고 모델 채택·운영 변경도 하지 않았다.

## 재현

- `python -X utf8 experiments/j1-official-lineups-20261103/collect.py`: 캐시 재사용 및 누락 대상만 재개. 403/429 기록 시 `collector.stop`을 남기고 자동 재개를 막는다. `collector.lock`은 중복 실행을 막으며 비정상 종료 시 소유 프로세스 종료를 확인한 뒤에만 수동 처리한다. 480건의 기록 요청 상한은 앞선 탐색 요청을 위한 여유를 둔다.
- `python -X utf8 experiments/j1-official-lineups-20261103/parse.py`와 `join.py`: 원문 해시를 검증하고 오프라인 파생물을 재생성한다. Python requests와 BeautifulSoup4가 필요하다.
- `python -X utf8 -m unittest discover -s experiments/j1-official-lineups-20261103 -p test_evidence.py -v`: 시즌 선택 규칙, 서로 다른 세 시기의 공식 원문·선발 구조, 프로필 없는 공식 ID, 83개 가격 원문과 부적격 마켓 배제를 검증한다. 이는 모델 성능 검증이 아니다.

`.gitattributes`는 이 디렉터리의 바이트 줄바꿈 변환을 끈다. `manifest.json`의 SHA는 압축 파일 자체 및 원문 파일을 포함한다. 운영 코드·DB·추천·월 손실 제한·일정·배포를 변경하지 않았다.

검증 결과: Python 테스트 5개 통과, J리그 원문 111건 SHA 일치, Git checkout `core.autocrlf=true`와 `false` 각각 manifest 파일 200개 SHA 일치, 캐시 재개 전후 요청 원장 111건으로 동일.
