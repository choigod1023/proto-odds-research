# 실제 운영 원장 비교와 앞으로의 동시 기록

## 이번에 확인한 것

현행 운영은 연구용 고정 9:1이 아니라 **2026-10-28부터 적용한 픽스터 최다 투표 선택**이다. 확률은 그 선택의 시장 기준 확률이며, 투표 지지율을 적중확률로 쓰지 않는다. 과거 연구의 수익률을 현행 서비스 수익률로 부르면 안 된다.

2026-10-29 12:47:48 UTC에 운영 SQLite 원장 8,674건을 읽기 전용으로 확보했다. 예측 7,454건과 정산 1,220건이며 전체 해시 연결을 검증했다. 기존에 확보한 6,999건 뒤에 새 1,675건을 이어 붙였다. 로컬 파일 경계의 마지막 개행 누락은 보완했으며 운영 원장을 변경한 것은 아니다. 공식 결과는 13:05:56 UTC에 별도 읽기 전용으로 확보한 `match_results`의 proto 원천 2026년 120회차 이후 2,051행이다. 미확정·취소·교정 이력도 포함했다.

현행 투표 정책의 최신 T-30 이전 기록은 56경기다. 한 MLB 경기에는 `as_of` 이후 수집한 실제 선수 통계가 함께 저장돼 있어 이번의 엄격한 입력 비교에서 제외했다. 나머지 **55경기 중 운영 선택 9경기, 보류 46경기**다. 공식 결과를 정확히 연결한 것은 45경기이며, 이 중 운영 선택은 4경기다. 10경기는 결과 연결 전이다. 이 숫자는 전체 원장의 8,674건이나 모든 서비스 경기 수와 다르다.

## 같은 4경기에 대한 결과

경기당 단폴 1만 원, 당시 저장 배당, 연구 계산에 월 손실 제한을 적용하지 않은 가정이다. 실매수 수익이나 실제 모의 지갑 수익이 아니다. 실제 모의 지갑의 월 순손실 5만 원 제한은 유지한다.

- 현행 운영 투표: 1승 3패, 적중률 25%, 순손익 **−27,800원**, ROI **−69.50%**.
- 시장 기준: 2승 2패, 적중률 50%, 순손익 **−13,100원**, ROI **−32.75%**.
- 같은 시점에 저장된 투표를 사용하는 9:1 비교안: 2승 2패, 적중률 50%, 순손익 **−13,100원**, ROI **−32.75%**.

이 9:1은 현재 기록에 있는 동일 투표 집합으로 `0.9 × 시장 확률 + 0.1 × 투표 비율`을 계산한 비교안이다. 과거 배포된 9:1 모델의 전체 수집 상태를 복원한 것은 아니다. 동률은 저장된 `selection_id` 오름차순으로 결정한다. 비교안의 혼합 점수는 보정된 적중확률로 검증되지 않았다.

공통 4경기는 모두 KST 2026-10-29 경기다.

- 02:30 세리에A 파르마–우디네세: 운영 원정 2.42, 공식 0–0, 실패. 시장·9:1도 같은 방향.
- 08:30 MLS 샬럿FC–CF몽레알: 운영 무승부 4.15, 공식 4–0, 실패. 시장·9:1은 홈 1.47로 적중.
- 19:00 ACL2 강원FC–쿠칭시티: 운영 홈 1.22, 공식 1–0, 적중. 시장·9:1도 같은 방향.
- 19:00 KBL 울산모비–부산KCC: 운영 원정 1.36, 공식 96–89, 실패. 시장·9:1도 같은 방향.

차이는 MLS **단 한 경기**에서 발생했다. 손실 14,700원이 줄었지만 하루 4경기로 리그별 우열·월 손실 안정성·미래 ROI를 판정할 수 없다. 결과가 더 좋았다는 이유로 이 4경기에 다시 비중을 맞추지 않았다.

## 보류를 포함하면

같은 정책의 결과 연결 45경기를 모두 시장 기준으로 선택하면 24승 21패, 순손익 −89,700원, ROI −19.93%다. 운영은 그중 4경기만 선택했다. **45경기 시장 수익률과 4경기 운영 수익률을 직접 순위로 비교하지 않는다.** 전체 기회에서 선택률·보류 수를 보여주고, 공통으로 선택한 4경기를 따로 비교했다.

현재 입력에는 유효한 전체 승패 스코어 모델 확률 벡터가 없어 `saved_score_reference`는 비교 불가다. 홈을 무조건 고르는 통제군도 함께 남겼다. 기존 MLB·KBO 연구 학습 모델은 인과적 운영 입력과 실행 엔진이 아직 연결되지 않았으므로, 이 통제군을 그 모델의 성능이라고 소개하지 않는다. KBO는 현행 선택의 정산 표본이 없고, MLB는 위 입력 시각 문제로 적격 표본이 없다.

이전 `market90-tipster10-v2`가 실제 적용된 최신 적격 15경기는 12승 3패, +14,400원, ROI +9.60%다. 10월 26~28일의 다른 경기이므로 오늘 투표 4경기와 모델 교체 근거로 비교하지 않는다. `feature_policy_version=market90-tipster10-v2`가 찍힌 기록 중 시장 대체 선택도 있으므로 실제 `operating_version`을 별도로 집계했다.

## 왜 기존 모의 비교만으로 답할 수 없었나

운영 API에서 읽은 예전 `per_event_shadow`는 9월 25일 시작해 10월 23일 종료됐고 `closed_settling` 상태였다. 대조군 858건 중 정산 770건, 도전자 선택 **0건**, 공통 정산 **0건**이었다. 대조군 과거 ROI −7.54%는 현행 투표와 새 학습 모델의 비교 결과가 아니다. 종료된 실험을 다시 열거나 과거 기록에 새 후보를 소급 삽입하지 않는다.

GitHub 모의 지갑의 새 `tipster-vote-single-v1` 계정은 확보 시점에 거래 0건이었다. 과거 계정의 두 경기 조합·주간 횟수별 거래를 현재 단폴 모델 수익으로 합산하지 않는다. 월 예산이 완전히 소진된 것으로 단정할 근거도 없었다. 저장된 예산상 잔여 손실 예산은 15,000원이었다. 명목 30분 GitHub 스케줄과 실제 실행 간격도 같다고 보장할 수 없다.

## 비교 방법과 제한

1. 경기 ID마다 `(as_of, captured_at, ledger_sequence)`로 T-30보다 이른 최신 revision을 먼저 선택한다. 결과·선택·가격이 마음에 들지 않는다고 이전 revision으로 되돌리지 않는다. 최신 보류도 유지한다.
2. 저장된 종목·리그·홈/원정·시작 시각으로 실제 경기 중복을 검사한다. 동일 실제 경기를 서로 다른 ID로 중복 계산하지 않는다. 경기 식별자가 없으면 중복 경기라고 추정하지 않고 식별 불가로 제외한다.
3. 같은 전체 승패/승무패의 완전한 배당 묶음만 사용한다. 핸디캡·합계의 운영 선택을 전체 승패 통제군과 비교하지 않는다. 현재 배당으로 과거 가격을 메우지 않는다.
4. 모든 비교 선택을 동결한 뒤 공식 결과를 연결한다. `match_results.kickoff`는 이 저장소의 명시적 KST 스키마로 읽는다. 원천 키별 최신 교정을 먼저 해결하며, 뒤에 나온 미확정 기록이 과거 확정 결과를 무효화하면 정산하지 않는다. 결과가 충돌하거나 공식 관측 시각이 경기 전이면 연결하지 않는다.
5. 결과가 없는 선택은 손실로 처리하지 않는다. 승패 시장의 무승부는 환급이며 ROI 분모에 해당 베팅 금액을 포함한다. 확률이 없더라도 선택과 가격을 증명할 수 있으면 ROI만 계산하고 확률은 만들어내지 않는다.
6. 낙폭은 **공식 결과 관측 배치가 닫힐 때** 누적 손익으로 계산한다. 같은 배치 안의 정산 순서를 알 수 없어 실제 장중 최대 낙폭으로 부르지 않는다. 하루·한 달의 독립 표본이 부족하면 수익 안정성을 입증하지 않는다.
7. 원장 해시는 기록 무결성을 확인한다. 외부 공식 원천의 진실성이나 그 가격으로 실제 구매 가능했음을 독립적으로 증명하지는 않는다.

이번에 새 비중을 학습하거나 결과를 본 뒤 모델을 채택하지 않았다. 판단 기준은 흑자나 적중률 동시 상승을 의무화하는 대신, **동일 기간의 손실 감소·낙폭·기간별 일관성·선택률**을 함께 보는 것이다. 현재 표본으로 교체를 정당화할 수는 없다.

## 앞으로 남기는 기록과 배포 상태

새 예측 원장에 `features.model_comparison`을 붙이도록 구현했다. 운영 선택, 시장 기준, 저장된 현재 투표의 9:1, 저장된 스코어 확률, 홈 고정 통제군을 같은 가격 묶음에서 기록한다. 레시피와 구현·가격·입력 해시를 남기며 payload는 경기당 8KB로 제한한다. 학습·네트워크 요청·별도 과거 원장 조회는 하지 않는다. 기존 저장 경로와 작업 주기를 사용한다.

운영 선택·확률·동결 ID·과거 기록·월 손실 제한은 변경하지 않는다. 이 부가 기록만으로 새로운 예측 revision을 만들지 않으며, 종료된 예전 shadow 실험을 재사용하지 않는다. 미래에 저장된 비교안은 레시피가 바뀌면 조용히 재계산하지 않고 계약 불일치로 차단한다.

**이 문서는 로컬 구현과 실제 과거 비교 결과다. 병합·배포 전이므로 새 비교 기록이 운영에서 쌓이고 있다고 주장하지 않는다.** 모델을 자동 교체하거나 학습 모델이 연결됐다고 주장하지도 않는다.

## 실행 산출물과 재현

- 결과: `experiments/operating-ledger-comparison-20261029/comparison.json` — 경기별 선택·가격·결과와 정책별/리그별 손익.
- 무결성·분포: 같은 폴더의 `production-ledger-readiness.json`.
- 공식 입력: `official-results.json.gz`, 출처·수집 시각·원문 SHA는 `official-results-metadata.json`.
- 운영 화면 원문 메타데이터: `live-recommendations-metadata.json`.
- 전체 운영 원장은 로컬 `.local-test/production-ledger-20261029.jsonl.gz`에 보관한다. 외부 원문·선수 입력 전체를 불필요하게 공개 저장소에 올리지 않는다. 비교 CLI는 전체 원장 해시 검증 실패 시 중단한다.

```powershell
python -X utf8 scripts/compare_operating_ledger.py --ledger .local-test/production-ledger-20261029.jsonl.gz --official-results experiments/operating-ledger-comparison-20261029/official-results.json.gz --evaluated-at 2026-10-29T13:05:56.181198Z --output .local-test/reproduced-comparison.json
```

원천: [운영 추천 API](https://proto-odds-collector.fly.dev/api/today-recommendations), 운영 SQLite `prediction_records`/`match_results`, [모의 원장 브랜치](https://github.com/choigod1023/proto-odds-research/tree/codex/paper-state-v1). 원장은 해당 시점 export이며 위 링크의 현재 값과 달라질 수 있다.

최종 로컬 검증: `OPERATING_LEDGER_TEST_EXPORT`에 위 읽기 전용 export 경로를 지정한 전체 `python -X utf8 -m pytest -q` 결과 **1,690 passed, 5 skipped, 93 subtests passed**. 보류 최신 revision, 사후 입력 차단, 결과 교정·미확정·중복 연결, 결과를 바꿔도 픽 불변, 미래 저장 비교안 변조 차단, 운영 픽·확률·원장 해시 보존과 Windows/Linux 줄바꿈 차이를 검증했다. UI나 실제 배포 확인을 수행한 결과는 아니다.
