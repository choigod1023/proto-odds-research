# K리그1 2025 공식 선발·교체 이력 확장

2025년 K리그1 공식 종료 경기 228경기 **전체**에서 양 팀 선발과 공식 결과를 연결했다. 각 경기 선발 22명, 총 5,016명이며 대기 4,097명, 포메이션 456개, 교체 이벤트 2,159건이다. 공식 일정의 경기 ID·날짜·홈원정 팀 ID·최종 점수가 페이지 및 경기 결과 응답과 일치한 건수는 228건, 미처리·실패는 각각 0건이다.

`fixtures.jsonl`은 선발·대기의 공식 선수 ID, 이름, 등번호, 포지션, 팀 ID, 포메이션과 공식 경기 결과를 보존한다. 별도 `timeline.jsonl`은 공식 응답의 전·후반과 연장전 이벤트 배열을 **원천 필드 그대로** 보존한다. 공식 이벤트 11,768건 중 `eventName=득점`으로 표기된 이벤트가 561건이고, 각 이벤트의 분·초·선수 ID 등도 응답 그대로 남겼다. 이는 해당 경기 후 자료이며 선수의 목표 경기 성적을 사전 예측 특징으로 만들거나 사용한 것이 아니다.

2025년 2~11월 공식 일정의 고유 종료 경기 228건을 미리 날짜 순으로 고정했다. 2026-11-01 수신한 기존 공식 일정 원문 10개와 로그는 이전 PR #484의 고정 커밋 `566301644c5d427e2e8a6b6492e2bdd69f119279`에서 바이트·SHA를 검증해 복사했다. 2025년 파일럿 1경기는 PR #516에 이미 보존된 원문과 실제 수신 시각을 그대로 재사용했고, 나머지 227경기는 각 GET·조회 전용 POST 1회씩 새로 수신했다. 시즌 내 총 456개 응답은 모두 HTTP 200이며 마지막 새 응답의 실제 수신은 2026-11-03 11:30:31 KST다. 각 요청의 정확한 시작·완료 시각, 매개변수, 상태, 원문 SHA 및 바이트 크기는 `requests.json`과 스냅샷의 요청 로그에 남겼다.

명단은 공식 경기 페이지에서 확인한 **사후 실제 선발 기록**이다. 당시 최초 공지 시각과 실제 사전 수신이 증명된 경기는 0/228이며, 이는 당시 공지가 없었다는 뜻은 아니다. 추후 회고 가정 계층을 명시해 사용할 수 있지만 현재 수신을 과거 시각으로 소급하지 않는다. 선발 공지 이후 변경 여부, 사전 선수 이력과 당일 실행 가능 가격은 이번 단계에서 확인하지 않았다. 별도 가격 연결 워커의 파일은 수정하지 않았다.

## 보존·재개·검증

2025년은 독립된 `season-2025/` 아래에 저장했다. 2026년 기존 파일과 manifest는 수정하지 않았으며 기존 인계에 기록한 434개 파일 및 HTTP 원문 426개의 해시를 그대로 검증했다. 2025년 원문은 수신 시점과 해시를 보존하고, 도출 결과는 요청 로그 SHA에서 파생한 `snapshots/<키>/`에 한 번만 쓴다. 이후 재개로 새 로그가 생기면 별도 스냅샷을 만들며 기존 스냅샷을 덮어쓰지 않는다. 결과 목록과 이벤트, 스냅샷별 요청 로그·manifest는 서로 SHA로 연결한다.

재개는 공식 시즌 고정 목록의 첫 경기부터 확인하되, 이미 받은 응답의 해시를 검증한 뒤 재사용한다. 요청 간 1초, timeout 15초, 응답 크기 상한, 401·403·429 중단을 유지하고 동일 collector 잠금으로 동시 수집을 막는다. 수신 로그가 없는 원문이 발견되면 자동으로 덮어쓰지 않고 중단한다.

```powershell
python experiments/kleague1-official-lineup-20261103/season-2025/run.py --capture --max-fixtures 228
python experiments/kleague1-official-lineup-20261103/season-2025/verify.py
python -m pytest -q tests/test_kleague1_lineup_2025.py tests/test_kleague1_official_lineup.py
```

`run.py`에 `--capture`가 없으면 저장된 원문만 읽는다. 2023·2024년의 추가 수집은 이번 범위가 아니다. 모델 학습·ROI·운영 원장·정책·스케줄·배포는 변경하지 않았다.
