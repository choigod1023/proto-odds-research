# 기존 입력 연결 복원: 운영 부분 스냅샷 독립 검산

이 작업은 운영 DB를 초기화하거나 변경하지 않는다. `mode=ro` 연결과 한 읽기
트랜잭션으로 지정 문서 4개, 최근 원장 256행(8766~9021), 특정 KBO 경기의
배당 696행을 추출했다. 사용자·모의 지갑·환경변수·비밀은 추출하지 않았다.
Windows SSH 클라이언트는 종료 코드 1을 반환했지만, 시작/종료 마커와 압축 해제
본문 SHA-256을 대조해 출력 완결성을 확인했다. 종료 코드를 성공으로 위장하지 않는다.

## 실제 복원

- 대상: 2026-11-01 14:00 KST, 삼성 홈–KIA 원정, 공식 ID `20261101HTSS0`.
- 696개 배당 행은 **1경기 × 8상품 × 87관측**이다. 696경기가 아니다.
- 원장 `evt_2b56a2c503d6a9eb` / `dec_3af20241522c0154`는 10월 31일에 저장됐다.
  예측 시각은 05:11:42 UTC, 원장 저장은 05:13:11 UTC다. 둘 다 경기 T-30 이전이다.
- 이미 보존한 `verified-fact-capture-20261031/capture-with-bytes.json`의 공식 원문은
  10월 31일 실제 수신됐고, 공식 경기 ID·팀 방향·킥오프와 예고 선발 선수 ID
  53375/55633 및 이름이 저장된 판정의 선수 입력과 일치한다.
- 원장은 전체 승패 양측 가격 `[1.73, 1.75]`, 홈 선택, 선택/상품 ID를 함께 동결했다.
  단, 원장의 가격 시각 05:04:55 UTC와 **정확히 같은 시각의 외부 배당 행은 없다**.
  05:09:57 UTC의 판정 전 별도 관측에서 같은 전체 가격 벡터를 대조했다.
  이는 원래 가격 응답의 재발견이나 구매 가능 가격의 인증이 아니다.
- 11월 2일 공식 결과를 새로 수신해 원문 바이트를 base64로 보존했다. 원문 SHA는
  운영 결과 캐시가 기록한 `035e59fd8cb96524a0ce296e7c1ed16476968ec1ac621040f7aea5aef4c16ff8`과 같다.
  최종 점수는 삼성 6–KIA 1이다. 이 결과는 정산용이며 과거 예측 입력에 넣지 않는다.
- 각 원장 행의 해시 256/256과 인접 연결 255개를 재계산했다. 앞선 원장 prefix와
  이 revision이 해당 경기의 최종 동결본인지는 확인하지 않았다.

**새 모형의 적중률/ROI 개선 실험이 아니다.** 기록된 한 선택의 설명용 정산은 가능하지만
한 경기의 적중을 성능 개선으로 계산하지 않는다. 공식 예고 선발은 최종 출전 확정과 다르다.
확정 9인 타순이 없어 완전한 선수 정보 모형의 적격 표본으로 승격하지 않는다.
원문·해시·로컬 수신 기록은 외부 독립 수신 인증을 뜻하지 않는다.

## 재현

검산 결과의 `source_files`는 JSON 래퍼의 개행 차이를 피하도록
`hash_basis=canonical_json_utf8`을 명시한다. HTTP 원문 바이트는 base64와
원래 바이트 SHA-256으로 별도 검증하며 그 개행이나 수신 시각을 바꾸지 않는다.

새 운영 조회는 필요하지 않다. 다음 명령은 보존된 입력만 검산한다.

```powershell
python scripts/verify_recovered_kbo_link.py --snapshot experiments/input-link-recovery-20261102/production-snapshot.json --facts experiments/verified-fact-capture-20261031/capture-with-bytes.json --result experiments/input-link-recovery-20261102/kbo-result-20261101.json --output <존재하지-않는-검산결과.json>
python -m pytest tests/test_link_recovery_snapshot.py tests/test_recovered_kbo_link.py -q
```

기존 캡처와 검산 결과는 덮어쓰지 않는다. 실수신 날짜를 바꿔 과거 자료로 만들지 않는다.
`export_link_recovery_snapshot.py`는 필요할 때만 수동 실행하는 제한된 읽기 도구다.
자동 스케줄·연구 큐·현재 수집기에 연결하지 않았다. 공식 결과의 첫 JSON 해석 요청은
실패했으며, 기존 공식 수집기와 같은 공개 요청 헤더를 사용한 다음 요청만 이 폴더에 보존됐다.
