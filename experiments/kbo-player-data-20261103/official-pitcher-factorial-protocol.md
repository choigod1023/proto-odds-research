# H2: 공식 일정상 선발투수 교체의 회고 가정 계약

등록 대상은 총괄 `official-player-factorial-contract.json` commit `38d25ef3` 및 scope 정정 `e03addcb`의 보조 2×2 비교다. 원래 주 분석과 H1 타순 193경기 계약을 변경하지 않는다. 고정 입력: 공식 v4 `92015aa1af2e23813b0b4d8c3c5bd182d1c0ee7b2226920af3445e86569ae67c`, 기존 projection `eca78a16ca59ccc1de6eca47713acded513541c59cddbbb4d8dd193e7c5b27ae`, H1 `ddc66e073ada98ef9cbf469fac64aed53e45ac3d4e44a1e4330f2c661eced627`.

193경기의 공식 일정 원문을 해시로 검증하고 정확한 경기·날짜·팀·더블헤더 연결을 재검사한다. 오직 일정의 `B_PIT_P_ID`·`T_PIT_P_ID`를 선발 ID 선택자로 사용한다. 서로 다른 양의 정수 ID가 없거나 원문과 수집 레코드가 충돌하면 해당 경기를 공통 교집합에서 제외하며 사유를 센다. `W_PIT_P_ID`/`L_PIT_P_ID`와 사후 박스스코어의 ID는 선택·누락 보완에 쓰지 않는다. 사후 박스스코어 첫 투수와의 일치/불일치는 별도 관측치로 기록하고 교집합 선택이나 예측 입력을 바꾸지 않는다. 세 경기에서만 원천 이름의 의미가 확인됐으며 모든 경기의 실제 선발 또는 사전 발표를 증명하지 않는다.

고정 모델의 이력 객체 형식을 유지하고 대상일보다 엄격히 이전 달력일에서만 해당 선수의 마지막 10개 등판 원문 fixture ID·날짜·아웃·ER·R·기타 원시값을 구성한다. 이전 이력이 없으면 null이고 당일 이력·대상 경기 ERA/FIP/성적·미래 정보로 채우지 않는다. 투구 이닝은 야구 아웃 단위로 변환하고 원본 bf 단위는 미검증 원시값으로만 둔다. 실제 완료·수신 시각은 null, 전날 완료는 회고 가정이다.

별도 `official_starter_only`는 원래 projection에서 두 starter_strength만 교체한다. 별도 `official_batting_and_starter`는 고정 H1 타순 overlay에서 같은 두 필드만 교체한다. 다른 특징과 기존 projection metadata는 값과 해시가 같아야 하며 각각 원래 선택자의 실제 출처가 아님을 명시한다. 예측·학습·스케일·가격·정산·운영을 건드리지 않는다. 193개 중 투수 양쪽이 유일하게 확인된 공통 표본, ID 결측/충돌, 선수 과거 이력 결측, 사후 첫 등판 ID의 일치·불일치를 각각 센다. 독립 시간 수신 검증/PIT 표본은 0건으로 유지한다.

생성 전 등록·커밋하고 타깃 선수 ID/성적/점수 및 당일·미래 변조, 누락/중복/팀·날짜·더블헤더 오류, 원문 SHA/Git blob 정확 바이트, 각 이전 이력의 날짜와 교체 이외 값 불변성을 검사한다. 데이터 handoff만 작성하고 모델 결과를 계산하지 않는다.
