# KBO 2026 이전 선수 이력 보강: 데이터 계약

상위 `fresh-history-comparison-contract.json` commit `497cf651`에 따른 고정 709경기의 회고 자료 품질 진단이다. 기존 709·193 결과가 알려져 있으므로 블라인드가 아니며 모델 적합·가중치·변환·하이퍼파라미터나 운영을 변경하지 않는다. 기존 raw, labels, projection, 공식 타순/투수 overlay와 manifest를 절대 덮지 않는다.

원천 PR #520 commit `d11367b7b37f3ea34f4c08987ca042af9235575e`의 `normalized-records.jsonl.gz` SHA-256 `e9d84a6ee8dd3d0262fa6ef04a8fc6e23c79b6b5b04f52fc85a4223b41bc3334`과 `supplement-v2.jsonl.gz` SHA-256 `0293a109c20c3f3344215dd1bd7bfad5e55f2755ada22e01e3c0a5329fd67c84`을 정확 Git blob·working bytes와 대조한다. 공식 response bundle SHA·수신 시각·HTTP/선수/경기별 필드 provenance를 확인하고 대상 원천과 동일 fixture·공식 game ID·팀·시리즈·날짜·선수 ID·행 식별에 맞는 경우만 결합한다. 사전 수신이나 가격 인증은 주장하지 않는다.

예상 타순과 선발의 과거 선택자는 기존 최근 유일 타순과 최근 5명 중 가장 오래 선발된 투수 규칙을 유지하되 이전 날짜의 검증된 공식 2026년 팀 기록을 추가로 이용한다. 동 일자의 더블헤더 등 순서가 불명확하면 임의로 고르지 않는다. 현재 타깃 공식 타순/투수는 공식 정보 시나리오의 별도 선택자일 뿐 projected 선택자가 아니다.

타자는 정확 AB·H·순수 BB가 모두 검증된 경기 관측의 이전 날짜별 마지막 10개를 쓴다. 확인된 0과 zero PA는 관측으로 보존한다. 누락·충돌은 이력 공백으로 기록하고 0이나 4사구로 채우지 않는다. 투수는 검증된 player ID별 ER·outs의 마지막 10개이며 불펜은 원래와 같은 전 1~2개 달력일 팀 구원 outs proxy다. 선수 ID가 없는 구원투수라도 공식 해당 경기·팀의 구원 등판과 outs가 검증됐으면 팀 합계에 쓸 수 있다. 당일·미래 기록, 대상 점수, 현재 개인 성적이나 가공 ERA/FIP를 사용하지 않는다. 완료·과거 수신 시각은 null로 남기며 현재 재수신 시각은 증거로만 기록한다.

같은 709경기의 projected/projected, 공식타순만, 공식선발만, 공식양쪽 네 파일을 새로 만들고 본래 비선수 feature를 고정한다. 193·516 부분집합과 7/26 전후의 겹치는 묶음별 선수별 component 사용 가능한 마지막 이력 날짜, 갭, 이력 부재·불완전 관측 및 median/p90/max, 14/30/60/90일 초과를 명시한다. 0PA도 관측 이력에 포함하되 단일 0PA는 수치 분모를 만들지 못함을 구분한다. 원래 모델 scalar와 후보 규칙은 고정하고 누락 시 null이다.

같은날/미래/타깃/점수 poison, 팀·선수·날짜·중복/더블헤더, zero/null/outs, 비선수 특징과 원본 불변, source raw SHA/Git blob 검사를 실제 실행한다. 성능 계산·재튜닝·실제 예측 또는 운영 수익률 주장은 하지 않는다.
