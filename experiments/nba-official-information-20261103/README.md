# NBA 공식 경기·부상 자료: 원천 조사와 부분 수집

상태: `partial_source_access_blocked_census`. 기존 `blocked_data`는 이전 저장 파일의 범위만 의미하며 공식 원천이 없다는 뜻이 아니었다. 2025-26 정규시즌의 서로 다른 3개 월에서 NBA 공식 경기 페이지 원문 3개를 현재 수신했다. 각 경기의 양 팀 사후 최종 선발 다섯 명, 선수 ID 및 경기 ID를 추출했다. 이는 **사전 확정 명단을 복원하거나 실제 사전 수신을 인증한 것이 아니다.**

## 고정 규칙과 분모

결과 조사 전에 `9e56cde975dbc530dbb91958091a30826de13521`에서 2025-10-22~2026-04-12, 27개 경기일과 월별 gameId 순 최대 18경기 선택을 고정했다. 2025-26 정규시즌에 한정하며 2026-27은 이번 표본 밖이다. 공식 게임 페이지의 연도별 달력에는 지정된 27일 합계 **198개 이벤트**가 표시된다. 이 달력은 정규시즌 외 이벤트도 포함하고 경기 ID를 주지 않으므로 198을 적격 NBA 경기 수라고 부를 수 없다. 월별 정규시즌 기회 수와 정확한 선택 명단은 미확정이다. 당초 최소 100개의 고정 규칙에 따른 표본은 0개 확인·100개 이상 목표가 미처리이며, 아래 3개는 공식 검색으로 발견한 **접근 검증용 별도 사례**다. 결과를 보고 고른 검증 사례이므로 정해진 선택 표본이나 모델 평가로 쓰지 않는다.

공식 프런트엔드의 게임 화면 JS는 `/feeds/gamecardfeed`를 호출한다. 2026-04-12에 대한 공식 `core-api.nba.com` 요청은 503, `cdn.nba.com` 일정 원문은 403, `stats.nba.com`은 15초 시간 초과였다. 403 호스트는 중단했고 보안 우회 없이 공식 웹페이지에서 제공한 달력 및 박스스코어만 보존했다. API 성공 없이 결과와 무관한 gameId 전체를 나열할 수 없어 임의 표본으로 100건을 채우지 않았다. 원문 캡처와 검증 결과는 `manifest.json`, `calendar-counts.json`, `postgame-samples.json`에 있다.

## 공식 부상 보고서와 시점

공식 [2026-04-12 12:00 ET PDF](https://ak-static.cms.nba.com/referee/injury/Injury-Report_2026-04-12_12_00PM.pdf)는 첫 접근에서 HTTP 200과 103,239바이트가 관측됐으나 원본 바이트·완료 시각을 저장하지 못해 해시 검증이나 개별 경기 연결을 주장하지 않는다. 이 문서의 공개 색인에는 해당 일자·12:00 PM 표제가 확인된다. [2026-01-15 12:00 ET PDF](https://ak-static.cms.nba.com/referee/injury/Injury-Report_2026-01-15_12_00PM.pdf) 역시 공개 색인에서 문서와 상태가 확인되지만 이번에 원본을 보존하지 않았다. 2025-11-22 정오 PDF 요청은 403이었고 같은 PDF 호스트의 남은 요청을 중단했다. 403 원문은 보존했다. PDF 파일명/본문 표제 시각은 공식 문서의 주장이지 실제 게시 완료·사용자의 과거 수신 시각 증명이 아니다. 확정적 사전 수신·선발 연결은 0건, 과거 부상 문서의 공식 파일시각과 실제 경기의 비교 완료 0건이다. `Probable`, `Questionable`, `Out`과 실제 출전 여부는 각각 별도로 취급한다.

## 가격 연결과 후속 가설

지정한 KBO 및 K리그 Betman 회차 원문 2개 디렉터리의 gzip 응답을 읽어 리그 코드 `BK002`의 동일 UTC 시작 시각을 조사했다. 세 경기 중 11월 경기에는 시각이 같은 4행, 4월 경기에는 24행, 1월 경기에는 0행이 있었다. 여러 경기·상품·회차가 섞여 있고 팀명에 대체 문자가 있으며 상품 정산을 확정할 수 없어 **이 수치는 후보 행이지 경기 연결 건수가 아니다**. 정확한 팀·동일 경기·시장·전체 선택 가격·연장/승5패 정산을 검증한 연결은 0/3, 미검증 3/3이다. ROI는 계산하지 않았다. 캐시의 경기시간이나 가격을 과거 수신으로 인증하지 않았다.

후속 가설 하나: 실제로 판정 이전에 수신된 공식 `Out` 상태와 선수의 과거 역할이 시장 확률에 더해 예측 로그손실을 개선할 수 있는지 검증한다. [NBA 공식 보고 규정과 갱신 안내](https://official.nba.com/nba-injury-report-2026-27-season)는 보고가 갱신됨을 설명한다. 이 가설은 선수별 입수 시점, 공식 ID, 사전 동일 상품의 전체 가격과 동결 운영 픽, 이전 경기 기록과 결과 수신이 필요하며 아직 효과를 주장하지 않는다. 사후 선발과 결장 사실로 당시 정보를 대체하지 않는다.

## 재개와 한계

새 공식 경기 목록 응답과 수신 바이트가 확보되면 사전 등록된 날짜별·월별 선택 규칙을 적용하고 각 월의 적격 수·선택·미처리 수를 확정한 뒤 100건 이상 원문을 수집한다. 기존 달력 198개만으로 대체할 수 없다. 복구 전에는 수집 재개 명령이 준비되지 않았으며, 다음 명령은 이미 보존한 3건의 **오프라인 재검증만** 한다: `python experiments/nba-official-information-20261103/audit.py`. 403/429 중단, 호스트당 1초, 15초 timeout, 캐시·잠금·누적 500회 제한을 갖춘 수집기와 체크포인트는 공식 목록이 확보된 후 구현·검증해야 한다. 자동 반복 또는 재수집은 설정하지 않았다.

`python -m pytest -q tests/test_nba_official_20261103.py`는 실제 공식 HTML 3건과 불완전 선발 합성 사례를 검사한다. 이는 사전 시점 인증이나 선수 효과 검증이 아니다. 운영 모델·지갑·DB·자동화·배포는 변경하지 않았다.
