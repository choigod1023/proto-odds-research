# 농구 공식 원천과 모델 입력 조사

KBL 공식 선수기록 한 경기와 NBA 공식 박스스코어 보존 원문 한 경기를 각각 기존 승패 가격 한 행에 연결했다. 두 경기 모두 선수기록은 경기 후 수집한 자료이며, 가격의 상품번호·기간·연장 정산·실제 수신 및 체결 시각은 없다. 따라서 이 연결은 **원천과 가격의 후보 연결**이지 당시 이용 가능했던 예측 입력이나 동일 상품 정산 증명이 아니다. 새 효율 모델의 적격 공통 학습·평가 경기는 이번 확인 범위에서 0건이며 모델 성능을 산출하지 않았다.

## 확인한 원천과 연결

### KBL

- 공식 일정은 `https://api.kbl.or.kr/match/list?fromDate=20250101&toDate=20250107&tcodeList=all`처럼 KST 날짜 범위를 지정한다. 기존 공식 캐시는 2025년 종료 결과 312경기, 2026년 종료 결과 214경기를 포함한다. 각각 과거 경기의 실제 사전 수신이 아닌 사후 보관 자료다.
- [S45G01N116 선수기록](https://api.kbl.or.kr/match/S45G01N116/player-stat)은 이번에 HTTP 200, 24행을 받았다. 응답은 `player.pcode`, `player.tcode`, `startFlag`, `records.playMin`, `playSec`, `score`, 야투·자유투·리바운드·턴오버 및 `poss`, `pace`, `offrtg`, `defrtg` 등을 포함한다. 이 필드의 통계 정의와 팀 단위 포제션 집계 방식은 별도 검증해야 한다.
- 공식 일정의 팀 ID 06/60, 2025-01-01 14:00 KST를 붙여 양 팀 12명씩, 출전시간 각각 200분, 개인 득점 합계 86–68과 공식 경기 결과를 대조했다. 보관된 수원 KT–부산 KCC 승패 가격 1행(1.31/2.68)과 날짜·팀·승자도 일치한다. 가격 원장의 시간대는 인증되지 않았다. 하나의 사후 경기 연결이 전체 과거 이력의 정확성이나 시간상 적격성을 의미하지 않는다.
- 기존 `collect_basketball_comparison_sources.py`의 경기 결과와 별도 postgame 선수 원문 경로를 활용했다. 새 [extract.py](extract.py)는 응답 해시·수신 완료시각·URL의 게임 ID·공식 일정/결과·선수/팀 ID·개인 득점 합계를 확인하고, 원래 필드와 수신 시각을 유지한다. 기존 수집기나 운영 데이터를 수정하지 않는다.

### NBA

- NBA 공식 `https://www.nba.com/games?date=2025-01-01` 및 `?date=2026-01-01` 기존 캐시에는 각각 공식 최종 결과 8경기와 5경기가 있다. 날짜는 NBA 동부시간 기준이며 원문을 2026년 11월에 받아 과거 경기 전 수신을 입증하지 않는다.
- 보존된 [NBA 공식 박스스코어 0022500274](https://www.nba.com/game/0022500274/box-score)의 원문 해시를 다시 검증했다. 2025-11-23 03:00 UTC 덴버 123–새크라멘토 128, 팀 ID 1610612743/1610612758, 선수 12/14명과 사후 선발 각 5명, 선수 ID·출전시간·득점·야투·리바운드·턴오버 열이 있다. 2026-11-03 수신된 사후 자료다. 보관 승패 가격 1행(1.09/4.31)과 KST 날짜·팀·승자가 일치한다. 원문의 예정 시각과 별개로 보관 가격의 시간대·상품 규칙은 검증되지 않았다.
- 새 요청에서 NBA 공식 `cdn.nba.com/static/json/liveData/boxscore/boxscore_0022500274.json`은 HTTP 403, `stats.nba.com/stats/boxscoretraditionalv3`는 15초 읽기 시간 초과였다. 재시도나 우회는 하지 않았다. 따라서 두 API의 이번 응답 스키마는 확인하지 못했고 NBA.com 보존 HTML의 `pageProps.game` 스키마와 같다고 주장하지 않는다. 기존 NBA 공식 일정·박스스코어 자료 감사는 제한된 자료에서 양 팀 최근 7일 박스와 부상, 적격 가격을 모두 갖춘 경기가 0건이었다.
- [NBA 부상 보고서 PDF](https://ak-static.cms.nba.com/referee/injury/Injury-Report_2026-11-04_12_15AM.pdf)는 이번에 8쪽을 받았고 첫 쪽의 문서상 시각은 2026-11-04 12:15 AM이다. 실제 이번 본문 수신은 2026-11-08 07:38:55 UTC다. 문서의 작성 시각을 이번 수신 시각이나 당시 실제 가용 증거로 대체하지 않는다. 별도 기존 수집에는 실제 경기 전 수신으로 기록된 14경기·119명 상태가 있으나 전체 시즌 커버리지가 아니다.

### WKBL

공식 경기 페이지는 예를 들어 `game/result.asp?game_no=72&game_type=01&gun=1&season_gu=046&viewType=2&ym=202602`처럼 시즌·경기번호·월로 특정한다. 검색 인덱스에 보이는 [공식 경기 페이지](https://www.wkbl.or.kr/game/result.asp?game_no=72&game_type=01&gun=1&season_gu=046&viewType=2&ym=202602)는 2026-02-15 우리은행 56–58 삼성생명을 표시한다. 이와 일치하는 보관 승패 가격은 1행이다. 그러나 이번 로컬 모바일 페이지 요청은 HTTP 403이었고 원문 선수 행·선수 ID·출전시간을 확보하지 못했다. 인덱스는 보존된 원본 응답이 아니므로 이 가격을 공식 원문에 검증 결합한 경기로 세지 않았다. 다른 접근 제한을 우회하지 않았다.

## 모델 가설과 부족한 입력

[사전 규약](PROTOCOL.md)은 팀의 최근 10경기 공격효율에서 수비효율을 뺀 차이를 같은 경기 시장확률의 로짓 잔차로 사용하는 후보 하나를 정했다. 이는 지난 결과만으로 만든 변수이며, 시장에 이미 반영되지 않은 정보가 실제로 남는지는 미지수다. [Poropudas·Halme의 논문](https://arxiv.org/abs/2305.13032)은 포제션과 팀 효율을 박스스코어로 분석하는 근거이지 이 가설의 예측 우위 증거가 아니다.

기존 #657의 KBL Student-t 승패 152경기는 선택이 정규 기준과 동일했고, 기존 NBA 선수쌍 연구의 411경기는 시장보다 승패 정확도가 낮았다. #656은 배구 세트, #658은 KBO 선발 이력, #659는 1픽 선정 규칙 연구다. 이번 가설은 그 결과를 재포장하지 않는다.

필요한 열은 각 팀의 직전 10경기 원문과 경기별 팀 ID, 분자에 필요한 득점·야투·자유투·공격리바운드·턴오버, 상대 팀 수비 열, 경기 및 실제 원문 수신 시각, 같은 상품의 전체 선택지 가격·가격 관측시각·기준점·기간·연장 규칙·공식 정산이다. 현재 KBL 박스 확인은 신규 1경기와 기존 2경기 표본, NBA 공식 박스는 기존 3경기 표본, WKBL은 이번 원문 선수 행 0경기다. 이 표본에서 10경기 이력과 정확한 사전 상품 조건의 교집합은 확인되지 않았다. 부상 문서도 해당 경기보다 이른 실제 수신과 경기/팀 ID 일치가 필요하다. 정산 성과와 가격 기반 ROI는 미산출이다.

## 보존 및 재현

이번 다섯 요청의 URL, 상태, 수신시각, 크기와 SHA-256은 [source-summary.json](source-summary.json)에 있다. 원문 gzip 및 영수증은 `C:/Users/user/AppData/Local/Temp/basketball-source-20261108d/`에만 보관한다. 기존 NBA 박스 원문은 저장소 Git 객체 `2df626042f633ba08f381f755ccc18f2068733f6`의 `experiments/nba-official-information-20261103/raw/box-0022500274.html`과 당시 manifest를 사용한다. 해시는 로컬 원문의 무결성 증거이며 제3자의 시각 인증이 아니다.

`python experiments/basketball-source-20261108d/probe.py`는 기존 검증 캐시를 재사용하며 실패 응답도 재요청하지 않는다. `python experiments/basketball-source-20261108d/extract.py --output <로컬 출력>`으로 선수 기록을 추출하고, `python experiments/basketball-source-20261108d/inventory.py`로 요약을 재생성한다. 공개 사이트의 제공 지속성·호출 허용 범위·재배포 라이선스는 보장되지 않으므로 확대 수집 전 각 사이트 조건을 확인해야 한다. 원장·운영·스케줄·배포는 변경하지 않았다.
