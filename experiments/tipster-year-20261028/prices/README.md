# 연간 Proto 공개 배당 아카이브

수집 대상은 2025-10-28~2026-10-27(한국 시각), K리그1·K리그2·KBO·NPB·MLB·NBA·KBL의 풀게임 승패/승무패 배당이다. 픽스터 원문, 자체 모델 예측, 공식 결과는 이 작업에서 수집하지 않는다. 부모 작업에서 같은 경기의 독립적인 공식 결과 및 추천 자료와 연결해야 한다.

## 수집과 체크포인트

- `offers.jsonl`: 이번에 공개 회차별로 새로 요청한 정상 배당 벡터. 배당 순서는 `odds_order`에 명시했다. 원본 연도·회차·경기번호와 SEQ, 출처 URL, 응답 SHA-256, 관측 시각을 보존한다.
- `parsed-facts.jsonl`: 대상 리그의 승패/승무패 행에서 추출한 사실. 제외 사유를 포함하며 원문 HTML 없이 정규화를 다시 실행할 수 있다.
- `rounds.jsonl`: 완료 또는 실패한 회차, 검증한 SEQ, 응답 해시, 파싱/허용/제외 건수, 아카이브 날짜 범위. 회차마다 기록한다.
- `requests.jsonl`: 실제 수집 요청의 주소·시각·상태·응답 해시. 응답마다 기록한다.
- `coverage.json`: 회차마다 갱신하는 월별 배당 수·고유 경기 수·리그별 수·미처리 회차·실패 내역·배당 없는 날짜.
- `old-preserved-offers.jsonl`, `preserved-inputs.json`: 기존 보존분과 그 파일/응답 해시. 새 수집분과 합산하지 않고 별도 보관한다. 원래 자료 중 요청 기간 밖의 2025년 7월은 제외했다.
- `verification.json`: 오프라인 재실행 검증 결과. 전체 수집 후 생성한다.

2025년 연도별 공개 페이지에서 실제 마지막 회차 154와 SEQ 30117을 확인했다. 2025년 120~154회차와 2026년 1~127회차(162개)를 시간순으로 요청한다. 앞 경계를 넉넉하게 잡았으며 2025년 120회차의 실제 날짜는 10월 10~13일이다. 날짜로 SEQ를 추산하지 않고 각 회차 index에 명시된 연도·회차·SEQ를 검증한다. 1회차의 12월 경기는 전년, 연말 회차의 1월 경기는 다음 해로 해석하고 기간 밖의 경기는 제외한다.

각 응답 후 최소 2.5초를 기다린다. 기존 클라이언트의 `X-Requested-With: XMLHttpRequest`를 사용하는 공개 GET만 허용하고 로그인·인증·리다이렉트·재시도·다른 엔드포인트 우회는 하지 않는다. 오류가 나면 호스트 수집을 중단하고 실패를 남긴다. 특히 HTTP 403 기록이 있으면 재실행해도 새 네트워크 요청을 막는다. 원문은 로컬 `raw/`에만 남기고 Git에는 넣지 않는다.

## 해석상 제한

Proto에 표시된 점수와 결과 라벨은 **리그 공식 결과가 아니다**. 모든 배당에 `official_result_verified=false`를 기록했다. `winner`도 아카이브 결과 라벨의 인덱스이며 부모의 독립 검증이 필요하다. 현재 관측한 회고 배당이므로 당시 구매 가능 시각·종료 전 배당·실제 체결 가격을 인증하지 않는다.

무효, 취소, 다른 마켓, 전반전, 승⑤패, 배당 벡터 누락, 점수/결과 불일치, 기간 밖 행을 제외한다. 두 회차에 같은 경기가 재발매되었다면 원본 가격 행은 보존한다. 여러 작성자나 회차의 같은 경기를 독립 경기로 세지 않도록 `coverage.json`에는 별도의 고유 경기 수를 둔다. 같은 날 같은 팀의 더블헤더는 경기 시각으로 구별한다. 배당 없는 날짜만으로 실제 경기 누락을 확정할 수 없으며, 시즌 휴식기나 수집 전 기간을 구별해서 읽어야 한다.

## 실행

저장소 루트에서 실행한다. 운영 DB, 서비스 설정, 배포에는 접근하지 않는다.

```powershell
python -X utf8 scripts/research_collect_year_proto.py --self-test --collect
python -X utf8 experiments/tipster-year-20261028/prices/test_collector.py
python -X utf8 scripts/research_collect_year_proto.py --replay
python -m pytest tests/test_wisetoto_round.py -q
```

`--collect`는 이미 완료한 회차를 다시 요청하지 않는다. 실패한 실행은 자동으로 재시도하지 않는다. `--replay`는 저장된 파싱 사실에서 만든 배당을 `offers.jsonl`과 정확히 비교하고, 원문이 로컬에 있으면 해시·SEQ·행 수도 확인한다. Git으로 받은 자료에서도 원문 없이 파싱 사실 기반 정규화 검증은 가능하다.

기준 문서: [연구 범위 정정](../../../docs/research/2026-10-25-research-scope-correction.md). 공개 출처는 각 행의 `source_url`과 요청 원장에 있다.
