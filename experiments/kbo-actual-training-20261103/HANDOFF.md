# 실제 타순·선발 학습 비교: 준비 인계

상태: `waiting_fixed_inputs`. 공식 원천 및 데이터 워커의 최종 커밋·manifest·SHA-256을 기다린다. 이 브랜치에는 미완료 수집 파일이나 추정 경기 수를 가져오지 않았고, 실제 2025/2026 학습·예측·정산을 실행하지 않았다. 부모가 복원을 계속 관리하고 고정 입력을 인계하면 이 브랜치에서 재개한다.

부모 사전 계약 커밋 `c5407e9bf50bc80a26794240d4ada218b28f2f7d`, SHA-256 `512c6172eb792ed6e5f7afe7b90d4cfaa0e4087b05e0a497ec7cf9a997cb2480`. 기존 고정 모델·코드는 `d08ccb708033fb6b067e84e80eae81ea3c9b4cfa` Git 객체에서 가져와 `vendor/manifest.json`의 해시로 고정했다. M0 base L2=10, 교정 M2 base L2=10/player L2=100, 타순 가중과 12개 양팀 결측 품질 합을 그대로 사용한다. 기존 PR #531과 모델·원본은 변경하지 않았다.

준비한 구성:

- `source_adapter.py`: 전달된 전체 길이 Git 커밋과 SHA-256의 원천 blob만 사용하고, 공식 실제 타순·선발 근거와 예상 선발 순환의 이전 경기 식별자를 확인한다. 데이터 워커의 최종 스키마에 맞는 파일 연결은 인계 후 해야 한다.
- `pipeline.py`, `workflow.py`: 예상·실제 명단의 경기 집합과 팀·날짜·불펜/비선수 특성 일치, 선수 이력의 이전 날짜·유효 성분·결측, 공식 ID 및 후향 가용성 표시를 검증한다. 학습 사전과 표준화는 각 fit에 한정하고 최소 100경기·2개 팀·세 결과 범주가 없으면 `blocked_data`로 중단한다. 예측 Git blob 검증 전에 결과 로더를 호출하지 않는다.
- `runner.py`: 2023~24 학습→2025 검증에서 4개 매칭 학습 조합을 두 평가 명단에 적용하고, 최종 2023~25 재학습에서 4개 조합과 별도 old-fulltrain M0/M2를 같은 테스트 명단에 적용한다. 새로운 모델 또는 하이퍼파라미터 선택은 하지 않는다.
- `settlement.py`, `independent_verify.py`: 6개 모델의 공통 배당 교집합, 무승부 환급, strict/extended 및 현재 buyReject 공통 제외, Decimal 월별·낙폭·주간 paired 구간, 독립 밀집 예측과 정산 재계산을 준비했다. 이전 전체 학습 모델을 매칭 학습과 혼동하지 않는다.
- `tests/test_kbo_actual_training_pipeline_20261103.py`: 합성 명단과 경기로 네 조합 학습 및 두 평가 명단의 6개 모델 예측을 실행하고, 독립 수식, ID·선발 증거, 같은 날/미래 이력, BB 결측·0, v2 양팀 결측, 예측 고정 전 결과 로더 차단과 환급 분모를 검사한다.

다음 단계는 고정된 세 시즌 공식 원천과 데이터 워커의 실제 입력 manifest를 받아 스키마를 `source_adapter.py`에 연결하고, 원천 해시·실제 선발 근거·제외 사유·2026 공통 분모를 확인하는 것이다. 양쪽 입력과 선수 이력이 동일한 적격 경기에서 2025 두 평가 명단의 네 조합을 계산한다. 그 후 2023~25 재학습과 2026 두 명단 6개 모델 예측을 별도 Git 커밋으로 고정한 뒤에만 결과·배당을 연결해 정산하고, 독립 재계산·테스트·PR 갱신을 마친다. 모든 시점 및 배당은 후향 가정이며 2026은 이미 열람한 표본이다. 운영·지갑·배포·병합은 범위 밖이다.
