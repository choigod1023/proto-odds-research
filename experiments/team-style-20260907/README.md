# 팀 경기 특징의 리그별 독립 실험

운영 코드·DB·추천 가중치를 바꾸지 않는 오프라인 연구 PR이다. 기존 #209/#210의
시장확률 보정과 달리, 실제 과거 경기 스코어로 만든 팀 특징을 예측 입력에 넣는다.
두 PR을 병합할 필요 없이 현재 main에서 독립 실행할 수 있다.

## 실행 결과

184,473개 원본 행에서 45,339개 확인된 경기의 시점별 특징을 생성했다.
평가 가능한 29개 리그·대회에서 17,881실경기 / 53,979시장을 평가했다.
20개 리그·대회가 최소 시장 수·실경기 수·관측 주 수를 함께 만족했으나,
406개 검정을 보정하고 연도별 재현성을 요구한 개선 판정은 **모두 미통과**였다.

- NPB: 기준 적중률 58.95% → full 59.16%, 기준 대비 Brier 오차 **0.605% 증가**.
- MLB: 58.65% → 58.62%, Brier 오차 **0.906% 증가**.
- KBO: 58.94% → 57.91%, Brier 오차 **1.662% 증가**.
- UECL·여배네이만 절편 보정보다 full의 Brier/log loss가 모두 작았지만,
  실제 관측 기간은 23주·3주로 최소 26주를 충족하지 못했다.

NPB 2026-08-25 경기 전 마지막 20경기의 관측 득점은 소프트뱅크 평균 5.35점,
히로시마 평균 2.95점이었다. 소프트뱅크의 득점 표준편차는 약 3.77점으로,
평균 득점 수준과 경기별 변동성을 별개로 볼 수 있다. 이 수치는 보관된 경기 기록의
기술통계이며 현재 팀 전력이나 향후 적중을 보장하지 않는다.

현재 스코어 특징과 고정 ridge를 결합한 후보는 운영 적용하지 않는다.
다음 실험에서는 과거 학습 구간 내부에서 특징 수·정규화 강도를 선택하는 절차를
먼저 정하고, 이미 확인한 평가 기간과 분리된 새 경기에 검증하는 것이 필요하다.
독립 리그별로 늘어난 계수 수·불완전한 경기/선수 데이터·배당에 이미 반영된 정보가
성능 악화의 가능한 설명이지만, 이번 결과만으로 그 원인을 확정하지는 않는다.

## 비교 대상

- baseline: 해당 보관 배당의 Shin 마진 제거 확률. 실제 서비스의 과거 동결 픽은 아니다.
- control: 같은 리그·시장·선택지 수 안에서 절편만 학습한 시장 offset 모델.
- scoring: 최근 5/10/20경기 득점·실점, 과거 상대를 반영한 득실점 잔차,
  시즌/홈원정 득실차, Elo, 최근 기록 수.
- full: scoring에 득점·실점·득실차 표준편차, 최다 득점 경기 비중,
  강팀/약팀 상대 기대 대비 성과, 상대 강도에 따른 성과 기울기,
  휴식·7일 경기 수·공격과 상대 수비의 상호작용을 추가.
- no_variance / no_opponent / no_matchup / no_scoring:
  full에서 각각 해당 특징군을 제거해 재학습. 파생 상호작용도 원인 특징군을
  제거할 때 함께 제거한다. no_scoring은 **득실 수준/Elo 그룹 제거**이지,
  다른 그룹에 필요한 모든 스코어 정보까지 지우는 비교는 아니다.

모든 후보는 동일한 시장행에서 비교한다. 승패·승무패·핸디캡·언오버는
리그 안에서도 별도 모델이다. 다른 리그의 학습 계수, 정규화 값, 팀 전적을 빌리지 않는다.
팀 특징 생성은 전 경기 승패/승무패의 확정 정수 스코어만 사용한다.
핸디캡 보정 점수나 전반·미확정·충돌 스코어를 실제 최종 점수로 쓰지 않는다.

## 특징의 해석

최근 범위는 지난 365일 안의 마지막 5/10/20경기다. 낮은 표본은 8경기 prior로 축소한다.
득실점 수준과 변동성은 그 시점까지 관측된 해당 리그의 팀당 평균 스코어로 나눈다.
기록이 없으면 0이 아니라 결측으로 남기고, 학습 구간의 중앙값과 결측 표시를 사용한다.
관측하지 못한 xG·포제션·선발·불펜·부상·라인업 값을 합성하지 않는다.

강팀/약팀은 **각 과거 경기 직전** Elo가 그 리그 당시 활성 팀 평균보다 50 이상
높거나 낮은 상대다. 시즌 최종 순위나 현재 전력으로 과거 상대를 다시 분류하지 않는다.
성과는 승/무/패를 1/0.5/0으로 평가한 값에서 경기 전 Elo 기대값을 뺀 잔차다.
이 값은 득점 기대값도, 3-way 승리 확률도 아니다. 강팀/약팀 표본 수를 함께 보존하며,
몇 경기만으로 팀을 '강강약약'이라고 확정하지 않는다.

공격·수비 잔차의 기대 스코어는 당시 리그 평균과 두 팀의 축소된 최근 득실점으로 만든
단순 가설이다. xG나 종목별 정교한 득점 생성 모델이라고 부르지 않는다.
배구는 보관 스코어가 세트 수일 수 있어 농구 득점이나 랠리 포인트로 해석하지 않는다.
소프트맥스 모델의 설명은 선택지와 차선 선택지 사이 로그오즈의 실제 특징 기여값이며,
인과적인 승패 원인이나 운영 추천 근거로 승격하지 않는다.

## 시간 분리와 평가

- 학습 시작 2023-01-01, 평가 2025-01-01~2026-08-25.
- 분기마다 해당 분기 시작 7일 전 **미만**의 결과만으로 재학습한다.
- 같은 날짜의 모든 경기 특징을 먼저 만들고 그 날짜의 결과를 한꺼번에 반영한다.
  더블헤더는 별도 경기로 유지하지만 첫 경기 결과도 같은 날 두 번째 경기에는 쓰지 않는다.
- 이후 평가 구간에서 끝난 경기는 다음 날 특징에 사용하고, 다음 분기 재학습에도 사용할 수
  있는 순차 평가다. 한 번 고정한 모델로 20개월 전체를 예측한 실험이 아니다.
- 학습 300시장 미만인 리그/시장/분기는 평가에서 제외하고 그 이유와 건수를 기록한다.
- ridge=100과 특징 정의는 고정. 결과가 좋은 가중치만 고르는 탐색을 하지 않았다.
- Brier는 클래스별 제곱오차의 **합**, log loss는 실제 결과 확률의 음의 로그다.
  작은 값이 좋다. 적중률은 각 모델 최확률 선택, ROI는 모든 시장에 동일 단위로
  가상 구매한 진단값이다. 경기당 한 픽·오늘 추천픽·실현 수익률과 다르다.
- 같은 경기의 여러 시장과 시간 상관을 고려해 4개 달력 주 블록으로 10,000회 재표집한다.
  비어 있는 주는 달력에는 남기되 실제 관측 주 수에는 넣지 않는다.
- 모든 평가 리그 × 7개 쌍 비교 × Brier/log loss를 하나의 Holm 다중검정 집합으로 보정한다.
  중심화 블록 bootstrap p값은 근사값이며 비정상적인 시간 변화에 강건함을 보장하지 않는다.
- 개선 판정은 평가 300시장·150실경기·26관측주 이상, 두 연도 모두 두 오차 개선,
  두 오차 개선 CI 하한 >0, 두 보정 p<0.05를 모두 요구한다.

## 제한과 1차 실행 이후 수정 기록

아카이브는 이전 실험에서도 이미 본 자료다. 배당 관측 시각·결과 공개 시각이 없어
확정적인 과거 T-30 재현이나 새로운 pristine holdout이라고 주장할 수 없다.
다음 날에는 전날 결과를 알 수 있었다는 가정도 지연 경기에서는 틀릴 수 있다.
북메이커가 발매한 확인 가능한 경기만 포함해 각 리그의 전체 일정이 아닐 수 있다.
후보 모델의 효과와 데이터 누락의 영향을 완전히 분리할 수 없으므로 실패 결과를
'팀 특징은 원래 쓸모없다'로 일반화하지 않는다.

첫 실행 뒤 독립 검토에서 비어 있는 주가 관측 주 수에 들어가는 오류를 찾아 고쳤다.
기간 마켓의 추가 방어와 코드/입력 해시의 실행 전후 검증도 추가했다.
no_scoring 비교는 첫 실행 결과를 본 뒤 누락을 보완한 **탐색 비교**다.
다른 후보의 특징과 ridge는 첫 결과를 보고 조정하지 않았다.
어떤 과거 개선이 보여도 이 PR에서 운영 적용은 금지한다.

## 재현

프로젝트 requirements.txt의 Python 의존성을 사용한다. CSV는 원본을 읽기만 하며,
실행 환경에서 DB 모드가 켜져 있어도 RuntimeDatabase를 생성하거나 호출하지 않는다.
결과 JSON은 원본 경로에 쓸 수 없고, 기존 결과를 덮어쓰지 않는다.

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
$env:PYTHONIOENCODING='utf-8'
python src/team_style_experiment.py --games <보관-games.csv-경로> --protocol experiments/team-style-20260907/protocol.json --output <새-report.json-경로> --workers 4
python -m pytest tests/test_team_style_experiment.py -q
```

report.json에는 입력/프로토콜/코드 해시, 실행 라이브러리 버전, 제외 사유,
분기별 표본과 모델 해시, 리그·시장·연도별 성능, 제거 실험, 특징 기여 예시,
팀별 마지막 **경기 전** 프로필이 있다. 해당 팀이 마지막으로 관측된 경기의 날짜이므로
프로필 간 기준일이 다를 수 있고, 현재 날짜의 최신 팀 정보가 아니다.

## 검증 기록

- 같은 입력으로 4개 프로세스 병렬 실행과 1개 프로세스 재실행의 전체 JSON이 정확히 일치.
- 새 회귀 테스트 27개: 날짜 누수, 입력 순서, 리그/시장 분리, 시즌 경계,
  전반/핸디캡 스코어 배제, 표본 축소, 관측 주 수, 제거군 의존성,
  실행 중 코드 변경 시 결과 저장 거부 등을 확인.
- 프론트 테스트 229개 통과 및 격리된 경로의 Vite 빌드 통과.
  프론트 테스트에는 기존 HMR 포트 점유 및 dependency scan 종료 경고가 출력됐지만
  실패한 테스트는 없다. 다른 프로세스를 종료하거나 서버를 재시작하지 않았다.
- 결과 SHA-256: `5cfd9e0b08bf5fbe308890835024fe2c7c246b33286f70dc4e4c75f1662a46a7`.
- Canvas는 TSX 문법 검사를 통과했으며 앱 미리보기 요청을 보냈다.
  실제 Canvas 렌더 화면의 시각 검증은 수행하지 않았다.
