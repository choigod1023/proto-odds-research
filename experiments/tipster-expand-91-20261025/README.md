# 고정 9:1 비교 확장 재현 계약

9:1은 저장 운영 확률 90%와 작성자별 첫 픽 투표 비중 10%다. 비중을 재탐색하지 않는다. 운영 기준·9:1·픽스터 단독을 동일 경기·배당·공식 결과에서 비교한다. 저장 운영 확률은 별도 학습 모델이라는 의미가 아니다.

## 표본과 시점

- 기존 59경기 ID를 제외한 `comparison_new`를 우선 확인한다. 이전 경기의 다른 시점 입력은 새 경기로 세지 않는다.
- `noon`은 기존 정오 ET 규칙을 재현한다. `t30`은 경기 시작 30분 전까지 관측한 별도 조건이다. 표본뿐 아니라 확률·배당·투표 관측 시점도 달라질 수 있다. `input_changes_previous`와 `comparison_previous_events`로 이를 구분한다.
- 모든 결과가 같은 오래된 로그 기간에서 나왔으므로 독립적인 미래 홀드아웃으로 부르지 않는다. 여러 작업 폴더의 로그 복사본을 새 표본으로 세지 않는다.
- Git 커밋 시각과 산출물 생성 시각 중 늦은 시각을 사용한다. 공식 경기 시각·당시 예측·투표 관측이 모두 결정 시점과 맞는지 검사한다. 일정 충돌·결과 누락은 실패시켜 조용히 삭제하지 않는다.
- 공식 일정 응답 본문, 입력/코드 해시, Git snapshot 해시, 전체 기회 원장을 저장한다.

## 2폴의 별도 제약

월 손실 5만 원을 넘기지 않도록 이번 확장 모의에서는 **월 총 투입 원금 5만 원 이하**라는 더 보수적인 한도를 사용한다. 정산 관측 이력을 완전히 복원하지 못했으므로 사후 판정으로 과거 예산을 풀거나 수익금을 재투입하지 않는다. 이는 기존 순손실 기준 재투입 모의와 동일한 규칙이 아니다.

장당 1만 원, 주 최대 2/3회, 같은 회차·서로 다른 경기, 같은 결정 시각에서만 2폴을 고른다. T30에서는 동시에 선택할 수 있는 경기만 묶으므로 전체 경기에서 사후 최적 조합을 고른 결과가 아니다. 선택 후 공식 결과로 정산한다. 손실 한도는 수익 보장이 아니다.
