# 2025 KBO 공식 확정 타순과 실제 선발투수 복원

고정된 비교 계약 `contract.json`의 2025년 736경기를 결과나 배당으로 표본 선택하지 않고 처리한다. 공식 [경기 일정](https://www.koreabaseball.com/Schedule/GameCenter/Main.aspx), `GetKboGameList`, `GetLineUpAnalysis` 및 공식 [경기기록](https://www.koreabaseball.com/Schedule/GameCenter/ReviewNew.aspx)의 `GetBoxScore`를 사용한다. 공식 응답의 원문과 현재 수신 시각은 결과와 함께 보존한다.

계약 SHA-256은 `512c6172eb792ed6e5f7afe7b90d4cfaa0e4087b05e0a497ec7cf9a997cb2480`, 원본 모집단은 PR #511의 `13291d23e855e0d500327cb39ac64a480e395837` 및 `rows.jsonl` SHA-256 `66433dd4706e602befd75f8084ee43eb2e84a54b2657438c37733e3d80531c8c`에 고정했다. 기존 타순 파서와 공식 응답 캐시는 PR #514에서 재사용하며 해당 작업의 상태나 산출물은 수정하지 않는다.

경기 ID·시즌·팀·더블헤더 차전이 맞고 `LINEUP_CK=true`이며 1~9번이 완전한 명단만 공식 확정 타순으로 기록한다. 경기 뒤 나온 타자 첫 9명이나 타순 번호만으로 선발을 추정하지 않는다. 경기 후 기록의 같은 경기·팀·타순·이름은 공식 프로필과 함께 **선수 신원 식별에만** 사용한다. 같은 타순의 후보 ID들을 모두 공식 프로필 이름과 비교해 유일하게 일치하는 경우에만 ID를 붙인다. 대상 경기의 타격 성적·점수·승패는 특성으로 내보내지 않는다.

고정 모집단의 포스트시즌 일부는 경기 ID 연도 자리에 별도 코드가 있다. 공식 일정에서 실제 날짜·팀·차전이 유일하고, 보관 ID와 공식 ID의 월일·팀·차전 부분이 정확히 같을 때만 연결한다. 2023년 독립 감사 `ffe52635f64b51b1b45e59202c4db99b0a528a5d`의 동일한 검증 조건을 참고했다. 점수로 후보를 고르지 않는다.

일정에 표시된 예정 선발투수와 실제 선발을 구별한다. 실제 선발은 동일 경기 공식 투수 기록의 `등판=선발` 표시를 확인하고, 공식 일정의 ID·이름과 대조한다. 실제 인물이 예정 선수와 다르면 같은 경기의 이름·ID 후보 및 공식 프로필로 검증하고, 확인되지 않으면 추측하지 않는다. 투수 `bf`는 사용하지 않는다.

일정과 경기기록의 이름이 달라도 해당 공식 일정 ID의 현재 공식 프로필 이름이 기록과 정확히 같고, 해당 경기의 같은 팀 투수 기록에서 그 이름이 유일하면 동일 ID의 이름 변경 가능성을 근거와 함께 기록한다. 일반적인 문자열 유사도로 개명을 추정하지 않는다. 같은 이름의 투수가 한 경기의 한 팀에서 여러 번 나오고 공식 기록의 선발 ID가 구별되지 않으면 제외한다.

명단은 현재 공식 페이지가 보여주는 확정 타순이다. 과거 당시 발표·수신 시점이나 발표 뒤 실제 타순 변경 여부는 증명되지 않는다. `complete_verified`는 확정 타순의 선수 ID와 실제 선발투수 식별이 완결됐다는 뜻이며, 당시 이용 가능성이나 발표 후 타순 변경이 없었다는 증거는 아니다. 모든 행의 `historical_receipt_proven`과 `eligible_as_pregame_feature`는 false다. 공식 경기 ID에 차전 번호가 포함된 경우, 기존 보관 시작 시각과 현재 일정의 시각 차이는 두 값을 남기고 표시한다. 경기 ID가 없는 동일일 동일 대진 중복은 추측하지 않는다.

요청은 독립 단일 수집기에서 캐시 우선, 최소 1.5초 간격, timeout, 429·timeout 백오프, 신규 직접 요청 상한 2,400회를 적용한다. `capture-state/progress.json`은 실행 중 갱신되며 체크포인트는 작업 전용이다. `collect.py`는 2025 타순을 우선 확보한 다음 공식 경기기록을 처리하고, `export.py --fetch-profiles`는 미확인 프로필을 한도 내에서 추가 확인한다. 원본 경기 자료, 운영 수집기·DB·원장·스케줄은 수정하지 않는다.

## 수집 결과와 인계

- 고정 736경기 전부에서 일정·타순·경기기록 단계를 처리했다. 공식 확정 타순은 731건이고 5건은 `LINEUP_CK=false`여서 최근·기본 명단을 확정 타순으로 사용하지 않았다.
- 확정 타순 18명의 ID와 양 팀 실제 선발투수 ID가 모두 확인된 경기는 **731건**이다. 같은 팀 투수 기록에 `이승현`이 두 명 나타난 5건은 동일 경기의 공식 후보 ID, 두 선수의 공식 프로필·좌우 구분, 날짜·상대가 유일한 공식 일별 기록의 `선발`/`구원` 표시를 대조해 ID `51454`를 선발로 확인했다. 경기 결과나 성적 수치를 사용해 선수를 고르지 않았다. 이 5건의 식별 근거는 `pitcher-daily-identity.json`에 별도 보존했다.
- 포스트시즌 16건의 보관 ID는 공식 일정의 실제 월일·팀·차전이 정확히 같은 연도 대체 표기로 확인했다. 보관 시작 시각과 현재 공식 일정 시각이 다른 9건은 양쪽 시각과 정확한 공식 경기 ID를 남겼다.
- 두 경기에서 일정의 `최채흥`과 공식 기록·현재 공식 프로필의 `최지명`은 공식 선수 ID `68419`로 확인했다. 이는 공식 동일 ID와 정확한 프로필 이름에 근거한 구분이며 문자열 유사도로 추측한 것이 아니다.
- 확정 표시가 없던 5경기는 공식 일정과 타순·경기기록 요청의 시즌·시리즈·경기 ID 및 날짜가 일치했다. 확인한 공식 타자 경기기록 표에는 명시적인 선발타자 플래그가 없어 추정으로 채우지 않았으며, 확인 근거는 `unconfirmed-review.json`에 있다.
- 신규 직접 요청은 1,892회였고 공식 원문과 실패 내역을 `raw-evidence.jsonl.gz`에 보존했다. `actual-lineups-2025.jsonl.gz`의 각 선수는 타순·이름·ID와 공식 명단·경기기록·프로필 SHA 및 수신 시각을 담는다. `identity-candidates-2025.jsonl.gz`에는 같은 경기의 이름·ID·타순 후보만 있고 성적 수치는 없다. 미확인 항목은 null과 이유를 유지한다. 압축 파일과 압축 해제 내용 해시는 `manifest.json`, 기계 판독용 인계는 `handoff.json`에 있다.

`python -X utf8 -m unittest discover -s experiments/kbo-actual-lineups-2025-20261103 -p 'test_*.py' -v`는 공식 확정 플래그, 날짜 별칭, 동명이인, 선발 표기, ID·프로필과 전체 원문 해시, 요청 간격 및 대상 경기 성적을 ID 이외 특성으로 쓰지 않는 경로를 검사한다. 이 파일은 명단 복원 결과이며 예측·적중률·ROI 분석이 아니다.
