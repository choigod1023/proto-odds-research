# 첫 반복 실험: 진행 기록

## 결론

K1의 다음 경기 슈팅을 예측하는 고정 ridge 후보는 **추천 모델로 확대하지 않는다**.
2025년~2026년 338경기 평가에서 단순 최근 평균은 앞섰지만, 상대 허용 슈팅까지
평균낸 간단한 기준을 확실히 넘지 못했다. 2026년만 보면 그 기준보다 나빴다.
이 실험의 목표는 슈팅 수이므로 여기서 승패 적중률 상승을 주장할 수 없다.

## K1 평가

- 원본 816경기에서 승강전 12경기를 먼저 제외했다. 2023~2025년 각각 228경기,
  2026년 120경기다. 고유 경기 번호·시즌별 12팀×38경기와 시즌 종료 후 번호 초기화를 확인했다.
- 최소 과거 5경기를 요구한 뒤 학습 421경기, 평가 338경기/128날짜.
  학습은 2023~2024년, 평가는 2025-02-15~2026-07-26이다.
- 상대별 최근 10경기 슈팅/유효슈팅과 홈 여부를 사용했다.
  날짜 D의 입력은 D−2일 이전 기록만 사용한다. 실제 공개시각 검증은 아니다.
- 슈팅 MSE: 최근 평균 19.7086 → 상대 포함 평균 18.3262 → 후보 17.9419.
  강한 기준 대비 오차 감소 0.3843의 날짜 bootstrap 99% 구간은 −0.4378~1.2084.
- 유효슈팅 MSE: 최근 평균 8.3190 → 상대 포함 평균 7.6329 → 후보 7.5415.
  강한 기준 대비 감소 0.0914의 구간은 −0.1963~0.3924.
- 2026년 115경기에서는 후보 슈팅 MSE 16.1820 대 기준 15.9896,
  유효슈팅 7.6796 대 기준 7.4527로 둘 다 악화됐다.

구간은 반복 탐색을 보정한 확증 검정이 아니다. 기존에 연구에 사용한 과거 구간이며,
공급자의 선수 통계 누락이 0으로 합산되는 한계도 있다. 정산 점수와 선수 득점 합계가
다른 경기가 50개여서 이를 무비판적으로 교환해서 사용하지 않았다.

## 다음에 실행할 별도 가설

단순 평균을 입력하는 회귀 대신 **상대 강도를 함께 추정하는 공격·수비 동적 count 모델**을
검증한다. 아직 실행하지 않았다. 동일 가설의 패널티 탐색으로 바꾸지 않는다.

- 타깃: K1 총 슈팅. SOG는 공급자 정의 확인 전 보조 진단으로만 둔다.
- 식: log(기대 슈팅) = 절편 + 홈 효과 + 팀 공격력 + 상대 허용 능력.
- 고정 설정: 직전 365일, 90일 반감기, 날짜 D−2일까지, team-effect L2=0.1
  (가중 평균 Poisson 음의 로그우도에 가산), 최적화 최대 300회.
- 두 팀 관측과 동일 날짜를 함께 묶는다. 연도별 결과를 각각 보고한다.
- 기본 최근 평균과 상대 포함 평균 모두를 비교한다. 실패하면 승패 단계로 연결하지 않는다.
- 그 다음에는 더 많은 회귀 변수를 추가하기보다 원본 통계의 완전성과 공개시각을
  검증할 수 있는 다른 리그의 장기 공개 데이터 확보 가능성을 우선 조사한다.

## 재현과 기록

```powershell
python src/soccer_process_gate.py --source data/raw/detail/kleague_shots_2023_2026.json --database outputs/process-gate/research.sqlite3 --report experiments/process-gate-20260909/new-report.md
python -m pytest tests/test_soccer_process_gate.py -q
```

동일 데이터·코드·설정의 재실행은 DB의 고유 서명이 차단한다. 위 재현 명령은 기존 원장에서는
차단되는 것이 정상이며, 독립 검증 환경에서는 새 DB 경로를 지정한다.
원본이 바뀌면 리그/품질 재감사를 요구한다.

`soccer.md`는 첫 실행, `soccer-verified.md`는 Windows SQLite 핸들 종료 수정 후의
기술적 재실행이다. 두 결과는 같으며 **두 독립 실험으로 세지 않는다**.
private SQLite에는 코드·입력 해시, 설정, 상태, 경기별 예측과 관측값이 저장된다.
원장은 `outputs/process-gate/research.sqlite3`이며 Git에 올리지 않는다.

방법의 출발점은 [Wheatcroft 2021](https://journals.sagepub.com/doi/10.3233/JSA-200462)의
경기 통계를 먼저 예측하는 접근이다. 이번 구현은 논문의 GAP/BA를 그대로 복제한 것이 아니다.
