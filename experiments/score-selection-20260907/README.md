# 득점 분포와 실제 추천 조건을 결합한 과거 실험

## 질문과 범위

최근 득실 특징으로 배당 확률을 보정한 #211/#212와 달리, 팀별 공격·수비와 홈 효과로
점수 분포를 추정하고 그 확률에서 경기별 픽과 오늘의 추천을 다시 고른다.
추천을 고르기 전 전체 시장의 정확도와 **추천을 고른 뒤의 적중률**을 구분한다.

이 PR은 원자료 정규화와 확인된 점수 추출을 재사용하므로 #211에 의존한다.
#212의 정규화 선택 모델에는 의존하지 않는다. 운영 가중치·DB·수집기·서버·배포는 바꾸지 않는다.
`production_allowed=false`는 결과가 좋아도 바뀌지 않는다.

## 현재 추천 조건의 실행

`scripts/replay_recommendation_policy.mjs`가 다음 실제 프론트 함수를 import한다.

- `recommendation-policy.js::finalRecommendedSelection`: 경기당 한 선택.
  홀짝, 유효하지 않은 배당, 2.20 이상, 같은 마켓의 최유력이 아닌 선택 제외.
  1.50 이상 우선, 없으면 1.00 초과~1.50 미만 보조. 확률→시장확률→낮은 배당→ID 정렬.
- `unified-recommendation.js::dailyHighlightedSelections`: KST 날짜·리그별로 55% 이상만 후보.
  해당 리그·날짜에 1.50 이상 적격 후보가 있으면 저배당 보조는 제외한다.
  기본 상위 3개, 그 밖에는 60% 이상을 추가한다. 강제 3개 채우기나 전체 개수 상한은 없다.
- 실험에서는 서로 다른 종목의 같은 리그 이름을 섞지 않도록 종목별로 호출한다.
  동일 경기는 앞 단계에서 한 개로 줄인다. 배당/확률 구간은 실험 결과에 맞춰 바꾸지 않는다.

모델 확률만 바꾸어 같은 함수에 전달한다. 이 입력은 연구용 가상 확률이며 운영 승격 조건을
통과했다는 표식을 만들지 않는다. Node 경계에는 정답·승패 판정·수익을 전달하지 않고,
선택 ID가 반환된 뒤 Python에서 공식 결과를 연결한다.

현재 main의 기본 운영 확률은 Shin 시장 확률(실패 시 비례 정규화)이다. 모델 확률은
별도의 승격 증거·해시 허용 목록 등이 필요하며 현재 목록은 비어 있다. 따라서 시장 확률에
현재 추천 조건을 적용한 것을 비교 기준으로 삼았다. 이는 실제 과거 사이트 픽의 복원은 아니다.

## 다섯 가지 비교

1. `market`: 현재 기준 확률 + 현재 추천 조건.
2. `score`: 새로운 득점 분포 확률 + 같은 추천 조건.
3. `blend`: 과거 내부 검증에서 선택한 시장/득점 확률 혼합 + 같은 조건.
4. `selector_market`: 시장 관련 정보로 최유력 선택의 적중 가능성을 학습 + 같은 조건.
5. `selector_score`: 시장 정보에 득점 모형과의 차이를 추가한 적중 가능성 학습 + 같은 조건.

4번은 5번의 개선이 실제 경기 득점 정보에서 온 것인지, 단순 시장 확률 보정인지 구분하는
대조군이다. 5번 대 4번의 직접 비교도 동일한 블록 검정과 전체 Holm 보정에 포함한다.
득점 선별기의 과거 개선 신호에는 이 직접 비교 통과도 요구한다.
이번 추천 선별은 출력 확률로 기존 문턱·순위를 통과시키는 방식이다.
새로운 임의의 관망 규칙이나 추천 개수 목표를 운영 코드에 추가한 것은 아니다.

## 득점 모델과 시간 순서

- 종목·리그별 독립 학습. 2023-01-01부터 확인된 정수 풀타임 점수만 사용한다.
- 예측 분기 시작 7일 전 미만, 최대 과거 730일, 반감기 180일로 가중한다.
  최소 100실경기, ridge 20을 고정한다. 선택 결과를 본 뒤 조정하지 않는다.
- 팀 공격·수비·홈 효과와 리그 평균 offset. 모든 계수에 ridge를 적용한다.
- 축구: 독립 Poisson. 야구: Poisson 평균 회귀와 과거 잔차로 추정한 NB2 분산,
  과산포가 없으면 Poisson. 농구: 가중 ridge 평균과 훈련 잔차 표준편차의 이산 정규분포.
- 같은 결합 점수 분포에서 승패·승무패·언더오버·2/3-way 핸디캡을 산출한다.
  2-way의 무승부·정수 라인 push는 조건부 확률에서 제외한다.
- 점수 격자는 꼬리 질량 오차를 확인하며 적응적으로 확장한다. 가격 계산 실패나
  수치 최적화 실패로 불리한 행을 누락하지 않고 전체 실험을 실패시킨다.
- 득점 분포는 홈/원정 독립 근사다. 공격·수비 평균은 팀별이지만 분산은 리그 공통이다.
  선발 구간/불펜 이닝, possession, 라인업, xG를 모델링했다고 부르지 않는다.
  이 정보의 과거 스냅샷이 없기 때문이다. 배구 세트 점수로 풀타임 포인트를 대체하지 않는다.
- 분기별 계수 재학습이므로 같은 분기 안의 팀 상태 변화는 반영하지 못한다.
  이는 계산량을 제한한 첫 기초 실험의 한계다.

2024년 시간순 외부 예측으로 혼합 비중과 선별기를 만든다. 사용 가능한 마지막 날짜는
2024-12-25 미만이다. 이 설정/계수는 2025-01-01~2026-08-25 평가에서 동결한다.
득점 모델 계수만 위의 과거 자료 조건으로 분기별 다시 학습한다.

혼합 후보는 득점 확률 비중 0/0.1/0.25/0.5/1이며 내부 평균 log loss 최소를 선택한다.
선별기는 시장 logit을 offset으로 한 ridge 20 이진 로지스틱 모델이다. 훈련 자료로만
중심/표준편차를 정하고 ±5로 제한한다. 시장 logit, log 배당, 마진, 최유력 격차,
시장 엔트로피를 사용한다. 득점 선별기만 득점-시장 logit 차이, 확률 차이 절대값,
득점 모델 사용 가능 여부를 추가한다. 실제 데이터 누락·선발 미확정 판정을 임의로 생성하지 않는다.

혼합/선별 모두 종목·리그·시장·선택지 수별 독립이다. 내부 검증 300시장·150경기·
26관측주가 부족하면 시장 기준으로 돌아간다. 선별기는 유효 배당 최유력 후보만 학습하고,
적중/실패 각각 20개 이상이 필요하다. 표본 부족과 성능 저하를 구분한다.

## 표본과 당시 가용성의 한계

원본 CSV는 읽기 전용이다. 중복·상충 가격/결과·미지원 시장을 명시적으로 처리하고,
시장 라벨을 유지한다. 취소 경기라도 유효 가격이 남아 있으면 추천 전에 제거하지 않는다.
정산 시 적중률에서는 제외하고 수익률에서는 환불(0수익)로 계산한다.
취소로 가격이 1.00 등으로 지워진 경우 당시 가격을 복구할 수 없다.

원자료에 배당 관측 시각·발매 가능 여부·취소 발표 시각·전체 일별 후보·T-30 동결 revision이
없다. 같은 날짜의 보관 후보들이 사전에 알려졌다고 가정한다. 운영의 오늘~내일 정오 검색과
시작/라이브 보존, 여러 시점의 후보 갱신을 재현하지 않는다. 같은 날 후보가 완전하지 않으면
리그 순위와 보조 배당 여부도 달라질 수 있다. **현재 정책을 적용한 회고 모의 추천**이지
당시 실제 오늘의 추천 적중률 또는 경기 전 완전 재현이 아니다.

2025~2026년은 이전 연구에서 이미 본 데이터다. 이번 실행의 내부 시간 분리를 지켜도
연구자가 결과를 알고 모형을 고른 영향까지 없앨 수 없다. 미래 적중률 상승을 보장하지 않는다.

## 적중률 상승 판정

- 현재 조건 그대로의 추천: 적중/정산 수, 추천 수, 추천 일수, 평균 배당, 저배당 비중,
  동일 금액 단식 ROI를 비교한다. 조합 베팅 수익률이 아니다.
- 추천 전 공통 시장행: 시장/득점/혼합의 다중분류 Brier·log loss·최확률 적중률.
  이진 적중 선별 확률을 다중분류 확률 벡터로 오인하지 않는다.
- 동일 수/가격 대조: 같은 날짜·종목·리그·시장·선택지 수·0.10 배당 구간 안에서
  시장 기준의 경기별 후보를 시장 확률순으로 맞춘다. 정답을 보지 않고, 경기 중복 없이
  같은 수를 선택한다. 매칭 못한 후보 비율을 공개한다. 이는 정확히 같은 가격이나
  수정 없는 하이라이트 정책이 아니라 추천 수/시장/배당 편향을 확인하는 진단이다.
- 종목/리그/전체의 추천 정책 비교와 매칭 비교에 대해 4주 원형 달력 블록 bootstrap
  10,000회로 적중률 차이·ROI 차이·평균 배당 차이 95% 구간을 구한다. 같은 블록에서
  후보/기준의 성공 수와 분모를 각각 재계산한다. 빈 주를 유지한다.
- 적중률 차이의 중심화 근사 p값을 모든 범위·후보·비교 방식에 대해 Holm 보정한다.
  개별 행 독립이나 서로 다른 추천 수에 동일 분모를 가정하지 않는다.
- 과거 개선 신호 조건: 정책/매칭 모두 적중률 개선 CI 하한>0 및 보정 p<0.05,
  각 비교 측 300정산 픽·26관측주 이상, 추천 수와 추천 일수 최소 95% 유지, 평균 배당 하락 최대 0.02,
  매칭 유지율 80% 이상, 평가 대상 두 연도 모두 적중률 개선.
  신호가 있더라도 운영 승격은 별개이며 항상 금지한다.

## 재현

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
python src/score_selection_replay.py --games <보관-games.csv> --protocol experiments/score-selection-20260907/protocol.json --output <새-report.json> --workers 4
python -m pytest tests/test_score_replay_model.py tests/test_score_selection_replay.py tests/test_replay_policy_bridge.py -q
```

입력/프로토콜/관련 소스 해시를 실행 전후 비교한다. 코드가 도중에 바뀌거나 출력이 이미
있으면 보고서를 덮어쓰지 않는다. Node 설치가 필요하지만 별도 패키지 설치 없이 정책을 호출한다.
실제 운영 파일을 가져오므로 정책 함수가 바뀌면 동일 입력이어도 다른 실험이 된다.
