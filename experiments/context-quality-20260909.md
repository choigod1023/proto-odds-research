# 슈팅 질·상황 데이터와 선수별 과거 이력 — 실제 실행 기록

## 범위

운영 모델을 바꾸지 않고 무료 공개/공식 데이터를 private SQLite에 확보하는 연구다.
예약 실행 없이 현재 대화에서 수집·검증·평가를 수행했다. 이 PR은 이전 PR218과
독립적인 데이터 파이프라인이며, 미병합 연구 변경을 운영 main에 적용하지 않는다.

## 축구: 수집과 복원 완료

출처: [StatsBomb Open Data](https://github.com/hudl/open-data).

원본 시즌은 EPL 2015/16의 380경기, 20팀 각 38경기로 확인했다. 최근 공개 분데스리가
2023/24 목록은 부분 표본이므로 완전 리그 학습용으로 채택하지 않았다.
K리그에 이 결과를 그대로 적용하지 않는다.

- 날짜순 2015-08-08~08-24의 첫 **30경기·785슈팅** 수집.
- 경기 목록 포함 **31요청·89,567,824바이트**. 호출당 요청/용량 상한을 지켰다.
- 원본 응답 URL·실제 수집시각·HTTP 상태·SHA256·본문을 SQLite에 저장했다.
- 슈팅 직전 점수 차, 인원 차, 홈/원정, 시간, 위치, 신체 부위, 공격 전개,
  페널티 여부, 공급자 xG와 골 여부를 분리했다.
- 골이 된 슛에도 득점 **이전** 점수 상태를 사용한다. 자책골 쌍을 중복 계산하지 않는다.
- 두 번째 경고/직접 퇴장을 중복 계산하지 않는다. 시작 명단·교체를 추적해 벤치 퇴장을
  경기장 인원 감소로 계산하지 않는다.
- **30/30경기 최종 점수 복원 일치**, 잘못된 xG를 0으로 대체하지 않음.
- 최종 파서로 원본을 오프라인 재복원해 785개 슈팅 행이 모두 동일함을 확인했다.

원본·선수별 상세 데이터는 Git에 올리지 않는다. 자료 공개 조건은 데이터 출처와 로고
표기를 요구하며, 제공된 연구용 자료가 현재 서비스의 상업적 이용 허가를 자동으로
의미하지는 않는다. 운영 사용 여부는 별도 검토 대상이다.

## 축구: 시간 분리 파일럿도 실행

비페널티 슈팅만 사용했다. 첫 20경기/486슈팅으로 학습하고, 뒤의 10경기/293슈팅
(3날짜, 2015-08-22 이후)으로 평가했다. 시험 구간 골은 20개다.

- 학습 골 비율을 모든 슈팅에 적용한 기준: Brier **0.064634**, 로그손실 **0.255487**.
- 공급자 슈팅별 xG: Brier **0.051953**, 로그손실 **0.196038**.
- xG에 절편 보정만 추가: Brier **0.052713**, 로그손실 **0.199965**.
- xG에 점수·인원·시간·홈 여부를 추가: Brier **0.053173**, 로그손실 **0.202552**.

이 작은 파일럿에서는 슈팅의 질을 구분하는 xG가 단순 평균보다 낫지만,
**우리가 추가한 상황 보정은 xG 단독보다 나빴다.** 채택하지 않는다.
고정 L2=10, 날짜 단위 70/30 분리이며 파라미터 탐색을 하지 않았다.

### 해석의 경계

이것은 **이미 발생한 슈팅이 골이 될 확률**의 진단이다. 해당 경기의 슈팅 위치·당시
점수·퇴장은 경기 전에 알 수 없다. 따라서 경기 전 승패나 추천 적중률 실험이 아니다.
공급자의 xG 모델이 어느 시점 데이터로 학습됐는지도 증명되지 않았다.
785슈팅을 785개의 독립 경기로 세지 않는다. 실제 독립 평가 날짜는 3개뿐이다.

득점/퇴장 상태별 슈팅 수와 xG 집계는 만들었지만, 상태별 노출 시간을 나누지 않았으므로
‘뒤질 때 슈팅을 더 많이 한다’ 같은 경기당/분당 발생률의 근거로 사용하지 않는다.
팀 경기력 보정에는 상태별 노출 시간과 상대 팀 효과, 다음 경기 이전 기록만 쓰는
추가 모델이 필요하다. 첫 3라운드 데이터만으로 시즌 전체 전력 모델을 학습하지 않는다.

## 야구: 선수별 과거 이력 확보 완료

공식 MLB StatsAPI에서 2024년 정규시즌과 2025-05-31까지의 타격·투구 기록을
별도 수집했다. **9요청·4,403,771바이트·2,821 선수/기간 기록**이다.
기간·역할별 최다 표본 선수의 날짜별 경기 로그와 합계를 대조한 4개 검사는 모두 일치했다.
이는 표본 날짜 검증이지 모든 선수의 당시 공개 시점까지 증명한 것은 아니다.

기존 30경기 캐시에서 6월 2~3일 평가 대상 1,177타석의 과거 기록 공백은 다음처럼 줄었다.

- 투수: **994 → 15타석**.
- 타자: **161 → 9타석**.

기록 확보율 개선과 예측력 개선은 다르다. 이 수치만으로 승패 적중률 상승을 주장하지 않는다.
집계 API는 기타 아웃과 실책·야수선택 출루를 분리하지 못하므로 기존 6분류 타석 평가에
임의로 끼워 넣지 않았다. 구체적인 검증·실행 경로는
[야구 수집 보고서](mlb_player_history/report-20260909.md)에 정리했다.

### 야구: 확보한 기록으로 타석 예측까지 재실행

기타 아웃과 잔여 출루를 `otherPA`로 합쳐 **빠짐없는 5분류**로 비교했다.
기존 2,247타석을 보존했고 모든 모델의 평가 대상은 6월 2~3일 15경기·1,177타석으로 같다.
2024년과 2025-05-31까지의 이력만 초기값에 쓰고, 6월 1일을 준비 구간으로 두었다.
같은 날짜의 예측을 모두 끝낸 뒤 기록을 갱신하며, 선수별 사전 강도는 100으로 고정했다.

- 과거 리그 평균: 로그손실 **1.322904**, 다분류 Brier **0.684605**.
- 과거 타자·투수 기록 결합: 로그손실 **1.307487**, Brier **0.679517**.
- 차이: 로그손실 **−0.015417**, Brier **−0.005087**. 두 평가 날짜에서 각각 개선됐다.

따라서 단순히 가중치를 더하는 것보다 **선수별 이력 공백을 해소하는 방향에는 개선 신호가 있다**.
다만 실제 출전한 타자·투수의 타석 결과 진단이다. 사전 라인업 예측이나 경기 승패 평가가 아니며,
두 날짜만으로 통계적 유의성·장기 성능·추천 적중률 상승을 확정하지 않는다.
[전체 결과와 감사 기록](mlb_player_history/five-class-report-20260909.md)을 별도로 남겼다.

## 이번 판단과 후속 검증 기준

- 야구: 선수별 이력 기반을 유지한 후보를 더 긴 미사용 기간에서 먼저 검증한다.
  이후 경기 전 확인 가능한 선발·라인업·불펜만으로 경기 결과 확률을 만들고,
  기존 추천 조건을 똑같이 적용한 적중률·추천 수·확률 오차를 비교해야 한다.
- 축구: 이번 단순 상황 보정은 채택하지 않는다. 슈팅 질을 다음 경기 이전의 팀 기록으로
  집계하고, 점수·퇴장 상태의 노출 시간과 상대 강도를 보정하는 단계가 필요하다.
  EPL 파일럿 결과를 K리그 성능으로 대체하지 않는다.
- 어느 종목도 이번 결과만으로 운영 가중치를 변경하지 않는다. 재사용한 작은 평가 구간에서
  반복 선택한 결과와 새 미사용 기간 검증을 구분한다. 예약·크론·배포는 추가하지 않았다.

## 재현

```powershell
python src/shot_context_pilot.py --output outputs/shot-context-20260909 --limit 30
python src/shot_quality_evaluation.py --source outputs/shot-context-20260909/pilot.sqlite3 --output outputs/shot-quality-evaluation-20260909
python -m pytest -q
```

출력 경로는 새 디렉터리여야 한다. 기존 경로를 덮어쓰지 않는다. 다시 수집하는 대신
저장된 원본으로 파서를 먼저 재검증한다. 수집기는 최대 45요청·100MB, 경기당12MB이며,
HTTP 오류·403·429에서 재시도 없이 중단한다.

private DB:

- `outputs/shot-context-20260909/pilot.sqlite3`: raw, matches, shots, run.
- `outputs/shot-quality-evaluation-20260909/evaluation.sqlite3`: 메타데이터·평가·예측.
