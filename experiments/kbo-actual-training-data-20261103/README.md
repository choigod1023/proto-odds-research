# 실제 명단 기반 KBO 학습 입력

상태: 수집 중. 고정된 명단 결과와 최종 handoff가 나오기 전까지 이 브랜치의 임시 수집 결과를 다른 작업에서 사용하지 않는다.

상위 계약은 `parent-contract.json` SHA-256 `512c6172eb792ed6e5f7afe7b90d4cfaa0e4087b05e0a497ec7cf9a997cb2480`, 원본 커밋 `c5407e9b`다. 2023년 723경기에서 기존 공식 응답·프로필 캐시를 우선 재사용하고 공식 확정 타순과 공식 실제 선발 표시를 확인한다. 2026년 고정 709경기도 실제 선발을 검증한다. 예정 선발과 실제 선발은 별개이며 다르면 공식 실제 기록과 선수 프로필로 식별 가능한 경우에만 변경을 기록해 보존한다. 일치하지 않거나 선수 ID가 모호한 경우 사유와 함께 제외한다.

요청은 최대 2,400회, 개별 워커의 요청 간격은 최소 1.5초다. 캐시, 타임아웃과 429/서버 오류 백오프, 실제 수집 시각, 원문 SHA 및 실패 사유를 보존한다. 수집 진행 상태는 `.research-state/kbo-actual-2023/progress.json`과 경기별 JSONL 체크포인트에 기록된다. 당일 선수 기록은 명단 ID 식별에만 사용할 수 있으며 수치·점수는 특징에 사용하지 않는다. 발표 및 수신 시점 증명은 0건이다.

`collect_lineups.py`는 기존 고정 연구 코드를 격리 공간에 복사한 뒤 요청 간격과 백오프·상태 기록을 추가했다. `collect_actual_starters.py`는 일정상 ID를 공식 실제 경기의 유일한 선발 표시와 교차 검증한다. `seed_2026_cache.py`는 해시 고정 공식 기록 256개를 재사용한다. `paired_core.py`와 `history_index.py`는 이전 날짜의 동일 최근 10개 완전 선수 이력으로 실제/추정 입력을 나란히 구성할 준비 코드다. `test_pinned_history.py`는 기존 선수 이력과 독립 재구성 결과를 대조한다.

수집 후 검증된 소스·경기별 제외 사유·원문 번들·해시를 고정하고, 다른 연도의 최종 커밋을 받은 뒤에만 공통 입력을 통합한다. 모델 적합·성능 계산·운영·병합·배포는 이 작업의 범위가 아니다.
