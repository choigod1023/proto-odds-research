# 2024 고정 예측과 전향 staging 독립 감사

## 2024 고정 예측

구현 `008668cfa429b3991ff9273b4c2a3df517206839`과 예측 `7f06e76dfe77cbb3dd7d9395995133effdb1b66a`를 검사했다. 2023 학습 723경기와 2023 전용 레이블만으로 baseline·shrink·NB 0.3을 다시 적합하고 2024 실제 명단 728경기 각각의 예측을 독립 수식으로 재생했다. 세 모델 2,184개 예측의 최대 확률 차이는 `3.33e-14` 미만이고, 무조건 3방향의 고정 1/3 평균과 그 뒤 조건부 승패 정규화 728건도 일치했다. fit 전용 표준화·선수 사전, 고정 L2, 목적함수와 기울기를 대조했다.

고정된 `historical/run.py`는 기존 `core.load()`나 기존 미래 학습 계수를 사용하지 않고 전용 2023 레이블을 연다. 이를 확인하기 위해 독립 재실행 프로세스에서 Python 파일 접근 감시를 걸어 2024·2025 결과가 포함된 `development-labels.jsonl.gz`, 미래 학습 baseline reference 및 평가·가격 파일을 차단했다. 차단 기능 자체를 두 번 시험한 후 실제 적합·예측 경로에서 금지 파일 접근 시도는 0건이었다. Python 접근 감시와 고정 코드의 로컬 재실행에 관한 증거이며 외부 독립 타임스탬프 인증은 아니다. 공통 패키지 자체는 여전히 여러 연도 레이블을 담고 있으므로 다른 호출자가 `core.load()`를 사용하면 접근 범위가 다시 달라진다.

2024 예측 SHA-256은 `2643db9ee19e01de8a31ac13316ad0b2c05366ccf5ffb911b4b8b865a0d4f92b`, 모델 SHA-256은 `6efad3c7f2ac7a966f65d377a6e1030d4ec957b3c8a7d8e9adcc0cb4c23f35dd`다. 2024 결과·가격은 이 감사에서 읽지 않았다. 2024는 2025에서 선택한 레시피를 이미 본 이전 기간에 적용한 후향 진단이며 새로운 holdout이 아니다.

## 전향 staging 코드: 시점 조건 두 건 보강 필요

고정 구현 `afa78bf63326e68a579038da5b82009f834ce82e`에 대해 합성 입력과 임시 원장으로 다음 두 반례를 재현했다. 현재 staging 기록은 모두 `eligible_for_effectiveness_validation=false`이고 검증된 전향 표본은 0이므로, 이 문제가 이미 공식 전향 성과에 유입됐다는 뜻은 아니다.

1. **경기 시작 정확히 30분 전 허용**: `forward.py`의 캡처 검사와 예측 완료 검사는 `>`를 사용하므로 `kickoff−30분` 정각이 통과한다. 사용자의 ‘그보다 빨라야’ 조건을 엄격히 적용하려면 정각도 거부해야 한다. 최초 수신과 예측 완료 양쪽 경계를 함께 검사해야 한다.
2. **이력의 미래 수신 시각 허용**: 선수 이력의 경기 날짜가 이전인 상태에서 해당 특성의 `received_at`을 캡처 다음 날로 바꿔도 통과했다. 날짜만 과거라는 사실은 그 통계나 정정본을 캡처 시점에 수신했다는 증명이 아니다. 제공된 이력·정정 수신 시각이 캡처 이후면 거부하고, 시각이 없는 이력의 미확인 상태를 명시해야 한다. 공식 원문과 정규화 값의 신뢰성은 별도 trusted adapter 검증이 필요하다.

현재 코드는 경기 전 공식 발표 선발을 허용하고 `postgame_actual_start_verified`를 거부한다. 합성 검사에서 당일 이력·잘못된 본문 해시·다른 상품·동일 상품 재캡처·경기 전 결과 기록을 거부했고, 무승부와 취소는 환급으로 기록했다. 첫 기록을 덮어쓰는 정산 정정은 거부되지만 별도 정정 기록 경로는 아직 없다. staging 원장에는 가상 단위 손익이 저장되지만 해당 기록은 비적격이며 `status`는 인증된 쌍 0·정식 점검 불가를 반환하고 ROI를 표시하지 않는다.

URI, 호출자가 제공한 canonical JSON과 그 SHA, 로컬 해시 체인만으로 공식 사실이나 외부 인증된 수신 시각을 입증하지 않는다. 특히 코드의 `local_receipt_proves_input_timing_not_source_authenticity` 문구는 로컬 시계에 기록된 시간 이상의 외부 증거로 읽히지 않도록 보강이 필요하다. 실제 구매·체결 증거도 없다. trusted source adapter 연결과 사용자 요청의 200정산 쌍·8주 조건은 아직 구현 검증 대상이다.
