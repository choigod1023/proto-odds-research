## 조회 및 한계

- 공식 [KBO 경기정보](https://www.koreabaseball.com/Schedule/GameCenter/Main.aspx)의 `POST /ws/Main.asmx/GetKboGameList`를 날짜별로 호출했다. 기존 검증 수집기와 같은 `leId=1`, `srId=0,1,3,4,5,6,7,8,9`, `date=YYYYMMDD`를 사용했다. 예정 6경기는 공식 `POST /ws/Schedule.asmx/GetLineUpAnalysis`에 해당 일정의 `leId`, `srId`, `seasonId`, `gameId`를 전달했다.
- 총 직접 요청은 20회(일정 14, 타순 6), 성공 20회다. 요청 간 최소 1.5초, 연결 timeout 5초·읽기 timeout 15초, 429·timeout 백오프, 최대 20회 제한을 적용했다. 실패가 있었다면 원인과 시각을 기록하도록 구현했다.
- `requests.json`에 실제 URL, 매개변수, UTC 요청·수신 시각, 상태와 원문 SHA-256이 있다. `evidence/*.body.gz`는 원문 바이트의 압축본이며 해시는 압축 해제 바이트 기준이다. `observations.json`은 경기·상태별 분류와 날짜별 응답을, `manifest.json`은 두 파일의 해시와 수집 범위를 고정한다.
- 확정 타순을 받아도 과거 실제 수신 시각이나 발표 이후 변경 여부를 소급해서 증명하지 않는다. 이 조회에서는 미래 타순 6건 모두 확정되지 않았다. 전향 입력에 필요한 배당 원천도 연결하지 않았으므로 모의 예측을 실행하거나 검증했다고 볼 수 없다. 지난 완료 경기 3건은 후속 연결 가능성만 확인했으며 경기 결과 재수집이나 성적 실험은 하지 않았다.
- `python -X utf8 experiments/kbo-m0-followup-20261103/sources/probe.py`는 저장된 응답을 해시 확인 후 재사용하므로 이 스냅샷의 오프라인 재생성이다. 현재 시점의 실시간 재확인이 아니다. `python -X utf8 -m unittest discover -s experiments/kbo-m0-followup-20261103/sources -p 'test_*.py' -v`는 원문 해시, 20회 제한, 간격, 14일·경기 ID 분류와 미확정 명단 처리를 검사한다. 자동화, 운영 스케줄, DB와 기존 원장은 변경하지 않았다.
