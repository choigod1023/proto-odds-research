## 초록

한국 프로토(체육진흥투표권 고정배당) 시장에서 **시장 가격을 이기는 우위를 찾을 수
있는가**를 물었다. 4년치 565회차를 수집해 가설을 시간순으로 검정했다.

**우위는 찾지 못했다.** 필요한 우위는 6.8%p 인데 동원 가능한 정보와 구조 선택을
모두 합쳐도 4.8%p 였다. 문헌상 세계 최고 수준의 베팅 엣지(+2~5%)를 그대로
가져와도 프로토 마진 12% 앞에서는 −7% 가 된다.

대신 **예측 없이 손실을 줄이는 방법**을 정량화했다. 다리 수를 줄이면 8.9%p,
최저배당 상한을 두면 적중률이 65.9% → 77.6% 로 오르면서 손실도 함께 준다.
전부 마이너스라는 점은 변하지 않는다.

부수적으로 **연구 과정에서 만든 가짜 발견 6건과 데이터 처리 결함 4건**을 기록했다.
이 프로젝트에서 가장 재사용 가능한 산출물이다.

> **2026-08-26 인과 감사:** 같은 날짜 결과 순서·경기시각 식별·과거 추천 재구성
> 누수를 고쳤다. 이전 findings 문서는 정정 표시가 없는 한 탐색 기록이며 운영 승격
> 근거가 아니다. 현재 공식과 승격 판정은 [적중률 공식 워크포워드](findings/적중률_공식_워크포워드.md)를 정본으로 삼는다.
> AI는 시장확률을 덮어쓰지 않고 새 정보의 잔차만 검증한다. 역할 분리, 선수 정보식,
> 승격 관문과 화면 계약은 [AI 적중률 통합 설계](findings/AI_적중률_통합_설계.md)에 고정했다.
> 여러 마켓 중 하루 한 픽을 고르는 유전 알고리즘은
> [자연선택 추천기 검증](findings/자연선택_추천기_검증.md)에 별도로 기록했다.

### 1.3 무료 경기 컨텍스트와 쏠림 분해

정배를 같은 방향으로 지지한다는 이유만으로 새 정보를 채택하지 않는다.
`src/free_context_eval.py`는 프로토 확률·독립 경기모델·시장 offset 모델을 분리하고,
시장 대비 검증 손실이 실제로 개선될 때만 예측 변수로 인정한다.

- `src/weather_watch.py`: API 키 없는 Open-Meteo K리그·KBO·NPB·MLB 경기장 예보를 관측시점별 보존
- `src/weather_features.py`: 예측 cutoff 이전 예보만 골라 킥오프 시간에 결합
- `src/context_features.py`: 휴식·최근 일정·이동거리·선수 workload 무료 파생
- `src/free_context.py`: `valid_at/observed_at/fetched_at` 및 쏠림 분해 정본
- `src/baseball_context_watch.py`: KBO·NPB·MLB keyless 공개 데이터의 선발 K-BB/9,
  상대 성적, 최근 팀 득실, 라인업 확인/변경을 append-only로 관측
- `src/pickster_watch.py`: TailSlips 공개 HTML의 MLB X 픽과 군중을 관측(`/api/` 미사용)
- `src/pickster_eval.py`: 최근 30일 화면 단면과 우리 수집 이후의 전향 성과를 분리
- `src/baseball_live_features.py`: 날씨·경기 내부 정보·픽스터 군중을 경기 날짜까지 맞춰 결합
- [1차 검증 결과](findings/무료_컨텍스트_쏠림분해.md): 현재 일정·이동 묶음은 시장을
  개선하지 않아 설명용으로만 유지
- [야구 3리그 검증](findings/무료_야구_컨텍스트_쏠림분해.md): KBO·NPB·MLB 모두
  일정·선발 컨텍스트의 시장 대비 개선 신뢰구간이 0을 넘지 못함


픽스터 성과는 [전향 검증 문서](findings/픽스터_공개픽_전향검증.md)에 자동 갱신된다.
첫 관측에 이미 끝난 픽은 baseline으로 격리한다. `logit(p_adj) = logit(p_market) + βᵀx`
형태로 결합할 수 있지만, β는 walk-forward에서 Brier·log-loss·calibration이 모두
개선되기 전에는 0으로 둔다. 즉 픽스터가 정배에 몰렸다는 이유만으로 정배 확률을
자동 상향하지 않는다.

### 2.1 왜 이길 수 없는가

```
필요한 우위      6.8%p    ← 프로토 2-way 마진 12% 를 넘으려면
정보의 크기      2.4%p    ← 샤프 마켓 자신의 24시간 갱신폭
구조 선택 이득   2.4%p    ← 규칙 7개를 전부 누적했을 때
               ─────
합쳐도           4.8%p  <  6.8%p
```

| 시장 | 마진 |
|---|---|
| Pinnacle 등 샤프북 | 2~3% |
| bet365 등 소프트북 | 5.6% |
| **프로토 2-way** | **12.0%** |

문헌이 확증한다 — 장기 수익 베터는 약 3%, 프로가 효율 시장에서 목표하는 CLV 는
+2~3%, 라인이 무른 틈새에서도 +5% 다
([Aoki et al. KDD 2017](https://arxiv.org/abs/1706.02447),
[PLOS One 2023](https://journals.plos.org/plosone/article?id=10.1371%2Fjournal.pone.0287601)).

### 2.2 검정 5번의 정정 — 창구는 있었고, 그래도 안 됐다

```
프로토 배당 확정   경기 60시간 전 (86.2% 가 끝까지 안 움직인다)
프로토 발매 마감   경기 시작 10분 전
축구 라인업 공개   킥오프 1시간 전
```

**라인업을 보고 60시간 전 가격에 살 수 있다.** 원래 "라인업은 배당보다 늦어서
못 쓴다" 로 닫았는데 그건 틀렸다. 효과 자체도 실재한다 — 비주전 투입
0–1명 승률 45.7% → 6명+ 30.1%, 팀 내부 비교로도 13팀 중 10팀 −6.08%p.

그런데 프로토 배당에 대고 재니 **−16.79% ~ −3.27%** 로 전부 음수였다
([`src/lineup_edge.py`](src/lineup_edge.py)). 효과가 있어도 마진 13% 를 못 넘는다.

## 3. 그래서 무엇을 만들었나 — 손실 축소 도구

예측을 포기하고 **산술로 얻는 것**만 남겼다.

### 3.1 지렛대 크기 순

| 지렛대 | 절약 | 근거 |
|---|---:|---|
| **단폴 vs 2폴** | **8.85%p** | 같은 선택도 1폴 −9.81% vs 2폴 −18.66% |
| 배당대 (아무거나 → 1.0–1.3) | 4.33%p | −13.58% → −9.25% |
| 구조 (3-way핸디 → 2-way) | 2.40%p | −15.12% → −12.72% |
| 회차 환급률 | 2.36%p | **배당대와 겹쳐 추가 이득 없음** |

**다리를 하나 줄이는 게 나머지를 다 합친 것보다 크다.** 조합은 마진을 곱한다.

⚠️ 단폴(한경기구매)은 '한경기' 로 지정된 경기만 가능하고 단위투표금액이
1,000원이다(조합 100원). [규정](https://www.sportstoto.co.kr/proto_rules.php)

### 3.2 적중률은 '경기를 버려서' 올린다

| 최저배당 상한 | 살 경기 | 적중 | ROI | 2폴 티켓 적중 |
|---|---:|---:|---:|---:|
| 전부 | 100% | 65.86% | −10.25% | 43.37% |
| ≤1.5 | 71.6% | 69.76% | −9.95% | 48.67% |
| **≤1.3** | **31.9%** | **77.61%** | **−9.55%** | **60.24%** |
| ≤1.2 | 17.8% | 82.63% | −8.82% | 68.28% |

**이 축에서만 적중률과 ROI 가 같이 좋아진다.** 다른 지렛대는 전부 교환관계다.
조이면 살 경기가 준다 — ≤1.3 이면 열 경기 중 세 경기다. 그날 2폴을 만들 수 있는
하한이 대체로 여기다.

### 3.3 마켓도 봐야 한다

같은 배당대라도 마켓마다 1~3%p 갈린다. 안정성 관문을 통과한 셀:

| 마켓 × 배당대 | n | 적중 | ROI |
|---|---:|---:|---:|
| **승무패 1.0–1.3** | 2,709 | **80.1%** | **−6.48%** |
| 승①패 3.0–5.0 | 9,528 | 26.4% | −9.00% |
| 핸디캡 1.3–1.5 | 10,850 | 64.1% | −9.12% |
| 언더오버 1.3–1.5 | 4,347 | 62.3% | −9.46% |

1.0–1.3 안에서 승무패 −6.48% vs 승패 −10.06% — 같은 배당대에서 **3.6%p** 갈린다.

⚠️ 언더오버가 적게 뽑히는 건 나빠서가 아니다. 발매사가 **라인을 옮겨 양쪽을
반반으로 맞추는** 마켓이라(야구 라인 5.5→11.5 이동에도 배당은 1.70~1.78)
배당이 1.5 아래로 내려가지 않는다. 우리 규칙이 찾는 물건을 안 판다.

### 3.4 확정된 규칙

| 규칙 | 근거 |
|---|---|
| **단폴이 가능하면 단폴** | 8.9%p. 다른 무엇보다 크다 |
| 안 되면 2폴, 다리는 최소로 | 다리당 −6%p |
| 배당 5.0 이상 금지 | −33.5% |
| 2-way 우선 | 환급률 87.8% vs 3-way핸디 86.8% |
| 3-way 선택지 규칙 **없음** | 15개 중 14개가 연도별로 뒤집힌다 |

> ⚠️ **전부 마이너스다.** 적중 77.6% 여도 −9.55% 다. 이건 이기는 도구가 아니다.

## 4. 방법론 기록 — 가짜를 여섯 번 만들었다

**이 프로젝트에서 가장 재사용 가능한 부분이다.** 전부 통계 문제가 아니라
데이터 처리 문제였고, Bonferroni·부트스트랩·시간분리를 **다 통과했다.**

| 가짜 | 겉보기 | 실제 | 원인 |
|---|---|---|---|
| KBL 승무패 | ROI **+30.05%** | 프로토 우위 | 결과 `⑤` 32% 가 조용히 버려짐 |
| FA컵 상위리그 | 라인 4/4 | −7.22% | 선택 효과 + 순환논리 |
| 승①패 중간 | −3.85% | 2024 −16.52% | 단일 연도 현상 |
| 마켓 정합성 | ROI **+12.48%** | −8.21% | 무승부 2,343건 제외 |
| 배구 언더오버 | 언더 **100%** | 단위 불일치 | 세트 모델에 득점 라인 |
| 라인업 우위 | ROI **+14.37%** | −16.79% | **무승부 제외 (같은 버그 재발)** |

**공통점: 표본이 갑자기 줄어드는데 결과가 좋아진다.** 줄어드는 이유가 결과값과
상관있으면 반드시 가짜다.

### 그리고 조용히 틀린 숫자를 넉 달 동안 발행했다

위 여섯은 **찾아낸** 가짜다. 아래 넷은 **아무 경보도 울리지 않고** 결과표에
그대로 실려 있었다. 전부 같은 원인 — **정본이 두 벌 이상 존재했다.**

| 결함 | 규모 | 원인 |
|---|---|---|
| 팀명에서 소수점을 못 벗김 | 경기 키 44,915 → **71,282** (유령 26,367) | `-?\d+` 사본 6벌. `맨체스C -1.5` 가 별개 팀이 됨 |
| 승패 매핑표에 홀짝 누락 | **19,012행(10.9%)** 이 집계에서 빠짐 | `WIN_IDX` 사본 4벌 중 한 벌만 갱신 |
| 수집 시 charset 추측 실패 | 11회차 **3,429행** 모지바케 | `r.text` 가 chardet 추측 — `result` 까지 깨져 전량 누락 |
| 화면에 실적 수치 하드코딩 | 62.34% → 실제 **65.32%** | 파이프라인만 고치고 화면 상수를 안 고침 |

**대표 지표가 실제로 움직였다** — 기준 적중률 62.20% → **65.86%**,
≤1.3 으로 조였을 때 살 수 있는 경기 22.1% → **31.9%**.
결론의 방향(적중률과 ROI 가 같이 좋아지는 유일한 축)은 그대로다.

> 넷 다 통계 검정을 통과했다. **부트스트랩은 잘못 만든 표본을 잘 요약할 뿐이다.**

**막은 방법: 정본을 하나로 강제한다.**
`matches.clean_team` (팀명) · `bets._WINNER` (결과→적중 인덱스) ·
`bets.SEL_NAMES` (선택지 이름) — 나머지는 전부 여기서 파생하고,
화면 수치는 `loss_grades.json` 을 읽는다. 자기검사가 사본 재등장을 잡는다.

### 검사 도구

```bash
python3 src/selftest_all.py     # 12종. 파이프라인을 고쳤으면 반드시
```

- [`src/guard.py`](src/guard.py) — 부분집합을 만들 때 **버려진 행의 적중률**을 z 검정
- **방향 뒤집기** — 반대로 사도 좋으면 필터가 잘못된 것이다
- **플라시보 대조** — 무작위 배정보다 못하면 가짜다
- **정규화 회귀표** — `clean_team` 이 정수·소수·앞뒤를 다 벗기는지, 벗긴 뒤
  숫자 토큰이 남는 행이 0인지 (샬케04·마인츠05 는 남겨야 하므로 '띄어쓰기로
  분리된 토큰' 만 본다)
- **매핑 커버리지** — 실제 데이터의 모든 (마켓, 선택지수) 조합에 이름과 확률이
  둘 다 있는지. 없으면 사이트에 `sel0` 이 그대로 나간다
- **모지바케 검사** — 팀명·결과에 키릴/라틴확장이 섞이면 실패

라인업 가짜는 뒤집기·플라시보로 잡았다(반대 방향 +25.73%, 무작위 +19.90%).
소수점·홀짝·모지바케는 **아무 검정도 안 울려서** 회귀표를 새로 만들어야 했다.
