# 로또 축소 모델의 순차 예측 검증

균등 무작위보다 낫다는 근거를 찾지 못했다. 학습에서 선택한 모델은 최근 기록의 반감기 50회, 사전 강도 4,500회였다. 작은 빈도 차이를 매우 강하게 축소하는 설정이다.

## 방법

번호별 출현 지표에 균등 출현율 6/45를 중심으로 Beta 의사 관측값을 더했다. 할인 출현 횟수와 할인 회차 수로 사후 평균을 구하고, 이를 오즈로 변환했다. 최종 조합 확률은 정확히 6개를 뽑는 조건에서 `P(S) = product(w_i, i in S) / e6(w)`로 정규화했다. 번호별 사후 평균을 조합 분포에 대입한 베이지안 축소 방식이며, 전체 결합 사후분포를 적분하는 완전한 베이지안 예측은 아니다. 할인 기록도 의사 우도 해석이다.

반감기 50회·200회·전체 기록과 사전 강도 45·450·4,500의 9개 조합에 균등 무작위를 추가했다. 201~740회에서 각 회차 직전 기록만으로 얻은 평균 로그점수가 가장 높은 설정을 선택했다. 이후 설정은 바꾸지 않고, 새로운 회차의 결과를 다음 회차 예측부터 반영했다. 균등 후보를 포함하지 않은 진단용 선택도 미리 정의했으나 실제 자료에서는 같은 설정이 선택됐다.

점수는 실제 당첨된 여섯 번호의 로그 확률에서 균등 조합의 로그 확률을 뺀 값이다. 양수가 개선이다. 기하평균 확률비는 이 점수의 지수값이며, 구매한 복권의 당첨률 상승률을 뜻하지 않는다.

## 결과

- 학습 201~740회: 평균 로그점수 차이 +0.000194578.
- 검증 741~990회, 250회: +0.000180409. 기하평균 확률비 1.000180426, 무작위 이력 대비 상측 p=0.205.
- 주 평가 구간 991~1238회, 248회: −0.000358423. 기하평균 확률비 0.999641642, p=0.665.
- 이전에 확인한 추가 구간 1239~1245회, 7회: +0.000188047. 기하평균 확률비 1.000188065, p=0.230.

주 평가 구간에서 실제 당첨 조합에 부여한 확률은 기하평균으로 균등보다 약 0.0358% 낮았다. 검증 구간의 미세한 양의 차이가 주 평가 구간에서는 재현되지 않았다.

균등 비복원 추첨 이력을 199개 생성하고, 각 이력에서 학습 설정 선택부터 순차 평가까지 전부 반복했다. 199개 중 90개는 균등 후보를 선택했다. p값은 `(1 + 실제 점수 이상인 가짜 이력 수) / 200`이며 해상도는 0.005다. 주 평가 하나를 사전에 지정했고, 나머지 구간과 비균등 진단은 설명용이다. 비균등 진단의 주 평가 p값도 0.470으로 개선 근거가 없다.

## 검증과 자원 사용

단일 Python 프로세스, BLAS/OpenMP 스레드 1개로 실행했으며 전체 실험 소요 시간은 약 17.42초였다. 대규모 시드 탐색이나 병렬 프로세스는 사용하지 않았다. 결과는 임시 파일에 기록하고 flush/fsync 후 교체했다. 정전·하드웨어 장애까지 방지한다고 보장하지는 않는다. CPU 사용률과 메모리의 최대치는 별도로 측정하지 않았다.

작은 표본 공간을 전수 열거해 정규화 공식을 확인했다. 미래 자료를 바꿔도 과거 예측과 설정 선택이 바뀌지 않는지, 강한 지속 편향을 주면 검출하는지 검사했다. 기존 확률 모듈의 스칼라 계산으로 평가 구간 505회 점수를 대조했다. 관련 테스트 12개가 통과했다.

## 한계와 재현

모든 회차는 이전 실험에서 이미 확인한 자료다. 이번 결과는 과거 자료를 이용한 탐색이며 신규 미공개 회차의 확증 검증이 아니다. 새로운 모델을 여러 번 시도해 온 전체 과정의 선택 편향까지 이번 p값이 보정하지는 않는다. 추가 7회는 표본도 매우 작다. 우월성을 발견하지 못한 것이 모든 가능한 편향이 없다는 증명은 아니다.

원장은 기존 `data/lotto/draws.jsonl`과 이전 실험에서 수집한 `data/lotto/reports/null-expanded/new-rounds/draws.jsonl`을 그대로 사용했다. 공식 출처는 [동행복권 회차별 결과](https://www.dhlottery.co.kr/lt645/result)이며 이번 실행에서 새 회차를 수집하지 않았다. 데이터·소스 해시, 사전에 고정한 설정은 `data/lotto/reports/shrinkage/protocol.json`, 원시 점수와 가짜 이력 결과는 같은 디렉터리에 저장했다.

재현: `python src/lotto_shrinkage.py`, 검산: `python scripts/verify_lotto_shrinkage.py`, 테스트: `python -m pytest tests/test_lotto_shrinkage.py tests/test_lotto645.py -q`.

운영 번호 생성 방식은 변경하지 않았다. 이 실험 결과로는 균등 무작위를 대체할 이유가 없다.
