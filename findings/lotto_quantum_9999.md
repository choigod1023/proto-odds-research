# 고정 양자 회로의 가짜 이력 9,999개 검증

**주 평가 p값은 0.0977이며, 이전 999개 결과 0.093과 비슷하다. 균등 무작위보다 우월하다는 근거가 부족하다는 결론은 달라지지 않았다.** 실제 모델 점수와 기존 999개 이력의 학습 결과가 정확히 재현됐다. 9,999개 학습 모두 정상 수렴했으며 중단 없이 완료했다.

## 결과

- 검증 741~990회: 평균 로그점수 차이 −0.002535766. 실제 이상의 가짜 이력 5,657/9,999개, 상측 p=0.5658. 이전 p=0.592.
- **주 평가 991~1238회:** 평균 로그점수 차이 +0.002956079. 실제 이상의 가짜 이력 **976/9,999개, 상측 p=0.0977**. 이전 p=0.093.
- 기존 추가 구간 1239~1245회: 평균 로그점수 차이 +0.001453065. 실제 이상의 가짜 이력 4,384/9,999개, 상측 p=0.4385. 이전 p=0.438.

주 평가의 귀무 모형 꼬리 확률에 대한 Clopper–Pearson 95% 구간은 **0.09186~0.10359**다. 이는 가짜 이력 수에 따른 몬테카를로 오차를 나타내며, 예측 효과나 실제 당첨 확률의 신뢰구간이 아니다. 균등 추첨에서도 이번 실제 점수 이상을 얻는 경우가 약 10%라는 결과다.

주 평가에서 당첨 조합에 부여한 확률은 기하평균으로 무작위보다 약 0.296% 높았지만, 앞선 검증 구간에서는 약 0.253% 낮았다. 이 실제 점수들은 이전 실험과 동일하며 개선이 일관되지 않는다. 5% 기준에서도 유의하지 않다. 운영 번호 생성 방식은 변경하지 않았다.

## 실험 규칙

이전 PR #304에서 검증한 6큐비트 모델을 그대로 사용했다. 원본 모델 소스의 Git 객체 해시와 LF 정규화 SHA-256을 확인했다. 학습 자료, 추가 구간 자료, 회로 구조, 초기 각도, 정규화, 최적화 설정, 평가 구간을 변경하지 않았다.

회로는 RY와 고리형 CNOT 2층, 매개변수 12개다. 로또 조합을 낮은 번호(1~22) 개수와 홀수 개수로 나타내며, 정확한 균등 조합 경우의 수로 Born 확률을 보정하고 5% 균등 혼합을 적용한다. 같은 범주 안의 조합은 동일 확률을 갖는다. 1~740회와 균등 의사 관측 740회로 한 번 학습한 뒤 회로를 고정한다. 이는 실제 양자 하드웨어가 아닌 CPU 상태벡터 모의실험이다.

가짜 이력의 시드는 `2026101700 + i`, `i=0..9998`이다. 각 이력은 균등 로또의 정확한 범주 분포에서 1,245회 생성한다. 이 모델은 범주만 사용하므로 전체 조합을 생성하는 것과 동일한 귀무 분포를 얻는다. 실제 자료와 기존 999개 이력은 다시 학습하여 이전 결과와 정확히 일치하는지 확인한다. 새로운 이력은 9,000개이고 최종 가짜 이력 수는 9,999개다.

주 평가 지표는 991~1238회에서 실제 당첨 조합에 부여한 로그 확률과 균등 조합 로그 확률의 평균 차이다. 741~990회와 1239~1245회는 설명용 부 평가 구간이다. p값은 `(1 + 실제 이상인 가짜 이력 수) / 10000`으로 계산한다. 모든 이력을 계산한 뒤 집계하며 중간 p값으로 표본 수를 바꾸지 않는다.

## 컴퓨터 부하와 중단 대비

단일 프로세스와 논리 CPU 하나, Windows BELOW_NORMAL 우선순위, 수치 라이브러리 스레드 1개를 사용한다. 각 이력 계산이 끝나면 해당 계산의 벽시계 소요 시간 이상 쉬며, 최소 휴식은 25ms다. 100개마다 추가로 1초 쉰다. 이 방식은 주 계산 루프의 CPU 점유를 낮추며 컴퓨터 전체의 부하나 온도를 제어한다는 뜻은 아니다.

한 실행의 벽시계 예산은 1,200초, 메모리 감시 기준은 256MiB다. 목적함수 평가와 반복 사이에서 확인하는 소프트웨어 감시이며 OS 수준의 강제 제한은 아니다. 100개 단위의 압축 체크포인트를 임시 파일에 기록하고 fsync, 재열기·내용 비교 후 교체한다. 프로토콜 해시와 연속 인덱스를 검증한 완료 블록에서 재시작할 수 있다. 완료한 블록의 SHA-256을 매니페스트에 기록한다.

실제 주 실험은 **1,072.97초(약 17분 53초)**, CPU 시간 **449.67초**, 프로세스 최대 작업 집합 **148.55MiB**를 사용했다. 총 100개 압축 블록으로 결과를 보존했고 중단·재시작 없이 완료했다. 이 수치는 실험 프로세스의 사용량이며 컴퓨터 전체의 온도·전력·다른 작업의 부하는 측정하지 않았다.

## 검산

별도의 64×64 밀집 행렬 계산으로 가짜 이력 9,999개와 실제 회로 1개를 모두 다시 계산했다. 가짜 이력의 평가 회차 5,049,495개에서 얻은 구간별 평균 로그점수를 원래 계산과 비교했으며 최대 오차는 약 6.94×10⁻¹⁶이었다. 실제 회로의 확률 벡터, 기존 999개 이력의 정확한 일치, 100개 압축 블록의 해시·연속성, p값 및 꼬리 확률 구간도 확인했다.

검산도 단일 CPU·낮은 우선순위·계산 사이 휴식으로 실행했다. 약 38.68초, CPU 시간 14.72초, 최대 작업 집합 139.80MiB였다. 체크포인트 재시작과 잘못된 프로토콜·인덱스 거부를 포함해 관련 테스트 16개가 통과했다.

## 해석의 한계

이미 확인한 과거 실제 회차만 재사용한다. 가짜 이력을 늘려도 새로운 실제 검증 자료가 생기지는 않는다. 99개와 999개 결과를 확인한 뒤 확장한 탐색이며, 여러 모델을 시도해 온 전체 연구 과정의 선택 편향을 보정한 확증 검정이 아니다. 이력 수 증가에 따른 p값 변화는 실제 모델의 성능 변화가 아니다.

로그점수의 지수값은 당첨 조합에 부여한 확률비의 기하평균으로, 구매 복권의 실제 적중률·1등 횟수 개선을 의미하지 않는다. 모델은 낮은 번호 개수와 홀수 개수만 표현하므로 모든 번호 관계를 검증하는 실험도 아니다.
