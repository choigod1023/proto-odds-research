# 로또 3회 이상 적중 시드 탐색 재현

앞선 100만 후보 실험과 동일한 `splitmix64-combinadic-v1` 생성기에서 첫 회차를 맞히는 조건부 후보를 10억 개로 확대했습니다. 학습은 1~740회, 검증은 741~990회, 최종 평가는 991~1238회로 고정했습니다. 첫 적중은 역산으로 만든 조건이며, 2~740회에서 추가로 2회 이상 맞혀야 생존합니다.

결과와 시드 목록은 [실험 보고서](../data/lotto/reports/seed-triple/report.md)에 기록합니다. 기존 평가 구간을 재사용한 후향 탐색이며 새로운 미래 성능 검증이 아닙니다.

## 실제 결과

10억 후보를 모두 검사하는 데 약 194초가 걸렸습니다. 2회 이상 적중은 90,542개, 3회 이상은 5개, 4회 이상은 0개였습니다. 생존 시드와 학습 적중 회차는 다음과 같습니다.

- `862879196780149093`: 1·43·306회
- `4133058859547278505`: 1·240·579회
- `10796522787573961961`: 1·517·569회
- `15585017975376459500`: 1·389·561회
- `18312488190086753215`: 1·43·277회

5개 시드 전체의 검증 구간 평균 일치는 0.784800개로 대조군 0.799949개보다 낮았습니다. 최종 구간도 생존군 0.776613개, 대조군 0.799997개였습니다. 동일 예산의 대조군 10,000개 그룹 중 85.67%가 최종 구간에서 생존군 이상이었습니다. 생존군의 이후 498회 1등 적중은 0회였습니다.

개별 시드 중 `862879196780149093`은 최종 평균 일치가 0.854839개로 무작위 평균보다 높았습니다. 그러나 원래 대조군에 포함된 무작위 시드 50,000개를 개별 비교한 결과, 14.338%가 이 시드 이상을 기록했습니다. 이 시드 역시 대조군 개별 평균의 95% 참고 범위(0.701613~0.899194) 안에 있습니다. 이 사후 개별 비교는 설명용이며 새로운 시드를 추천하거나 선택하는 데 사용하지 않았습니다. 상세 분포는 `individual-comparison.json`에 저장했습니다.

이번 탐색에서는 3회 적중한 시드를 찾았지만 이후 우위의 근거는 나타나지 않았습니다. 17개 테스트를 통과했고, 생존 시드 5개 × 1,238회 = 6,190조합을 별도 Python 스칼라 구현으로 복원해 학습 적중 회차와 검증·최종 분포가 모두 일치함을 확인했습니다.

## 실행

저장소 루트에서 Python, NumPy와 C++17을 지원하는 g++가 필요합니다. 실행 파일은 작업 공간 내부에만 생성합니다.

```powershell
New-Item -ItemType Directory -Force .local-build
g++ -O3 -march=native -std=c++17 -pthread -static src/lotto_seed_scan.cpp -o .local-build/lotto_seed_scan.exe
python src/lotto_seed_triple.py --executable .local-build/lotto_seed_scan.exe --output .local-build/triple-repeat
python -m pytest tests/test_lotto_seed_triple.py tests/test_lotto_seed_expanded.py tests/test_lotto645.py -q
python scripts/verify_lotto_seed_expanded.py --report data/lotto/reports/seed-triple
python scripts/lotto_seed_individual.py --report data/lotto/reports/seed-triple
```

기본 후보 수는 10억 개이며 배치는 1억 개씩, 작업 스레드는 8개입니다. `--candidate-count`, `--batch-size`, `--workers`로 변경할 수 있습니다. 평가 대조군은 10,000회 반복하며, 매회 생존군과 같은 시드 수·회차 수·티켓 수를 사용합니다.

실행 전에 `protocol.json`에 후보 수·구간·기준·대조군 난수 시드와 소스·실행 파일·원장 해시를 저장합니다. 각 배치의 후보 범위·적중 횟수 분포·생존 시드·계산 시간을 기록합니다. 동일한 명령을 다시 실행하면 완료 배치를 재사용하고, 설정이나 소스·실행 파일이 다르면 기존 디렉터리의 재개를 거부합니다. 평가 결과를 보고 선별 조건을 바꾸지 않습니다.

## 메모리를 제한하면서 중복 없이 탐색하는 방법

첫 회차 조합의 순번을 `r`, 전체 조합 수를 `N=8,145,060`이라 하면, 이 조합으로 연결되는 64비트 출력은 `r+q*N`입니다. 가능한 `q`의 개수를 `P`라고 할 때, `q=(20,261,015+i*1,000,003) mod P`로 후보를 열거합니다. `gcd(1,000,003,P)=1`임을 검사하므로 `i<P` 범위에서 후보는 중복되지 않습니다.

순열을 역산해 시드를 만든 뒤, 동일한 생성기로 1~740회의 조합 순번을 계산합니다. 모든 후보를 끝까지 검사하며 3회 이상 적중한 시드를 저장합니다. 첫 회차 적중 조건은 이전 실험과 같지만, 후보 추출은 이전 무작위 표본에서 이번 아핀 순회로 바뀌었습니다. 아핀 순회 자체가 무작위 표본이라는 주장은 하지 않습니다.

Python은 고정 프로토콜, 배치 실행, 결과 저장과 이후 평가를 담당합니다. C++는 학습 구간의 조합 순번 일치만 계산합니다. 별도 Python 스칼라 구현은 생존 시드의 실제 6개 번호를 복원해 학습 적중과 이후 일치 분포를 다시 확인합니다.

테스트에는 C++와 NumPy의 전체 적중 횟수 분포 비교, 의도적으로 만든 3회 이상 적중 사례, 배치 분할·작업 스레드 수 변경 시 동일 결과, 재개 시 중복 집계 방지, 설정 변경 거부, 동일 예산의 대조군 검증을 포함했습니다. 운영 추천 번호 생성이나 배포 설정은 변경하지 않습니다.
