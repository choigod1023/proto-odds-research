# 로또 시드 생존 실험 사용법

기존 생성 CLI에 `seed-survival` 명령을 추가했습니다. 운영 번호 생성과 별도로 실행하며 공개 추천 번호나 사전등록 파일을 수정하지 않습니다.

```powershell
python src/lotto_pipeline.py seed-survival --candidate-count 20000 --train-end 740 --validation-end 990 --min-wins 1 --baseline-repeats 100
```

기본 원장은 `data/lotto/draws.jsonl`입니다. 다른 원장은 하위 명령 앞에 `--data 경로`를 지정합니다. 결과는 `data/lotto/reports/seed-survival/experiment.json`과 `report.md`에 저장됩니다. 실험을 바꿀 때는 `--report-dir`로 다른 경로를 지정해 이전 기록을 보존하세요.

## 선별 규칙

- 후보는 `--start-seed`부터 연속된 정수입니다. 기본 시작값은 0입니다.
- 시드마다 `random.Random("seed-survival-v1|시드")`로 고정된 난수열을 만들고, 1회차부터 회차별로 1~45 중 서로 다른 6개를 균등 추출합니다. 구간 경계에서 난수열을 다시 시작하지 않습니다.
- 학습 구간에서 6개가 모두 일치한 횟수로 1회 이상, 2회 이상, 3회 이상 등의 생존 목록을 저장합니다. 부분 일치로 생존 조건을 완화하지 않습니다.
- 평가할 단계는 실행 전에 `--min-wins`로 고정합니다. 2회 이상 단계가 비어도 1회 이상 시드로 자동 대체하지 않습니다.
- 검증 및 최종 평가에서는 시드와 규칙을 바꾸지 않습니다. 선별 설정, 학습 자료 해시, 시드 목록, 대조군 목록을 묶은 해시를 보존합니다.
- 무작위 대조군은 후보 범위 바로 다음의 미선별 시드들로 구성합니다. 매 반복마다 생존군과 같은 시드 수·회차 수·티켓 수를 평가합니다.

## 해석과 한계

1등 횟수, 0~6개 일치 분포, 티켓당 평균 일치 수를 보고합니다. 대조군 평균 일치의 95% 범위는 반복 대조군의 경험적 분위수입니다. 선택군의 신뢰구간이나 예측력 검정의 p값이 아닙니다. 1등은 매우 드물어 후보 2만 개에서도 2회 이상 생존 시드가 없을 수 있습니다.

동일한 시드와 원장으로 재현할 수 있도록 Python 버전, 생성기 버전, 원장 해시를 저장합니다. Python 버전에 따라 `random.sample` 구현이 달라질 수 있으므로 동일 버전을 사용하세요. 시드 간 같은 조합이 나오면 비용을 동일하게 계산하기 위해 별도 티켓으로 셉니다.

이 실험은 이미 알려진 당첨 자료를 시간순으로 나눈 후향 평가입니다. 실험 결과를 보고 후보 범위·구간·생존 조건을 다시 고르면 최종 구간도 더 이상 미사용 자료가 아닙니다. 실제 미래 성능은 규칙과 시드를 먼저 등록한 뒤 새 회차에서 별도로 확인해야 합니다. 미래 적중률 향상이나 수익을 보장하지 않습니다.

원자료는 저장소 원장의 회차별 `source_url`과 수집 시각으로 확인할 수 있습니다. 공식 출처는 [동행복권](https://www.dhlottery.co.kr/)입니다. 이번 실행의 실제 수치는 함께 커밋한 `data/lotto/reports/seed-survival/report.md`를 참조하세요.
