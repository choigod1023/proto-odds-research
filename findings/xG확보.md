# K리그 xG 확보 — 어디서, 어떻게, 어디까지

측정일 2026-07-27. **사실**(측정값)과 **의견**(해석)을 구분 표기한다.

---

## 왜 xG 를 쫓았나

야구에서는 과정 지표가 통했다. 결과(실점)보다 과정(FIP·xFIP)이 다음 경기를
잘 맞혔고, 시장과의 격차를 1/3.6 로 줄였다. 축구에 같은 논리를 적용하려면
축구판 FIP 가 필요한데, 문헌이 쓰는 건 **xG(기대득점)** 다.

먼저 공짜로 구할 수 있는 대용품 — **유효슈팅** — 으로 시험했다.

### [사실] 유효슈팅은 득실차에 졌다 (`src/soccer_process.py`)

K리그 816경기(2023-02-25 ~ 2026-07-26), 프로토 결합 567경기,
학습 326 / 검증 241. 기준(Elo 단독) 검증 Brier 0.24762.

| 피처 | 계수 | z | Brier 개선 |
|---|---:|---:|---:|
| 득실 차 (결과 지표) | 0.3097 | 1.30 | **+0.00299** |
| 유효슈팅 차 (과정 지표) | 0.1823 | **2.63** | +0.00062 |
| 총 슈팅 차 | 0.0704 | 1.31 | −0.00162 |
| 결정력 차 (운 지표) | −2.2721 | −1.70 | −0.00220 |

야구와 **정반대**다. 야구에서는 과정이 이겼는데 축구에서는 결과가 이겼다.

### [의견] 그런데 이게 xG 를 포기할 이유는 아니다

눈여겨볼 건 z 값이다. 유효슈팅 계수의 z 는 2.63 으로 득실차(1.30)보다
**오히려 강하다.** 즉 유효슈팅에 실제 신호가 있는데도 검증 Brier 는 뒤집혔다.

가장 그럴듯한 해석: **유효슈팅은 슛의 질을 못 본다.** 페널티박스 안 1대1과
30m 중거리포가 같은 1개로 계산된다. 그 질을 넣은 게 정확히 xG 다.
그러니 이 결과는 "축구엔 과정 지표가 안 통한다"가 아니라
"**대용품이 거칠어서 부족하다**"로 읽는 게 맞다. (검증 표본 241경기로
작다는 점도 감안해야 한다.)

## xG 소스 전수 조사

| 소스 | K리그 | 자동 접근 | 비고 |
|---|:--:|:--:|---|
| Understat | ❌ | ⚠️ | 유럽 5대리그만 · TLS 지문 차단 |
| FBref | ✅ | ❌ | Cloudflare 차단 |
| SofaScore | ✅ | ❌ | 403 |
| FotMob | ✅ | ⚠️ | API 경로 변경 |
| StatsBomb Open | ❌ | ✅ | 특정 시즌 유럽만 |
| API-Football | ? | ❌ | 공개 문서 403, 키 필수(계정 필요) |
| 네이버 | shots/SOG만 | ✅ | xG 없음 |
| **FootyStats** | **✅** | **✅** | **차단 없음 · robots 명시 허용** |

### [사실] FootyStats 가 유일하게 열려 있다

- `robots.txt` 에 **`User-agent: ClaudeBot / Crawl-delay: 1`** 명시 허용
- 경기 페이지(`/south-korea/{home}-vs-{away}-h2h-stats`)는 Disallow 목록에 없음
- 일정 페이지에서 경기 링크 186개 확인
- K리그1 선수별 시즌 xG 확인 (예: Yago Cariello 6.81 xG / 9골)
- 경기 페이지에서 **팀별 xG·xGA 를 전체/홈/원정 분리**로 제공
  - 예: 전북 xG 1.70(홈 1.72) / xGA 1.37, 서울 xG 1.55(원정 1.64) / xGA 1.30

### [사실] 없는 것 — 경기별 xG 이력

- API 스키마에 있는 xG 필드는 전부 **평균**: `xg_avg`,
  `xg_for_avg_overall/home/away`, `xg_against_avg_overall/home/away`
- 경기별 `team_a_xg` 같은 필드는 스키마에 없다
- H2H(지난 맞대결) 구간에도 xG 없음

### [사실] 유료 경계선

- **API 무료 티어 = 프리미어리그 전용** (Hobby 50리그 / Serious 150리그 / 전체 1500+)
- **CSV 다운로드는 로그인 필수** — "You must Login to Download CSVs.
  However, you can download the Premier League CSV's from below for free."
- K리그 경기별 CSV 링크는 존재: `/c-dl.php?type=matches&comp=16627`

### ⚠️ 접근 정책 — 지킨 선

`robots.txt` 가 `/c-dl.php*` 를 **명시적으로 Disallow** 한다.
그래서 **자동 수집기는 CSV 경로를 건드리지 않는다** (`xg_watch.py` 의
`FORBIDDEN` 리스트가 요청 자체를 막는다). Cloudflare·TLS 지문 우회를 거부한 것과
같은 원칙이다.

사람이 브라우저로 직접 받는 건 다른 얘기다 — 사이트가 제공하는 기능을
사용자가 쓰는 것이므로, 계정이 있다면 정상 경로다.

## 그래서 택한 방법 — 스냅샷 전진 수집

### 누수 문제

FootyStats 가 주는 xG 는 **오늘 시점의 시즌 누적**이다.
이미 끝난 경기에 그대로 붙이면 그 경기 결과가 피처에 섞인다 — 데이터 누수다.
과거를 긁어서 백테스트하는 건 원리상 불가능하다.

### 해결

과거를 긁는 대신 **미래를 향해 매일 찍는다.** 오늘 찍은 값은 내일 경기에 대해
100% 경기 전 정보다. 이미 돌리고 있는 `snapshot.py`(프로토 배당)·
`info_watch.py`(선발 예고)·`overseas_watch.py`(해외 배당)와 같은 방식이다.

`src/xg_watch.py`
- 일정 페이지 → 경기 페이지 → 팀별 xG/xGA(전체·홈·원정) 파싱
- `data/raw/xg_snapshots.jsonl` 에 append-only, 같은 날 재실행 멱등
- crawl-delay 1.5s (robots 요구 1s 보다 여유)
- `LEAGUES` 에 K리그1·K리그2 — **J리그는 여기 한 줄 추가하면 붙는다**

```bash
python3 src/xg_watch.py kleague1
```

### 비용과 이득

- **즉시**: 다가오는 경기의 경기 전 xG → 라이브 픽에 바로 쓸 수 있다
- **누적 후**: 라운드가 쌓이면 누수 없는 패널 → 그때 walk-forward 백테스트
- ⚠️ 백테스트 통과 전에는 **모델에 채택하지 않는다** (절대 원칙 1)

## 남은 선택지 (사용자 판단 영역)

경기별 xG 이력을 **지금 당장** 원하면 길은 하나다 —
FootyStats 계정으로 K리그 matches CSV 를 직접 받는 것.
무료 티어는 프리미어리그뿐이라 K리그는 유료 구간(Hobby 이상)이다.
돈 쓰는 결정이라 대신 하지 않았다.

받아오면 `xg_watch.py` 와 같은 스키마로 흡수하는 건 바로 된다.
