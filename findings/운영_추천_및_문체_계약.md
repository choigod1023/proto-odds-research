# 운영 추천 및 문체 계약

## 추천 정책의 정본

Python 생성기는 `src/recommendation_policy.py`, 브라우저는
`web/src/lib/recommendation-policy.js`를 사용하고
`tests/test_recommendation_policy_parity.py`가 후보·방향의 동등성을 검사한다.

우선순위는 다음과 같다.

1. 현재 발매 배당이 있고 검증된 +EV 승격 관문을 통과한 선택
2. 운영 가격대의 시장 최유력 균형 선택
3. 사전 정의된 조건을 모두 만족한 역배 도전 선택
4. 구매 가능한 선택이 없으면 보류

조합은 단폴을 허용하고 2폴을 기본 비교 단위로 삼되, 목표 배당을 맞추기 위해
검증되지 않은 선택을 추가하지 않는다. Python과 브라우저가 다른 결과를 내면
회귀 테스트 실패로 배포를 막는다.

## 구매 가능 시간

날짜창은 탐색 범위일 뿐이다. 최종 표시는 현재 발매 회차, 현재 배당 revision,
경기 시작 전 조건을 함께 통과해야 한다. 다음 날 11:59까지의 후보도 현재 발매
회차에서 빠지거나 배당이 없으면 구매 후보가 아니다. 날짜 경계 테스트는 현재
시각을 고정해 실행하며 실행 날짜에 따라 결과가 바뀌지 않는다.

## 실험과 운영 승격

연구 artifact 기본 상태는 `shadow_only`다. 시간순 미래 표본, 최소 표본수,
Brier/log loss bootstrap CI, 평균 배당과 coverage 보존을 모두 통과하고 코드의
허용 목록에 등록된 artifact만 최종 확률에 반영한다. 자체 JSON에 `promoted`라고
쓴 것만으로는 승격되지 않는다. 실패하거나 필드가 누락되면 시장 확률로 닫힌다.

## 한국어 문체

시스템이 완료한 계산과 선택은 확정형으로 쓴다.

- 허용: `승패 시장 1순위는 홈 승이다.`
- 허용: `최종 수치 선택은 언더다. 다만 선발 변경 시 다시 계산해야 한다.`

경기 결과와 미래 사실은 보장하지 않는다.

- 금지: `홈팀이 반드시 이긴다.`
- 금지: `언더 적중이 확실하다.`
- 금지: `100% 적중한다.`

`src/commentary_llm.py`의 `_looks_safe` validator는 새 숫자·새 민감 사실,
결정 방향 변경, 결과 보장, 존댓말 종결을 거부한다. 거부되면 LLM 출력 대신
검증된 원문 템플릿을 사용한다.

## 선수 자료 시점

선수 revision은 `source_published_at`, `collected_at`, `first_seen_at`,
`revision_id`를 분리한다. `player_info_revisions` append-only stream에는 동일
내용을 중복 저장하지 않되 변경 revision은 보존한다. 판정은
`first_seen_at <= feature_cutoff_at`인 revision만 사용한다. 최초 관측 ID가 없는
선수 자료는 설명에는 보일 수 있지만 운영 확률에는 반영하지 않는다.
