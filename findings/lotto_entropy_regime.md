# 엔트로피 상태 검증과 6개 모델 계열 합의 5게임

엔트로피 상태에 따라 예측 분포를 바꾸는 6개 규칙을 검증했으나 모두 평가 구간에서 기준보다 낮은 로그 점수를 냈다. 전체 탐색을 반영한 순열 p=0.405, 균등 이력 비교 p=0.425였다. 이 결과를 반영해 당첨 확률 상승을 주장하지 않는다. 요청한 5게임은 6개 모델 계열의 선호를 종합한 탐색적 선택이다.

## 엔트로피의 정의와 검증

기존 자료 1~1245회, 보너스 제외. 조합을 22 이하 번호 개수와 홀수 개수로 분류한다. 범주 크기는 정확한 조합 수로 계산하고 범주 안에서는 균등하다고 가정한다. 이 가정하에 전체 조합 분포 엔트로피는 H=log2(C(45,6))-KL(p_category || uniform_category)다. 최대 엔트로피는 22.957493896비트이며 H를 이 값으로 나눠 비율을 정의했다. 추첨 장치의 물리적 엔트로피를 관측한 값은 아니다.

범주별 과거 횟수를 회차마다 0.98배 할인하고 균등 기준 의사 관측 100개를 더한다. 매 회차 결과가 나오기 전에 H와 확률을 계산하고, 결과 후 놀라움 -log2(P(실제 조합))에서 당시 H를 빼 잔차를 만든다. 미래 회차 결과는 해당 회차의 입력에 사용하지 않는다.

여섯 입력은 엔트로피 비율, 비율의 20회 변화, 놀라움 잔차의 최근 20·50·100회 평균, 최근 20회 평균과 그 이전 20회 평균 차이다. 각각 학습 구간 중앙값으로 두 상태로 나눈다. 학습은 101~740회, 평가는 741~1245회 505회다. 상태별 범주 분포는 상태를 쓰지 않는 학습 분포 쪽으로 의사 관측 100개만큼 축소한다. 초기 100회는 상태 입력 준비에 사용한다. 학습하지 않은 신규 임계값이나 주기는 결과를 보고 추가하지 않았다. 주기 스펙트럼 전반이나 모든 상태 정의를 탐색한 것은 아니다.

회차 순서를 199번 섞을 때마다 입력 상태 계산과 학습부터 다시 수행한다. 6개 중 최고 평가 점수를 각 순열의 최고 점수와 비교한다. 별도로 균등 범주 이력 199개에서도 전체 절차를 반복한다. p값은 (1+실제 이상 최고 점수 수)/200이며 해상도는 0.005다. 범주만 사용하는 검사이므로 정확한 균등 범주 확률로 모의 이력을 생성했다.

평가 총 로그 이득(nats):

- 엔트로피 비율: -26.128752.
- 엔트로피 비율 20회 변화: -27.361015.
- 놀라움 잔차 최근 20회: -12.321594.
- 최근 50회: -16.393613.
- 최근 100회: -30.477728.
- 최근 20회와 이전 20회 차이: -29.151233.

이미 확인했던 과거 자료의 탐색이다. 이번 6개 선택은 보정하지만 이전 전체 연구의 반복 선택을 보정하지 않는다. 신호 부재가 모든 엔트로피 기반 의존성의 부재를 증명하지 않는다. 별도 편향 주입 검출력 시험은 이번 상태 모델에는 수행하지 않았으며, 이전 XOR 실험의 검출력을 이 모델에 옮겨 주장하지 않는다.

## 5게임 선택

1245회까지의 기존 자료 기준으로 1246회에 대한 후보를 만들었다. 새 실제 결과를 수집하지 않았다. 고정 난수 시드 2026101707로 100,000개 균등 조합을 생성해 중복 제거한 99,387개를 비교했다. 전체 8,145,060개 전수 최적화가 아니다.

비교 계열은 양자, 고전 범주 빈도, 축소(반감기50·사전강도4500), 시간 의존성 2개, 비선형 24개, 엔트로피 상태 6개다. 양자·고전 분포와 기존 조건부 모델의 학습 설정은 유지했다. 축소 모델은 원래 순차 갱신 규칙대로 1245회까지 반영했다. 조건부 모델의 다음 상태는 1245회까지의 관측으로 계산했다. 기존 양자 확률은 quantum-actual.json, 새 엔트로피 확률은 results.json에 보존했다. 이전 두 검사 모듈의 복사본을 entropy_support에 보관했다.

각 모델의 후보 내 순위를 동률 중간 순위로 환산하고 같은 계열 안에서 평균했다. 6개 계열 중 최저 백분위가 높은 후보를 우선하고 평균 백분위로 동률을 풀었다. 모델들을 독립적인 증거로 간주하거나 실패한 모델에 통계적 신뢰도를 부여한 것이 아니다. 특징 일부만 예측하는 비선형 모델은 당첨 조합 확률이 아닌 선호 점수로만 포함했다. 시드 생성기와 혼잡도 전략은 공통 확률 점수가 없어 제외했다.

1. 02 · 04 · 05 · 13 · 16 · 20
2. 02 · 04 · 05 · 15 · 16 · 18
3. 04 · 06 · 07 · 13 · 28 · 32
4. 04 · 06 · 07 · 13 · 24 · 32
5. 03 · 04 · 05 · 18 · 28 · 38

평균 선호 백분위는 순서대로 85.28, 83.13, 78.06, 77.15, 76.90이며 모두 최저 계열 백분위 63.65다. 이 수치는 당첨 확률이나 신뢰도가 아니다. 공정한 추첨에서는 각 조합의 1등 확률은 동일하다. 비슷한 번호가 많이 겹치며 조합 간 다양성을 최적화한 선택도 아니다. 전체 자료에서 실제로 가장 확률이 높다고 검증된 5게임은 아니다.

## 자원·검증·재현

단일 CPU, BelowNormal, 수치 라이브러리 스레드1, 검증 반복마다 계산 시간25% 휴식, 600초 예산을 적용했다. 상태 검증은 16.535초, 프로세스 CPU 12.906초, 해당 프로세스 최대 메모리 97.348MiB였다. 합의 계산은 0.331초, 해당 프로세스 최대 메모리 165.098MiB였다. 프로세스별 최대값이며 컴퓨터 전체 합계가 아니다. 온도는 측정하지 않았고 두 실행은 종료했다.

테스트 4개: 정확한 범주 조합 수와 초기 엔트로피, 과거만 사용하는 입력·학습 임계값, 확률 정규화·엔트로피 범위, 동률 p값. 저장된 통합 p값과 소스 해시도 재계산했다.

```text
python scripts/lotto_entropy_regime.py
python scripts/lotto_regime_consensus.py
python -m pytest tests/test_lotto_entropy_regime.py -q
```

입력·프로토콜·검증 점수 배열·모델별 결과·합의 점수는 data/lotto/entropy-regime/에 보존했다. 결과는 탐색용이며 구매·배포·자동 감시는 실행하지 않았다.
