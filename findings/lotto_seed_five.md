# 128비트 시드 5회 이상 적중 탐색

128비트 생성기 `splitmix64-paired128-v1`을 유지하고, 학습 구간에서 홀수 부분 3회 이상·짝수 부분 2회 이상 적중한 부분들을 결합합니다. 완성 시드는 학습 구간에서 최소 5회 적중합니다. 후보 수·선별 조건·대조군 난수 시드를 실행 전에 고정하고 생존 부분의 모든 결합을 이후 회차에서 평가합니다.

실제 수치와 시드 예시는 [실험 보고서](../data/lotto/reports/seed-five/report.md), 전체 시드와 학습 적중 회차는 `data/lotto/reports/seed-five/selection.json`에 저장합니다.

## 실제 결과

홀수 후보 10억 개 중 3회 적중 부분은 3개, 짝수 후보 200만 개 중 2회 적중 부분은 117개였습니다. 그 결과 완성된 128비트 시드 351개가 모두 정확히 5회 적중했습니다. 탐색한 조건에서 6회 이상 시드는 없었습니다. 선별에 약 160.69초, 이후 평가에 약 17.83초가 걸렸습니다.

검증 741~990회에서는 생존군 평균 일치가 0.758256개, 대조군은 0.799961개였습니다. 최종 991~1238회에서는 생존군 0.788668개, 대조군 0.800133개였습니다. 최종 대조군 10,000개 중 70.86%가 생존군 이상의 성적이었고 생존군 평균은 대조군의 95% 참고 범위 안에 있었습니다. 이후 498회에서 생존군의 1등 적중은 0회였습니다.

최종 최고 시드 `95d4f445dac194e935bb0c4588cc450c`의 평균 일치는 0.907258개였습니다. 대조군에서도 같은 수의 시드 중 최고를 고르면 평균 0.922433개였고, 대조군 최고값의 70.34%가 생존군 최고값 이상이었습니다. 개별 최고를 고르는 효과까지 반영해도 이번 실험에서는 예측 우위가 나타나지 않았습니다.

21개 테스트를 통과했습니다. 별도 스칼라 Python 구현으로 351개 시드 × 1,238회 = 434,538티켓의 학습 적중과 이후 분포를 검증했습니다. 부분 공유를 캐시해 직접 복원한 스트림별 회차 번호는 74,280개이며, 모든 결합 시드의 각 회차를 대조했습니다.

## 확대 범위와 병렬 구조

- 홀수 부분: 기존 100만 개에서 10억 개로 확대했습니다. 첫 홀수 회차의 적중을 구성하는 역상들을 중복 없는 아핀 순열로 순회합니다. 이는 기존 무작위 표본 방식과 다른 후보 열거 방식입니다.
- 짝수 부분: 기존 100만 개에서 200만 개로 확대했습니다. 첫 짝수 회차 적중 조건에서 중복 없는 무작위 표본을 뽑는 방식을 유지합니다.
- 홀수·짝수 탐색을 별도 프로세스로 동시에 실행합니다. 큰 홀수 탐색은 C++의 네 스레드로 처리하고, 이후 검증·최종 평가는 두 프로세스로 나눕니다.
- 학습은 1~740회, 검증은 741~990회, 최종 평가는 991~1238회로 유지합니다. 대조군은 동일 부분 개수와 전체 결합 구조로 10,000회 생성합니다.

처음 두 적중은 역산으로 만든 조건이며 미래 예측 성과가 아닙니다. 3+2회 이상 조건을 탐색한 것이므로 2+3회나 1+4회 등 다른 배분의 5회 적중 시드를 전부 검색했다고 해석하면 안 됩니다. 후보 부분 수의 곱을 실제 검사한 독립 시드 수로 보고하지 않습니다.

## 검증 방식

학습에서 적중한 홀수·짝수 부분만 고정해 모든 조합을 평가합니다. 여러 완성 시드가 같은 부분을 공유하므로, 대조군도 같은 홀수·짝수 부분 개수와 Cartesian 결합 구조를 사용합니다. 이를 통해 같은 티켓 수뿐 아니라 공유로 인한 상관도 반영합니다.

개별 시드 중 최고를 보면 다중 비교가 생깁니다. 최고값은 대조군에서도 같은 수 중 최고를 고른 값과 비교합니다. 개별 성적을 보고 새로 좋은 시드만 고르지는 않습니다. 1등 티켓 수와 같은 스트림의 중복을 제외한 적중 건수를 구분합니다.

네이티브 탐색은 학습 자료만 받습니다. 반환된 생존 부분의 적중 횟수는 Python에서 다시 확인합니다. 테스트에는 정확히 2회와 3회 적중의 경계, 배치·스레드 수 변경 시 동일한 결과, 순차·병렬 전체 평가 동일성, 이후 당첨 결과를 변경해도 학습 선별이 유지되는지, 결과 덮어쓰기 방지를 포함했습니다.

## 재현

```powershell
New-Item -ItemType Directory -Force .local-build
g++ -O3 -march=native -std=c++17 -pthread -static src/lotto_seed_scan.cpp -o .local-build/lotto_seed_scan.exe
python src/lotto_seed_five.py --executable .local-build/lotto_seed_scan.exe --output .local-build/five-repeat
python -m pytest tests/test_lotto_seed_five.py tests/test_lotto_seed_128.py tests/test_lotto_seed_expanded.py tests/test_lotto645.py -q
python scripts/verify_lotto_seed_128.py --report data/lotto/reports/seed-five
```

설정·소스·실행 파일·원장 해시는 `protocol.json`, 배치별 후보 수와 적중 분포는 `odd-batch-*.json`, 평가 전체는 `experiment.json`에 보존합니다. 기존 결과 디렉터리는 덮어쓰지 않습니다. 부분별 후보 수와 네이티브 스레드 수는 CLI 옵션으로 실행 전에 변경할 수 있습니다.

별도 스칼라 Python 구현은 생존 시드의 실제 6개 번호를 복원해 학습 적중 회차 및 이후 분포와 대조합니다. 같은 부분의 회차별 번호는 캐시하지만 모든 완성 시드의 티켓을 검증합니다. 검증 건수는 `verification.json`에 기록합니다.
