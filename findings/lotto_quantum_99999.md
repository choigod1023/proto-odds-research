# 고정 양자 회로의 가짜 이력 99,999개 검증 — 실행 중

아직 99,999개 결과와 최종 p값은 나오지 않았다. 이전 9,999개 결과의 주 평가 p값은 0.0977이며, 이는 이번 확장 실험의 결과가 아니다.

## 고정한 조건

PR #305의 6큐비트 RY/CNOT 2층 모델, 매개변수 12개, 초기 각도, 균등 혼합 5%, 의사 관측 740회, L-BFGS-B 설정을 그대로 사용한다. 학습은 1~740회, 주 평가는 991~1238회, 부 평가는 741~990회와 1239~1245회다. 새 실제 회차나 새 모델 선택은 없다. 원본 모델 소스와 데이터 해시가 이전 실험과 일치하는지 확인했다.

이미 검산을 마친 기존 가짜 이력 9,999개를 파일 해시와 프로토콜·인덱스 검증 후 재사용하고, 같은 시드 순서에서 90,000개를 추가한다. 총 99,999개이며 시드는 `2026101700 + i`, `i=0..99998`이다. 실제 평가 결과를 재계산하고 기존 이력 0·998·9998번을 재학습하여 정확히 일치하는지도 확인한다. 최종 p값은 `(1 + 실제 이상의 가짜 이력 수) / 100000`이다.

## 컴퓨터 부하와 재시작

논리 CPU 하나, BELOW_NORMAL 우선순위, 수치 라이브러리 스레드 1개를 사용한다. 각 이력 계산 시간 이상(최소 25ms) 쉬고 100개마다 1초 더 쉰다. 100개 결과만 메모리에 보유한 뒤 압축 저장하며, 전체 학습 객체를 한꺼번에 메모리에 올리지 않는다. 집계에는 구간별 점수만 유지한다.

메모리 감시 기준은 256MiB, 블록별 시간 예산은 120초, 한 실행의 총 예산은 12시간이다. 이는 소프트웨어 감시이며 OS 수준의 강제 메모리 제한은 아니다. OS 파일 잠금으로 같은 작업의 중복 실행을 막는다. 체크포인트는 fsync 및 내용 재확인 후 교체하고, 재실행 때 기존 블록의 해시·프로토콜·연속성을 검사한다.

계산 완료 뒤에는 별도 밀집 행렬 구현으로 가짜 이력 99,999개와 실제 회로 1개를 모두 검산한다. 최종 p값은 이 단계가 통과한 뒤 보고한다. 일부 최적화가 수렴하지 않아도 그 이력을 임의로 버리지 않고 고정 규칙의 결과를 포함하여 수렴 수를 별도로 기록한다.

## 실행과 확인

전체 작업: `python scripts/run_lotto_quantum_99999.py`.

읽기 전용 진행 확인: `data/lotto/reports/quantum-99999/progress.json`. `state=verified` 및 `verification.json`의 `status=passed`가 최종 검산 완료 기준이다. 실행 중에는 요약 파일이 없거나 검산이 끝나지 않을 수 있다.

모델·체크포인트 관련 테스트 17개가 통과했다. 첫 새 블록 100개를 실제 실행해 기존 9,999개 다음인 10,099개까지 저장하는 것도 확인했다. 그 이후 실행은 이 체크포인트에서 이어간다.

결과가 나와도 과거 자료를 반복 사용한 탐색이며 신규 미공개 회차의 확증 검증은 아니다. 가짜 이력을 늘리는 것은 몬테카를로 오차를 줄이는 일이지 모델의 실제 점수를 높이는 일이 아니다. 실제 양자 하드웨어나 양자 우위를 검증하는 실험도 아니다.
