# 고정 양자 회로의 가짜 이력 99,999개 검증 — 완료

**주 평가 p값은 0.0997이다. 이전 9,999개 결과 0.0977과 거의 같으며, 균등 무작위보다 우월하다는 근거가 부족하다는 결론은 유지된다.** 실제 모델의 점수는 바뀌지 않았다.

## 최종 결과

- 741~990회: 실제 평균 로그점수 차이 −0.002535766, 실제 이상의 가짜 이력 57,108개, p=0.57109. 이전 p=0.5658.
- **991~1238회:** 실제 평균 로그점수 차이 +0.002956079, 실제 이상의 가짜 이력 **9,969개/99,999개, p=0.0997**. 이전 p=0.0977.
- 1239~1245회: 실제 평균 로그점수 차이 +0.001453065, 실제 이상의 가짜 이력 44,314개, p=0.44315. 이전 p=0.4385.

주 평가의 귀무 모형 꼬리 확률에 대한 Clopper–Pearson 95% 구간은 **0.09784~0.10156**다. 이는 몬테카를로 불확실성 구간이며 실제 예측 효과나 당첨 확률의 신뢰구간이 아니다. 균등 추첨에서도 약 10%가 이번 실제 이상의 점수를 얻는다는 결과다.

주 평가의 기하평균 확률비는 이전과 같은 1.002960452다. 실제 당첨 조합에 부여한 확률이 약 0.296% 높았다는 의미이며, 구매 복권의 당첨률이 그만큼 높아졌다는 뜻은 아니다. 앞선 검증 구간에서는 무작위보다 낮았고 개선이 일관되지 않았다. 운영 번호 생성 방식은 변경하지 않았다.

## 고정한 조건

PR #305의 6큐비트 RY/CNOT 2층 모델, 매개변수 12개, 초기 각도, 균등 혼합 5%, 의사 관측 740회, L-BFGS-B 설정을 그대로 사용한다. 학습은 1~740회, 주 평가는 991~1238회, 부 평가는 741~990회와 1239~1245회다. 새 실제 회차나 새 모델 선택은 없다. 원본 모델 소스와 데이터 해시가 이전 실험과 일치하는지 확인했다.

이미 검산을 마친 기존 가짜 이력 9,999개를 파일 해시와 프로토콜·인덱스 검증 후 재사용하고, 같은 시드 순서에서 90,000개를 추가한다. 총 99,999개이며 시드는 `2026101700 + i`, `i=0..99998`이다. 실제 평가 결과를 재계산하고 기존 이력 0·998·9998번을 재학습하여 정확히 일치하는지도 확인한다. 최종 p값은 `(1 + 실제 이상의 가짜 이력 수) / 100000`이다.

## 컴퓨터 부하와 재시작

논리 CPU 하나, BELOW_NORMAL 우선순위, 수치 라이브러리 스레드 1개를 사용한다. 각 이력 계산 시간 이상(최소 25ms) 쉬고 100개마다 1초 더 쉰다. 100개 결과만 메모리에 보유한 뒤 압축 저장하며, 전체 학습 객체를 한꺼번에 메모리에 올리지 않는다. 집계에는 구간별 점수만 유지한다.

메모리 감시 기준은 256MiB, 블록별 시간 예산은 120초, 한 실행의 총 예산은 12시간이다. 이는 소프트웨어 감시이며 OS 수준의 강제 메모리 제한은 아니다. OS 파일 잠금으로 같은 작업의 중복 실행을 막는다. 체크포인트는 fsync 및 내용 재확인 후 교체하고, 재실행 때 기존 블록의 해시·프로토콜·연속성을 검사한다.

별도 밀집 행렬 구현으로 가짜 이력 99,999개와 실제 회로 1개를 모두 검산했다. 가짜 이력 평가 회차 50,499,495개로 구간별 평균 로그점수를 재계산했으며 최대 오차는 약 7.11×10⁻¹⁶이었다. 모든 99,999개 학습이 정상 수렴했다. 기존 자료의 해시, 새 압축 블록 900개와 기존 블록 100개의 연속성, 전체 기록 수와 꼬리 확률 요약을 확인했다. 실제 자료와 모델 소스 해시는 이전과 일치했다.

## 측정한 시간과 자원

첫 새 블록 100개를 사전 실행한 뒤, 10,099개 체크포인트에서 99,999개까지 백그라운드로 이어갔다. 이 주 실행은 **8,337.29초(2시간 18분 57초)**, CPU 시간 **3,429.78초**, 최대 작업 집합 **123.41MiB**였다. 이후 전체 검산은 **401.35초(6분 41초)**, CPU 시간 **150.05초**, 최대 작업 집합 **111.60MiB**였다. 주 실행과 검산의 합은 약 2시간 25분 39초이며, 첫 블록 사전 실행 약 8.63초, 준비·대기 시간 및 이전 9,999개 계산 시간은 포함하지 않았다.

주 실행 중 오류로 재시작하지 않았으며 오류 로그도 비어 있다. 실행 중 별도 10초 측정에서 계산 프로세스는 전체 16개 논리 CPU 기준 약 2.6%를 사용했다. 이는 해당 측정 구간의 값이며 전체 실행 평균은 아니다. 컴퓨터 전체의 온도·전력은 측정하지 않았다. 계산과 검산 프로세스는 모두 종료됐다.

## 실행과 확인

전체 작업: `python scripts/run_lotto_quantum_99999.py`.

읽기 전용 진행 확인: `data/lotto/reports/quantum-99999/progress.json`. `state=verified` 및 `verification.json`의 `status=passed`가 최종 검산 완료 기준이다. 실행 중에는 요약 파일이 없거나 검산이 끝나지 않을 수 있다.

모델·체크포인트 관련 테스트 17개가 최종 상태에서 통과했다. `summary.json`, `verification.json`, `final-audit.json`에 집계·검산·해시 및 전체 기록 점검 결과를 저장했다.

결과가 나와도 과거 자료를 반복 사용한 탐색이며 신규 미공개 회차의 확증 검증은 아니다. 가짜 이력을 늘리는 것은 몬테카를로 오차를 줄이는 일이지 모델의 실제 점수를 높이는 일이 아니다. 실제 양자 하드웨어나 양자 우위를 검증하는 실험도 아니다.
