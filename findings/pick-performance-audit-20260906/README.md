# 적중률 집계·추천 필터 감사 — 2026-09-06

## 결론

현재 API 스냅샷을 화면과 같은 방식으로 결합하면 **93/161 = 57.8%**다. 사용자가 본 57.9% 시점의 원본은 없어 그 숫자 자체는 검증하지 못했다. 별도 이벤트 집계와 화면 집계의 건수는 일치한다. **평생 누적 성과가 정확하다거나 예측 능력이 검증됐다는 뜻은 아니다.**

- 저장된 사전 예측 355건: 적중 93, 실패 68, 무효 1, 미판정 193. 기록 없는 경기 행은 299건이며 성과에 넣지 않는다.
- 이번 응답에서 중복 행·중복 revision·경기 시작 이후 캡처·판정 충돌은 발견되지 않았다.
- 적중/실패 161건 중 공식 마켓 판정 104건, 종료 점수 기반 임시 판정 57건. 공식만 보면 **55/104 = 52.9%**다. 임시 판정은 38/57이며 공식 판정으로 확정해야 한다.
- `/api/picks` 자체에는 정산 결과가 없어 단독 집계는 0건이다. `/api/live-odds`와 `/api/live-scores`를 결합해야 위 숫자가 나온다. 브라우저가 보유한 이전 중계 기록에 따라 순간 수치가 다를 수 있다.
- 운영 응답에는 `prediction_performance`가 없다. 현재 집계는 내려온 경기의 저장 기록에 한정되며 전체 원장과 대조하지 못했다. 코드의 원장 지원 여부와 실제 API 제공 여부를 구분해야 한다.
- 9월 5일 이전 178건 중 122건이 아직 미판정이다. 단순히 진행 중인 경기만 빠진 것이 아니다. 누락 결과가 무작위라고 볼 수 없어 현재 적중률에 선택 편향이 있을 수 있다.
- 전체 판정 표본의 동일 금액 단건 모의 ROI는 **-5.8%**, 평균 배당 1.631. 57.8% 적중이 수익을 의미하지 않는다. 적중률 Wilson 95% 구간은 50.0~65.1%로 넓다.

## 추천 방식 비교

현재 오늘의 추천 API는 **1.50 이상 2.20 미만 후보 우선 → 없으면 저배당 보조 → 최종 확률 순**이며, 응답의 확률 방식은 Shin이다. 당시 후보 전체와 실제 노출 추천의 변경 이력을 확보하지 못했으므로 이 순위 방식 자체를 역사적으로 재현한 백테스트는 아니다. 이번 비교는 **저장된 경기별 픽을 고정하고 엄선 필터만 달리 적용한 모의 비교**다.

결과를 보기 전에 고정한 기준은 전체, 저장 확률 55/58/60/65% 이상, 저장 배당 1.70 이하다. 저장된 원래 확률·배당·선택만 사용하며 경기 후 옵션이나 모델로 재선택하지 않는다. 모든 기록의 KST 경기 날짜를 정렬해 앞 70% 날짜와 뒤 날짜를 나눴다. 기준일은 2026-09-05다. 이는 탐색용 시간 분리이지 사전 등록된 미래 실험은 아니다.

뒤 검증 구간의 결과:

- 전체: **55/105, 52.4%, ROI -14.4%**. 후보 177건 중 105건 판정.
- 확률 55% 이상: **25/50, 50.0%, ROI -21.6%**. 후보 유지 50.8%.
- 확률 58% 이상: **9/21, 42.9%, ROI -34.5%**. 후보 유지 23.2%.
- 확률 60% 이상: **1/3, 33.3%, ROI -50.0%**. 후보 유지 4.5%; 판단하기에 너무 작다.
- 확률 65% 이상: 판정 0건, 비교 불가. 후보 1건은 미판정.
- 배당 1.70 이하: **44/87, 50.6%, ROI -18.8%**. 후보 유지 83.1%.

전체 기간만 보면 확률 60% 이상이 5/7로 71.4%, 65% 이상이 2/2로 100%다. 그러나 극소 표본이며 뒤 구간에서 재현되지 않는다. 이런 숫자를 근거로 추천 기준을 바꾸거나 홍보하면 안 된다.

전체 기간의 승패 30/44, 핸디캡 23/35는 언더오버 37/74보다 높았지만 **결과를 본 뒤 찾은 탐색 결과**다. 종목 구성과 결과 확보 비율도 다르므로 승패/핸디캡 우선은 차기 검증 후보이지 즉시 적용안이 아니다.

## 권고

1. **원장·결과 완결성 우선**: 오래된 미판정 기록의 공식 결과를 대조하고, 전체 원장과 화면의 집계 범위를 일치시킨다. 수치 설명에는 공식/임시 판정과 미판정 수를 유지한다.
2. **추천 이력 별도 보존**: 경기별 사전 픽과 실제 '오늘의 추천' 노출을 구분하고, 추천 시각·정책 버전·후보 집합·원래 확률·배당·결과를 연결한다. 같은 픽의 반복 노출을 새 성과로 세지 않는다.
3. **운영 기준 유지, 실험은 병렬 기록**: 위 고정 필터 및 승패/핸디캡 우선 후보를 실제 추천에 영향을 주지 않는 방식으로 평가한다. 같은 경기 기간에서 판정 완결성·표본 수·적중률·확률 오차·ROI·추천 유지율을 함께 비교한 후 변경한다.
4. **확률은 검증된 보정만**: 평균 저장 확률은 55.1%, 전체 적중률은 57.8%지만 뒤 구간은 확률 55.1% 대비 적중 52.4%다. 일괄 상향할 근거가 없다. 충분한 이전 데이터로만 보정기를 학습하고 이후 기간의 Brier/log loss와 보정 구간을 비교한다.

이번 작업은 감사 도구·결과만 추가한다. 서비스 추천 기준, 표시 확률, 과거 픽 및 운영 DB는 변경하지 않는다. 별도 서비스 배포가 필요한 변경은 없다.

## 재현·범위

Node.js로 저장된 압축 API 응답을 재생한다. 네 응답 원문의 SHA-256, API 생성 시각, 이벤트별 선택/결과/판정 출처, 전체 정책·종목·마켓·보정 구간 결과는 `report.json`에 있다. 공개 스포츠 API 데이터만 보존한다.

```sh
node scripts/audit-pick-performance.mjs --input findings/pick-performance-audit-20260906
node --test scripts/audit-pick-performance.test.mjs
# 새 스냅샷은 별도 위치에 수집 (기존 감사 기준을 덮어쓰지 않음)
node scripts/audit-pick-performance.mjs --capture data/runtime/new-pick-audit
```

기준 API 생성 시각(KST): picks/live-odds 11:48:24, live-scores 11:55:07, today-recommendations 11:50:48. 기록된 경기 날짜 범위는 8월 28일~9월 7일이며 미래·미판정 경기는 적중률 분모에서 제외한다. 응답 네 개는 원자적 스냅샷이 아니다.

이벤트 집계 구현은 별도지만 결과 판정은 서비스의 `recommendationOutcome`을 재사용한다. 그러므로 건수 재현과 판정 충돌 탐지이지, 모든 실제 경기 결과를 외부 기관과 독립 검증한 감사는 아니다. 캡처 시각의 원장 무결성도 이번 공개 API 감사에서는 독립 검증하지 못했다. ROI는 유효 배당의 적중/실패 픽에 각 1단위, 무효 제외, 수수료·체결 차이 미포함이다. 신뢰구간은 경기 간 독립을 가정한 참고치다.
