# 고정 6큐비트 모델의 가짜 이력 999,999개 검증

999,999개 계산과 독립 검산을 완료했다. 주 평가 p값은 이전 99,999개 실험의 **0.0997에서 0.102115**로 바뀌었다. 무작위보다 우수하다는 통계적 근거는 확인하지 못했다. 실제 모델과 실제 자료의 점수는 바뀌지 않았다.

## 결과

- 주 평가(991~1238회): 평균 로그 이득 0.00295607881356895, 실제 이상인 가짜 이력 102,114개, p=0.102115. 몬테카를로 꼬리 확률의 95% Clopper–Pearson 구간은 [0.101521281, 0.102709229].
- 부 평가(741~990회): 평균 로그 이득 -0.0025357664010134937, 초과·동률 568,844개, p=0.568845.
- 이미 확인했던 추가 구간(1239~1245회): 평균 로그 이득 0.0014530650075181611, 초과·동률 442,795개, p=0.442796.
- 999,999개 학습 모두 수렴했다. 미수렴이나 낮은 점수 이력을 제거하지 않았다.

주 평가에서 실제 결과에 부여한 확률의 기하평균 비율은 균등 기준 대비 약 1.00296045로 이전과 같다. 이는 당첨률이 0.296% 높아졌다는 뜻이 아니다. 이번 확장은 가짜 이력의 수를 늘려 몬테카를로 오차를 줄인 작업이다. 위 구간도 실제 예측 효과의 신뢰구간이 아니다.

## 고정 조건과 실행 방식

PR #306의 모델 코드를 그대로 사용했다. 6큐비트 RY/CNOT 2층, 매개변수 12개, 낮은 번호 개수·홀수 개수 인코딩, 균등 혼합 5%, 균등 의사 관측 740회, 초기 각도와 L-BFGS-B 설정을 유지했다. 학습은 1~740회다. 새 실제 자료 수집이나 모델 재선택은 없었다.

기존 99,999개를 해시·프로토콜·연속성 확인 후 재사용하고 900,000개를 추가했다. 시드는 `2026101700 + i`, `i=0..999998`이다. p값은 `(1 + 실제 이상의 가짜 이력 수) / 1000000`이다. 실제 자료 재계산과 병렬 작업자의 기존 이력 0·998·9998·99998번 재학습 결과는 기존 기록과 정확히 일치했다.

계산 프로세스 2개를 서로 다른 논리 CPU 하나씩에 고정하고 낮은 우선순위·수치 라이브러리 스레드 1개를 유지했다. 각 이력 계산 후 계산 시간의 25% 이상, 최소 5ms 쉬었다. 검산은 단일 프로세스다. 프로세스별 256MiB 소프트웨어 메모리 감시, 블록별 300초 예산, 동시에 최대 2개 블록, OS 파일 잠금을 사용했다. 500개씩 압축·fsync·재열기 확인 후 저장했다. 모델 수학과 최적화 조건은 바꾸지 않았다.

## 시간과 자원 측정 범위

초기 병렬 시험에서 새 이력 1,000개를 약 38.7초에 계산했다. 이후 100,999개 체크포인트에서 이어서 실행한 본 계산은 **33,062.231초(9시간 11분 2초)**, 독립 검산은 **2,008.464초(33분 28초)**였다. 두 구간 합계는 약 9시간 44분 31초이며, 초기 시험·사전 파일 검사·기존 99,999개를 만들었던 시간은 포함하지 않는다. 오류로 재시작한 적은 없으며, 초기 제한 실행 후 체크포인트에서 이어갔다.

새 900,000개 블록의 작업자 CPU 시간 합계는 50,290.141초다. 이는 두 작업자의 누적 CPU 시간으로, 실제 경과 시간과 다르며 초기 시험 블록을 포함한다. 조정 프로세스·사전 재학습·검산 CPU 시간은 제외한다.

- 본 작업자 PID 15024: 920블록, CPU 25,703.250초, 최대 메모리 113.164MiB.
- 본 작업자 PID 41708: 878블록, CPU 24,532.078초, 최대 메모리 113.652MiB.
- 초기 시험 작업자 PID 16388·21788: 각 1블록, CPU 27.563·27.250초, 최대 메모리 111.809·111.766MiB.
- 조정 프로세스 최대 메모리: 109.914MiB.
- 별도 검산: CPU 1,322.563초, 최대 메모리 114.285MiB.

개별 프로세스 최대 메모리는 전체 프로세스의 동시 최대 합계가 아니다. 본 실행 초기 10초 표본에서 계산 작업자의 CPU 사용량 합계는 전체 16개 논리 CPU 기준 약 9.46%, 작업자 두 개와 조정 프로세스 메모리 합계는 약 324.29MiB였다. 실행용 부모 프로세스는 제외했다. 이후 5초 표본에서는 세 프로세스 CPU 약 9.8%, 메모리 약 305MiB, 컴퓨터 여유 메모리 약 13.3GiB였다. 컴퓨터 전체 CPU 순간값은 초기에 85%, 이후에 13%로 다른 작업의 영향도 있었다. 전체 실행 평균·온도·전력은 측정하지 않았다.

## 검산과 재현

별도 밀집 행렬 회로 구현으로 가짜 회로 999,999개와 실제 회로 1개, 가짜 평가 504,999,495회분을 검산했다. 평균 로그 점수의 최대 차이는 9.1854e-16이었다. `progress.json`은 `verified`, `verification.json`은 `passed`다. 오류 로그는 비어 있고 실행 프로세스는 종료했다.

추가 스트리밍 감사로 999,999개 인덱스 연속성, 새 압축 파일 1,800개, 기존 99,999개 파일과 모델 소스·실제 자료 해시, 실제 결과 동일성, 수렴 수, p값·꼬리 구간·분위수의 정확한 재계산 일치를 확인했다. 감사 결과는 `data/lotto/reports/quantum-million/final-audit.json`에 저장했다.

관련 테스트 **20개 통과**:

```text
python -m pytest tests/test_lotto_quantum_million.py tests/test_lotto_quantum_99999.py tests/test_lotto_quantum_9999.py tests/test_lotto_quantum_999.py tests/test_lotto_small_quantum.py tests/test_lotto645.py -q
```

실행 명령은 `python scripts/run_lotto_quantum_million.py`, 결과 경로는 `data/lotto/reports/quantum-million/`이다.

## 해석의 한계

과거 실제 자료를 반복 사용하는 탐색이므로 신규 미공개 회차의 확증 검증이 아니다. 여러 모델을 시도하고 결과를 확인하며 표본을 늘린 전체 선택 과정까지 p값이 보정하지 않는다. 양자 회로를 일반 컴퓨터에서 모의실험한 것이며 실제 양자 하드웨어나 양자 우위, 1등 당첨률 향상을 입증하지 않는다.
