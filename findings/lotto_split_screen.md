# 회차를 나눠 후보를 좁히면 약한 관계를 더 잘 찾는가

2026-10-17. 정해 둔 모의실험 기준을 통과해 같은 규칙으로 과거 자료도 검사했다. 실제 자료에서 고른 두 후보는 다른 구간에서 모두 확인되지 않았다.

관계가 없는 이력 100개와 여섯 효과 강도별 30개를 합쳐 **280개 가상 이력**을 검사했다. 각 이력은 독립적인 1,245회 추첨이다. 규칙·강도·반복 수·시드·실제 자료 적용 기준을 첫 실험 전에 `protocol.json`과 Git 커밋 `6b213ee8`에 고정했다. 모든 이력에서 두 방법은 같은 1,245회 자료를 썼다. 결과를 보고 분할 위치·후보 수·유의수준을 바꾸지 않았다.

## 정확한 관계 식별과 후보 선별

각 칸은 성공 횟수, 비율, 해당 칸의 정확한 95% Clopper–Pearson 구간이다. 30회 반복의 추정치이므로 구간이 넓다. 전체 칸을 동시에 덮는 구간은 아니다. 아래는 로또 당첨률이 아니라 **주입한 관계의 탐지율**이다.

| 주입한 동반 출현 확률 | 800회에서 해당 관계를 후보로 선택 | 분할 방법: 445회에서 그 후보까지 확인 | 전체 1,245회에서 해당 관계 식별 |
|---|---|---|---|
| 두 번호 1.5배 | 1/30 (3.3%; 0.1~17.2%) | 1/30 (3.3%; 0.1~17.2%) | 0/30 (0.0%; 0.0~11.6%) |
| 두 번호 2배 | 17/30 (56.7%; 37.4~74.5%) | 13/30 (43.3%; 25.5~62.6%) | 3/30 (10.0%; 2.1~26.5%) |
| 두 번호 3배 | 30/30 (100.0%; 88.4~100.0%) | 30/30 (100.0%; 88.4~100.0%) | 29/30 (96.7%; 82.8~99.9%) |
| 세 번호 3배 | 0/30 (0.0%; 0.0~11.6%) | 0/30 (0.0%; 0.0~11.6%) | 0/30 (0.0%; 0.0~11.6%) |
| 세 번호 5배 | 8/30 (26.7%; 12.3~45.9%) | 4/30 (13.3%; 3.8~30.7%) | 7/30 (23.3%; 9.9~42.3%) |
| 세 번호 8배 | 24/30 (80.0%; 61.4~92.3%) | 19/30 (63.3%; 43.9~80.1%) | 29/30 (96.7%; 82.8~99.9%) |

후보가 된 횟수와 최종 확인 횟수의 차이는 검증 구간에서 놓친 경우다. 후보에 들지 못한 관계는 검증 표본이 아무리 좋아도 이 규칙으로 발견할 수 없다. '아무 관계나 유의'와 '의도적으로 넣은 관계를 정확히 식별'은 구분했다. 모든 지표의 개별 기록은 `records.json`에 있다.

무관계 자료 100개에서 아무 관계나 유의한 횟수는 분할 방식 **4/100**, 전체 탐색 **3/100**이었다. 분할 오탐률의 단측 95% 상한은 **8.92%**다. 작은 대조 실험만으로 오탐률이 정확히 5% 또는 0%임을 증명하지 않는다.

## 고정한 방법과 공정한 비교

1. 앞 800회에서 990개 두 번호 관계와 14,190개 세 번호 관계의 조건부 표준화 편차를 계산한다. 각 종류에서 절댓값이 가장 큰 후보 하나씩, 총 두 개를 고른다. 동률은 사전식 번호 순서로 결정한다. 증가/감소 방향도 여기서 고정한다.
2. 뒤 445회에서는 이 두 후보만, 앞 구간에서 정한 방향의 단측 검정으로 검사한다. 두 검정에 Bonferroni 보정을 적용해 보정 p≤0.05일 때 확인한다. 검증 자료를 보고 후보·방향을 다시 선택하지 않는다.
3. 비교 방법은 전체 1,245회를 사용해 15,180개 후보의 양측 maxT 검정을 유의수준 0.05로 실시한다. 이전 연구의 '전체 통계 세 범주' 보정 계수 3을 추가하지 않았다. 분할 방법을 불필요하게 보수적인 비교 대상과 비교하지 않기 위해서다. 이번 비교 수치를 이전 1,000회 연구와 같은 조건의 수치로 혼동하면 안 된다.

개별 번호 빈도는 무작위 교환 과정에서 정확히 보존한다. 후보 선별 구간의 구간 경계는 200, 400, 600, 800회다. 검증 구간은 445회 전체를 하나의 구간으로 묶는다. 전체 탐색에서도 동일한 다섯 구간의 빈도를 고정한다. 이 귀무모형은 각 구간 안에서 단일 번호 가중치만 있고 조합 상호작용은 없는 독립 추첨이다. 구간 안에서 가중치가 계속 변하는 경우까지 포괄하지 않는다.

한 회차에 서로 다른 번호 여섯 개를 뽑는 제약 때문에 생기는 번호 간 의존성은 귀무모형에 포함했다. 여기서 '무관계'는 그 기본 구조를 넘어서는 추가 상호작용이 없다는 뜻이다.

가역 Curveball의 공통 중간 상태와 독립 경로 끝점을 사용했다. 후보 선별은 199개, 검증과 전체 탐색은 각각 999개 끝점을 쓴다. 각 경로 길이는 해당 자료 회차 수의 20배다. 관측 자료도 중심·분산 계산에 대칭적으로 포함한다. 모든 교환 표본에서 행 크기 여섯 개와 구간별 번호 횟수를 검사한다. 전체 탐색과 분할 방법은 같은 자료를 쓰지만 서로 다른 고정 난수열로 비교 분포를 생성한다.

모형은 이전 연구와 같은 주변확률 보존 방식이다. 두 번호 동반 출현은 1.5·2·3배, 세 번호는 3·5·8배를 넣었다. 모든 개별 번호 확률은 6/45이며, 세 번호 모형에서는 모든 쌍의 주변확률도 균등 기준과 같다. 이력마다 대상 번호를 무작위로 정한다. 회차 사이에는 독립성이 유지된다. 이 두 생성 모형이 모든 약한 관계·시간 변화·분산된 의존성을 대표하지는 않는다.

## 실제 자료에 적용할 사전 기준

다음 네 조건을 모두 요구했다. 오탐률 상한 12%는 작은 모의 검사의 운영 기준이며, 실제 검정 유의수준을 12%로 바꾼 것이 아니다. 실제 검정 기준은 계속 5%다.

- 무관계 100개에서 분할 오탐률의 단측 95% 상한 ≤12%.
- 약한 효과 묶음(두 번호 1.5·2배, 세 번호 3·5배, 총 120개)에서 정확한 관계 식별률이 전체 탐색보다 5%p 이상 높음.
- 같은 자료 쌍의 분할만 성공/전체만 성공 횟수를 비교한 단측 이항 진단 p≤0.05.
- 두 번호 3배 대조 조건에서 분할 방식의 정확한 관계 식별률 ≥50%.

실제 결과: 분할만 성공 **11개**, 전체 탐색만 성공 **3개**, 약한 묶음의 차이 **+6.67%p**, 단측 짝 비교 p=**0.028687**. 두 번호 3배의 분할 탐지율은 **100.0%**였다.

- `null_upper95_le_012`: 통과
- `weak_gain_at_least_005`: 통과
- `paired_one_sided_p_le_005`: 통과
- `pair3_power_at_least_half`: 통과

이 비교는 고정한 합성 효과 묶음에서의 도입 판단이다. 서로 다른 효과 크기를 묶은 짝 비교를 모든 가능한 관계에 대한 보편적 우월성 검정으로 해석하지 않는다. 통과하지 않았다고 분할 방식 전체가 무용하다는 뜻도 아니다. 다른 후보 수나 분할 비율은 새로운 모의 검증을 거쳐야 한다.

## 실제 자료와 해석 한계

- [26, 32]: 함께 덜 나오는 방향으로 선별. 검증 구간 동반 출현 7회, 원 p=0.689, 보정 p=1.000. 검증 미통과.
- [14, 30, 38]: 함께 더 나오는 방향으로 선별. 검증 구간 동반 출현 1회, 원 p=0.580, 보정 p=1.000. 검증 미통과.

실제 자료 검사의 별도 벽시계 시간은 0.882초, CPU 0.547초, 해당 프로세스 최대 작업 집합 157.395MiB였다.

실제 자료 검사 절차는 1~800회 후보 선별, 801~1,245회 검증이다. 후보와 방향을 검증 통계량 계산 전에 파일로 저장하도록 고정했다. 이 당첨 이력은 여러 이전 연구에서 이미 살펴본 자료이므로, 실제 적용 결과는 **과거 자료를 다시 검사한 결과**로 해석한다. 새 회차의 전향적 검증이나 새로운 당첨 예측력의 확증으로 제시하지 않는다.

이번 연구가 직접 말해 주는 것은 한정된 자료량에서 특정 선별 규칙의 검정력이 얼마나 되는지다. 실제 관계가 존재한다거나 없다는 결론, 1등 확률이 높아졌다는 결론은 이 모의실험만으로 내릴 수 없다.

## 자원·재현·검산

- 주 실험: 마지막 280번째 결과 저장 시점까지 벽시계 727.529초, 전체 CPU 시간은 마지막 요약 저장 오류로 기록되지 않음, 해당 시점까지 프로세스 최대 작업 집합 253.543MiB. 시작 시 완료 기록 0개. 이 시간에는 이후의 요약 오류 처리·복구·실제 자료 검사·감사·테스트 시간이 포함되지 않는다.
- 계산 280개가 모두 끝난 뒤 요약 JSON 저장에서 NumPy 불리언 자료형 오류가 났다. 개별 이력은 재계산하지 않고 저장된 기록으로 요약만 복구했다. `binomtest`의 p값을 Python float로 바꾸는 한 줄을 수정했으며 수치·판정 규칙은 그대로다. 원 프로토콜과 원 소스, 수정 기록을 보존하고 프로토콜의 변경은 해당 소스 해시뿐임을 검산했다. 복구 전후 기록 파일 해시와 수치 게이트가 같음을 확인했다.
- CPU 하나, BelowNormal, 수치 라이브러리 단일 스레드. 계산 묶음과 분석 뒤 계산 시간의 50% 이상 휴식. 최대 작업 집합 384MiB와 실행당 1,800초 감시. OS 배타 잠금으로 중복 실행을 방지했다. 전체 시스템 메모리와 온도는 측정하지 않았다.
- 감사: 20.535초. 일곱 대표 이력의 전체 횟수 행렬 해시·후보·p값·판정을 다시 계산해 원 기록과 비교했다. 280개 기록의 요약, 사전 게이트, 원 소스 해시도 검산했고 `verification.json` status=passed다.
- 컴파일러·Python·NumPy 버전과 바이너리 해시는 감사 파일에 기록했다. 비트 단위 재현은 같은 실행 환경을 기준으로 하며 다른 C++ 표준 라이브러리의 난수 구현까지 동일하다고 가정하지 않는다. 실행 중 별도 5초 표본에서는 한 CPU 기준 약 62.1%를 사용했고 낮은 우선순위와 CPU 지정 상태를 OS에서 확인했다. 이 짧은 측정은 전체 실행 평균이나 컴퓨터 전체 부하를 뜻하지 않는다.
- `python -m pytest tests/test_lotto_combination_dependence.py tests/test_lotto_dependence_power.py tests/test_lotto_split_screen.py tests/test_lotto_split_screen_followup.py -q`: 관련 테스트 26개.
- 생성: `python scripts/lotto_split_screen.py`. 미완료 체크포인트만 재개하고 완료 결과는 덮어쓰지 않는다. 검산: `python scripts/audit_lotto_split_screen.py`. 실제 자료 후속 검사: `python scripts/lotto_split_screen_followup.py --source-dir <기존 자료 경로>`이며 게이트 미통과 때는 자료를 읽지 않는다.

방법의 배경: 후보 선별과 독립 자료의 확인을 나누는 발상은 [Wasserman·Roeder의 Screen and Clean 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC2752029/)를 참고했다. 해당 논문의 회귀모형 정리를 로또에 그대로 적용한 것은 아니며, 여기서는 독립 구간의 조건부 교환 검정과 후보 두 개의 Bonferroni 보정을 사용했다. 교환 가능한 MCMC 검정의 근거는 [Ramdas 외, §4.2](https://arxiv.org/html/2204.13581v5#S4.SS2)다.
