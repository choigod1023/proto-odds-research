# 128비트 시드에서 과거 4회 적중과 이후 성능 비교

홀수·짝수 회차를 담당하는 64비트 값을 결합해 128비트 시드 생성기를 만들었습니다. 학습 구간에서 4회 적중한 시드 3,008개를 찾았지만, 이후 회차에서 생존군 전체가 무작위보다 잘 맞히는 결과는 나오지 않았습니다.

## 후보 구성과 선별

128비트 시드는 32자리 16진수로 저장합니다. 상위 64비트는 홀수 회차, 하위 64비트는 짝수 회차의 조합을 생성합니다. 회차별로 한 부분만 쓰므로 완성 시드 하나당 한 회차에 한 조합을 생성합니다. 각 부분은 기존 SplitMix64 순열과 조합 순번 변환을 사용합니다.

1~740회 학습 구간을 홀수·짝수로 나눠 각각 후보 100만 개를 검사했습니다. 첫 홀수 회차인 1회와 첫 짝수 회차인 2회의 적중은 역산으로 미리 구성한 조건입니다. 담당하는 나머지 학습 회차에서도 한 번 더 적중한 부분만 남겼습니다.

- 홀수 부분: 2회 적중 47개, 3회 이상 0개
- 짝수 부분: 2회 적중 64개, 3회 이상 0개
- 완성 시드: 47 × 64 = 3,008개, 모두 정확히 4회 적중

모든 생존 부분의 조합을 평가했습니다. 후보 부분 집합을 결합할 수 있다고 해서 독립적인 128비트 후보 1조 개를 실제 전수 검사한 것은 아닙니다. 또한 각 부분에서 2회 이상인 조건을 사용했으므로 1+3회 등 다른 4회 적중 패턴을 모두 찾는 탐색은 아닙니다.

## 평가와 중복 구조

741~990회를 검증, 991~1238회를 최종 평가로 사용했습니다. 생존군의 검증 평균 일치 수는 0.799109개, 대조군은 0.799996개였습니다. 최종 평균은 생존군 0.792679개, 대조군 0.800072개였습니다. 이후 498회에서 생존군 1등 적중은 0회였습니다.

최종 구간의 동일 구조 대조군 10,000개 중 86.25%가 생존군 이상의 평균 일치를 기록했습니다. 생존군 평균은 대조군의 95% 참고 범위 안에 있습니다.

3,008개 시드는 홀수 부분 47개와 짝수 부분 64개를 공유합니다. 따라서 3,008개가 독립적인 시드인 것처럼 표본 크기를 부풀리면 안 됩니다. 대조군도 무작위 홀수 부분 47개와 짝수 부분 64개를 결합하는 방식으로 만들었습니다. 각 반복의 생성 티켓 수뿐 아니라 공유로 인한 상관 구조도 맞췄습니다.

최종 구간에서 명목 티켓은 745,984개지만, 공유 부분을 한 번씩만 계산하면 스트림별 티켓은 13,764개입니다. 같은 번호를 생성한 티켓은 같은 비용의 별도 티켓으로 집계합니다. 따라서 이 실험의 명목 티켓 수를 모두 다른 조합의 개수나 구매 효율로 해석하면 안 됩니다.

## 개별 최고 시드 해석

전체 평균과 별도로 최고 시드를 확인하면 다중 비교 효과가 생깁니다. 이에 무작위 대조군에서도 같은 수의 부분을 결합한 시드 중 최고를 골라 비교했습니다. 최고 시드와 동일 조건의 최고 대조군 비교는 [실험 보고서](../data/lotto/reports/seed-128/report.md)의 각 평가 구간에 기록했습니다. 개별 결과는 설명용이며 그 결과로 새로운 추천 시드를 선택하지 않았습니다.

최종 최고 시드 `dc1964d728f3b99d35bb0c4588cc450c`의 평균 일치는 0.963710개였습니다. 하나의 임의 무작위 시드와 비교하면 좋아 보이지만, 대조군에서도 3,008개 중 최고를 고를 때 평균은 0.964011개였습니다. 대조군 최고값의 50.82%가 생존군 최고값 이상이었습니다. 따라서 최고 시드만 보더라도 같은 탐색 기회를 준 무작위 대조군보다 우수하다는 근거가 나타나지 않았습니다.

## 재현과 검증

```powershell
python src/lotto_seed_128.py --output .local-build/seed-128-repeat
python -m pytest tests/test_lotto_seed_128.py tests/test_lotto_seed_expanded.py tests/test_lotto645.py -q
python scripts/verify_lotto_seed_128.py
```

기본값은 부분별 후보 100만 개, 대조군 10,000회입니다. `--candidates-per-half`, `--baseline-repeats`, `--train-end`, `--validation-end`를 실행 전에 지정할 수 있습니다. 결과 디렉터리가 비어 있지 않으면 덮어쓰지 않습니다. Python 및 NumPy 버전, 원장·소스 해시와 모든 설정을 저장합니다.

18개 테스트를 통과했습니다. 테스트는 128비트 인코딩·복원과 회차별 부분 선택, 4회 적중 조건, 평가 구간의 결과를 바꿔도 동일한 학습 선별 결과, 공유 구조 집계와 명시적 전체 조합 집계의 일치, 최고값 대조군 비교를 확인합니다.

별도 스칼라 Python 구현으로 실제 6개 번호를 복원해 생존 시드 전체의 학습 적중과 이후 분포를 검증합니다. 공유 부분의 번호 생성은 캐시하지만 모든 결합 시드의 각 회차 티켓을 확인합니다. 상세 검증 건수는 `verification.json`에 기록합니다.

실제 검증은 3,008개 시드 × 1,238회 = 3,723,904티켓에 대해 통과했습니다. 캐시로 중복을 제외하고 직접 복원한 부분별 회차 번호는 68,709개였습니다. 최고값 비교를 추가한 재실행에서도 생존 시드와 기존 평가 분포가 모두 같았습니다.

## 한계와 자료

128비트로 확장한 별도 생성기이며 64비트 실험 결과와 구분해야 합니다. 두 적중은 구성했고 나머지도 과거 기록으로 선별했습니다. 이전 실험에서 확인한 검증·최종 구간을 다시 쓴 후향 탐색입니다. 대조군 비율은 설명용 비교 지표이며 새로운 미래 성능의 확증 검정이 아닙니다. 128비트라는 길이 자체가 예측력을 높이지 않습니다.

전체 시드와 학습 적중 회차는 `selection.json`, 각 시드의 평가 분포와 대조군 비교는 `experiment.json`에 저장했습니다. 원자료는 `data/lotto/draws.jsonl`의 회차별 출처·수집 시각을 따릅니다. 공식 출처: [동행복권](https://www.dhlottery.co.kr/).

운영 추천 번호, 기존 생성기, 배포 설정은 변경하지 않았습니다.
