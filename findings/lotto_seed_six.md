# 128비트 시드 6회 이상 적중 탐색

기존 `splitmix64-paired128-v1` 생성기를 유지하고 학습 구간의 홀수·짝수 회차에서 각각 3회 이상 적중한 부분을 결합합니다. 완성 시드는 학습 구간에서 최소 6회 적중합니다. 후보 예산은 홀수·짝수 각각 20억 개이며, 평가 성적을 보고 탐색 범위나 생존 조건을 바꾸지 않습니다.

실제 결과와 예시 시드는 [실험 보고서](../data/lotto/reports/seed-six/report.md), 전체 시드와 적중 회차는 `data/lotto/reports/seed-six/selection.json`에 저장합니다.

## 실제 결과

홀수·짝수 각각 20억 후보를 모두 검사했습니다. 홀수에서 3회 적중한 부분 3개, 짝수에서 3회 적중한 부분 1개를 찾아 완성 시드 3개를 만들었습니다. 모두 정확히 6회 적중했고 탐색한 조건에서 7회 이상 시드는 없었습니다. 선별에 약 387.86초, 평가에 약 0.56초가 걸렸습니다.

- `95d4f445dac194e9eee160f4852da09c`: 1·2·366·464·517·569회
- `d8491b46906436eceee160f4852da09c`: 1·2·366·389·464·561회
- `fe2306fc33a82bbfeee160f4852da09c`: 1·2·43·277·366·464회

검증 741~990회의 평균 일치는 생존군 0.762667개, 무작위 대조군 0.799646개였습니다. 최종 991~1238회도 생존군 0.783602개, 대조군 0.800482개였습니다. 이후 498회에서 생존군 1등 적중은 0회였습니다.

같은 부분 공유 구조의 대조군 10,000개 중 66.77%가 최종 구간에서 생존군 이상이었습니다. 생존군 평균은 대조군의 95% 참고 범위 안에 있습니다. 최종 최고 시드 평균 일치도 0.794355개로, 대조군 최고값의 80.97%가 이 이상이었습니다. 이번 실험에서는 과거 6회 적중 시드의 이후 예측 우위가 나타나지 않았습니다.

테스트 23개를 통과했습니다. 독립 스칼라 Python으로 완성 시드 3개 × 1,238회 = 3,714티켓을 검증했고 학습 적중 및 이후 분포가 모두 일치했습니다. 공유 부분을 제외하고 직접 복원한 스트림별 회차 번호는 2,476개입니다.

## 앞선 실험에서 바뀐 점

직전 5회 적중 실험의 후보 수는 홀수 10억 개, 짝수 200만 개였습니다. 이번에는 홀수를 2배, 짝수를 1,000배로 확대했습니다. 홀수 생존 기준은 3회를 유지하고 짝수 생존 기준을 2회에서 3회로 올렸습니다.

양쪽 모두 첫 담당 회차의 적중을 만드는 역상들을 중복 없는 아핀 순열로 열거합니다. 홀수는 앞선 탐색 순서의 확장이며, 짝수는 앞선 무작위 표본 방식에서 아핀 순회로 바뀌었습니다. 생성기 자체와 홀짝 회차별 부분 사용 규칙은 같습니다. 첫 두 적중은 역산으로 만든 조건이며 예측 성과가 아닙니다.

두 부분을 별도 프로세스에서 동시에 탐색하고, 각 부분의 네이티브 계산에는 스레드 네 개를 사용합니다. 배치당 1억 후보를 계산해 홀수·짝수별 별도 파일로 기록합니다. 전체 고정 예산을 끝까지 계산한 뒤 생존 부분의 모든 조합을 평가합니다.

## 평가와 검증

학습 구간은 1~740회, 검증은 741~990회, 최종 평가는 991~1238회입니다. 무작위 대조군 10,000개는 생존군과 같은 홀수·짝수 부분 개수 및 전체 결합 구조를 사용합니다. 여러 완성 시드가 같은 부분을 공유하는 상관을 무시하지 않고, 생성 티켓 수와 공유 스트림 수를 따로 기록합니다.

최고 시드도 대조군에서 같은 수 중 최고를 고른 결과와 비교합니다. 평가 결과로 좋은 시드만 다시 추리거나 추천으로 채택하지 않습니다. 이후 회차의 자료는 선별 작업에 전달하지 않습니다.

네이티브에서 찾은 각 부분은 Python으로 학습 적중 횟수를 다시 계산합니다. 독립 스칼라 검증 스크립트는 128비트 시드의 실제 6개 번호를 복원해 모든 학습 적중과 이후 분포를 대조합니다. 최소 적중 조건도 홀수 3회·짝수 3회로 검사합니다.

테스트는 짝수 네이티브 탐색의 3회 조건, 3+3회 결합, 순차·병렬 실행의 전체 결과 일치, 평가 당첨번호 변경 시 선별 불변, 홀수·짝수 배치 기록의 분리 등을 포함합니다. 기존 3+2회 실험도 계속 실행할 수 있게 유지했습니다.

## 재현

```powershell
New-Item -ItemType Directory -Force .local-build
g++ -O3 -march=native -std=c++17 -pthread -static src/lotto_seed_scan.cpp -o .local-build/lotto_seed_scan.exe
python src/lotto_seed_six.py --executable .local-build/lotto_seed_scan.exe --output .local-build/six-repeat
python -m pytest tests/test_lotto_seed_six.py tests/test_lotto_seed_five.py tests/test_lotto_seed_128.py tests/test_lotto_seed_expanded.py tests/test_lotto645.py -q
python scripts/verify_lotto_seed_128.py --report data/lotto/reports/seed-six
```

후보 수는 `--odd-candidates`, `--even-candidates`, 병렬 설정은 `--workers`, `--native-threads`로 실행 전에 정합니다. 설정·소스·실행 파일·원장 해시는 `protocol.json`, 배치별 전체 적중 분포는 `odd-batch-*.json`과 `even-batch-*.json`에 저장합니다. 기존 결과 디렉터리를 덮어쓰지 않습니다. `--even-search-seed`는 기존 3+2회 실험의 무작위 표본용 옵션이며, 이번 아핀 순회에서는 `--offset`과 `--stride`가 후보 열거를 결정합니다.

## 해석의 범위

이번 조건은 3+3회입니다. 2+4회나 1+5회 등 모든 배분의 6회 적중 시드를 전수 탐색한 것은 아닙니다. 부분 후보 수의 곱을 실제 검사한 독립 시드 수로 해석하지 않습니다.

이미 확인한 평가 구간을 재사용한 후향 탐색입니다. 비교 비율은 설명용이며 새로운 미래 성능의 확증 검정이 아닙니다. 더 많이 맞는 과거 시드를 찾거나 병렬 계산으로 더 많은 후보를 검사한 사실만으로 미래 예측력의 개선을 주장하지 않습니다.
